# Computer Science Major 101 (1/10): 컴퓨터학과에서는 무엇을 배우는가

처음 전공 과목표를 펼치면 이름부터 서로 너무 다르게 보입니다. 수학, 프로그래밍, 시스템, 데이터, AI, 프로젝트가 한 학과 안에 왜 함께 들어 있는지 감이 잘 오지 않습니다.

이 글은 컴퓨터학과 전공 학습 가이드 101 시리즈의 첫 번째 글입니다.

![Computer Science Major 101 1장 흐름 개요](https://yeongseon-books.github.io/book-public-assets/assets/computer-science-major-101/01/01-01-major-learning-map.ko.png)
*컴퓨터학과 전공 가이드 1장 흐름 개요*

> 컴퓨터학과의 핵심은 과목 이름을 외우는 것이 아니라, 각 영역이 다음 영역을 위한 기초가 되는 방식을 이해하는 데 있습니다.

## 이 글에서 다룰 문제

- 컴퓨터학과 4년 과정은 어떤 큰 축으로 이해하면 좋을까요?
- 수학, 프로그래밍, 시스템, 데이터, AI, 프로젝트는 왜 따로 떨어진 과목이 아니라 이어진 흐름일까요?
- 과목 이름만 외우는 것과 전공 지도를 이해하는 것은 무엇이 다를까요?
- 전공 지도를 모르면 실무에서 어떤 문제가 생길까요?
- 초보자가 전공 구조에서 가장 자주 놓치는 포인트는 무엇일까요?

## 왜 이렇게 구성되었는가

컴퓨터학과 커리큘럼을 처음 보는 학생이 가장 많이 하는 말은 "이걸 다 배워야 해?"입니다. 과목 수가 많고 이름도 생소하며, 서로 무슨 관계인지 설명해 주는 사람도 드뭅니다. 전공 첫 학기가 지나도 "내가 왜 미적분을 배우는지 모르겠다"는 느낌이 남는 이유입니다.

이 혼란의 핵심 원인은 하나입니다. 과목의 **이름**은 알지만 과목 간 **의존성**을 모른다는 것입니다. 미적분이 머신러닝의 최적화 직관으로 이어진다는 것, 운영체제가 성능 디버깅의 기반이 된다는 것, 자료구조가 데이터베이스 인덱스 설계와 직접 연결된다는 것을 모르면 4년이 단절된 과목들의 나열처럼 느껴집니다.

전공의 큰 그림이 없으면 4년이 생각보다 쉽게 흩어집니다. 반대로 지도가 있으면 지금 듣는 과목이 왜 필요한지, 다음 과목과 어떻게 이어지는지, 어디를 더 보강해야 하는지가 분명해집니다.

## 전공의 여섯 축

전공은 과목 목록이 아니라 흐름입니다. 수학과 프로그래밍이 출발점이 되고, 그 위에 시스템 이해가 올라가고, 데이터와 AI가 응용 축을 만들며, 마지막에는 프로젝트가 앞선 지식을 실제 결과물로 묶습니다.

- **전공(major)**: 대학에서 가장 깊게 배우는 주된 분야입니다.
- **전공 필수 과목(core course)**: 반드시 이수해야 하는 핵심 과목입니다.
- **전공 선택 과목(elective)**: 관심에 따라 고를 수 있는 과목입니다.
- **트랙(track)**: 전공 안의 세부 전문화 방향입니다.
- **캡스톤(capstone)**: 졸업 전후에 수행하는 종합 프로젝트입니다.

> 전공은 과목 이름의 모음이 아니라, 기초에서 응용과 프로젝트로 이동하는 학습 지도입니다.

## 커리큘럼 지도: 과목 분류표

전공 과목표를 제대로 읽으려면 과목 이름을 사전처럼 외우는 방식에서 벗어나야 합니다. 가장 먼저 할 일은 과목을 문제 종류 기준으로 다시 묶는 것입니다.

| 분류 축 | 대표 과목 | 먼저 확보할 능력 | 이후 직접 연결되는 과목 |
| --- | --- | --- | --- |
| 수학 기초 | 미적분, 선형대수, 이산수학, 확률통계 | 식을 해석하고 가정을 분해하는 능력 | 알고리즘, ML, 컴퓨터그래픽스 |
| 프로그래밍 기초 | 프로그래밍 입문, 객체지향, 자료구조 실습 | 문제를 함수·모듈 단위로 분해하는 능력 | 시스템 프로그래밍, 백엔드 프로젝트 |
| 시스템 코어 | 컴퓨터구조, 운영체제, 컴파일러, 네트워크 기초 | 실행 경로와 자원 비용을 읽는 능력 | 성능 최적화, 분산 시스템 |
| 데이터 코어 | 데이터베이스, SQL, 데이터모델링 | 저장 구조와 조회 패턴을 설계하는 능력 | 데이터 엔지니어링, 분석 플랫폼 |
| 지능형 응용 | 머신러닝, 딥러닝, 데이터마이닝 | 특징·라벨·평가 지표를 정의하는 능력 | 추천 시스템, 비전, NLP |
| 통합 실전 | 소프트웨어공학, 캡스톤, 팀 프로젝트 | 요구사항을 일정과 산출물로 바꾸는 능력 | 취업 포트폴리오, 대학원 연구 |

이 표의 핵심은 과목 난이도 비교가 아니라 의존성 이해입니다. 예를 들어 운영체제를 듣기 전에 프로그래밍 입문과 자료구조 감각이 없으면 스케줄링이나 메모리 관리 개념을 코드로 연결하기 어렵습니다. 반대로 자료구조를 잘 이해하고도 데이터베이스 모델링이 약하면 서비스 개발에서 조회 패턴을 설명하지 못하게 됩니다.

## 왜 여기서 막히는가: 흔한 시나리오

**시나리오 1 — "수학은 시험 과목인 줄 알았는데"**

지수는 2학년 때 자료구조 과목을 들었습니다. 알고리즘 분석 파트에서 점화식이 나왔고, 지수는 이산수학에서 점화식을 본 기억은 있지만 어떻게 푸는지 기억이 나지 않았습니다. 수업을 따라가기는 했지만 복잡도 증명 문제에서 계속 막혔습니다. 이산수학을 "시험용"으로만 공부했기 때문입니다.

이 경우 발생하는 신호: 알고리즘 분석 파트에서 논리 점프가 잦아지고, "외워서 쓰는" 방식으로 버티게 됩니다.

해결 방향: 이산수학의 증명 구조를 복잡도 분석과 연결해 다시 정리하는 것입니다. "이 점화식이 O(n log n)이 되는 이유를 한 문장으로 설명할 수 있는가"를 기준으로 삼으면 됩니다.

**시나리오 2 — "프로그래밍은 잘하는데 시스템이 왜 필요하지?"**

민준은 Python을 잘 다루고 웹 개발 토이 프로젝트도 여러 개 해 봤습니다. 그런데 운영체제 과목에서 프로세스, 스케줄링, 메모리 페이징을 배우다 "이게 실제 개발에서 뭔 소용인가?"라는 생각이 들었습니다. 4학년 때 서버 성능 이슈를 디버깅하면서 처음으로 "아, 그때 그걸 배웠어야 했구나"를 깨달았습니다.

이 경우 발생하는 신호: 성능 병목 원인을 "서버가 느린 것 같다"는 수준으로만 설명하게 됩니다. 시스템 지식이 없으면 CPU-bound인지 I/O-bound인지조차 구분하지 못합니다.

해결 방향: 운영체제 과목을 들을 때 각 개념을 "실제 장애 상황에서 어떤 신호로 보이는가"와 매핑해 정리하면 추상적 암기에서 벗어날 수 있습니다.

**시나리오 3 — "선택 과목을 너무 자유롭게 골랐다"**

수아는 재미있어 보이는 과목만 골라 들었습니다. AI 관련 선택 과목을 3개 들었는데 막상 수업에서 행렬 역전파(backpropagation) 계산이 나오자 선형대수가 약해서 따라가기 어려웠습니다. 필수 과목 의존성을 먼저 채우지 않고 응용 과목부터 들은 결과입니다.

이런 경우 수업을 포기하거나 계산만 따라하고 원리는 이해 못 한 채 학점을 받게 됩니다. 졸업 후 같은 개념을 업무에서 만나도 스스로 설명하지 못합니다.

## 선행 과목 의존성 표

| 과목 영역 | 선행 과목 | 바로 이어지는 과목 | 놓쳤을 때 나타나는 신호 |
| --- | --- | --- | --- |
| 이산수학 | 기초 수학 | 자료구조, 알고리즘 | 증명형 문제에서 논리 점프가 잦아집니다 |
| 프로그래밍 기초 | 없음 | 자료구조, 시스템 프로그래밍 | 구현 속도는 빠른데 오류율이 높아집니다 |
| 자료구조 | 프로그래밍 기초, 이산수학 | 알고리즘, 데이터베이스, 운영체제 | 복잡도 분석 없이 코드를 완성 여부로만 평가합니다 |
| 컴퓨터구조 | 기초 프로그래밍 | 운영체제 | 성능 병목 원인을 추측으로만 설명합니다 |
| 데이터베이스 | 프로그래밍 기초 | 백엔드 프로젝트 | SQL은 작성하지만 스키마 근거를 설명하기 어렵습니다 |
| 확률·통계 | 미적분, 선형대수 | 머신러닝 | 지표 해석에서 과신 또는 과소평가가 반복됩니다 |

의존성 표는 수강 신청 전에 한 번 읽어 두면 됩니다. 선행 과목이 비어 있는 상태로 응용 과목을 듣는 것이 가장 많은 시간 낭비를 만들기 때문입니다.

## 나만의 전공 지도 만들기

전공 지도를 실제로 만들어 보면 어떤 과목이 어디에 놓이는지 감이 빠르게 옵니다.

```python
areas = ["math", "programming", "systems", "data", "ai", "project"]

# 학년별 무게 배치 (대략적인 기준)
plan = {
    1: ["math", "programming"],
    2: ["systems", "programming"],
    3: ["data", "ai"],
    4: ["project", "ai"]
}

# 영역별 학점 배분 예시
credits = {
    "math": 9,
    "programming": 9,
    "systems": 9,
    "data": 6,
    "ai": 6,
    "project": 6
}

total = sum(credits.values())  # 45학점

# 약한 영역 찾기 (6학점 미만)
weak = [a for a, c in credits.items() if c < 6]
print(f"보강 필요 영역: {weak}")

# 진로별 추천 강화 축
career_emphasis = {
    "backend": ["systems", "data", "programming"],
    "ml_engineer": ["math", "ai", "programming"],
    "data_engineer": ["math", "data", "systems"],
    "security": ["systems", "programming"],
}
```

이 코드는 실제 학점표가 아니라 균형 감각을 보기 위한 모델입니다. 특정 축이 지나치게 비어 있지는 않은지 확인하는 데 도움이 됩니다.

## 이 과목이 실무에서 어떻게 쓰이는가

채용 공고를 차분히 읽어 보면 전공 과목의 조합과 크게 다르지 않습니다.

| 목표 직무 | 핵심 과목 조합 | 실무 연결 포인트 |
| --- | --- | --- |
| 백엔드 엔지니어 | 자료구조, 운영체제, 데이터베이스, 네트워크 | API 지연 진단, 쿼리 최적화, 시스템 장애 분석 |
| 데이터 엔지니어 | 확률통계, 데이터베이스, 알고리즘, 분산시스템 | 파이프라인 설계, 처리량 최적화, 데이터 품질 |
| ML 엔지니어 | 선형대수, 확률통계, 머신러닝, 프로그래밍 | 특성 설계, 모델 평가, 서빙 최적화 |
| 보안 엔지니어 | 운영체제, 네트워크, 암호학, 시스템 프로그래밍 | 취약점 분석, 로그 탐색, 침투 테스트 |
| 게임 클라이언트 | 컴퓨터그래픽스, 선형대수, 자료구조, C++ | 렌더링 최적화, 물리 시뮬레이션, 메모리 관리 |
| 임베디드/펌웨어 | 컴퓨터구조, C, 운영체제 기초 | 인터럽트 처리, 메모리 매핑, 전력 최적화 |

직무마다 강조하는 과목 축이 다르지만, 어떤 직무에서도 기초 두 축(수학, 프로그래밍)은 공통입니다. 기초 축을 건너뛰고 응용 직무를 목표로 하면 면접에서 기초 질문에 막히는 패턴이 반복됩니다.

## 진로를 역추적해 과목 조합 설계하기

전공 지도를 실제 의사결정에 쓰려면 관심 진로에서 역방향으로 과목 조합을 추적해야 합니다.

- **백엔드 엔지니어**: 자료구조 → 운영체제 → 네트워크 → 데이터베이스 → 소프트웨어공학
- **데이터 직무**: 선형대수 + 확률통계 → 데이터베이스 → 머신러닝 → 실험 설계
- **보안 직무**: 운영체제 + 네트워크 → 암호학 → 시스템 프로그래밍 → 로그 분석
- **연구/AI**: 선형대수 + 미적분 + 확률통계 → 머신러닝 → 딥러닝 → 논문 구현

역추적의 구체적인 방법은 목표 직무의 최신 JD(Job Description)를 5개 이상 모아 공통 키워드를 뽑는 것입니다. 키워드가 어떤 과목과 연결되는지 위 의존성 표와 대조하면 수강 계획이 구체화됩니다.

진로가 다르면 강조점은 달라지지만 기초 축을 건너뛸 수는 없습니다. 공통 원칙은 "기초를 먼저 고정하고, 응용을 나중에 확장한다"입니다.

## 수강 전략 체크포인트

학기 시작 전에 아래 네 가지 질문을 쓰면 계획의 품질이 빠르게 올라갑니다.

1. 이번 학기 과목 중 다른 과목의 전제가 되는 과목은 무엇인가.
2. 프로젝트에 바로 쓰일 과목은 무엇이고, 선행 보강이 필요한가.
3. 팀 과제에서 내가 책임질 수 있는 축은 무엇인가.
4. 다음 학기 목표 과목을 위해 지금 어떤 구멍을 메워야 하는가.

학기 단위로는 "기초 2 + 응용 1 + 통합 1" 비율을 권장합니다. 기초 과목 두 개로 바닥을 유지하고, 응용 과목 하나로 동기를 확보하고, 통합 과목 하나로 산출물을 남기는 방식입니다. 이 비율을 유지하면 성취감과 내실 사이 균형이 무너지지 않습니다.

## 학년별 일반적인 흐름

학교마다 세부 과목 이름과 순서는 다르지만, 아래 흐름은 대부분의 국내외 컴퓨터학과에서 공통적으로 나타납니다.

**1학년**: 수학 기초(미적분, 선형대수, 이산수학)와 프로그래밍 입문을 동시에 진행합니다. 두 축이 동시에 시작되는 이유는 이후 모든 과목에서 두 능력이 함께 필요하기 때문입니다.

**2학년**: 자료구조와 알고리즘, 컴퓨터구조, 운영체제 입문이 등장합니다. 코드를 실제로 돌리는 무대를 이해하는 단계입니다.

**3학년**: 데이터베이스, 네트워크, 머신러닝 입문, 소프트웨어공학이 쌓입니다. 응용 영역과 팀 협업 역량이 동시에 요구되기 시작합니다.

**4학년**: 캡스톤 프로젝트, 심화 선택 과목, 인턴십, 취업 준비가 겹칩니다. 이 시점에 기초가 약하면 프로젝트에서 구현이 아니라 생존에 에너지를 씁니다.

## 자주 하는 실수 5가지

1. **전공 필수 과목을 마지막 학기까지 미루는 일입니다.** 의존성이 있는 과목을 늦게 들으면 이후 선택 과목 기회가 좁아집니다.
2. **이론만 보거나 실습만 보는 식으로 한쪽만 고르는 일입니다.** 개념과 구현은 세트로 누적됩니다.
3. **초반 수학의 중요성을 과소평가하는 일입니다.** 알고리즘, AI, 그래픽스 모두 수학 감각 위에 서 있습니다.
4. **프로젝트를 단순한 학점 채우기로 보는 일입니다.** 포트폴리오 자산이 될 수 있는 기회를 흘려보냅니다.
5. **과목과 진로를 따로 생각해서 연결하지 않는 일입니다.** 목표 직무를 먼저 정하면 수강 계획이 달라집니다.

## 전공 지도를 기록으로 남기는 방법

지도를 머릿속에만 두면 학기마다 리셋됩니다. 노트나 스프레드시트에 아래 형식으로 기록해 두면 3학년 이후에도 참조할 수 있습니다.

- 과목명 / 영역 분류 / 선행 과목 / 핵심 개념 3가지 / 이후 연결 과목 / 실습 산출물

예를 들어 "운영체제 / 시스템 코어 / 컴퓨터구조, 프로그래밍 기초 / 프로세스·스케줄링·메모리 가상화 / 분산시스템, 성능 엔지니어링 / 미니 쉘 구현"처럼 한 줄로 정리할 수 있습니다. 이 표가 10개 과목만 채워져도 전공 지도의 60%는 완성됩니다.

## 운영 체크리스트

- [ ] 전공을 큰 영역으로 나눠 보았습니다.
- [ ] 각 영역이 어느 학년에 많이 나오는지 적어 보았습니다.
- [ ] 선행 과목 의존성 표를 내 상황에 맞게 확인했습니다.
- [ ] 목표 직무에서 역추적해 필요한 과목 조합을 정리했습니다.
- [ ] 약한 축을 보강할 계획을 하나 적어 보았습니다.
- [ ] 현재까지 들은 과목을 영역별로 분류해 보았습니다.
- [ ] 다음 학기 수강 신청 전에 선행 과목 확인을 마쳤습니다.

## 처음 질문으로 돌아가기

- **컴퓨터학과 4년 과정은 어떤 큰 축으로 이해하면 좋을까요?**
  - 수학/프로그래밍(기초) → 시스템(이해) → 데이터/AI(응용) → 프로젝트(통합)로 이어지는 여섯 축으로 이해하면 과목이 단절되어 보이지 않습니다. 1학년의 수학이 4학년 프로젝트에서 쓰이는 경로가 있다는 것을 처음부터 알면 동기 유지도 달라집니다.

- **수학, 프로그래밍, 시스템, 데이터, AI, 프로젝트는 왜 이어진 흐름일까요?**
  - 각 축이 다음 축의 전제가 됩니다. 수학 없이 알고리즘이 흔들리고, 시스템 없이 성능 디버깅이 막히고, 데이터 없이 AI가 허공에 뜹니다. 지수 시나리오처럼 한 축을 "시험용"으로만 공부하면 이어진 과목에서 정확히 그 구멍이 다시 드러납니다.

- **과목 이름만 외우는 것과 전공 지도를 이해하는 것은 무엇이 다를까요?**
  - 지도가 있으면 새 과목을 들을 때 "이 과목이 어떤 선행 지식을 요구하고 어디로 연결되는지"를 먼저 파악할 수 있습니다. 지도 없이는 과목마다 처음부터 다시 시작하는 느낌이 반복됩니다. 수아 시나리오가 이 차이를 잘 보여 줍니다.

- **전공 지도를 모르면 실무에서 어떤 문제가 생길까요?**
  - 성능 문제를 접했을 때 어느 계층에서 원인을 찾아야 하는지 모르게 됩니다. 네트워크, 운영체제, 데이터베이스, 코드 로직 중 어디를 먼저 보아야 하는지 기준이 없기 때문입니다. 민준 시나리오처럼 "서버가 느린 것 같다"는 수준에서 멈추게 됩니다.

- **초보자가 전공 구조에서 가장 자주 놓치는 포인트는 무엇일까요?**
  - 과목 간 의존성을 모른다는 점입니다. 어떤 과목이 어떤 과목의 바닥이 되는지 모르면 선행이 부실한 상태에서 응용 과목을 들어 계속 막히게 됩니다. 의존성 표 한 장이 이 문제를 크게 줄여 줍니다.

## 정리

컴퓨터학과는 과목 이름이 많은 학과가 아니라, 수학과 프로그래밍에서 출발해 시스템, 데이터, AI, 프로젝트로 이어지는 구조를 가진 학과입니다. 이 지도를 먼저 잡아 두면 이후 과목이 훨씬 덜 단절되어 보입니다. 지도는 수강 신청 시즌마다 꺼내 보는 도구입니다. 다음 글에서는 1학년 과목이 왜 그렇게 배치되는지 더 구체적으로 봅니다.
