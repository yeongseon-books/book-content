# Computer Science Major 101 (6/10): AI와 데이터사이언스

AI와 데이터사이언스는 가장 화려해 보이는 분야이지만, 막상 들어가 보면 통계와 데이터 정리, 평가와 검증 같은 기초 작업이 훨씬 더 많은 비중을 차지합니다.

이 글은 Computer Science Major 101 시리즈의 6번째 글입니다.

![Computer Science Major 101 6장 흐름 개요](https://yeongseon-books.github.io/book-public-assets/assets/computer-science-major-101/06/06-01-ai-learning-pipeline.ko.png)
*컴퓨터학과 전공 가이드 6장 흐름 개요*

> AI와 데이터사이언스의 핵심은 모델이나 기법이 아니라, 데이터의 가정과 문제 상황을 올바르게 짝지어 선택하는 데 있습니다.

## 이 글에서 다룰 문제

- AI와 데이터사이언스는 전공 안에서 어떻게 나뉘고 어떻게 연결될까요?
- 통계, 머신러닝, 딥러닝, 데이터 분석은 어떤 흐름으로 이어질까요?
- 모델만 보는 공부가 왜 금방 한계에 부딪힐까요?
- 선행 과목이 약하면 AI/ML 과목에서 어떤 패턴으로 막히게 될까요?
- 학부 단계에서 AI 학습을 제대로 쌓는 방법은 무엇일까요?

## 왜 통계와 수학 선행이 중요한가

AI와 데이터사이언스 과목은 화려해 보이지만 실제로는 통계와 수학이 튼튼하게 깔려 있어야 합니다. 이 바닥이 약하면 모델을 쓸 수는 있어도 무슨 일이 벌어지는지 이해하지 못한 채 블랙박스처럼 다루게 됩니다.

- **선형대수**: 행렬 곱, 고유값 분해가 신경망 가중치 업데이트와 PCA의 기반입니다.
- **미적분**: 경사 하강법은 손실 함수를 편미분해 최솟값을 찾습니다. 학습률이 왜 중요한지는 미분 감각 없이 설명하기 어렵습니다.
- **확률·통계**: 베이즈 정리, 분포, 가설검정이 데이터 편향 진단과 모델 평가의 언어입니다.

데이터가 출발점이고, 통계는 그 데이터를 읽는 언어입니다. 머신러닝과 신경망은 그 위에서 예측 모델을 만들고, 분석은 결과를 해석하고 실제 문제에 연결합니다.

## 핵심 개념

- **특성(feature)**: 모델이 입력으로 받는 변수입니다.
- **레이블(label)**: 맞혀야 하는 목표 값입니다.
- **학습(training)**: 데이터로부터 패턴을 익히는 과정입니다.
- **추론(inference)**: 학습한 모델로 예측을 수행하는 과정입니다.
- **과적합(overfitting)**: 학습 데이터에는 잘 맞지만 새 데이터에서 성능이 떨어지는 현상입니다.
- **편향-분산 트레이드오프(bias-variance tradeoff)**: 모델 복잡도가 높을수록 편향은 줄지만 분산이 커집니다.

> 데이터는 재료이고, 통계는 읽는 언어이며, 모델은 그 위에서 패턴을 계산하는 도구입니다.

## 왜 여기서 막히는가: 흔한 시나리오

**시나리오 1 — "모델 정확도가 99%인데 실제로는 쓸모없다"**

민아는 스팸 메일 분류 모델을 만들었는데 정확도가 99%가 나왔습니다. 자랑스럽게 발표했지만 교수가 "그 데이터셋에서 스팸 비율이 얼마인지 확인해 봤냐"고 물었습니다. 확인해 보니 99%가 정상 메일이었고, 모델이 모든 것을 "정상"으로 예측해도 99% 정확도가 나오는 구조였습니다. 클래스 불균형을 고려하지 않은 전형적인 실수입니다.

발생 신호: 정확도는 높은데 실제 예측이 한쪽으로만 쏠립니다. Precision, Recall이 한쪽은 0에 가깝습니다. 혼동 행렬(confusion matrix)을 보면 False Negative 또는 False Positive가 지배적입니다.

해결 방향: 데이터 분포를 먼저 확인하고, 불균형 데이터에는 정확도 대신 F1 점수, AUC-ROC 같은 지표를 사용해야 합니다. SMOTE 같은 오버샘플링이나 클래스 가중치 조정도 고려해야 합니다.

**시나리오 2 — "학습 데이터에서는 잘 되는데 테스트에서는 안 된다"**

상우는 학습 세트와 테스트 세트를 섞어 전처리를 한 뒤 나눴습니다. 정규화 통계(평균, 표준편차)를 전체 데이터로 계산한 것이 문제였습니다. 테스트 데이터의 정보가 학습에 새어 들어간 데이터 누수(data leakage) 상황입니다.

발생 신호: 학습 성능과 테스트 성능 차이가 비정상적으로 작습니다. 교차 검증 점수가 너무 높게 나옵니다. 실제 운영 환경에서 성능이 급락합니다.

해결 방향: 전처리 파라미터(평균, 스케일러)는 반드시 학습 세트로만 계산하고, 테스트 세트에는 그 파라미터를 그대로 적용해야 합니다. scikit-learn의 Pipeline을 쓰면 이 실수를 구조적으로 방지할 수 있습니다.

**시나리오 3 — "기준선 없이 복잡한 모델부터 썼다"**

하은은 수요 예측 프로젝트에서 바로 딥러닝을 도입했습니다. 모델이 왜 이런 예측을 하는지 이해할 수 없었고, 성능 개선 방향도 잡기 어려웠습니다. 단순 선형 회귀나 이동 평균 같은 기준선 모델을 먼저 세웠다면 어느 정도 향상이 의미 있는지 판단할 수 있었을 것입니다.

발생 신호: 고도화된 모델의 성능이 단순한 방법보다 왜 낫는지 설명하지 못합니다. 디버깅할 비교 기준이 없어서 오류 원인을 찾기 어렵습니다.

해결 방향: 무조건 평균값 예측, 최빈값 분류 같은 가장 단순한 기준선부터 만들고 단계별로 올라가야 합니다. 기준선 대비 얼마나 나은지를 수치로 보여야 개선이 증명됩니다.

## 미니 ML 파이프라인

```python
# 1단계 — 데이터: 입력과 정답의 짝
xs = [1, 2, 3, 4, 5]
ys = [2, 4, 6, 8, 10]

# 2단계 — 탐색적 분석: 모델 전에 데이터를 먼저 읽는다
avg_y = sum(ys) / len(ys)
print(f"평균: {avg_y}, 최솟값: {min(ys)}, 최댓값: {max(ys)}")

# 3단계 — 기준선 모델: 단순한 것부터 시작
baseline_pred = avg_y  # 가장 단순한 예측: 항상 평균값

baseline_mae = sum(abs(baseline_pred - y) for y in ys) / len(ys)
print(f"기준선 MAE: {baseline_mae:.2f}")

# 4단계 — 선형 회귀 기울기 계산
def slope(xs, ys):
    mx = sum(xs) / len(xs)
    my = sum(ys) / len(ys)
    num = sum((x - mx) * (y - my) for x, y in zip(xs, ys))
    den = sum((x - mx) ** 2 for x in xs)
    return num / den

def intercept(xs, ys, m):
    return sum(ys) / len(ys) - m * sum(xs) / len(xs)

m = slope(xs, ys)
b = intercept(xs, ys, m)
print(f"기울기: {m:.2f}, 절편: {b:.2f}")

# 5단계 — 예측과 평가
preds = [m * x + b for x in xs]
mae = sum(abs(p - y) for p, y in zip(preds, ys)) / len(ys)
print(f"선형 회귀 MAE: {mae:.2f}")
print(f"기준선 대비 개선: {(baseline_mae - mae) / baseline_mae * 100:.1f}%")

# 6단계 — 평가 지표 선택: 문제 유형에 따라 다르다
def precision(tp, fp):
    return tp / (tp + fp) if (tp + fp) > 0 else 0.0

def recall(tp, fn):
    return tp / (tp + fn) if (tp + fn) > 0 else 0.0

def f1(p, r):
    return 2 * p * r / (p + r) if (p + r) > 0 else 0.0
```

이 코드에서 주목할 점:
- 탐색적 분석이 모델보다 먼저 옵니다.
- 기준선(baseline)이 없으면 개선 여부를 증명할 수 없습니다.
- 평가 지표(MAE)를 고정해야 두 모델을 공정하게 비교할 수 있습니다.
- 분류 문제에서 Precision, Recall, F1은 세트로 봐야 합니다.

## 이 과목이 실무에서 어떻게 쓰이는가

데이터 감각은 이제 특정 직무만의 능력이 아니라 거의 모든 현대 엔지니어에게 필요한 기본기입니다.

**백엔드 엔지니어**: A/B 테스트를 설계하고 결과를 해석합니다. 두 버전의 전환율 차이가 통계적으로 유의한지 판단해야 합니다.

**데이터 엔지니어**: 파이프라인에서 데이터 품질을 검증합니다. 분포 변화(distribution shift)를 감지해야 다운스트림 모델이 안전합니다.

**ML 엔지니어**: 모델 운영 중 성능 모니터링이 핵심입니다. 학습 당시 데이터와 운영 데이터가 달라지면(data drift) 성능이 빠르게 하락합니다.

| 문제 유형 | 입력 데이터 | 1차 기준선 | 고도화 방향 | 핵심 지표 |
| --- | --- | --- | --- | --- |
| 이진 분류 | 고객 이탈 여부, 스팸 여부 | 로지스틱 회귀 | 트리 앙상블, 신경망 | Precision/Recall/F1 |
| 회귀 | 수요 예측, 가격 예측 | 선형 회귀 | GBM, 시계열 모델 | MAE/RMSE |
| 군집 | 사용자 세그먼트 | K-means | HDBSCAN, 임베딩 기반 군집 | 실루엣 점수, 해석 가능성 |
| 추천 | 사용자-아이템 로그 | 인기순 baseline | 협업 필터링, 딥러닝 | CTR, NDCG |
| 이상 감지 | 서버 로그, 금융 거래 | 통계적 임계값 | 오토인코더, 고립 포레스트 | Recall, FPR |

## 통계 과목과 ML 과목의 연결 지점

- 표본과 모집단 개념은 데이터 편향을 설명하는 출발점입니다.
- 분산과 공분산 이해는 특성 스케일링과 상관 구조 해석에 필요합니다.
- 가설검정 개념은 성능 차이가 우연인지 아닌지 판단하는 근거입니다.
- 과적합/과소적합 진단은 편향-분산 균형 감각과 직결됩니다.

즉, 통계는 ML을 위한 선택 과목이 아니라 안전장치입니다. 통계가 약하면 모델 성능 숫자를 과신하기 쉽고, 운영에서 성능 하락 원인을 잘못 해석하게 됩니다.

## 선행 과목 의존성

| 선행 과목 | AI/ML에서 사용되는 장면 | 없을 때 나타나는 신호 |
| --- | --- | --- |
| 선형대수 | 가중치 행렬, 역전파, PCA | 신경망 구조 이해 불가, 차원 축소 설명 불가 |
| 미적분 | 경사 하강법, 역전파, 학습률 | 모델이 왜 학습되는지 설명 불가 |
| 확률·통계 | 손실 함수, 정규분포, 베이즈 | 모델 성능 해석 오류, 데이터 편향 감지 불가 |
| 프로그래밍 | 실험 구현, 데이터 전처리 | NumPy 브로드캐스팅 오류, 코드 디버깅 어려움 |
| 자료구조 | 효율적 데이터 전처리, 그래프 탐색 | 대용량 처리 병목, 그래프 신경망 이해 어려움 |

선행 과목 감각이 없을 때 가장 먼저 드러나는 증상은 "라이브러리를 쓸 수는 있는데 왜 이런 결과가 나오는지 모른다"입니다. 이 상태에서는 하이퍼파라미터를 바꿔도 이유를 모르고 바꾸게 됩니다.

## 데이터 품질 체크리스트

모델보다 데이터를 먼저 확인하는 습관이 모든 AI/ML 작업의 기본입니다.

**탐색 단계**:
- 각 컬럼의 데이터 타입과 결측값 비율 확인
- 수치형 변수의 분포(히스토그램, 박스플롯) 확인
- 범주형 변수의 고유값 수와 빈도 확인
- 레이블 분포 확인 (클래스 불균형 감지)

**전처리 단계**:
- 결측값 처리 전략 결정 (삭제/평균/보간/모델 예측)
- 스케일링 방법 선택 (표준화/정규화/로그 변환)
- 학습/검증/테스트 분할을 전처리 전에 수행
- 시계열 데이터는 시간 순서를 유지한 분할

**검증 단계**:
- 학습 세트와 테스트 세트의 분포 비교
- 피처 중요도를 통한 데이터 누수 확인
- 교차 검증으로 분산 추정

## 실전형 학습 루프

1. 문제를 비즈니스 문장으로 다시 쓰기: "모델을 만든다" → "고객이 다음 달에 이탈할 확률을 예측한다"
2. 라벨 정의와 평가 지표를 먼저 고정하기
3. 기준선 모델 구축 후 오차 사례 분석
4. 고도화 모델 도입 전 데이터 품질 점검
5. 결과를 재현 가능한 노트/리포트로 기록

이 루프를 한 번이라도 끝까지 돌려 보면 AI 과목이 도구 사용 과목이 아니라 판단 과목이라는 점이 분명해집니다. "어떤 모델을 쓸까"보다 "무엇을 예측할 것인가"와 "어떻게 평가할 것인가"가 먼저라는 감각이 생깁니다.

## 논문 읽기 가이드와 실험 기록 템플릿

AI 과목에서는 논문을 읽고 구현 가설로 바꾸는 능력이 중요합니다. 아래 순서로 읽으면 최신 모델 문서도 과장 없이 해석할 수 있습니다.

1. 문제 정의와 평가 지표를 먼저 확인합니다.
2. 데이터셋 구성과 전처리 조건을 확인합니다.
3. 기준선 대비 개선폭과 통계적 유의성을 확인합니다.
4. 실패 사례와 한계 항목을 먼저 기록합니다.
5. 내 과제에서 재현 가능한 최소 실험으로 축소합니다.

권장 실험 기록 템플릿: `가설`, `데이터`, `모델`, `지표`, `결과`, `다음 실험` 여섯 칸. 이 틀을 유지하면 캡스톤, 취업 포트폴리오 모두에서 일관된 품질을 유지할 수 있습니다.

## 딥러닝을 언제 써야 하는가

딥러닝은 강력하지만 모든 문제의 첫 번째 선택이 되어서는 안 됩니다. 딥러닝이 의미 있는 경우와 그렇지 않은 경우를 구분하는 기준이 필요합니다.

**딥러닝이 유리한 상황**:
- 데이터가 충분히 많을 때 (보통 수만 건 이상)
- 구조화되지 않은 데이터 (이미지, 텍스트, 음성)
- 특성 엔지니어링 비용이 높을 때
- 비선형 패턴이 복잡하게 얽혀 있을 때

**딥러닝보다 단순한 모델이 나을 수 있는 상황**:
- 데이터가 수백~수천 건 수준
- 결과 해석이 중요한 규제 산업 (금융, 의료)
- 실시간 추론이 필요하고 지연이 민감한 환경
- 특성과 목표 관계가 선형에 가까울 때

하은 시나리오처럼 처음부터 딥러닝을 쓰면 "왜 이렇게 예측하는가"를 설명할 수 없고, 오류 원인을 찾기도 어렵습니다. 단순 모델 → 트리 모델 → 딥러닝 순서로 올라가는 접근이 결국 더 빠릅니다.

## 자주 하는 실수 5가지

1. **데이터 누수를 만드는 일입니다.** 테스트 데이터 정보가 학습에 포함되면 실제 성능이 과장됩니다.
2. **학습 데이터와 테스트 데이터를 섞는 일입니다.** 전처리 전에 반드시 분리해야 합니다.
3. **스케일 차이를 무시한 채 비교하는 일입니다.** 연봉과 나이를 그대로 넣으면 스케일이 큰 값이 지배합니다.
4. **기준선 모델 없이 복잡한 모델부터 고르는 일입니다.** 개선 여부를 증명할 기준점이 없어집니다.
5. **평가 지표를 모호하게 두는 일입니다.** 정확도만으로는 클래스 불균형 문제를 놓칩니다.

## 운영 체크리스트

- [ ] 학습용과 평가용 데이터를 분리했습니다.
- [ ] 기준선 모델을 하나 세워 보았습니다.
- [ ] 어떤 지표로 비교할지 정했습니다.
- [ ] 시드 고정과 재현성의 의미를 이해했습니다.
- [ ] 데이터 분포를 탐색적으로 확인했습니다.
- [ ] 레이블 불균형이 있는지 확인했습니다.
- [ ] 전처리 파라미터를 학습 세트로만 계산했습니다.

## 처음 질문으로 돌아가기

- **AI와 데이터사이언스는 전공 안에서 어떻게 나뉘고 어떻게 연결될까요?**
  - 데이터사이언스는 데이터를 분석하고 인사이트를 뽑는 쪽에, AI/ML은 예측 모델을 만드는 쪽에 무게가 있습니다. 하지만 둘 다 통계와 데이터 품질이 바닥이 되고, 프로그래밍으로 구현합니다. 현실에서는 두 역할이 겹치는 경우가 훨씬 많습니다.

- **통계, 머신러닝, 딥러닝, 데이터 분석은 어떤 흐름으로 이어질까요?**
  - 통계가 데이터를 읽는 언어를 주고, 데이터 분석이 문제를 정의하고, 머신러닝이 패턴을 찾고, 딥러닝이 복잡한 패턴을 자동으로 학습합니다. 바닥이 약하면 위로 올라갈수록 더 많이 흔들립니다. 딥러닝부터 공부하면 통계가 필요할 때 처음부터 다시 시작해야 합니다.

- **모델만 보는 공부가 왜 금방 한계에 부딪힐까요?**
  - 모델은 파이프라인의 한 단계입니다. 데이터 품질이 낮거나 평가 기준이 잘못됐거나 전처리에 누수가 있으면 좋은 모델을 써도 결과가 의미 없어집니다. 민아 시나리오가 이 함정을 잘 보여 줍니다.

- **선행 과목이 약하면 AI/ML 과목에서 어떤 패턴으로 막히게 될까요?**
  - 선형대수가 약하면 역전파를 계산할 때 막힙니다. 통계가 약하면 민아 시나리오처럼 클래스 불균형을 놓칩니다. 프로그래밍이 약하면 실험을 구현하다가 NumPy 오류에서 멈춥니다. 이 세 가지가 갖춰져야 하나의 실험을 끝까지 돌릴 수 있습니다.

- **학부 단계에서 AI 학습을 제대로 쌓는 방법은 무엇일까요?**
  - 기준선부터 시작하는 습관이 핵심입니다. 복잡한 모델보다 단순한 모델이 왜 틀렸는지 분석하면 고도화 방향이 보입니다. 재현 가능한 실험 기록을 남기는 것이 두 번째입니다. 실험 기록 하나가 포트폴리오에서 가장 강한 증거가 됩니다.

## 정리

AI와 데이터사이언스는 다른 이름을 갖고 있지만, 전공 안에서는 데이터 이해와 모델링이라는 하나의 흐름 안에 놓여 있습니다. 통계와 데이터 분석이 바닥을 만들고, 그 위에 머신러닝과 딥러닝이 올라갑니다. "어떤 모델을 쓸까"보다 "무엇을 예측할 것인가, 어떻게 평가할 것인가"를 먼저 정하는 습관이 이 과목에서 가장 오래 남는 자산입니다. 다음 글에서는 이렇게 쌓은 지식을 실제 산출물로 묶는 프로젝트 과목을 봅니다.
