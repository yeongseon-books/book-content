# Computer Science Major 101 (8/10): 전공 공부 방법

같은 시간을 써도 어떤 학생은 개념이 남고, 어떤 학생은 강의 직후부터 빠르게 잊어버립니다. 차이를 만드는 것은 재능보다 공부 방법의 구조인 경우가 많습니다.

이 글은 컴퓨터학과 전공 학습 가이드 101 시리즈의 8번째 글입니다.

![Computer Science Major 101 8장 흐름 개요](https://yeongseon-books.github.io/book-public-assets/assets/computer-science-major-101/08/08-01-study-loop.ko.png)
*컴퓨터학과 전공 가이드 8장 흐름 개요*

> 효과적인 학습의 핵심은 수동적 이해가 아니라, 문제를 풀고, 설명하고, 틀리고, 다시 하는 능동적 루프에 있습니다.

## 이 글에서 다룰 문제

- 같은 시간을 써도 공부 방법에 따라 결과가 크게 달라지는 이유는 무엇일까요?
- 강의, 노트, 복습, 코딩 연습은 어떤 흐름으로 묶는 것이 좋을까요?
- 시험 직전 몰아서 하는 공부가 전공 과목에서 특히 잘 통하지 않는 이유는 무엇일까요?
- 과목 유형별로 학습 방법을 어떻게 다르게 설계해야 할까요?
- 질문하는 습관이 학습 속도를 얼마나 바꾸는가?

## 왜 공부 방법이 성과를 결정하는가

전공에서는 남은 차이를 만드는 요소가 공부 효율인 경우가 많습니다. 같은 강의를 들어도 복습 간격, 실습 빈도, 질문 습관이 다르면 이해 속도와 유지 시간이 크게 달라집니다.

강의를 듣는 순간이 끝이 아니라 시작입니다. 노트로 압축하고, 복습으로 다시 꺼내고, 연습으로 손을 움직이고, 질문으로 막힌 부분을 푸는 흐름이 반복되어야 실력이 붙습니다.

- **루틴(routine)**: 반복 가능한 학습 일정입니다. 완벽하지 않아도 일관성이 있어야 합니다.
- **노트(note)**: 핵심을 짧게 정리한 기록입니다. 나중에 타인이 읽어도 이해할 수 있어야 합니다.
- **복습(review)**: 이미 본 내용을 다시 확인하는 과정입니다. 48시간 내 1차 복습이 효과적입니다.
- **드릴(drill)**: 반복 연습 문제입니다. 이해와 구현은 별개입니다.
- **오피스 아워(office hour)**: 교수나 조교에게 질문할 수 있는 시간입니다.

## 왜 여기서 막히는가: 흔한 시나리오

**시나리오 1 — "강의는 다 이해했는데 시험 보면 모른다"**

영진은 강의를 들으면서 "아, 이해했다"는 느낌을 받습니다. 하지만 시험지를 받으면 어디서부터 시작해야 할지 모릅니다. 수동적 이해와 능동적 인출은 다릅니다. 강의를 보며 이해하는 것은 책을 보며 음악을 듣는 것과 같습니다. 직접 꺼내 보는 연습 없이는 시험에서 나오지 않습니다.

발생 신호: 강의 이해도는 높다고 생각하는데 문제 풀이에서 막힙니다. 비슷한 예제를 보면 알겠는데 새 문제는 어렵습니다.

해결 방향: 강의 직후 책을 닫고 배운 내용을 빈 종이에 써 보는 습관이 필요합니다. 떠오르지 않는 부분이 실제로 모르는 부분입니다.

**시나리오 2 — "시험 전날 밤을 새웠는데 일주일 후 아무것도 기억 안 난다"**

수연은 시험 전날 밤을 새워 강의 자료를 전부 읽고 A를 받았습니다. 다음 과목에서 같은 개념이 나왔을 때 전혀 기억이 나지 않았습니다. 몰아서 공부는 단기 점수에는 효과가 있지만 장기 기억 전환이 안 됩니다.

발생 신호: 각 과목 시험이 끝나면 그 내용이 휘발됩니다. 다음 학기에 선행 개념을 다시 처음부터 찾아보게 됩니다.

해결 방향: 주간 루틴 안에 복습을 분산해야 합니다. 48시간 내 1차 복습, 1주일 내 2차 복습이 장기 기억 형성에 효과적입니다.

**시나리오 3 — "모르는 게 있는데 질문을 못 하겠다"**

종현은 수업 중 이해 안 되는 부분이 있는데 "이런 거 물어보면 이상해 보일까봐" 질문을 하지 않습니다. 혼자 3시간 씨름하다가 결국 포기합니다. 질문을 하지 않으면 막힌 지점이 다음 개념의 전제 조건인 경우 계속 쌓입니다.

발생 신호: 막힌 지점이 2일 이상 넘어가도 해결이 안 됩니다. 같은 유형의 문제에서 반복적으로 틀립니다.

해결 방향: 30분 이상 막히면 질문하는 것이 규칙이어야 합니다. 질문을 잘 하면 오히려 이해도가 높다는 인상을 줍니다.

## 주간 복습 루프 추적기

```python
from collections import defaultdict
from datetime import date, timedelta

sessions = [
    {
        "course": "algorithms",
        "lecture_date": date(2026, 5, 4),
        "study_minutes": 100,
        "review_completed": True,
        "questions": ["Why does merge sort stay O(n log n)?"],
    },
    {
        "course": "operating-systems",
        "lecture_date": date(2026, 5, 5),
        "study_minutes": 60,
        "review_completed": False,
        "questions": ["What exactly causes context-switch overhead?"],
    },
    {
        "course": "databases",
        "lecture_date": date(2026, 5, 6),
        "study_minutes": 45,
        "review_completed": False,
        "questions": [],
    },
]

def build_weekly_report(entries):
    totals = defaultdict(int)
    weak_areas = []
    lines = []

    for entry in entries:
        next_review = entry["lecture_date"] + timedelta(days=2)
        totals[entry["course"]] += entry["study_minutes"]
        status = "done" if entry["review_completed"] else "pending"
        lines.append(
            f"{entry['course']}: lecture={entry['lecture_date']}, "
            f"next_review={next_review}, review={status}, "
            f"questions={len(entry['questions'])}"
        )

    for course, minutes in totals.items():
        if minutes < 90 or any(
            e["course"] == course and not e["review_completed"] for e in entries
        ):
            weak_areas.append(course)

    summary = ", ".join(f"{c}={m}m" for c, m in totals.items())
    weak_summary = ", ".join(weak_areas) if weak_areas else "none"
    return "\n".join(lines + [f"weekly_totals: {summary}", f"weak_areas: {weak_summary}"])

print(build_weekly_report(sessions))
```

출력 예시:
```text
algorithms: lecture=2026-05-04, next_review=2026-05-06, review=done, questions=1
operating-systems: lecture=2026-05-05, next_review=2026-05-07, review=pending, questions=1
databases: lecture=2026-05-06, next_review=2026-05-08, review=pending, questions=0
weekly_totals: algorithms=100m, operating-systems=60m, databases=45m
weak_areas: operating-systems, databases
```

이 출력에서 확인할 수 있는 것: 언제 복습해야 하는지, 아직 풀지 못한 질문이 어디 남아 있는지, 어느 과목이 실제로 약하게 굴러갔는지입니다.

## 이 과목이 실무에서 어떻게 쓰이는가

신입 엔지니어의 성장 속도는 종종 질문 빈도와 기록 습관에서 드러납니다. 막히는 지점을 빨리 드러내고, 해결 과정을 남기고, 같은 실수를 줄이는 사람이 훨씬 빠르게 적응합니다.

학습 습관이 실무 습관으로 이어지는 지점:

| 학습 습관 | 실무에서 나타나는 형태 |
| --- | --- |
| 강의 직후 3줄 요약 | 회의 직후 액션 아이템 정리 |
| 오답 원인 분류 | 버그 원인 분류(개념/조건/환경) |
| 질문 전 5분 정리 | 이슈 제출 전 재현 조건 정리 |
| 주간 약점 점검 | 스프린트 회고 |
| 기록 남기기 | 의사결정 문서, 포스트모텀 |

## 과목 유형별 학습 루프

전공 과목은 모두 같은 방식으로 공부하면 효율이 떨어집니다.

| 과목 유형 | 1차 목표 | 주간 루프 | 성과 확인 방법 |
| --- | --- | --- | --- |
| 개념 중심(OS/DB/Network) | 용어·구조 정확화 | 강의 요약 3줄 + 다이어그램 재작성 | 빈 종이에 구조 설명 가능 여부 |
| 문제풀이 중심(Algo/Math) | 풀이 전략 자동화 | 문제 3개 + 오답 원인 분류 | 새로운 문제에 패턴 전이 가능 여부 |
| 구현 중심(PL/Project) | 실행 가능한 산출물 | 작은 기능 구현 + 테스트 + 회고 | 데모 가능 상태 유지 여부 |

## 일주일 루틴 예시

| 요일 | 해야 할 일 | 이유 |
| --- | --- | --- |
| 월요일 | 강의 직후 핵심 개념 3줄 요약 | 기억이 가장 선명할 때 압축해야 노트가 살아 있습니다 |
| 화요일 | 알고리즘 또는 프로그래밍 실습 1시간 | 손을 움직이지 않으면 이해가 실행 능력으로 바뀌지 않습니다 |
| 수요일 | 개념 과목 복습 | 이론 과목은 간격을 두고 다시 봐야 오래 남습니다 |
| 목요일 | 질문 목록 정리 후 교수·조교·동료에게 확인 | 막힌 지점을 일주일 안에 푸는 습관이 중요합니다 |
| 금요일 | 이번 주 학습 시간과 약한 과목 점검 | 숫자로 보면 과목별 편향이 바로 드러납니다 |
| 주말 | 다음 주 예습 30분 + 밀린 과제 마무리 | 주말은 새 학습보다 누적 정리에 쓰는 편이 안정적입니다 |

## 몰아서 공부가 실패하는 구조적 이유

몰아서 공부하면 단기 점수는 나올 수 있지만 전공 유지율은 낮아집니다.

1. **인출 연습 간격이 없어 장기 기억 전환이 약합니다.** 에빙하우스 망각 곡선에 따르면 반복 없이는 48시간 내 50% 이상 잊습니다.
2. **구현 과목은 손의 반복이 필요합니다.** 압축 학습으로는 디버깅 감각이 붙지 않습니다.
3. **협업 과목은 시간에 따라 의사결정 기록이 쌓여야 합니다.** 단기 몰입으로는 로그가 남지 않습니다.

최소 고정 루틴:
- 48시간 내 1차 복습
- 주간 1회 오답/오해 패턴 정리
- 과목별 1개 산출물(노트, 코드, 다이어그램, 회고)

## 질문 습관을 성과로 바꾸는 방식

좋은 질문은 학습 압축 도구입니다. 질문을 잘하려면 막힌 지점의 형태를 먼저 분류해야 합니다.

질문 템플릿:

- 내가 이해한 현재 상태 2문장
- 시도한 방법 1~2개
- 실패 증거(오류 로그, 반례, 성능 수치)
- 원하는 도움의 종류(개념 설명/힌트/리뷰)

이 템플릿만 지켜도 전공 학습 속도는 눈에 띄게 빨라집니다.

## 학기 운영 템플릿: 과목별 시간 배분

| 과목 | 계획 시간(주) | 실제 시간(주) | 이해도(1~5) | 다음 주 조정 |
| --- | --- | --- | --- | --- |
| 알고리즘 | 6h | 5h | 3 | 문제 풀이 2개 추가 |
| 운영체제 | 5h | 3h | 2 | 복습 슬롯 2회 추가 |
| 데이터베이스 | 4h | 4h | 4 | 유지 |

학점 리스크는 조기에 계산할수록 대응이 쉽습니다.

```text
중간 점검 GPA(예시)
= (A- 3학점×3.7 + B0 3학점×3.0 + B+ 3학점×3.5) / 9
= 3.4

목표 GPA 3.7이라면 약한 과목의 보강 시간을 다음 4주에 우선 배치합니다.
```

이 방식은 점수 집착이 아니라 시간 재배치를 위한 경보 체계입니다.

## 자주 하는 실수 5가지

1. **노트를 받아 적기만 하고 다시 보지 않는 일입니다.** 노트는 나중에 꺼내 봐야 의미가 있습니다.
2. **복습 없이 진도만 따라가는 일입니다.** 앞 개념이 빠지면 나중 개념이 흔들립니다.
3. **코딩 연습을 시험 직전으로 미루는 일입니다.** 구현 능력은 손에 익히는 시간이 필요합니다.
4. **질문을 부끄러워해서 오래 끌고 가는 일입니다.** 막힌 지점이 누적될수록 회복 비용이 커집니다.
5. **수면 시간을 줄여 공부량만 늘리는 일입니다.** 수면 부족은 기억 공고화를 방해합니다.

## 처음 질문으로 돌아가기

- **같은 시간을 써도 공부 방법에 따라 결과가 크게 달라지는 이유는 무엇일까요?**
  - 수동적 이해(강의 보기)와 능동적 인출(직접 써보기) 사이의 차이 때문입니다. 영진 시나리오처럼 이해한 것 같아도 인출 연습이 없으면 시험에서 나오지 않습니다.

- **강의, 노트, 복습, 코딩 연습은 어떤 흐름으로 묶는 것이 좋을까요?**
  - 강의 → 24시간 내 요약 → 48시간 내 복습 → 72시간 내 구현 연습 순서가 기억 전환에 효과적입니다. 각 단계를 건너뛰면 다음 단계에서 막힙니다.

- **시험 직전 몰아서 하는 공부가 전공 과목에서 특히 잘 통하지 않는 이유는 무엇일까요?**
  - 전공 과목은 다음 과목의 전제 조건이 됩니다. 수연 시나리오처럼 단기 점수는 가능해도, 다음 학기에 같은 개념이 나올 때 처음부터 다시 해야 합니다. 누적 비용이 점점 커집니다.

- **과목 유형별로 학습 방법을 어떻게 다르게 설계해야 할까요?**
  - 개념 과목은 다이어그램 재작성, 알고리즘 과목은 문제 반복 풀이, 구현 과목은 작은 기능 완성이 각각 핵심입니다. 모든 과목을 같은 방식(노트 필기)으로 공부하면 구현 능력이 특히 약해집니다.

- **질문하는 습관이 학습 속도를 얼마나 바꾸는가?**
  - 종현 시나리오처럼 혼자 3시간 씨름하는 것과 질문 후 10분에 해결하는 것의 차이가 누적됩니다. 학기 내내 이 차이가 쌓이면 이해 깊이와 진도 모두에서 큰 격차가 생깁니다.

## 정리

전공 공부는 의욕만으로 오래 버티기 어렵습니다. 강의, 노트, 복습, 연습, 질문이 하나의 흐름으로 묶여야 누적이 생깁니다. 같은 시간을 써도 방법이 다르면 결과는 크게 달라집니다. 다음 글에서는 과제와 프로젝트를 밖에서 읽히는 포트폴리오로 바꾸는 방법을 봅니다.
