# 바이브코딩을 위한 AI 평가 (5/10): Rubric 기반 채점 설계

> 이 글은 **바이브코딩을 위한 AI 평가** 시리즈 5편입니다. LLM 출력의 여러 차원을 동시에 채점하는 Rubric 기반 채점 방법을 다룹니다.

바이브코딩으로 만든 AI 앱의 출력 품질은 하나의 숫자로 표현하기 어렵다. 정확성은 높은데 근거가 없거나, 근거는 있는데 어투가 부적절하거나, 내용은 좋은데 형식이 요구사항을 벗어나는 경우가 현실에서 자주 일어난다.

Rubric 기반 채점은 이 문제를 해결한다. 평가 대상을 여러 차원으로 나누고, 각 차원을 독립적으로 채점한다. 예를 들어 "고객 지원 답변"을 평가한다면 정확성(Accuracy), 친절함(Tone), 완전성(Completeness), 간결함(Conciseness) 네 차원으로 나눌 수 있다.

각 차원에는 명확한 기준이 필요하다. "5점: 질문의 핵심에 정확히 답변하고 근거를 제시했다. 4점: 핵심에 답변했지만 근거가 일부 부족하다. 3점: 질문과 관련 있지만 핵심을 벗어난 부분이 있다."처럼 구체적으로 정의해야 한다.

JSON 출력 형식을 사용하면 점수를 자동으로 파싱해서 분석할 수 있다. `{"accuracy": 4, "tone": 5, "completeness": 3, "reason": "..."}` 형태로 받으면 각 차원의 점수를 데이터베이스에 저장하고, 시간에 따른 변화를 추적할 수 있다.

멀티-차원 채점의 가장 큰 이점은 개선 방향이 명확해진다는 것이다. 전체 점수가 낮다는 사실보다, "정확성은 높은데 완전성이 낮다"는 정보가 훨씬 실행 가능한 피드백이 된다.

> Rubric은 채점 기준이자 앱이 달성해야 할 목표를 명문화한 것이다. Rubric이 없는 채점은 방향 없는 개선이다.

## 이 글에서 다룰 문제

- 단일 점수의 한계와 멀티-차원 채점이 필요한 이유는 무엇인가요?
- 좋은 Rubric은 어떻게 설계하고, 각 차원의 기준을 어떻게 정의할까요?
- JSON 출력을 활용해 채점 결과를 어떻게 분석할 수 있을까요?
- 차원별 가중치는 어떻게 설정해야 할까요?
- Rubric의 신뢰도를 어떻게 검증할 수 있을까요?

## Before / After: Rubric 채점 전후

| 상황 | 단일 점수 | Rubric 멀티-차원 채점 후 |
|------|---------|----------------------|
| 낮은 점수 원인 파악 | "3.2점이네요. 왜 낮은지 모름" | 정확성 4.5, 완전성 2.1, 완전성 개선 필요 |
| 프롬프트 개선 방향 | 막막함 | 낮은 차원 집중 개선 |
| 모델 A vs B 비교 | A 3.8, B 4.1로 B 승 | B가 정확성 높지만 A가 친절함 더 높음 |
| 품질 트래킹 | 숫자 변화만 | 차원별 변화 추적 |

## 흔한 실수

| 실수 | 결과 | 올바른 접근 |
|------|------|------------|
| 차원이 너무 많음 | 채점 일관성 저하, 비용 증가 | 핵심 3-5개 차원에 집중 |
| 차원 간 중복 정의 | 상관관계 높아 정보 중복 | 각 차원이 독립적이어야 함 |
| 기준 없이 숫자만 | 채점자마다 다른 기준 | 각 점수 수준을 예시로 정의 |
| 가중치 없이 단순 평균 | 중요하지 않은 차원이 점수 왜곡 | 비즈니스 목표에 맞는 가중치 설정 |

## AI 팁: Rubric 빠르게 설계하는 방법

Claude나 GPT-4에게 앱의 목적과 사용 시나리오를 설명하고, "이 앱의 출력을 평가하기 위한 3-5개 차원 Rubric을 설계해줘"라고 요청한다. 초안을 받은 뒤 팀원과 함께 각 차원의 정의를 검토하고, 실제 좋은 답변/나쁜 답변 예시를 붙여가며 다듬는다. AI가 초안을 잡아주면 설계 시간이 크게 줄어든다.

## 운영 체크리스트

- [ ] 핵심 평가 차원을 3-5개로 정의했는가
- [ ] 각 차원의 기준을 점수 수준별 예시와 함께 정의했는가
- [ ] JSON 출력 형식을 강제하고 파싱이 자동화되어 있는가
- [ ] 차원별 가중치가 비즈니스 목표와 정렬되어 있는가
- [ ] 사람 채점과의 일치도를 검증했는가

## 처음 질문으로 돌아가기

- **멀티-차원 채점이 필요한 이유는?** 단일 점수로는 개선 방향을 알 수 없다. 차원별 점수가 있어야 어디를 고쳐야 하는지 보인다.
- **Rubric 차원 수는 얼마나?** 3-5개가 최적이다. 너무 많으면 일관성이 떨어지고, 너무 적으면 정보가 부족하다.
- **가중치는 어떻게 설정?** 비즈니스 목표에서 역산한다. 고객 지원이라면 정확성이 친절함보다 중요할 수 있다.

## 정리

Rubric 기반 채점은 LLM 앱 품질 관리를 "느낌"에서 "측정"으로 바꾸는 핵심 도구다. 잘 설계된 Rubric은 팀 전체가 품질을 같은 기준으로 이야기할 수 있게 만들고, 개선 방향을 명확하게 제시한다.

처음에는 3개 차원으로 시작하고, 실제 운영하면서 조금씩 다듬으면 된다.
