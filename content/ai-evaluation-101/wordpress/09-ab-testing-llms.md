# 바이브코딩을 위한 AI 평가 (9/10): LLM A/B 테스팅 — 어느 프롬프트가 더 나은가

> 이 글은 **바이브코딩을 위한 AI 평가** 시리즈 9편입니다. 두 개의 프롬프트나 모델 중 어느 것이 더 나은지 통계적으로 판단하는 A/B 테스트 방법을 다룹니다.

바이브코딩으로 프롬프트를 계속 개선하다 보면 어느 순간 "A 버전과 B 버전 중 어느 게 더 나은가?"라는 질문이 생긴다. 그냥 몇 가지 케이스를 눈으로 비교하고 결정하는 경우가 많은데, 이는 확증 편향에 빠지기 쉽다. 내가 바꾼 버전을 더 좋아하는 경향이 자연스럽게 생기기 때문이다.

LLM A/B 테스팅은 이 선택을 통계적 근거를 갖고 내리게 해준다. 핵심은 두 가지다. 충분한 샘플로 테스트하고, 통계적 유의성을 확인한다.

Win Rate는 A/B 테스팅의 가장 기본 지표다. 동일한 질문 세트에 A와 B를 모두 실행해서, LLM-as-Judge나 사람이 각 케이스에서 어느 것이 더 좋은지 선택한다. A가 이기는 비율이 Win Rate다. 60% 이상이면 통계적으로 의미 있는 차이일 가능성이 높다.

통계적 유의성 검정도 중요하다. 단순히 "A가 53번, B가 47번 이겼으니 A가 낫다"고 할 수 없다. 우연일 수도 있기 때문이다. 이항 검정(Binomial test)이나 t-검정으로 이 차이가 통계적으로 유의미한지 확인해야 한다. p-value < 0.05를 기준으로 사용하는 것이 일반적이다.

Pairwise 비교는 A/B 테스팅을 더 강력하게 만드는 방법이다. 같은 질문에 대한 A와 B의 답변을 나란히 놓고 "어느 것이 더 좋은가?"를 판단하게 한다. 절대적인 점수보다 상대적 비교가 더 안정적인 신호를 준다.

> "느낌상 B가 더 좋은 것 같아요"는 결정의 근거가 될 수 없다. 통계적으로 검증된 A/B 테스트 결과만이 확신을 주는 이유를 제공한다.

## 이 글에서 다룰 문제

- LLM A/B 테스트가 단순 비교와 다른 이유는 무엇인가요?
- Win Rate를 어떻게 계산하고 해석해야 할까요?
- 통계적 유의성 검정을 어떻게 적용해야 할까요?
- 몇 개의 케이스가 있어야 의미 있는 A/B 테스트가 가능한가요?
- 프롬프트 변경 외에 모델 교체 A/B 테스팅은 어떻게 다른가요?

## Before / After: A/B 테스트 도입 전후

| 상황 | 도입 전 | 도입 후 |
|------|---------|---------|
| 프롬프트 선택 | "B가 더 좋은 것 같아요" 주관적 판단 | B Win Rate 67%, p<0.05로 B 채택 |
| 모델 비교 | 몇 가지 예시로 비교 | 100케이스 체계적 비교, 통계 검증 |
| 개선 효과 측정 | "더 좋아진 것 같아요" | 정확한 개선 폭 수치로 표현 |
| 의사결정 신뢰도 | 낮음 | 통계적 근거로 팀 설득 가능 |

## 흔한 실수

| 실수 | 결과 | 올바른 접근 |
|------|------|------------|
| 너무 적은 케이스 | 우연한 결과를 과신 | 최소 50케이스, 통계 검정 필수 |
| 같은 케이스로 비교 | 각 버전에 유리한 케이스 편향 | 무작위 샘플링된 대표 케이스 사용 |
| 순서 편향 무시 | A를 먼저 본 채점자가 A 선호 경향 | Pairwise에서 순서 무작위화 |
| 단일 지표만 | 한 차원에서 A가 낫고 다른 차원에서 B가 나음 | 멀티-차원 비교 |

## AI 팁: A/B 테스트 설계 빠르게 하는 방법

Claude나 GPT-4에게 "이 두 프롬프트를 100개 케이스로 A/B 테스트하는 Python 코드를 작성해줘"라고 요청하면 기본 골격을 얻을 수 있다. 이항 검정은 `scipy.stats.binom_test()`로 한 줄이면 된다. 중요한 것은 케이스를 사전에 정의하고, A와 B를 같은 케이스에 무작위 순서로 실행하는 것이다.

## 운영 체크리스트

- [ ] 최소 50개 케이스로 A/B 테스트를 진행하는가
- [ ] 통계적 유의성 검정(이항 검정 또는 t-검정)을 수행하는가
- [ ] Pairwise 비교에서 순서를 무작위화하는가
- [ ] 전체 Win Rate 외에 카테고리별 Win Rate도 확인하는가
- [ ] 결과를 팀이 이해할 수 있는 형태로 정리하는가

## 처음 질문으로 돌아가기

- **A/B 테스트가 단순 비교와 다른 이유는?** 통계적 유의성을 확인하기 때문에 우연한 차이와 실제 차이를 구분할 수 있다.
- **Win Rate 해석 방법은?** 60% 이상이고 p<0.05이면 의미 있는 차이. 50-60%는 미미한 차이로 다른 요소도 고려한다.
- **필요 케이스 수는?** 최소 50개. 차이가 작을수록 더 많은 케이스가 필요하다.

## 정리

LLM A/B 테스팅은 "느낌"을 "근거"로 바꾸는 도구다. 통계적으로 검증된 결정은 팀 내 논쟁을 줄이고, 잘못된 방향으로 가는 위험을 낮춘다.

바이브코딩의 빠른 실험 문화와 A/B 테스팅의 체계적 검증이 만나면, 빠르면서도 신뢰할 수 있는 AI 앱 개발이 가능해진다.
