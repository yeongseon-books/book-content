# 바이브코딩을 위한 클린 코드 (7/10): AI가 주석을 잔뜩 넣었는데 코드와 안 맞다

이 글은 바이브코딩을 위한 클린 코드 시리즈의 7번째 글입니다.

AI에게 코드를 요청할 때 "주석을 충분히 달아줘"라고 하면 거의 모든 줄에 주석이 달린 코드가 나옵니다. 처음엔 친절해 보입니다. 그런데 몇 가지 문제가 있었습니다.

첫 번째, AI가 달아준 주석 중 절반은 코드를 그대로 반복했습니다. `# i를 1 증가`와 `i += 1`이 한 쌍을 이루는 식입니다. 이런 주석은 정보가 없습니다.

두 번째, 코드를 수정하고 나서 주석을 업데이트하는 것을 잊었습니다. 두 달 뒤에 코드를 열었더니 주석이 "10% 할인을 적용한다"고 되어 있는데 코드는 15%를 적용하고 있었습니다. 무엇을 믿어야 할지 알 수 없었습니다.

세 번째, AI가 생성한 주석은 "왜" 이렇게 했는지는 설명하지 않습니다. "무엇"을 하는지만 설명합니다. "결제 게이트웨이가 HTTP 200을 반환해도 실제로는 실패할 수 있기 때문에 응답 본문을 직접 확인한다"는 컨텍스트는 코드에서 파악할 수 없고, 그 배경을 아는 사람이 직접 적어야 합니다.

주석은 코드의 "무엇"을 반복하는 것이 아니라 코드가 표현할 수 없는 "왜"를 설명하는 도구입니다. 가장 좋은 주석은 이름과 구조를 잘 짜서 주석이 필요 없게 만드는 것입니다.

> 주석을 쓰기 전에 먼저 이름과 구조를 고칠 수 있는지 봐야 합니다.

---

## 이 글에서 다룰 문제
- AI가 생성한 과도한 주석을 어떻게 정리해야 할까요?
- 좋은 주석과 나쁜 주석의 차이는 무엇인가요?
- 코드가 스스로 설명하게 만드는 방법은 무엇인가요?
- 공개 함수에 docstring을 어떻게 작성해야 할까요?
- AI가 만든 주석이 코드와 맞지 않을 때 어떻게 처리해야 할까요?

## AI 주석의 특성

AI는 주석을 달라고 하면 모든 줄에 주석을 달려고 합니다. 그 결과 세 가지 종류의 나쁜 주석이 나옵니다.

**1. 코드를 반복하는 주석**
```python
# 나쁜 주석
# i에 1을 더한다
i += 1

# 사용자를 저장한다
user.save()
```
이런 주석은 삭제해야 합니다. 코드 자체가 이미 말하고 있습니다.

**2. 오래된 주석**
```python
# 10% 할인 적용 (주석)
discount_rate = 0.15  # 코드는 15%
```
주석과 코드가 다를 때 읽는 사람은 무엇을 믿어야 할지 모릅니다. 코드가 항상 진실입니다.

**3. "왜"가 없는 주석**
```python
# HTTP 200이어도 body.status를 확인
if response.json().get("status") == "PAID":
```
이런 주석은 좋습니다. 결제 게이트웨이의 특이한 동작 때문에 이렇게 할 수밖에 없다는 배경이 담겨 있습니다.

### 이름을 고치면 주석이 사라진다

```python
# 나쁜 버전 - 주석이 필요
def p(a, b):
    # 사용자가 구매할 수 있는지 확인
    if a and b > 0:
        return True
    return False

# 좋은 버전 - 주석 불필요
def can_purchase(is_active_user: bool, stock_quantity: int) -> bool:
    return is_active_user and stock_quantity > 0
```

이름을 잘 지으면 주석이 필요 없어집니다.

### 공개 함수에는 docstring을

내부 함수는 이름으로 충분하지만, 다른 사람이 사용하는 함수는 계약을 문서화해야 합니다.

```python
def calculate_refund_amount(total_cents: int, cancel_fee_rate: float) -> int:
    """환불 금액을 센트 단위로 계산합니다.

    Args:
        total_cents: 원 결제 금액 (센트 단위)
        cancel_fee_rate: 취소 수수료 비율 (0 이상 1 이하)

    Returns:
        수수료를 차감한 환불 금액 (센트 단위)

    Raises:
        ValueError: 수수료 비율이 범위를 벗어난 경우
    """
    if not 0 <= cancel_fee_rate <= 1:
        raise ValueError("cancel_fee_rate must be in [0, 1]")
    return max(int(total_cents * (1 - cancel_fee_rate)), 0)
```

## Before / After

```python
# AI가 생성한 코드 - 과도한 주석
# 사용자 ID를 확인한다
user_id = request.get("user_id")

# user_id가 None인지 확인한다
if user_id is None:
    # None이면 False를 반환한다
    return False

# user_id가 None이 아니면 True를 반환한다
return True
```

```python
# 정리된 버전 - 주석 없이 의도가 명확
def has_user_id(request: dict) -> bool:
    return request.get("user_id") is not None
```

함수 이름이 모든 것을 설명합니다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| "주석 달아줘"만 요청 | 쓸모없는 주석이 대부분 | 주석 목적을 구체적으로 지정 |
| 코드 수정 후 주석 방치 | 거짓말하는 주석 발생 | 코드 수정 시 해당 주석도 함께 확인 |
| 모든 함수에 형식적 docstring | 정보량 0인 문서가 됨 | 공개 API와 복잡한 함수에만 |
| 주석에 비밀값이나 경로 포함 | 보안 위험 | 주석에는 로직 설명만 |
| "왜"가 없는 주석 | 코드 동작만 반복 | 외부 제약, 배경, 위험만 주석으로 |

## AI에게 클린 코드 요청하는 팁

```
프롬프트 예시:
"함수를 구현해줘.
주석 규칙:
- 코드를 그대로 반복하는 주석은 달지 말 것
- 외부 API의 특이한 동작이나 비직관적인 결정에만 주석을 달 것
- 공개 함수에는 Args, Returns, Raises 형식의 docstring 작성
- TODO가 있으면 반드시 담당자와 날짜 포함"
```

## 운영 체크리스트
- [ ] 코드만으로 충분히 설명되는가?
- [ ] 주석이 "왜"를 설명하는가? (무엇이 아니라)
- [ ] 공개 함수에 docstring이 있는가?
- [ ] TODO에 담당자와 날짜가 있는가?
- [ ] 기존 주석이 현재 코드와 일치하는가?

## 처음 질문으로 돌아가기

- **AI가 생성한 과도한 주석을 어떻게 정리해야 할까요?**
  코드를 그대로 반복하는 주석은 삭제합니다. 이름을 더 명확하게 바꾸면 주석이 필요 없어지는 경우가 많습니다.

- **좋은 주석과 나쁜 주석의 차이는?**
  나쁜 주석은 코드가 이미 말하는 것을 반복합니다. 좋은 주석은 코드만으로 표현하기 어려운 외부 제약, 배경, 위험을 담습니다.

- **AI가 만든 주석이 코드와 맞지 않을 때?**
  코드가 항상 진실입니다. 주석이 틀렸거나 오래됐다면 주석을 삭제하거나 업데이트합니다.

## 정리

AI는 "주석 달아줘"라고 하면 모든 줄에 주석을 달아줍니다. 하지만 대부분의 AI 주석은 코드를 반복하거나 금방 오래됩니다. 진짜 가치 있는 주석은 코드만으로 전달하기 어려운 배경과 이유를 담는 것입니다. 가장 좋은 방법은 이름과 구조를 잘 짜서 주석이 필요 없게 만드는 것입니다. 다음 글에서는 AI가 만든 코드를 어떻게 테스트 가능하게 만드는지 다룹니다.
