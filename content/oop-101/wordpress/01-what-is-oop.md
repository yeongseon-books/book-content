# 바이브코딩을 위한 객체지향 기초 (1/10): 객체지향이란 무엇인가?

이 글은 **바이브코딩을 위한 객체지향 기초** 시리즈의 첫 번째 글입니다. AI와 함께 코딩할 때 만나는 클래스 구조를 스스로 읽고 판단할 수 있도록, OOP 핵심 개념을 10편에 걸쳐 정리합니다.

---

바이브코딩을 하다 보면 AI가 자연스럽게 클래스를 만들어 줍니다. "사용자 관리 기능을 만들어 줘"라고 했더니 `User`, `UserService`, `UserRepository`가 줄줄이 나옵니다. 코드는 동작하는데, 왜 이렇게 나눠서 짰는지 이해가 안 갑니다. 수정하려고 손을 대면 어디를 건드려야 할지 막막합니다.

AI가 클래스 계층을 만들어줬는데 왜 이렇게 짰는지 이해하려면 OOP를 알아야 합니다. 클래스를 쓰면 코드가 더 고급스러워 보인다는 생각으로 시작하면 안 됩니다. 현업에서는 반대로 묻습니다. "이 문제에서 정말 데이터와 동작을 함께 묶어야 하는가, 아니면 함수 몇 개로 끝내는 편이 더 나은가?"

객체지향은 문법 기능이 아니라 구조를 잡는 방식입니다. 코드가 커질수록 관련 데이터와 로직이 여러 함수에 흩어지고, 한 군데를 고치면 다른 군데도 함께 손봐야 할 때가 많아집니다. 그때 객체라는 경계를 세워 책임을 모으는 접근이 힘을 발휘합니다.

> "클래스는 설계도입니다. 설계도를 읽지 못하면 AI가 지어 준 집을 고칠 수 없습니다."

## 핵심 개념 잡기

절차지향과 객체지향의 가장 큰 차이는 **데이터와 동작의 위치**입니다.

```text
Procedural                     Object-Oriented
┌────────────────────┐        ┌────────────────────┐
│ Function A         │        │ Object A           │
│ Function B         │        │  ├─ Data           │
│ Function C         │        │  └─ Methods        │
│                    │        ├────────────────────┤
│ Global Data        │        │ Object B           │
│  ├─ var 1          │        │  ├─ Data           │
│  └─ var 2          │        │  └─ Methods        │
└────────────────────┘        └────────────────────┘
```

절차지향에서는 데이터가 전역에 놓이고 함수들이 그 데이터를 가져다 씁니다. 객체지향에서는 데이터와 그 데이터를 다루는 메서드가 하나의 클래스 안에 같이 있습니다.

| 용어 | 설명 |
|------|------|
| 클래스(class) | 객체를 생성하기 위한 템플릿(설계도)입니다 |
| 인스턴스(instance) | 클래스를 기반으로 생성된 실제 객체입니다 |
| 속성(attribute) | 객체가 가진 데이터입니다 |
| 메서드(method) | 객체가 수행하는 행위(함수)입니다 |
| 캡슐화(encapsulation) | 데이터와 메서드를 하나로 묶고 외부 접근을 제한하는 것입니다 |

## Before / After: AI가 리팩터링해 주는 패턴

AI에게 "사용자 관리 코드를 개선해 줘"라고 하면 아래와 같이 변환해 줍니다. 왜 이런 변환이 일어나는지 이해하는 것이 이 글의 목표입니다.

```python
# Before: 절차지향 — 데이터와 함수가 분리됨
users = []

def create_user(name, email):
    user = {"name": name, "email": email, "active": True}
    users.append(user)
    return user

def deactivate_user(user):
    user["active"] = False

def get_user_display(user):
    status = "active" if user["active"] else "inactive"
    return f"{user['name']} ({status})"
```

```python
# After: OOP — 데이터와 동작이 한 클래스에 함께 있음
class User:
    def __init__(self, name: str, email: str) -> None:
        self.name = name
        self.email = email
        self.active = True

    def deactivate(self) -> None:
        self.active = False

    def display(self) -> str:
        status = "active" if self.active else "inactive"
        return f"{self.name} ({status})"
```

After 코드에서 `user.deactivate()`를 호출하면 `user` 객체가 자기 자신의 상태를 바꿉니다. 이것이 OOP의 핵심입니다. 데이터와 동작이 같은 경계 안에 있습니다.

## 바이브코딩 관점: AI는 왜 클래스를 만드는가?

AI가 클래스를 생성할 때는 보통 다음 신호를 감지합니다.

1. **같은 데이터 묶음이 여러 함수에서 반복적으로 사용될 때** — AI는 이 데이터를 클래스의 속성으로 올립니다.
2. **함수 이름이 같은 명사를 공유할 때** — `create_user`, `get_user`, `delete_user`가 모두 `user`를 공유하면 `User` 클래스로 묶습니다.
3. **상태 변화가 필요할 때** — `active = True/False` 같은 상태 전환 로직은 클래스 메서드로 들어갑니다.

```python
# AI가 만들어준 클래스를 보는 방법
class Dog:
    def __init__(self, name: str, breed: str) -> None:
        self.name = name      # 이 객체가 가진 데이터
        self.breed = breed

    def bark(self) -> str:
        return f"{self.name} says woof!"  # 이 데이터를 사용하는 동작

my_dog = Dog("Buddy", "Golden Retriever")
print(my_dog.bark())  # Buddy says woof!
```

`self`는 "이 인스턴스 자신"을 가리킵니다. `self.name`은 이 특정 개의 이름입니다. 여러 인스턴스가 있어도 각자 독립적인 데이터를 가집니다.

## 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 방법 |
|------|------------|----------|
| `__init__`에서 self를 빠뜨림 | 인스턴스 변수가 아닌 지역 변수가 됩니다 | 반드시 `self.속성 = 값` 형태로 작성합니다 |
| 클래스 변수에 가변 객체 사용 | 모든 인스턴스가 같은 리스트를 공유합니다 | 가변 객체는 `__init__`에서 인스턴스 변수로 선언합니다 |
| 클래스와 인스턴스를 혼동 | `Dog.bark()` 호출 시 TypeError입니다 | 반드시 인스턴스를 생성한 후 메서드를 호출합니다 |
| 모든 것을 클래스로 감쌈 | 불필요한 복잡성이 추가됩니다 | 간단한 로직은 함수만으로 충분합니다 |
| `__repr__` 미정의 | 디버깅 시 `<__main__.Dog object>` 출력입니다 | `__repr__`을 정의하여 유용한 정보를 출력합니다 |

- "이 클래스가 관리하는 상태(속성)는 무엇인가?" — `__init__`의 `self.` 로 시작하는 변수들을 찾아보세요.

## 처음 질문으로 돌아가기

- **객체지향은 절차지향과 무엇이 다를까요?**
  절차지향은 데이터와 함수가 분리되어 있고, 객체지향은 관련 데이터와 동작을 한 클래스 안에 함께 둡니다. AI가 클래스를 만드는 것은 "이 데이터를 다루는 책임을 한곳에 모으기 위해"입니다.

- **클래스, 인스턴스, 속성, 메서드는 어떻게 관계를 맺을까요?**
  클래스는 설계도, 인스턴스는 그 설계도로 만든 실물입니다. 속성은 인스턴스가 가진 데이터, 메서드는 그 데이터로 하는 동작입니다. `self`가 이 모든 것을 연결합니다.

- **언제 객체가 더 자연스러울까요?**
  같은 데이터 묶음이 세 곳 이상에서 함께 변경되거나, 상태 전이가 있을 때입니다. 그 전까지는 함수로 충분합니다.

## 정리

객체지향은 데이터와 행위를 하나의 단위로 묶어 코드의 구조를 명확하게 만드는 프로그래밍 방식입니다. AI가 클래스를 만들어 줄 때는 이 원칙에 따라 관련 데이터와 동작을 함께 묶은 것입니다. 다음 글에서는 클래스와 인스턴스를 더 깊이 다루고, AI가 생성하는 생성자 패턴을 분석합니다.
