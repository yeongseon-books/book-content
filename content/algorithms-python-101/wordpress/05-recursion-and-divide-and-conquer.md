# 바이브코딩을 위한 Python 알고리즘 (5/10): 재귀와 분할 정복

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 5번째 글입니다.

AI에게 트리 순회, 폴더 탐색, 피보나치 계산 등을 요청하면 자주 재귀 코드가 나옵니다. 재귀는 겉으로 보면 단순한데, 실제로 읽을 때는 갑자기 어렵게 느껴지는 코드입니다. 특히 기저 조건이 없거나 입력이 크면 스택 오버플로가 발생합니다.

바이브코딩에서 AI가 재귀 코드를 줬을 때 두 가지를 반드시 확인해야 합니다. 첫째, 기저 조건이 있는가? 둘째, 입력 크기가 Python의 재귀 한도(기본 1000)를 초과하지 않는가? 이 두 가지를 모르면 런타임 오류를 프로덕션에서 만나게 됩니다.

재귀는 한 번 감이 잡히면 많은 알고리즘 패턴이 훨씬 일관되게 보이기 시작합니다. 이진 탐색, 병합 정렬, 퀵 정렬처럼 이미 본 알고리즘들이 모두 분할 정복이라는 패턴 위에 서 있다는 것을 알게 됩니다.

> 분할 정복은 문제를 더 작은 조각으로 나누고(Divide), 각 조각을 해결하고(Conquer), 결과를 합치는(Combine) 전략입니다.

## 이 글에서 다룰 문제

- 재귀 함수는 어떻게 동작하고 호출 스택은 어떤 모양일까요?
- 기저 조건은 왜 그렇게 중요할까요?
- 분할 정복의 세 단계는 어떻게 구분할 수 있을까요?
- AI가 재귀 코드를 줬을 때 무엇을 검토해야 할까요?
- Python에서 재귀 한도를 초과하면 어떻게 대처할까요?

재귀는 트리 순회, 그래프 순회, 정렬, 동적 계획법의 기반입니다. 재귀를 이해하지 못하면 이후 알고리즘 주제들이 갑자기 훨씬 불투명해집니다. 바이브코딩에서는 AI가 재귀를 줬을 때 그것을 검토하고 안전하게 개선할 수 있어야 합니다.

## Before / After

**Before — AI가 준 재귀 코드를 검토 없이 사용:**

```python
# AI가 준 피보나치 재귀 — 기저 조건은 있지만 지수 시간
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# O(2^n) — n=40이면 10억 번 호출, 느리고 스택 깊이 문제
```

**After — 알고리즘 원리를 이해하고 AI에게 개선 요청:**

```python
# "피보나치를 메모이제이션으로 O(n)에 만들어줘"
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# O(n) — 각 n 값을 한 번만 계산
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 기저 조건 없는 재귀 수령 | 무한 재귀로 스택 오버플로 | AI 코드에서 기저 조건 먼저 확인 |
| Python 재귀 한도 무시 | n=1000 초과 시 RecursionError | 반복문 변환 또는 sys.setrecursionlimit 고려 |
| 순수 재귀 피보나치를 큰 n에 사용 | 지수 시간으로 굉장히 느림 | 메모이제이션 또는 DP로 변환 요청 |
| 분할 정복과 단순 재귀를 혼동 | 패턴 이해 없이 복사 | Divide-Conquer-Combine 세 단계 확인 |
| 재귀 디버깅을 포기 | 스택 추적이 어려움 | print(n)으로 호출 순서 시각화 |

## AI 협업 팁

재귀 관련 AI 프롬프트 패턴:

1. **입력 크기 명시**: "n이 최대 10^4일 때"
2. **효율 요구**: "메모이제이션 사용해서 O(n)으로"
3. **안전 요구**: "Python 재귀 한도를 고려해서"

예시 프롬프트:
> "폴더 구조를 재귀로 순회하는 함수를 만들어줘. 최대 깊이가 100 정도야. 기저 조건과 예외 처리를 포함해줘."

AI가 재귀 코드를 주면 반드시 물어보세요:
> "이 코드의 최대 재귀 깊이는 얼마야? Python 기본 한도(1000)를 초과할 수 있어?"

## 처음 질문으로 돌아가기

AI가 재귀 코드를 줬을 때 두 가지만 확인하면 됩니다. 기저 조건이 있는가, 그리고 입력 크기가 재귀 한도를 초과하는가. 이 두 가지를 확인하는 습관이 재귀 관련 버그의 대부분을 막습니다. 분할 정복 패턴을 이해하면 AI가 준 복잡한 재귀 코드도 Divide, Conquer, Combine 세 단계로 읽을 수 있습니다.

## 정리

재귀는 함수가 자기 자신을 호출해 반복 작업을 처리하는 방식이며, 기저 조건이 반드시 필요합니다. 분할 정복은 문제를 작은 조각으로 나누어 해결하는 전략으로, 이진 탐색과 병합 정렬이 모두 이 패턴입니다. 바이브코딩에서는 AI가 준 재귀 코드의 기저 조건과 재귀 깊이를 먼저 확인하는 습관이 중요합니다.

다음 글에서는 동적 계획법을 다룹니다. 재귀의 중복 계산 문제를 메모이제이션으로 해결하는 방법을 배웁니다.
