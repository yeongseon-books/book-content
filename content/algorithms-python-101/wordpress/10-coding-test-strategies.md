# 바이브코딩을 위한 Python 알고리즘 (10/10): 코딩 테스트 문제 접근법

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 10번째이자 마지막 글입니다.

9개의 글에서 알고리즘을 배웠습니다. 이제 실제 문제 앞에 서면 무엇을 써야 할지 결정해야 합니다. 알고리즘을 안다는 것과 시간 제한 안에서 적용하는 것은 다른 문제입니다. 코딩 테스트의 진짜 난점은 구현 전에 제약을 빠르게 읽고 문제를 적절한 패턴에 연결하는 데 있습니다.

바이브코딩에서는 AI와 함께 코딩 테스트를 준비할 수 있습니다. 하지만 AI에게 "이 문제 풀어줘"라고 요청하는 것이 아니라, "이 입력 크기에서 어떤 알고리즘이 적합해?", "이 복잡도로 제한 시간 안에 통과할 수 있어?"라고 물을 수 있어야 합니다. 그 판단력을 갖추는 것이 이 시리즈의 최종 목표입니다.

핵심은 문제 유형을 빠르게 분류하고, 입력 제약에서 거꾸로 필요한 시간 복잡도를 추론하는 능력입니다. 이 흐름이 반복 가능한 접근법이 되면, 처음 보는 문제에서도 방향을 잡을 수 있습니다.

> Problem-Solving Flow = 입력 분석 → 유형 분류 → 알고리즘 선택 → 구현 → 검증

## 이 글에서 다룰 문제

- 입력 크기 제약을 보고 어떤 알고리즘을 먼저 버려야 할까요?
- 문제 유형을 어떻게 알고리즘에 연결할까요?
- 한 문제를 이해, 계획, 구현, 검증으로 어떻게 끝까지 끌고 갈까요?
- AI와 함께 코딩 테스트를 준비할 때 어떻게 활용해야 할까요?
- 이 시리즈에서 배운 알고리즘들을 어떻게 체계적으로 정리할까요?

이 시리즈의 알고리즘을 모두 공부했더라도, 실제 문제 앞에서 무엇을 써야 할지 결정하지 못하면 소용이 없습니다. 입력 크기에서 복잡도를 역산하는 능력이 핵심입니다.

## Before / After

**Before — 문제를 읽고 바로 구현 시작:**

```python
# n = 10^6인데 O(n²) 구현 시작
# 제한 시간 1초, 연산 횟수 10^12 → 당연히 TLE(시간 초과)

def solve(n, arr):
    result = 0
    for i in range(n):
        for j in range(i, n):  # O(n²)
            result = max(result, arr[i] + arr[j])
    return result
```

**After — 입력 크기 확인 후 복잡도 역산:**

```python
# n = 10^6 → O(n) 또는 O(n log n)만 허용
# "두 수 합의 최댓값" → 정렬 후 처음+끝 = O(n log n)

def solve(arr):
    arr.sort()  # O(n log n)
    return arr[-1] + arr[-2]  # O(1)
# 전체 O(n log n) — 10^6에서 제한 시간 내 통과
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 입력 크기 확인 없이 구현 | 복잡도가 맞지 않아 TLE | 첫 번째 단계로 n 크기와 허용 복잡도 역산 |
| 문제 유형 분류 없이 코드 시작 | 잘못된 알고리즘 선택 | 탐색/정렬/그래프/DP 중 어떤 유형인지 먼저 파악 |
| AI에게 "풀어줘"만 요청 | 학습이 안 됨, 면접에서 설명 불가 | "이 유형에 맞는 알고리즘 추천해줘"로 접근 |
| 경계 조건 테스트 없이 제출 | 엣지 케이스에서 오답 | n=0, n=1, 최댓값, 중복 입력으로 테스트 |
| 복잡도 분석 없이 최적화 | 방향 없는 최적화로 시간 낭비 | Big-O 먼저 계산 후 병목 파악 |

## AI 협업 팁

코딩 테스트에서 AI를 활용하는 올바른 방법:

1. **복잡도 역산 질문**: "n이 10^6일 때 어떤 복잡도가 허용돼?"
2. **유형 분류 도움**: "이 문제의 키워드가 '최단 경로'인데 어떤 알고리즘이 적합해?"
3. **반례 생성**: "내 풀이에서 실패할 수 있는 반례를 만들어줘"

입력 크기별 허용 복잡도:
- n ≤ 10^6: O(n) 또는 O(n log n)
- n ≤ 10^4: O(n²)
- n ≤ 500: O(n³)
- n ≤ 20: O(2^n) (비트마스크 DP)

문제 유형별 알고리즘 매핑:
- "최단 경로" + 가중치 없음 → BFS
- "최단 경로" + 가중치 있음 + 양수 → 다익스트라
- "최대/최소" + 겹치는 부분 문제 → DP
- "최대/최소" + 그리디 선택 속성 → 그리디
- "존재 여부" + 그래프 → BFS/DFS

- [ ] 틀렸을 때 반례를 찾아서 알고리즘을 수정했는가?

## 처음 질문으로 돌아가기

이 시리즈를 통해 알고리즘이 무엇인지, 복잡도를 어떻게 읽는지, 각 알고리즘이 언제 적합한지를 배웠습니다. 코딩 테스트에서든, 바이브코딩에서든, AI와 협업할 때든 이 지식은 동일하게 적용됩니다. 입력 크기를 보고 복잡도를 역산하고, 문제 유형에 맞는 알고리즘을 선택하고, AI에게 정확한 조건을 전달하는 것이 핵심입니다.

## 정리

알고리즘을 안다는 것만으로는 충분하지 않습니다. 문제를 보고 빠르게 유형을 분류하고, 입력 제약에서 허용 복잡도를 역산하고, 그에 맞는 알고리즘을 선택하는 반복 가능한 접근법이 필요합니다. 바이브코딩에서 AI는 이 과정의 파트너가 될 수 있습니다. 단, 여러분이 올바른 질문을 할 수 있어야 합니다.

이 시리즈를 마친 여러분은 이제 AI에게 "이 코드의 복잡도는?", "더 나은 알고리즘 있어?", "이 입력 크기에서 통과할 수 있어?"라고 물을 수 있습니다. 그것이 바이브코딩 시대의 알고리즘 역량입니다.
