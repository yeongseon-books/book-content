# 바이브코딩을 위한 Python 알고리즘 (3/10): 선형 탐색과 이진 탐색

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 3번째 글입니다.

"사용자 목록에서 특정 이름 찾아줘"라고 AI에게 요청하면, 대부분 처음부터 끝까지 하나씩 확인하는 선형 탐색 코드가 나옵니다. 사용자가 100명이면 문제없습니다. 그런데 100만 명이 되면? 최악의 경우 100만 번을 확인해야 합니다.

정렬된 데이터에서는 이야기가 완전히 달라집니다. 이진 탐색은 매 단계마다 탐색 범위를 절반으로 줄입니다. 100만 명 데이터에서 많아야 20번 비교로 찾을 수 있습니다. 이 차이를 알고 AI에게 요청해야 합니다.

탐색은 프로그래밍에서 가장 자주 하는 작업입니다. 작은 리스트라면 선형 탐색으로 충분하지만, 큰 정렬 리스트라면 매 단계마다 탐색 범위를 절반으로 줄이는 순간 문제의 성격이 완전히 달라집니다. 그 차이를 AI에게 정확히 전달하는 것이 바이브코딩의 핵심입니다.

> 이진 탐색은 매 단계마다 남은 데이터의 절반을 제거해, 정렬된 데이터에서 O(log n)을 달성합니다.

---

## 이 글에서 다룰 문제

- 선형 탐색은 어떻게 동작하고, 한계는 무엇일까요?
- 이진 탐색은 어떤 원리로 동작하며 어떻게 구현할까요?
- Python의 bisect 모듈은 언제 유용할까요?
- 탐색 알고리즘 선택에서 AI에게 어떻게 요청해야 할까요?
- 이진 탐색의 함정(정렬 전제)을 바이브코딩에서 어떻게 다룰까요?

데이터가 100개일 때는 선형 탐색으로 충분합니다. 하지만 100만 개가 되면 이진 탐색은 많아야 20번 정도 비교하면 되고, 선형 탐색은 최악의 경우 100만 번 모두 확인해야 합니다. 바이브코딩에서 이 판단을 AI에게 맡기려면, "정렬된 데이터인가?"라는 선행 조건을 먼저 확인해야 합니다.

## Before / After

**Before — AI에게 조건 없이 요청:**

```python
# "사용자 이름으로 찾는 함수 만들어줘"
def find_user(users, name):
    for user in users:
        if user["name"] == name:
            return user
    return None
# O(n) — 100만 명에서 최악 100만 번 비교
```

**After — 정렬 조건을 명시하고 이진 탐색 요청:**

```python
import bisect

# "이름으로 정렬된 리스트에서 O(log n)으로 찾는 함수 만들어줘"
def find_user_binary(sorted_names, name):
    i = bisect.bisect_left(sorted_names, name)
    if i < len(sorted_names) and sorted_names[i] == name:
        return sorted_names[i]
    return None
# O(log n) — 100만 명에서 최악 20번 비교
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 정렬 여부 확인 없이 이진 탐색 요청 | 정렬 안 된 데이터에서 틀린 결과 | "이 데이터는 정렬되어 있어"를 AI에게 명시 |
| 선형 탐색을 무조건 느리다고 오해 | 작은 데이터에선 충분히 빠름 | 데이터 크기에 따라 탐색 전략 선택 |
| bisect 모듈 존재를 모름 | 직접 구현해 오류 발생 | Python 표준 라이브러리 먼저 확인 |
| 이진 탐색 경계 조건 실수 | off-by-one 오류 | AI에게 경계 케이스 포함 요청 |
| "정확한 값 찾기"만 이진 탐색으로 알고 있음 | 조건 만족 범위 탐색에 못 씀 | bisect_left/bisect_right 활용법 배우기 |

## AI 협업 팁

탐색 알고리즘 관련 AI 프롬프트 패턴:

1. **데이터 상태 명시**: "이름으로 정렬된 리스트에서", "정렬 안 된 딕셔너리에서"
2. **복잡도 요구 명시**: "O(log n)으로 찾아줘"
3. **라이브러리 활용 요청**: "Python bisect 모듈 사용해서"

예시 프롬프트:
> "정렬된 정수 배열에서 특정 값이 처음 등장하는 인덱스를 O(log n)으로 찾는 함수를 만들어줘. bisect 모듈을 활용하고, 값이 없을 때는 -1을 반환해줘."

이렇게 요청하면 AI는 `bisect_left`를 사용한 정확한 구현을 제공합니다.

## 처음 질문으로 돌아가기

AI에게 "리스트에서 값 찾아줘"라고만 하면 선형 탐색 코드가 나옵니다. 하지만 "정렬된 리스트에서 O(log n)으로 찾아줘"라고 하면 이진 탐색이 나옵니다. 그 차이를 만드는 것은 여러분의 알고리즘 지식입니다. 정렬 여부를 확인하는 습관 하나가 탐색 성능을 수천 배 바꿀 수 있습니다.

## 정리

선형 탐색은 어떤 데이터에든 쓸 수 있지만 O(n)입니다. 이진 탐색은 정렬된 데이터에만 쓸 수 있지만 O(log n)으로 훨씬 빠릅니다. 바이브코딩에서는 데이터의 정렬 여부를 AI 프롬프트에 명시하는 것이 핵심입니다.

다음 글에서는 정렬 알고리즘을 다룹니다. 이진 탐색의 전제가 되는 "정렬"이 어떻게 이루어지는지, 그리고 Python에서 언제 직접 구현 대신 sorted()를 쓰는지 배웁니다.
