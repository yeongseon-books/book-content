# 바이브코딩을 위한 Python 알고리즘 (2/10): 시간 복잡도와 Big-O

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 2번째 글입니다.

"내 노트북에서 0.1초밖에 안 걸리는데요?"라고 말하는 개발자를 종종 봅니다. 그런데 그 코드를 프로덕션에 올렸더니, 데이터가 1만 개에서 100만 개로 늘어나자 10초가 걸리기 시작했습니다. 하드웨어는 바뀌고, 런타임도 바뀌고, 테스트 데이터도 바뀌지만, 입력이 커질 때 실행 시간이 얼마나 빨리 증가하는지는 그대로 남습니다.

바이브코딩을 할 때 AI에게 "이 코드 빠른가요?"라고 물어보면, AI는 Big-O로 답합니다. "O(n log n)입니다"라는 답을 받았을 때 "그게 빠른 건가요?"라고 다시 물어야 한다면, 이 글이 필요한 시점입니다.

Big-O는 하드웨어와 무관하게 알고리즘의 확장성을 설명하는 공통 언어입니다. "이 코드는 느립니다"가 아니라 "O(n²)인데 입력이 10만 개면 무너집니다"라고 말할 수 있어야, AI와 제대로 된 대화를 할 수 있습니다.

> Big-O 표기법은 입력 크기가 커질 때 알고리즘 실행 시간의 최악 성장률을, 상수항과 낮은 차수항을 무시하고 표현합니다.

---

## 이 글에서 다룰 문제

- 시간 복잡도는 무엇이며, 실제 실행 시간만으로는 왜 부족할까요?
- Big-O 표기법은 어떻게 읽고 써야 할까요?
- O(1)부터 O(n²)까지의 대표 복잡도는 어떻게 구분할까요?
- AI가 생성한 코드에서 복잡도를 어떻게 추정할 수 있을까요?
- 바이브코딩에서 복잡도 지식이 없을 때 어떤 문제가 생기나요?

Big-O는 코드를 서비스에 올리기 전에도, 코딩 테스트 화이트보드 앞에 서기 전에도 알고리즘을 비교할 수 있게 해 주는 실용적인 언어입니다. AI 협업에서는 더욱 중요합니다. AI는 동작하는 코드를 줄 뿐, 성능 제약을 모르면 최적화를 하지 않습니다.

## Before / After

**Before — 복잡도를 모르고 AI 코드를 그대로 사용:**

```python
# 중복 확인 — AI가 준 단순한 버전
def has_duplicate(data):
    for i in range(len(data)):
        for j in range(i + 1, len(data)):
            if data[i] == data[j]:
                return True
    return False
# O(n²) — 데이터 10만 개면 100억 번 비교
```

**After — 복잡도를 이해하고 AI에게 조건 명시:**

```python
# "O(n)으로 중복 확인하는 함수 만들어줘"라고 요청
def has_duplicate(data):
    return len(data) != len(set(data))
# O(n) — 데이터 100만 개도 선형 시간으로 처리
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| "빠르게 만들어줘"만 요청 | AI가 기준을 모름 | 입력 크기와 허용 복잡도를 함께 명시 |
| 로컬 테스트 시간만 믿음 | 하드웨어와 데이터 크기가 달라지면 무너짐 | Big-O로 성장률을 먼저 확인 |
| O(n log n)과 O(n²) 차이를 무시 | 10만 개에서 100배 이상 차이 | 입력 크기별 허용 복잡도 표를 외워두기 |
| 중첩 루프를 보고도 복잡도 추정 안 함 | 나중에 병목 발생 | 이중 루프 = O(n²) 경고 신호로 인식 |
| 공간 복잡도 무시 | 메모리 부족 오류 | 시간과 공간 트레이드오프 함께 고려 |

## AI 협업 팁

AI에게 복잡도를 명시하며 요청하는 방법:

1. **허용 복잡도 명시**: "O(n log n) 이하로 구현해줘"
2. **입력 크기 명시**: "n이 최대 10^6일 때"
3. **복잡도 설명 요청**: "이 코드의 시간/공간 복잡도를 설명해줘"

예시 프롬프트:
> "정수 배열에서 중복을 O(n) 시간, O(n) 공간으로 확인하는 함수를 만들어줘. 시간 복잡도 이유도 설명해줘."

입력 크기별 허용 복잡도 가이드:
- n ≤ 10^8: O(n) 이하
- n ≤ 10^7: O(n log n) 이하
- n ≤ 10^4: O(n²) 허용
- n ≤ 500: O(n³) 허용

## 처음 질문으로 돌아가기

AI가 "O(n log n)입니다"라고 답했을 때, 그게 내 데이터 크기에서 허용되는지 판단할 수 있어야 합니다. Big-O는 AI와 성능에 대해 대화하는 공통 언어입니다. 이 언어를 배우면 AI 코드 리뷰와 성능 최적화 요청이 훨씬 정밀해집니다.

## 정리

시간 복잡도와 Big-O는 하드웨어와 무관하게 알고리즘의 확장성을 설명하는 언어입니다. AI와 협업할 때 입력 크기와 허용 복잡도를 함께 명시하면, 훨씬 더 나은 코드를 얻을 수 있습니다.

다음 글에서는 선형 탐색과 이진 탐색을 비교합니다. "데이터가 정렬되어 있으면 O(n)을 O(log n)으로 줄일 수 있다"는 아이디어를 구체적으로 구현합니다.
