# 바이브코딩을 위한 Python 알고리즘 (9/10): 그리디 알고리즘

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 9번째 글입니다.

"최소 동전 수로 거스름돈 만들어줘"라고 AI에게 요청하면, 그리디 전략(가장 큰 동전부터 사용)이나 DP 전략이 나올 수 있습니다. 동전 종류가 일반적이면(예: 1, 5, 10, 50원) 그리디로 최적해를 보장합니다. 하지만 동전 종류가 특수하면(예: 1, 3, 4원에서 6원 만들기) 그리디로 틀린 답이 나올 수 있습니다.

그리디 알고리즘은 어려워 보이는 문제를 짧고 빠른 구현으로 바꿔 주는 경우가 많아서 매력적입니다. 올바른 상황에서는 정렬 한 번과 단일 순회로 O(n log n)에 해결됩니다. 하지만 그리디가 항상 최적해를 보장하지는 않습니다. 그리디 선택 속성과 최적 부분 구조가 모두 성립해야 합니다.

바이브코딩에서 AI가 그리디 코드를 줬을 때, "이 문제에서 그리디가 항상 최적해를 보장하나요?"라고 질문하는 습관이 중요합니다. AI는 이 질문에 반례를 제시하거나 증명을 설명해줍니다.

> 그리디는 매 단계에서 지역적으로 최선인 선택을 하고, 그것이 전체 최적해로 이어지기를 기대하는 전략입니다.

## 이 글에서 다룰 문제

- 그리디 알고리즘이 최적해를 만드는 두 조건은 무엇일까요?
- 동전 거스름돈, 활동 선택 문제는 어떻게 풀까요?
- 그리디와 동적 계획법은 어떻게 구분할까요?
- AI에게 최적화 문제를 요청할 때 어떤 조건을 확인해야 할까요?
- 그리디 반례를 어떻게 찾을 수 있을까요?

그리디는 짧고 빠릅니다. 많은 문제가 정렬 한 번과 단일 순회로 O(n log n)에 해결됩니다. 그러나 그리디가 적용 가능한지 판단하는 능력이 없으면, AI가 틀린 그리디 코드를 줘도 모를 수 있습니다.

## Before / After

**Before — 그리디 적용 여부 확인 없이 AI 코드 수령:**

```python
# "동전 최소 개수로 거스름돈 만들어줘" → 그리디
# 동전: [1, 3, 4]원, 목표: 6원
def min_coins_greedy(coins, amount):
    coins.sort(reverse=True)
    count = 0
    for coin in coins:
        while amount >= coin:
            amount -= coin
            count += 1
    return count

# min_coins_greedy([1, 3, 4], 6) → 3개 (4+1+1)
# 하지만 최적해는 2개 (3+3)! 그리디 실패!
```

**After — DP로 올바른 최적해 요청:**

```python
# "동전 최소 개수를 DP로 구해줘. 동전 종류가 임의적일 때"
def min_coins_dp(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

# min_coins_dp([1, 3, 4], 6) → 2개 (3+3) 정확한 최적해
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 그리디 적용 가능성 확인 없이 사용 | 특정 입력에서 틀린 결과 | "이 문제에서 그리디가 최적해를 보장해?"라고 AI에게 질문 |
| 그리디와 DP 구분 못 함 | 잘못된 알고리즘 선택 | 그리디 선택 속성 + 최적 부분 구조 동시 확인 |
| 반례 테스트 없이 그리디 사용 | 엣지 케이스에서 실패 | AI에게 반례 케이스 생성 요청 |
| "빠르니까 그리디" 선택 | 속도보다 정확성이 중요 | 그리디 적용 조건 먼저 검증 |
| 활동 선택 문제에서 잘못된 기준 정렬 | 최적 스케줄 못 만듦 | 종료 시간 오름차순 정렬이 핵심임을 기억 |

## AI 협업 팁

그리디 관련 AI 프롬프트 패턴:

1. **최적해 보장 여부 먼저 확인**: "이 문제에서 그리디가 항상 최적해를 보장해?"
2. **반례 요청**: "그리디 실패하는 반례를 만들어줘"
3. **DP와 비교 요청**: "그리디와 DP 중 어떤 게 이 문제에 맞아?"

예시 프롬프트:
> "활동 선택 문제를 그리디로 풀어줘. n개의 활동이 있고 각각 시작과 종료 시간이 있어. 겹치지 않는 최대 활동 수를 구해줘. 왜 이 문제에서 그리디가 최적해를 보장하는지도 설명해줘."

그리디 검증 질문:
> "내가 제시한 동전 종류 [1, 3, 4]에서 그리디가 실패하는 입력을 찾아줘."

AI가 그리디 코드를 줬을 때, "이 알고리즘이 항상 최적해를 보장하나요?"라고 반드시 질문해야 합니다. 이 질문 하나가 그리디와 DP의 선택을 결정하고, 프로덕션에서 틀린 결과를 내는 버그를 막습니다.

## 정리

그리디는 매 단계에서 지역 최적 선택을 하는 전략으로, 그리디 선택 속성과 최적 부분 구조가 모두 성립할 때만 전체 최적해를 보장합니다. 활동 선택, 분할 가능한 배낭 문제는 그리디가 적합하고, 0-1 배낭 문제나 임의 동전 거스름돈은 DP가 필요합니다.
