# 바이브코딩을 위한 Python 알고리즘 (1/10): 알고리즘이란 무엇인가?

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 1번째 글입니다.

"AI한테 코드 짜달라고 하면 되는데 알고리즘을 왜 배워야 하나요?"라는 질문을 자주 받습니다. 맞습니다. Claude나 ChatGPT에게 "리스트에서 최댓값 찾는 함수 만들어줘"라고 하면 코드가 즉시 나옵니다. 그런데 그 코드를 프로덕션에 올렸더니, 데이터 100개일 때는 빠르던 게 100만 개가 되자 응답이 수 초씩 걸리기 시작했습니다.

AI가 잘못 짠 걸까요? 아닙니다. AI는 동작하는 코드를 줬습니다. 문제는 여러분이 "O(n log n) 말고 O(n)으로 바꿔줘"라고 말할 수 있어야 한다는 것입니다. 그 언어를 모르면 AI에게 더 나은 코드를 요청할 수 없습니다.

바이브코딩 시대에 알고리즘을 배우는 이유는 코드를 외우려는 게 아닙니다. AI와 대화할 때 "이 코드의 시간 복잡도는 뭐야?", "더 빠른 방법 있어?"라고 물을 수 있는 판단력을 갖추기 위해서입니다. 같은 문제라도 어떤 알고리즘을 선택하느냐에 따라 한쪽은 수천 배 더 빠를 수 있고, 그 차이를 AI에게 설명할 수 있어야 합니다.

> AI에게 더 나은 코드를 받으려면, 먼저 어떤 코드가 더 나은지 판단할 수 있어야 합니다.

---

## 이 글에서 다룰 문제

- 알고리즘은 정확히 무엇이며, 어떤 성질을 가져야 할까요?
- 알고리즘을 의사코드나 Python 코드로 어떻게 표현할 수 있을까요?
- 같은 문제를 푸는 두 알고리즘은 왜 효율이 크게 달라질까요?
- 이 개념을 실무에서 잘못 적용하면 어떤 문제가 생길까요?
- 바이브코딩에서 알고리즘 지식이 없을 때 어떤 문제가 생기나요?

프로그래밍은 결국 문제를 푸는 일입니다. 같은 답을 내는 코드라도 입력이 커지면 완전히 다른 성능을 보일 수 있고, 그 차이는 대개 알고리즘에서 시작됩니다. AI 협업에서도 이 원리는 동일합니다.

## Before / After

**Before — AI가 생성한 "동작하는" 코드:**

```python
# AI에게 그냥 "리스트에서 최댓값 찾아줘"라고 했을 때
data = [3, 7, 2, 9, 4]
sorted_data = sorted(data)
maximum = sorted_data[-1]  # O(n log n) — 불필요한 정렬 비용
```

**After — 알고리즘을 알고 AI에게 조건을 명시한 코드:**

```python
# "한 번 순회로 O(n)에 최댓값 찾아줘"라고 요청했을 때
data = [3, 7, 2, 9, 4]
maximum = data[0]
for x in data[1:]:
    if x > maximum:
        maximum = x
# O(n) — 100만 개 데이터도 선형 시간으로 처리
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| AI 코드를 복잡도 확인 없이 복붙 | 동작하지만 규모에서 무너짐 | "이 코드의 시간 복잡도는?" 반드시 질문 |
| "빠르게 만들어줘"만 요청 | AI가 기준을 모름 | 입력 크기와 시간 예산 함께 명시 |
| 로컬 소규모 테스트만 믿음 | 작은 데이터는 무조건 빠름 | 10배, 100배 데이터로도 테스트 |
| 알고리즘 대신 언어를 탓함 | Python이 아니라 O(n²)이 느린 것 | 알고리즘 선택을 먼저 점검 |
| 의사코드 없이 바로 구현 요청 | 논리 오류를 나중에 발견 | AI에게 의사코드 먼저 요청 후 구현 |

## AI 협업 팁

바이브코딩에서 알고리즘 프롬프트를 잘 쓰려면 세 가지를 포함하면 됩니다.

1. **입력 크기 명시**: "데이터가 최대 100만 개일 때"
2. **성능 기대치 명시**: "1초 안에 응답해야 해"
3. **복잡도 질문 추가**: "이 코드의 시간 복잡도는? 더 좋은 방법 있어?"

예시 프롬프트:
> "정수 리스트에서 최댓값을 찾는 함수를 만들어줘. 리스트 크기가 최대 10^6이야. 코드 옆에 시간 복잡도도 적어줘."

이렇게 하면 AI는 O(n) 단일 순회를 제안하고, 왜 O(n log n) 정렬이 과하다는지도 설명해줍니다.

## 처음 질문으로 돌아가기

AI가 짜준 코드가 느릴 때, "AI가 잘못했다"고 말하는 대신 "이 알고리즘은 O(n log n)인데 O(n)으로 바꿀 수 있어?"라고 물을 수 있어야 합니다. 그 언어를 배우는 것이 이 시리즈의 목표입니다.

알고리즘은 입력, 출력, 명확성, 유한성, 효과성으로 정의됩니다. AI 코드를 읽을 때도, 프롬프트를 쓸 때도, 성능 이슈를 디버깅할 때도 이 다섯 가지가 출발점입니다.

## 정리

알고리즘은 문제를 해결하는 명확한 절차이며, 어떤 알고리즘을 선택하느냐가 성능과 확장성을 크게 좌우합니다. 바이브코딩에서 알고리즘 지식은 코드를 외우는 게 아니라, AI와 성능에 대해 대화할 수 있는 언어를 갖추는 것입니다.

다음 글에서는 시간 복잡도와 Big-O 표기법을 다룹니다. "이 코드 빠른가요?"라는 질문에 정확하게 답하는 방법을 배웁니다.
