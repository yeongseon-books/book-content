# 바이브코딩을 위한 Python 알고리즘 (6/10): 동적 계획법 기초

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 6번째 글입니다.

"피보나치 수열을 재귀로 구현해줘"라고 AI에게 요청하면, 종종 지수 시간 코드가 나옵니다. n=40만 되어도 10억 번 이상 함수가 호출됩니다. AI에게 "동적 계획법으로 최적화해줘"라고 말할 수 있으면, O(2^n)을 O(n)으로 바꿀 수 있습니다.

동적 계획법이 중요한 이유는 같은 부분 문제를 반복해서 풀면 끝없이 느려지는 문제를 해결하기 때문입니다. 부분 문제 결과를 저장해 중복 계산을 피하면, 지수 시간 문제가 다항 시간으로 바뀝니다. 이 패턴을 알고 AI에게 요청하면 훨씬 효율적인 코드를 얻을 수 있습니다.

DP는 코딩 테스트에서도 자주 나오지만, 더 중요한 가치는 겹치는 부분 문제와 재사용 가능한 상태를 알아보는 눈을 기르는 데 있습니다. 바이브코딩에서 이 눈이 있으면 AI에게 "이 문제 DP로 풀 수 있어?"라고 물을 수 있습니다.

> DP는 부분 문제 결과를 저장해 중복 계산을 피함으로써, 지수 문제를 다항 문제로 바꾸는 기법입니다.

---

## 이 글에서 다룰 문제

- DP가 적용되는 두 조건(최적 부분 구조, 중복 부분 문제)은 무엇일까요?
- 메모이제이션(top-down)과 테뷸레이션(bottom-up)은 어떻게 다를까요?
- AI에게 DP 문제임을 어떻게 설명하면 올바른 코드를 받을 수 있을까요?
- DP 코드를 받았을 때 공간 최적화가 가능한지 어떻게 판단할까요?
- 바이브코딩에서 DP와 재귀, 그리디를 어떻게 구분할까요?

재귀만으로는 지수 시간이 걸릴 수 있습니다. DP는 부분 문제 결과를 저장해 그 비용을 다항 시간으로 줄입니다. 이 차이를 이해하고 AI에게 전달하는 것이 바이브코딩에서 DP를 제대로 활용하는 방법입니다.

## Before / After

**Before — 재귀 피보나치를 AI로 받아 그대로 사용:**

```python
# "피보나치 구현해줘" → 지수 시간 재귀
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# O(2^n) — fib(40) = 약 1억 번 호출
```

**After — DP 조건을 이해하고 AI에게 명시하여 요청:**

```python
# "피보나치를 DP 테뷸레이션으로 O(n), O(1) 공간으로 만들어줘"
def fib(n):
    if n <= 1:
        return n
    prev, curr = 0, 1
    for _ in range(2, n + 1):
        prev, curr = curr, prev + curr
    return curr
# O(n) 시간, O(1) 공간 — fib(10000)도 즉시 처리
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 지수 재귀를 그대로 사용 | 입력이 조금만 커져도 폭발적으로 느려짐 | "DP로 최적화해줘" 요청 |
| DP인지 그리디인지 구분 못 함 | 잘못된 알고리즘 선택 | 최적 부분 구조 + 중복 부분 문제 체크 |
| 메모이제이션 캐시 크기 무시 | 메모리 부족 | lru_cache maxsize 설정 고려 |
| 2D DP 테이블을 공간 최적화 없이 사용 | 불필요한 메모리 사용 | "공간 최적화 가능해?"라고 AI에게 질문 |
| DP 점화식을 AI에게 설명 없이 코드만 요청 | 잘못된 점화식 수령 | 문제를 수식으로 먼저 설명 후 구현 요청 |

## AI 협업 팁

DP 관련 AI 프롬프트 패턴:

1. **DP 조건 확인 요청**: "이 문제가 DP로 풀 수 있는지 확인해줘"
2. **구현 방식 명시**: "top-down(메모이제이션)으로" 또는 "bottom-up(테뷸레이션)으로"
3. **공간 최적화 요청**: "공간 복잡도를 O(1)로 최적화 가능해?"

예시 프롬프트:
> "0-1 배낭 문제를 DP bottom-up으로 구현해줘. n개의 물건과 용량 W인 배낭이 있어. 점화식도 설명해줘."

AI에게 물어볼 추가 질문:
> "이 DP 코드의 공간 복잡도를 줄일 수 있어? 현재 2D 배열을 1D로 줄이는 방법이 있어?"

## 처음 질문으로 돌아가기

지수 시간 재귀를 받았을 때 "DP로 최적화해줘"라고 말할 수 있어야 합니다. DP의 두 조건인 최적 부분 구조와 중복 부분 문제를 이해하면, 어떤 문제가 DP 대상인지 AI와 함께 판단할 수 있습니다. top-down과 bottom-up의 차이를 알면 더 정밀한 요청도 가능합니다.

## 정리

DP는 부분 문제 결과를 저장해 중복 계산을 제거하는 기법입니다. 메모이제이션은 필요할 때만 계산하는 top-down 방식이고, 테뷸레이션은 모든 경우를 순서대로 채우는 bottom-up 방식입니다. 바이브코딩에서 이 차이를 AI에게 전달하면 더 정확한 구현을 받을 수 있습니다.

다음 글에서는 그래프 탐색(BFS, DFS)을 다룹니다. DP가 상태를 저장하며 문제를 푼다면, 그래프 탐색은 연결 관계를 탐색하며 문제를 풉니다.
