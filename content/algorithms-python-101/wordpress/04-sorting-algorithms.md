# 바이브코딩을 위한 Python 알고리즘 (4/10): 정렬 알고리즘

이 글은 바이브코딩을 위한 Python 알고리즘 시리즈의 4번째 글입니다.

"데이터 정렬해줘"라고 AI에게 요청하면 대부분 `sorted()`나 `.sort()`가 나옵니다. 맞습니다. 실무에서는 거의 항상 Python 내장 정렬을 써야 합니다. 그런데 AI가 버블 정렬 구현을 줬을 때 "이게 맞는 코드인가?"를 판단하려면, 정렬 알고리즘의 원리를 알아야 합니다.

정렬은 이진 탐색, 중복 제거, 순위 계산, 그룹화의 기반입니다. 1만 개를 넘어가면 O(n²)와 O(n log n)의 차이는 금방 체감 가능한 수준으로 벌어집니다. 바이브코딩에서 "정렬된 결과가 필요해"라고 AI에게 요청할 때, 안정성이 필요한지, 기준이 복잡한지를 함께 알려줄 수 있어야 합니다.

정렬은 초보자가 생각하는 것보다 훨씬 많은 문제의 바닥에 깔려 있습니다. 실전에서는 `sorted()`를 거의 항상 사용합니다. 그래도 원리를 이해해야 `key`를 제대로 설계하고, 안정성을 의식하고, 병목이 "정렬 알고리즘 선택" 때문인지 "정렬 기준 설계" 때문인지 구분할 수 있습니다.

> 정렬은 데이터를 특정 순서로 재배열하는 일이며, 실무에서는 알고리즘 재구현보다 올바른 정렬 기준과 검증 루프를 설계하는 능력이 더 자주 필요합니다.

---

## 이 글에서 다룰 문제

- 실무에서 직접 정렬 알고리즘을 구현하는 대신 sorted()를 우선해야 하는 이유는 무엇일까요?
- O(n²) 정렬 알고리즘들은 어떤 원리로 동작하며 어디까지 학습용으로 봐야 할까요?
- 병합 정렬과 퀵 정렬은 어떤 차이가 있을까요?
- 안정 정렬이 중요한 상황은 언제일까요?
- AI에게 정렬 관련 요청을 할 때 어떤 조건을 명시해야 할까요?

1만 개를 넘어가면 O(n²)와 O(n log n)의 차이는 금방 체감됩니다. Python의 내장 `sorted()`는 Timsort를 사용해 O(n log n)이고 안정 정렬입니다. 바이브코딩에서는 "왜 sorted()를 써야 하는가"를 이해하는 것이 출발점입니다.

## Before / After

**Before — AI가 준 학습용 구현을 프로덕션에 그대로 사용:**

```python
# AI가 "정렬 함수 만들어줘"에 줄 수 있는 버블 정렬
def bubble_sort(data):
    n = len(data)
    for i in range(n):
        for j in range(0, n - i - 1):
            if data[j] > data[j + 1]:
                data[j], data[j + 1] = data[j + 1], data[j]
    return data
# O(n²) — 1만 개에서 1억 번 비교, 프로덕션 사용 금지
```

**After — 내장 정렬과 명확한 기준 설계:**

```python
# "이름 오름차순, 점수 내림차순으로 정렬해줘"라고 요청
students = [
    {"name": "Alice", "score": 90},
    {"name": "Bob", "score": 85},
    {"name": "Alice", "score": 95},
]
sorted_students = sorted(
    students,
    key=lambda s: (s["name"], -s["score"])
)
# O(n log n), 안정 정렬, 원본 유지
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| AI가 준 버블 정렬을 실제 코드에 사용 | O(n²)로 규모에서 무너짐 | sorted() 또는 .sort() 사용 원칙 |
| 안정 정렬 필요 여부를 무시 | 같은 키에서 순서가 뒤바뀔 수 있음 | Python sorted()는 기본 안정 정렬임을 인지 |
| 복잡한 정렬 기준을 AI에게 설명 못 함 | 원하지 않는 정렬 결과 수령 | lambda와 tuple key 패턴 이해 |
| .sort()와 sorted() 차이 무시 | 원본 데이터 변경 여부 실수 | .sort()는 원본 변경, sorted()는 새 리스트 반환 |
| 정렬 결과 검증 생략 | 버그를 늦게 발견 | 첫 번째, 마지막 원소와 중간 샘플 확인 |

## AI 협업 팁

정렬 관련 AI 프롬프트에 포함할 내용:

1. **정렬 기준 명시**: "이름 오름차순, 점수 내림차순"
2. **안정 정렬 여부**: "같은 이름에서 원래 순서 유지해줘"
3. **원본 변경 여부**: "원본 리스트는 유지하고 새 리스트 반환"

예시 프롬프트:
> "딕셔너리 리스트를 'score' 내림차순, 같은 score면 'name' 오름차순으로 정렬하는 코드 만들어줘. sorted()와 lambda key를 사용하고 원본은 유지해줘."

## 처음 질문으로 돌아가기

AI가 버블 정렬 코드를 줬을 때 "이걸 써도 되나요?"라고 판단할 수 있어야 합니다. 대부분의 경우 답은 "No"입니다. 알고리즘 원리를 알기 때문에 Python 내장 정렬이 왜 더 나은지 이해할 수 있고, 복잡한 정렬 기준을 AI에게 정확히 전달할 수 있습니다.

## 정리

정렬 알고리즘 학습의 목적은 버블 정렬을 외우려는 게 아닙니다. O(n²)와 O(n log n)의 차이를 이해하고, Python sorted()가 왜 최선인지 알고, 복잡한 정렬 기준을 AI에게 정확히 전달하는 능력을 기르는 것입니다.

다음 글에서는 재귀와 분할 정복을 다룹니다. 병합 정렬과 이진 탐색이 모두 이 패턴 위에 있다는 것을 연결해서 이해합니다.
