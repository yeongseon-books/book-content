# 바이브코딩을 위한 소프트웨어 공학 기초 (1/10): 소프트웨어 엔지니어링이란 무엇인가?

이 글은 **바이브코딩을 위한 소프트웨어 공학 기초** 시리즈의 첫 번째 글입니다. AI가 코드를 대신 만들어주는 시대에도, 소프트웨어 공학 지식이 없으면 프로젝트가 실패하는 이유를 10편에 걸쳐 풀어갑니다.

---

바이브코딩이 유행하면서 이런 말을 자주 듣습니다. "AI한테 시키면 코드가 나오는데, 굳이 소프트웨어 공학을 배울 필요가 있나요?"

그 질문에 답하려면 먼저 한 가지를 물어봐야 합니다. 코드가 나왔다고 해서 프로젝트가 성공한 건가요?

처음에는 AI가 척척 코드를 만들어줍니다. 로그인 기능? 뚝딱. 결제 연동? 금방. 그런데 3개월 뒤 어떤 일이 벌어지는지 아시나요? 요구사항이 조금 바뀌었는데 어디를 고쳐야 할지 모르겠고, 버그가 어디서 오는지 추적이 안 되고, 팀원이 합류했더니 아무도 코드를 이해 못하는 상황이 됩니다. AI가 만든 코드라도 소프트웨어 공학 없이는 무너집니다.

이번 글에서는 코딩과 소프트웨어 엔지니어링이 왜 다른지, 그 차이가 바이브코딩 프로젝트에서 어떻게 드러나는지 설명합니다.

> 엔지니어링은 '코드를 쓸 수 있는가'가 아니라 '시간과 사람의 변화 속에서도 시스템을 운영 가능한 상태로 유지할 수 있는가'에 대한 답입니다.

## 이 글에서 다룰 문제

- 코드를 작성하는 일과 소프트웨어 엔지니어링은 무엇이 다를까요?
- 엔지니어는 코드 외에 어떤 영역까지 책임져야 할까요?
- AI가 코드를 만들어줘도 엔지니어링 지식이 필요한 이유는 무엇일까요?
- 바이브코딩 프로젝트에서 이 개념을 모르면 어떤 문제가 생길까요?
- 처음 배우는 사람이 가장 자주 놓치는 포인트는 무엇일까요?

---

## 바이브코딩의 함정: AI가 코드를 만들어도 실패하는 이유

바이브코딩으로 만든 프로젝트가 초반에는 빠르게 진행되다가 어느 순간 멈추는 패턴이 있습니다. 이유는 단순합니다. AI는 지금 이 순간의 코드를 만들 수 있지만, 6개월 뒤에도 그 코드가 살아남을 구조를 설계하지는 않습니다.

실무에서 중요한 것은 "코드를 만들 수 있는가"보다 "시간과 사람의 변화 속에서도 시스템을 운영 가능한 상태로 유지할 수 있는가"입니다. AI한테 "로그인 기능 만들어줘"라고 하면 코드가 나옵니다. 하지만 "이 로그인 기능이 6개월 뒤에도 버그 없이 유지되고, 새 팀원도 이해할 수 있으며, 사고 났을 때 빠르게 복구할 수 있는 구조로 만들어줘"라고 하면 AI만으로는 부족합니다. 그 판단은 엔지니어링 지식을 가진 사람이 해야 합니다.

## 코딩 vs 소프트웨어 엔지니어링: Before / After

**Before — 바이브코더의 시각**

```text
요청 -> AI가 코드 생성 -> 실행됨 -> 완료
```

"코드가 동작한다" = "프로젝트가 성공했다"는 착각에 빠집니다.

**After — 엔지니어의 시각**

```text
요구사항 합의 -> 설계 -> 구현 -> 테스트 -> 배포 -> 운영 -> 변경 -> 반복
```

같은 코드라도 어떤 맥락에서 어떤 책임을 지느냐에 따라 전혀 다른 일이 됩니다.

## AI가 만든 코드가 엔지니어링을 만나면 어떻게 달라지는가

### 1단계 — AI가 만든 빠른 코드

```python
# AI가 뚝딱 만들어준 코드
import sys
n = int(sys.argv[1])
print(sum(range(n)))
```

지금 한 번 돌리고 끝이라면 이것으로도 됩니다. 하지만 팀 프로젝트에 들어간다면?

### 2단계 — 다른 사람이 써야 하는 코드

```python
def sum_to(n: int) -> int:
    """0부터 n-1까지의 합을 반환합니다."""
    if n < 0:
        raise ValueError("n은 0 이상이어야 합니다")
    return n * (n - 1) // 2
```

AI에게 "타입 힌트와 docstring을 추가해줘"라고 할 수 있습니다. 하지만 **언제**, **왜** 이게 필요한지 아는 건 엔지니어링 지식입니다.

### 3단계 — 운영 환경에서 살아남는 코드

```python
import logging
log = logging.getLogger(__name__)

def sum_to(n: int) -> int:
    if n < 0:
        log.warning("잘못된 입력 n=%s", n)
        raise ValueError("n은 0 이상이어야 합니다")
    return n * (n - 1) // 2
```

장애가 났을 때 로그가 없으면 원인을 찾을 수 없습니다. 이 판단을 AI에게 시키려면, 먼저 사람이 "운영 환경에서 로그가 왜 필요한가"를 이해해야 합니다.

### 4단계 — 변경해도 안전한 코드

```python
import pytest
from app import sum_to

def test_sum_to_basic(): assert sum_to(5) == 10
def test_sum_to_zero(): assert sum_to(0) == 0
def test_sum_to_negative():
    with pytest.raises(ValueError): sum_to(-1)
```

테스트가 없으면 AI가 리팩터링한 코드가 기존 동작을 망가뜨렸는지 알 수 없습니다.

### 5단계 — 다음 사람(또는 미래의 나)을 위한 코드

```text
## sum_to 함수
- 입력: 음이 아닌 정수
- 출력: 0부터 n-1까지의 합
- 복잡도: O(1)
- 이력: 2026-05 v1
```

문서가 없으면 3개월 뒤의 나도 이 코드를 이해하는 데 시간이 걸립니다.

## 바이브코딩 프로젝트에서 자주 나오는 실수

| 상황 | 바이브코딩만 할 때 | 소프트웨어 공학 적용 시 |
|------|-------------------|------------------------|
| 요구사항 변경 | "AI한테 다시 만들어달라고 하면 되지" | 변경 영향 범위를 먼저 파악 |
| 버그 발생 | 어디서 나온 건지 몰라 전체를 다시 만듦 | 로그와 테스트로 원인 추적 |
| 팀원 합류 | 코드를 하나씩 설명해야 함 | 문서와 테스트가 설명 역할 |
| 배포 후 사고 | 무엇을 롤백할지 모름 | 버전 관리와 롤백 절차 |

## AI 팁: 바이브코딩에서 엔지니어링 원칙 활용하기

AI에게 코드를 요청할 때 이렇게 프롬프트를 바꿔보세요.

**단순 요청:**
```
로그인 API 만들어줘
```

**엔지니어링 관점 요청:**
```
로그인 API를 만들어줘.
- 실패 케이스(잘못된 비밀번호, 존재하지 않는 계정)에 대한 에러 처리 포함
- 단위 테스트 코드도 함께 작성
- 로깅 포인트 추가 (어떤 이벤트를 로그로 남겨야 하는지 주석으로 설명)
```

두 번째 방식으로 요청하면 AI도 훨씬 나은 코드를 만들어줍니다. 그리고 그 차이를 만드는 건 엔지니어링 지식입니다.

## 처음 질문으로 돌아가기

- **코드를 작성하는 일과 소프트웨어 엔지니어링은 무엇이 다를까요?**
  - 코딩은 지금 동작하는 것을 만드는 일이고, 엔지니어링은 시간이 지나도 유지 가능한 구조를 만드는 일입니다. AI는 코딩을 도와주지만, 엔지니어링 판단은 사람이 해야 합니다.

- **AI가 코드를 만들어줘도 엔지니어링 지식이 필요한 이유는 무엇일까요?**
  - AI는 지금 순간의 코드를 만듭니다. 하지만 6개월 뒤에 버그를 추적하고, 팀원이 이해할 수 있게 하고, 사고 났을 때 복구하는 구조는 엔지니어링 지식이 있어야 설계할 수 있습니다.

- **바이브코딩 프로젝트에서 이 개념을 모르면 어떤 문제가 생길까요?**
  - 처음에는 빠르게 만들어지지만, 요구사항이 바뀌거나 버그가 생기거나 팀이 커지는 순간 전부 다시 만들어야 하는 상황이 생깁니다.

## 정리

소프트웨어 엔지니어링은 코드를 더 많이 쓰는 일이 아닙니다. AI가 코드를 만들어주는 시대에도, 그 코드가 시간이 지나도 유지 가능한 구조를 갖추게 하는 건 엔지니어링 지식입니다.

다음 글에서는 모든 작업의 출발점인 요구사항을 다룹니다. AI에게 무엇을 만들어달라고 할 때, 어떻게 요구사항을 정리해야 하는지 살펴봅니다.
