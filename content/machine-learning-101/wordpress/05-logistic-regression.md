# 바이브코딩을 위한 머신러닝 기초 (5/10): AI가 로지스틱 회귀를 쓴 이유를 이해하려면

이 글은 바이브코딩을 위한 머신러닝 기초 시리즈의 5번째 글입니다.

이탈 고객 예측 모델을 만들어 달라고 AI에게 요청했더니 `LogisticRegression`을 사용한 코드가 나왔습니다. "회귀(Regression)라는 이름이 붙었는데 왜 분류 문제에 쓰는 거지?"라는 생각이 들었습니다. 더 당황스러웠던 건 모델이 0 또는 1 대신 0.73 같은 숫자를 출력할 수 있다는 사실이었습니다.

로지스틱 회귀가 이름은 "회귀"이지만 분류 문제를 푸는 이유, 그리고 확률을 출력하는 것이 단순히 0/1을 출력하는 것보다 왜 더 유용한지 이해하면 AI가 만든 분류 코드를 훨씬 잘 활용할 수 있습니다.

바이브코딩에서 로지스틱 회귀를 알아야 하는 핵심 이유는 임계값(threshold) 때문입니다. AI는 기본적으로 0.5를 임계값으로 사용합니다. 하지만 "이탈 고객을 놓치면 안 된다"는 비즈니스 상황에서는 0.5가 최선의 선택이 아닐 수 있습니다. 이 판단을 내리려면 로지스틱 회귀가 확률을 어떻게 만드는지 알아야 합니다.

> 로지스틱 회귀의 진짜 출력은 "예/아니오"가 아니라 확률입니다. 임계값은 그 확률을 어디서 자를지 결정하는 비즈니스 판단입니다.

## 이 글에서 다룰 문제
- 이름은 회귀인데 왜 분류 문제에 쓰나요?
- 시그모이드 함수가 선형 점수를 확률로 바꾸는 방식은?
- AI가 기본값으로 쓰는 임계값 0.5는 항상 올바른 선택인가요?
- `predict`와 `predict_proba`의 차이는 무엇인가요?
- 이탈 예측처럼 "놓치면 안 되는" 상황에서 임계값을 어떻게 조정하나요?

## 로지스틱 회귀 핵심 개념 한눈에

| 개념 | 설명 | AI 요청에 활용 |
|---|---|---|
| 시그모이드 | 어떤 숫자도 0~1 확률로 변환 | "확률 출력 모델 필요해" |
| predict_proba | 각 클래스의 확률 반환 | "확률값도 함께 출력해줘" |
| 임계값(threshold) | 확률을 클래스로 변환하는 기준 | "threshold를 0.3으로 바꿔줘" |
| 정밀도/재현율 | 임계값에 따라 트레이드오프 | "재현율 우선으로 임계값 설정해줘" |

## 시그모이드: 확률을 만드는 방법

로지스틱 회귀가 "회귀"인 이유는 내부에서 선형 점수를 계산하기 때문입니다. 하지만 그 점수를 시그모이드 함수로 0~1 사이 확률로 바꿔서 분류에 사용합니다.

```python
# AI가 만들어 주는 로지스틱 회귀 코드
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(max_iter=1000).fit(Xtr, ytr)

# predict: 0.5 기준으로 0 또는 1 반환
pred = model.predict(Xte)

# predict_proba: 각 클래스의 확률 반환
proba = model.predict_proba(Xte)
# [[0.27, 0.73], ...] → 클래스 0 확률 27%, 클래스 1 확률 73%
```

`predict`는 0.5 기준으로 자른 결과이고, `predict_proba`는 자르기 전 확률입니다. 비즈니스 상황에 맞는 임계값을 직접 정하려면 `predict_proba`가 필요합니다.

## Before / After

**Before**: AI가 만든 코드에서 `model.predict(Xte)`만 확인했습니다. 정확도 88%로 좋아 보였지만, 실제 이탈 고객을 40%밖에 잡아내지 못했습니다(재현율 0.40).

**After**: "predict_proba 사용하고 threshold를 0.3으로 낮춰줘"라고 요청해서 재현율을 0.70까지 높였습니다. 정밀도는 낮아졌지만 이탈 고객을 더 많이 잡아낼 수 있었습니다.

## 임계값 조정: 바이브코딩의 핵심 활용 포인트

AI에게 이렇게 요청하면 임계값 효과를 바로 볼 수 있습니다.

```python
# AI에게 요청: "임계값별 정밀도와 재현율 출력 코드 만들어줘"
prob = model.predict_proba(Xte)[:, 1]
for t in [0.3, 0.4, 0.5, 0.6, 0.7]:
    pred_t = (prob >= t).astype(int)
    from sklearn.metrics import precision_score, recall_score
    p = precision_score(yte, pred_t)
    r = recall_score(yte, pred_t)
    print(f"threshold={t:.1f}  precision={p:.3f}  recall={r:.3f}")
```

이 코드 하나로 임계값을 바꾸면 정밀도와 재현율이 어떻게 움직이는지 볼 수 있습니다. 비즈니스 상황에 따라 어느 쪽을 더 높일지 판단할 수 있게 됩니다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| predict만 사용, proba 확인 안 함 | 임계값 조정 불가 | predict_proba 함께 요청 |
| 0.5 임계값을 항상 최선으로 가정 | 비즈니스 비용 무시 | 재현율/정밀도 트레이드오프 확인 |
| 불균형 데이터에서 정확도만 보고 | 다수 클래스만 잘 맞춰도 정확도 높음 | F1, 재현율, 정밀도 함께 확인 |
| 피처 스케일링 없이 학습 | 로지스틱 회귀는 스케일에 민감 | StandardScaler 추가 요청 |

## AI에게 ML 관련 질문하는 팁

**로지스틱 회귀 완전한 요청 패턴:**

"이탈 예측 분류 모델 만들어줘. 다음 조건 포함해:
1. StandardScaler로 피처 스케일링
2. predict_proba로 확률 출력
3. classification_report로 정밀도/재현율/F1 출력
4. 임계값 0.3, 0.4, 0.5, 0.6, 0.7에서 재현율 변화 출력
5. 이탈 고객 놓치는 게 더 나쁘므로 재현율 우선"

**AI에게 임계값 결정 요청:**
- "재현율 0.8 이상을 유지하면서 정밀도가 최대가 되는 임계값 찾아줘"
- "FN(이탈 고객 미탐지) 비용이 FP의 3배일 때 최적 임계값 계산해줘"

## 운영 체크리스트
- [ ] predict 대신 predict_proba도 확인합니다
- [ ] 임계값 0.5가 비즈니스 상황에 맞는지 검토했습니다
- [ ] 불균형 데이터에서 정확도 외 재현율/정밀도도 확인했습니다
- [ ] 피처 스케일링이 포함되어 있는지 확인했습니다
- [ ] 재현율과 정밀도의 트레이드오프를 이해했습니다

## 처음 질문으로 돌아가기

- **이름은 회귀인데 왜 분류에 쓰나요?**
  - 내부에서 선형 점수(회귀)를 계산한 뒤 시그모이드로 확률로 변환해서 분류에 사용하기 때문입니다. "로지스틱"은 시그모이드의 다른 이름입니다.
- **시그모이드가 뭔가요?**
  - 어떤 실수도 0과 1 사이 값으로 변환하는 S자 모양 함수입니다. 선형 회귀 점수를 확률로 만들어 줍니다.
- **임계값 0.5가 항상 최선인가요?**
  - 아닙니다. 이탈 고객을 놓치면 안 되는 상황에서는 0.3으로 낮춰서 재현율을 높여야 할 수 있습니다. 비즈니스 비용에 따라 결정해야 합니다.
- **predict와 predict_proba의 차이는?**
  - `predict`는 임계값(기본 0.5) 기준으로 0 또는 1을 반환합니다. `predict_proba`는 각 클래스의 확률(0.27, 0.73 같은 값)을 반환해서 임계값을 직접 조정할 수 있게 합니다.
- **재현율 우선 임계값은 어떻게 설정하나요?**
  - AI에게 "임계값별 재현율과 정밀도 표를 만들어줘"라고 요청하고, 재현율이 원하는 수준 이상인 임계값 중 가장 높은 것을 고릅니다.

## 정리

로지스틱 회귀를 이해하면 AI가 만든 분류 코드를 활용하는 방식이 달라집니다. `predict_proba`로 확률을 확인하고, 비즈니스 상황에 맞는 임계값을 설정하는 것이 단순히 `predict` 결과만 보는 것보다 훨씬 강력합니다. "이탈 고객을 놓치면 안 된다"는 상황에서는 정확도보다 재현율을 우선하고 임계값을 낮추라는 요청을 AI에게 구체적으로 전달할 수 있어야 합니다.
