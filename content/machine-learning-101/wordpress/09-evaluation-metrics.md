# 바이브코딩을 위한 머신러닝 기초 (9/10): AI가 "정확도 95%"라고 했는데 진짜 좋은 건지 — 평가 지표

이 글은 바이브코딩을 위한 머신러닝 기초 시리즈의 9번째 글입니다.

암 진단 보조 모델을 만들어 달라고 AI에게 요청했습니다. "정확도 95%가 나왔습니다"라는 결과를 받았습니다. 처음에는 좋다고 생각했습니다. 그런데 데이터를 보니 암 환자가 5%밖에 없었습니다. 모든 사람을 "정상"으로 예측해도 정확도는 95%가 됩니다. AI가 만든 모델이 실제로 암 환자를 한 명도 잡지 못하면서 95%가 나온 것이었습니다.

이것이 "정확도의 함정"입니다. 바이브코딩에서 AI가 "정확도 N%"라고 보고할 때, 그게 진짜 좋은 건지 판단하려면 더 많은 정보가 필요합니다. 특히 데이터가 불균형하거나, "놓치면 안 되는" 경우가 있을 때는 정확도 하나로 충분하지 않습니다.

평가 지표를 이해하면 AI가 보고하는 숫자를 제대로 검토할 수 있습니다. 그리고 "이 문제에서는 재현율이 더 중요해"라고 AI에게 명확하게 전달해서 더 의미 있는 결과를 얻을 수 있습니다.

> "어떤 모델이 더 좋아요?"라고 물으면 AI가 정확도로 답합니다. "어떤 실패가 더 나쁜가요?"를 먼저 정해야 올바른 지표를 고를 수 있습니다.

---

## 이 글에서 다룰 문제
- 정확도 95%가 실제로 아무 의미 없을 수 있는 상황은 언제인가요?
- 혼동 행렬의 네 칸(TP, FP, FN, TN)은 각각 무슨 뜻인가요?
- 재현율과 정밀도 중 어느 쪽이 더 중요한지 어떻게 판단하나요?
- ROC-AUC와 PR-AUC는 각각 언제 더 유용한가요?
- AI에게 "이 문제에 맞는 지표로 평가해줘"라고 어떻게 요청하나요?

## 분류 지표 한눈에 보기

| 지표 | 질문 | 언제 중요한가 |
|---|---|---|
| 정확도(Accuracy) | 전체 중 얼마나 맞혔나 | 클래스 균형이 맞을 때만 |
| 정밀도(Precision) | 양성 예측 중 실제 양성 비율 | 오탐(FP) 비용이 클 때 |
| 재현율(Recall) | 실제 양성 중 잡아낸 비율 | 미탐(FN) 비용이 클 때 |
| F1 Score | 정밀도와 재현율의 조화 평균 | 둘 다 중요할 때 |
| ROC-AUC | 임계값 전반에서 분리 능력 | 임계값 미결정 상태 비교 |
| PR-AUC | 불균형 데이터의 분리 능력 | 양성 클래스가 희소할 때 |

## 혼동 행렬: 숫자의 진실

```python
# AI에게 요청: "혼동 행렬 출력해줘"
from sklearn.metrics import confusion_matrix, classification_report

pred = model.predict(Xte)
cm = confusion_matrix(yte, pred)
print("혼동 행렬:")
print(cm)
print()
print(classification_report(yte, pred))
```

혼동 행렬 예시:

```
           예측 음성  예측 양성
실제 음성    TN=880   FP=70
실제 양성    FN=35    TP=215
```

- **FP=70**: 정상인을 암이라고 잘못 예측 (불필요한 추가 검사)
- **FN=35**: 암 환자를 정상으로 놓침 (이게 더 위험)

암 진단에서는 FN(암 환자를 놓침)이 FP(정상인을 암으로 예측)보다 훨씬 비용이 큽니다. 따라서 재현율(Recall)을 높이는 방향으로 임계값을 조정해야 합니다.

## Before / After

**Before**: AI가 "정확도 95%"라고 보고, 확인해보니 모든 데이터를 다수 클래스(정상)로 예측하고 있었습니다. 실제 양성 클래스(암)의 재현율은 0이었습니다.

**After**: AI에게 "classification_report, 혼동 행렬, ROC-AUC를 함께 출력해줘. 이 문제는 재현율이 중요해"라고 요청해서 재현율 0.82 모델을 얻었습니다.

## 불균형 데이터에서 올바른 지표 선택

```python
from sklearn.metrics import (
    classification_report, roc_auc_score,
    average_precision_score, confusion_matrix
)

# 확률 예측
prob = model.predict_proba(Xte)[:, 1]
pred = model.predict(Xte)

# 여러 지표 한 번에 확인
print("Classification Report:")
print(classification_report(yte, pred))
print(f"ROC-AUC: {roc_auc_score(yte, prob):.3f}")
print(f"PR-AUC : {average_precision_score(yte, prob):.3f}")
print("Confusion Matrix:")
print(confusion_matrix(yte, pred))
```

**양성 클래스가 5% 이하로 희소할 때**: PR-AUC가 ROC-AUC보다 더 엄격한 평가를 합니다. AI에게 "ROC-AUC 외에 PR-AUC도 출력해줘"라고 요청합니다.

## 회귀 지표도 함께 알아두기

| 지표 | 민감도 | 언제 사용 |
|---|---|---|
| MAE | 이상치에 강함 | 오차 크기가 직관적으로 중요할 때 |
| RMSE | 이상치에 민감 | 큰 오차에 더 큰 페널티를 줄 때 |
| R² | 설명력 | "얼마나 설명하는가"가 중요할 때 |

AI에게 회귀 평가를 요청할 때는 "MAE와 RMSE 둘 다 출력해줘"라고 하면 이상치의 영향을 비교할 수 있습니다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 정확도만 보고 모델 채택 | 불균형 데이터에서 거짓 성공 | classification_report 항상 요청 |
| "좋은 모델 선택해줘" 요청 | AI가 정확도 기준으로 고름 | "재현율 우선" 또는 "F1 기준" 명시 |
| ROC-AUC만 봄 | 불균형 데이터에서 낙관적 | PR-AUC도 함께 확인 |
| 회귀에서 R²만 봄 | 이상치 영향 파악 못 함 | MAE, RMSE도 함께 확인 |

## AI에게 ML 관련 질문하는 팁

**평가 지표 완전한 요청 패턴:**

"모델 평가 결과 출력해줘. 다음 모두 포함:
1. classification_report (정밀도, 재현율, F1)
2. 혼동 행렬
3. ROC-AUC와 PR-AUC
4. 이 문제는 [FN/FP] 비용이 더 크므로 [재현율/정밀도]를 우선 지표로 볼 것"

**지표 해석 질문:**
- "이 데이터에서 정확도 95%가 의미 있는 건가요?"
- "FN 비용이 FP의 3배라면 어떤 임계값이 최적인가요?"
- "ROC-AUC와 PR-AUC 결과가 많이 다른데 어떤 걸 믿어야 하나요?"
- "두 모델을 비교할 때 어떤 지표를 기준으로 해야 할까요?"

## 운영 체크리스트
- [ ] 정확도 외에 precision, recall, F1도 함께 확인합니다
- [ ] 혼동 행렬에서 FP와 FN 중 어느 쪽이 더 비싼지 판단합니다
- [ ] 불균형 데이터에서는 PR-AUC도 확인합니다
- [ ] 회귀에서는 MAE와 RMSE를 함께 봅니다
- [ ] 비즈니스 비용 구조에 맞는 지표를 AI에게 명시합니다

## 처음 질문으로 돌아가기

- **정확도 95%가 의미 없을 수 있는 상황은?**
  - 양성 클래스가 5%밖에 없을 때 모든 걸 음성으로 예측해도 정확도 95%가 됩니다. 클래스 불균형이 있을 때 정확도만 보면 안 됩니다.
- **혼동 행렬의 FN은 왜 중요한가요?**
  - FN(실제 양성을 음성으로 예측)은 "놓친 케이스"입니다. 암 진단에서 FN은 암 환자를 정상으로 보낸 것이고, 이건 FP(정상을 암으로 예측)보다 훨씬 더 위험합니다.
- **재현율과 정밀도 중 어느 쪽이 더 중요한가요?**
  - 문제에 따라 다릅니다. "놓치면 안 된다"는 상황(암 진단, 사기 탐지)에서는 재현율, "틀린 알람이 비용이 크다"는 상황(마케팅 타겟팅)에서는 정밀도를 우선합니다.
- **ROC-AUC와 PR-AUC 중 어느 걸 써야 하나요?**
  - 클래스가 균형 잡혀 있으면 ROC-AUC, 양성 클래스가 희소하면 PR-AUC가 더 정직한 평가를 합니다.
- **AI에게 지표를 명시해서 요청하는 방법은?**
  - "이 문제에서 FN 비용이 FP보다 크므로 재현율을 우선 지표로 하고, threshold를 0.3으로 낮춰서 평가해줘"처럼 비즈니스 맥락을 함께 전달합니다.

## 정리

"정확도 95%"라는 숫자 하나로 모델을 판단하면 안 됩니다. 특히 클래스 불균형이 있거나 "놓치면 안 되는" 케이스가 있을 때는 혼동 행렬, 재현율, 정밀도, F1, AUC를 함께 봐야 합니다. AI에게 평가를 요청할 때 "이 문제에서는 재현율이 정밀도보다 중요해"처럼 비즈니스 맥락을 함께 전달하면 더 의미 있는 평가 결과를 받을 수 있습니다.
