# 바이브코딩을 위한 머신러닝 기초 (1/10): ML이 뭔지 알아야 AI에게 제대로 시킬 수 있다

이 글은 바이브코딩을 위한 머신러닝 기초 시리즈의 1번째 글입니다.

Claude에게 "이 데이터로 예측 모델 만들어줘"라고 했더니 코드가 뚝딱 나왔습니다. `fit`, `predict`, `score` 세 줄에 정확도 97%. 그런데 다음날 팀장이 "이 모델 실제 서비스에 써도 되나요?"라고 물었을 때, 뭐라고 답해야 할지 몰랐습니다. AI가 만든 코드가 돌아가는 건 알겠는데, 그 숫자가 무엇을 뜻하는지, 왜 97%가 사실 믿을 수 없는 숫자인지 설명할 수 없었던 것입니다.

바이브코딩 시대에 AI는 코드를 순식간에 만들어 줍니다. 하지만 그 코드가 올바른 문제를 풀고 있는지, 출력된 숫자가 실제로 무엇을 의미하는지 판단하는 건 여전히 사람의 몫입니다. 머신러닝의 세 가지 핵심 개념, 학습·일반화·예측을 이해하지 못하면 AI가 만든 코드를 검토할 수가 없습니다.

머신러닝은 한 문장으로 정리하면 이렇습니다. "데이터에서 함수를 학습해 새로운 입력에 대해 예측하는 방식." AI에게 모델을 만들어 달라고 요청할 때, 내가 원하는 게 정확히 무엇인지 설명할 수 있어야 AI도 제대로 된 코드를 만들어 줍니다. "예측 모델"이라는 말 하나로는 충분하지 않습니다. 무엇을 예측하는지, 정답 데이터가 있는지, 숫자를 맞춰야 하는지 범주를 나눠야 하는지, 이 질문들에 답할 수 있어야 AI와의 대화가 정확해집니다.

> AI가 코드를 만들어도, 그 코드가 올바른 문제를 풀고 있는지 판단하는 건 여전히 사람의 몫입니다.

---

## 이 글에서 다룰 문제
- AI가 만들어 준 ML 코드, 정확도 97%가 왜 믿을 수 없는 숫자일까요?
- "예측 모델 만들어줘"라고 할 때 AI에게 전달해야 할 정보는 무엇일까요?
- 학습, 일반화, 예측은 각각 무슨 뜻이고 왜 구분해야 할까요?
- 지도학습, 비지도학습, 강화학습 중 내 문제는 어디에 속할까요?
- ML이 적합한 문제와 그냥 `if-else`로 해결해야 하는 문제는 어떻게 구분할까요?

## ML 유형 비교

| 유형 | 입력 | 출력 | AI에게 요청할 때 |
|---|---|---|---|
| 지도학습 | X, y (레이블 있음) | 분류/회귀 예측 | "이 데이터로 스팸 분류기 만들어줘" |
| 비지도학습 | X (레이블 없음) | 구조 발견 | "고객을 비슷한 그룹으로 나눠줘" |
| 강화학습 | 상태, 보상 | 행동 정책 | "게임에서 최적 전략 학습시켜줘" |

바이브코딩에서 가장 자주 마주치는 건 지도학습입니다. "정답 데이터가 있고, 새 데이터에 대해 예측하고 싶다"는 상황이 대부분이기 때문입니다.

## AI와 ML 코드 작업할 때 알아야 할 핵심 개념

- **학습(Learning)**: 데이터에서 함수를 추정하는 과정입니다. AI가 `model.fit(X, y)`를 쓰는 이유입니다.
- **일반화(Generalization)**: 훈련 때 보지 못한 데이터에도 잘 동작하는 성질입니다. 97% 정확도가 거짓말일 수 있는 이유입니다.
- **예측(Prediction)**: 학습된 함수를 새로운 입력에 적용하는 일입니다. `model.predict(new_data)`가 하는 일입니다.
- **피처(Feature)**: 모델에 들어가는 입력 변수입니다. "어떤 정보를 줄 것인가"입니다.
- **레이블(Label)**: 예측하려는 정답입니다. "무엇을 맞추려 하는가"입니다.

## Before / After

**Before**: AI에게 "예측 모델 만들어줘"라고 했더니 코드가 나왔고, 정확도 97%를 보고 성공했다고 생각했습니다. 팀장 질문에 아무 말도 못 했습니다.

**After**: "훈련 데이터 정확도가 97%인데, 이건 같은 데이터로 평가한 거라서 실제 성능이 아닙니다. 새 데이터로 검증이 필요합니다"라고 설명할 수 있게 됐습니다.

## AI가 만든 첫 ML 코드 읽어보기

AI가 만들어 준 전형적인 코드입니다.

```python
from sklearn.datasets import load_iris
from sklearn.linear_model import LogisticRegression

X, y = load_iris(return_X_y=True)
model = LogisticRegression(max_iter=1000).fit(X, y)
print("Accuracy:", model.score(X, y))  # 예: 0.97
```

여기서 `model.score(X, y)`는 학습에 쓴 같은 데이터로 점수를 재는 겁니다. 마치 시험 문제를 미리 알고 시험 보는 것과 같습니다. 이 점수는 "모델이 데이터를 얼마나 외웠는가"이지 "새 데이터에서 얼마나 잘 맞히는가"가 아닙니다.

AI에게 이렇게 추가 요청해야 합니다: "train/test split을 추가하고 테스트 세트 정확도도 함께 보여줘."

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| AI 코드 그대로 정확도만 확인 | 훈련 데이터 점수는 과대평가됨 | train/test split 후 테스트 점수 확인 |
| 문제 유형 설명 없이 "모델 만들어줘" | AI가 잘못된 유형 선택 가능 | "분류 문제", "회귀 문제" 명시 |
| 피처와 레이블 설명 없이 데이터만 전달 | X와 y가 뭔지 AI가 추측해야 함 | "y 컬럼이 예측 대상" 명시 |
| 모든 문제에 ML 적용 | 간단한 규칙으로 해결 가능한 것도 있음 | 데이터와 패턴 복잡도 먼저 판단 |

## AI에게 ML 관련 질문하는 팁

ML 작업을 AI에게 요청할 때 이 정보를 함께 주면 훨씬 좋은 코드가 나옵니다.

1. **문제 유형 명시**: "분류 문제입니다" / "연속값 예측 문제입니다"
2. **데이터 구조 설명**: "X는 10개 피처, y는 0 또는 1 이진 레이블입니다"
3. **평가 기준 제시**: "정확도보다 재현율이 중요합니다"
4. **제약 조건 전달**: "결과를 설명해야 하므로 해석 가능한 모델이 필요합니다"

이 네 가지만 챙겨도 AI와의 ML 작업 품질이 완전히 달라집니다.

## 운영 체크리스트
- [ ] X(입력)와 y(출력)가 무엇인지 한 문장으로 설명할 수 있습니다
- [ ] 내 문제가 분류인지 회귀인지 군집인지 구분할 수 있습니다
- [ ] 훈련 정확도와 테스트 정확도가 다를 수 있다는 걸 이해했습니다
- [ ] AI에게 ML 요청할 때 필요한 4가지 정보를 알고 있습니다
- [ ] ML이 적합하지 않은 문제(규칙 명확, 데이터 부족)를 구분할 수 있습니다

## 처음 질문으로 돌아가기

- **AI가 만든 정확도 97%, 왜 믿을 수 없나요?**
  - 같은 데이터로 학습하고 같은 데이터로 점수를 재면 숫자는 좋아 보이지만 일반화 성능이 아닙니다. 분리된 테스트 데이터로 확인해야 합니다.
- **"예측 모델 만들어줘"에 추가해야 할 정보는?**
  - 문제 유형(분류/회귀), 데이터 구조(피처/레이블), 평가 기준, 제약 조건을 함께 전달해야 합니다.
- **학습, 일반화, 예측의 차이는?**
  - 학습은 데이터에서 함수를 찾는 것, 일반화는 새 데이터에서도 잘 동작하는 것, 예측은 학습한 함수를 새 입력에 적용하는 것입니다.
- **내 문제가 어떤 ML 유형인지 어떻게 알 수 있나요?**
  - 정답 데이터가 있으면 지도학습, 없으면 비지도학습입니다. 예측 대상이 범주면 분류, 숫자면 회귀입니다.
- **ML이 필요 없는 문제는 어떤 것인가요?**
  - 규칙이 명확하고 안정적이거나, 데이터가 거의 없거나, 결정 과정이 완전히 투명해야 하는 경우입니다.

## 정리

바이브코딩에서 AI는 ML 코드를 빠르게 만들어 줍니다. 하지만 그 코드가 올바른 문제를 풀고 있는지, 출력된 숫자가 무엇을 의미하는지 판단하려면 머신러닝의 기본 개념이 필요합니다. 학습은 데이터에서 함수를 찾는 것, 일반화는 새 데이터에서도 잘 동작하는 것, 그리고 훈련 정확도와 테스트 정확도는 전혀 다른 숫자라는 점, 이 세 가지를 알면 AI와의 ML 작업 방식이 달라집니다.
