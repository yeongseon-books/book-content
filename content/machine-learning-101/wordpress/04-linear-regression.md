# 바이브코딩을 위한 머신러닝 기초 (4/10): AI가 선형 회귀를 썼는데 맞는 선택인지 판단하려면

이 글은 바이브코딩을 위한 머신러닝 기초 시리즈의 4번째 글입니다.

집값 예측 모델을 만들어 달라고 AI에게 요청했습니다. AI가 `LinearRegression`을 사용한 코드를 만들어 줬고, R² 점수가 0.72가 나왔습니다. "꽤 좋은 것 같은데?"라고 생각했지만, 동료가 "잔차 플롯 봤어요?"라고 물었습니다. 잔차가 뭔지도 몰랐고, R² 0.72가 좋은 건지도 사실 잘 몰랐습니다.

AI는 요청에 맞게 코드를 만들어 주지만, 그 모델이 데이터에 적합한지, 결과를 어떻게 해석해야 하는지는 내가 판단해야 합니다. 선형 회귀를 이해하면 AI가 만든 회귀 코드를 검토하고, 결과를 해석하고, "더 좋게 만들어줘"라고 구체적으로 요청할 수 있습니다.

선형 회귀는 가장 단순하고 해석 가능한 회귀 모델입니다. 바로 그래서 가장 먼저 시도해야 하는 베이스라인이기도 합니다. AI가 선형 회귀를 선택했다면 그건 나쁜 선택이 아닙니다. 다만 그 결과가 믿을 만한지 확인하는 방법을 알아야 합니다.

> 선형 회귀 결과를 평가하는 세 가지 도구: 계수(coef\_), R², 잔차 플롯. 이 세 가지를 함께 보지 않으면 모델을 절반만 이해한 겁니다.

---

## 이 글에서 다룰 문제
- AI가 선형 회귀를 선택했을 때 그게 적합한 모델인지 어떻게 확인하나요?
- R² 0.72는 좋은 건지 나쁜 건지 어떻게 판단하나요?
- 계수(coef\_)를 읽을 때 어떤 점을 주의해야 하나요?
- 잔차 플롯에서 어떤 패턴이 보이면 선형 모델이 부족하다는 신호인가요?
- AI에게 "선형 회귀 검증해줘"라고 요청할 때 뭘 포함해야 할까요?

## 선형 회귀 결과 해석 가이드

| 지표 | 의미 | 좋은 신호 | 나쁜 신호 |
|---|---|---|---|
| R² | 모델이 분산을 얼마나 설명하는가 | 도메인 기준으로 높음 | 음수이거나 0에 가까움 |
| MSE | 평균 제곱 오차 | 작을수록 좋음 | 이상치가 있으면 왜곡됨 |
| 잔차 패턴 | 설명 못 한 부분의 패턴 | 무작위로 흩어짐 | 곡선, 깔때기 모양 |
| 계수 부호 | 피처와 예측값의 관계 | 상식과 일치 | 상식과 반대 방향 |

## AI가 만든 선형 회귀 코드 검토하기

AI가 주로 만들어 주는 코드 패턴입니다.

```python
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error, r2_score

model = LinearRegression().fit(Xtr, ytr)
pred = model.predict(Xte)

print("MSE:", mean_squared_error(yte, pred))
print("R^2:", r2_score(yte, pred))
```

이 코드에서 추가로 확인해야 할 것들을 AI에게 요청합니다.

```python
# 계수 확인: 어떤 피처가 얼마나 영향을 주는가
for name, coef in zip(feature_names, model.coef_):
    print(f"{name}: {coef:.3f}")

# 잔차 확인: 선형 모델로 설명 못 한 패턴이 있는가
residuals = yte - pred
# residuals를 플롯하면 패턴이 보임
```

## Before / After

**Before**: AI가 만든 선형 회귀 코드, R² 0.72를 보고 "72% 설명하니까 괜찮다"고 보고했습니다. 나중에 잔차에 곡선 패턴이 있어서 비선형 모델이 필요했다는 걸 알게 됐습니다.

**After**: AI에게 "MSE, R², 잔차 플롯, 계수 출력을 모두 포함한 회귀 평가 코드 만들어줘"라고 요청해서 처음부터 완전한 검토를 했습니다.

## 선형 회귀가 적합하지 않은 상황 파악하기

AI가 선형 회귀를 썼더라도 이런 신호가 보이면 다른 모델이 필요합니다.

**잔차 패턴으로 확인:**
- 잔차가 예측값에 따라 곡선을 그린다 → 비선형 관계, 다항 피처 추가 필요
- 잔차의 퍼짐이 커졌다 작아졌다 한다 → 등분산성 위반, 로그 변환 고려
- 특정 구간에 잔차가 몰려 있다 → 중요한 피처가 빠졌을 가능성

AI에게 이렇게 요청합니다: "잔차 vs 예측값 플롯을 그려줘. 패턴이 있으면 어떤 문제인지 설명해줘."

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| R² 하나만 보고 판단 | 잔차 패턴이 나쁠 수 있음 | MSE + R² + 잔차 플롯 함께 확인 |
| 스케일 다른 계수 직접 비교 | 큰 단위 피처가 작아 보임 | 피처 표준화 후 계수 비교 |
| 이상치 확인 안 함 | 한 점이 직선을 끌고 감 | 잔차 큰 샘플 별도 확인 |
| 선형성 가정 확인 안 함 | 곡선 관계에 직선 맞추기 | 산점도로 선형성 먼저 확인 |

## AI에게 ML 관련 질문하는 팁

**선형 회귀 검증 요청 패턴:**

"선형 회귀 모델 만들어주고 다음 내용도 포함해줘:
1. MSE와 R² 출력
2. 잔차 vs 예측값 플롯 코드
3. 피처별 계수와 부호 출력
4. 잔차 분포가 정규분포인지 확인하는 코드"

**AI에게 결과 해석 요청하기:**
- "R² 0.72는 이 문제에서 좋은 건가요, 나쁜 건가요?"
- "잔차에 이런 패턴이 있는데 어떤 의미인가요?"
- "계수 중 부호가 예상과 반대인 게 있는데 왜 그럴 수 있나요?"
- "선형 회귀 대신 어떤 모델을 시도해봐야 할까요?"

## 운영 체크리스트
- [ ] MSE와 R² 두 가지를 함께 보고합니다
- [ ] 잔차 플롯에서 곡선 패턴이 없는지 확인합니다
- [ ] 계수를 비교하기 전에 피처를 표준화했는지 확인합니다
- [ ] 이상치가 직선을 끌어당기고 있지 않은지 확인합니다
- [ ] R² 기준치를 도메인 맥락으로 판단합니다

## 처음 질문으로 돌아가기

- **AI가 선형 회귀를 선택한 게 맞는지 어떻게 확인하나요?**
  - R²와 잔차 플롯을 확인합니다. 잔차에 곡선 패턴이 없고 R²가 도메인 기준으로 충분하면 선형 회귀가 적합합니다.
- **R² 0.72는 좋은 건가요?**
  - 도메인에 따라 다릅니다. 금융 예측에서 0.72는 매우 좋을 수 있고, 물리 측정에서는 부족할 수 있습니다. 베이스라인 없이 숫자 하나만으로 판단하기 어렵습니다.
- **계수를 읽을 때 주의할 점은?**
  - 스케일이 다른 피처의 계수를 직접 비교하면 안 됩니다. 표준화 후 계수를 비교하거나, 계수보다 부호(방향)를 먼저 상식과 맞는지 확인합니다.
- **잔차 플롯에서 어떤 패턴이 나쁜 신호인가요?**
  - 무작위가 아닌 곡선, 깔때기 모양, 특정 구간 편향이 보이면 선형 모델이 부족합니다. 비선형 피처 추가나 다른 모델을 고려해야 합니다.
- **"더 좋게 만들어줘"를 구체적으로 요청하려면?**
  - "잔차에 곡선 패턴이 있어서 2차 다항 피처 추가해줘" 또는 "이상치 3개가 영향이 커서 Ridge로 바꿔줘"처럼 구체적인 근거를 함께 전달합니다.

## 정리

선형 회귀를 이해하면 AI가 만든 회귀 코드를 제대로 검토할 수 있습니다. R² 하나만으로는 부족하고, 잔차 플롯과 계수 부호까지 함께 봐야 합니다. 잔차에 패턴이 있으면 "선형 회귀가 부족하다"는 신호이고, AI에게 구체적인 개선 방향을 요청할 수 있습니다. 베이스라인으로서의 선형 회귀는 항상 가장 먼저 시도해볼 가치가 있습니다.
