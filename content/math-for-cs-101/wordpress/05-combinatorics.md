이 글은 **바이브코딩을 위한 CS 수학** 시리즈의 5편입니다. 조합론이 알고리즘 설계, 테스트 케이스 설계, 탐색 공간 추정에서 어떤 역할을 하는지 바이브코딩 관점에서 살펴봅니다.

---

"모든 경우를 테스트하면 되지 않나요?" — 3개의 설정 값이 각각 10가지 옵션을 가지면 10³ = 1,000가지 조합이 생깁니다. 5개 설정이 되면 100,000가지입니다. 조합론은 이 경우의 수 폭발을 예측하고 관리하는 도구입니다.

바이브코딩 환경에서 AI에게 "모든 경우를 처리해줘"라고 할 때, 그 경우의 수가 얼마나 되는지 모르면 실행 불가능한 코드를 받아도 알아채기 어렵습니다.

> "조합은 경우의 수 폭발을 눈으로 보이게 만듭니다. 탐색하기 전에 먼저 세어봐야 합니다."

## 순열과 조합: 순서가 중요한가?

### Before: 순열/조합 구분 없이 구현

```python
# 팀 구성 — 순서 중요하지 않은데 순열로 구현
from itertools import permutations
team = list(permutations([1, 2, 3, 4], 2))
print(len(team))  # 12 — 실제 필요한 조합의 2배
```

### After: 조합으로 정확하게

```python
from itertools import combinations, permutations
from math import comb, perm

# 조합: 순서 무관 (팀 구성, 부분집합)
teams = list(combinations([1, 2, 3, 4], 2))
print(len(teams))  # 6 = C(4,2)

# 순열: 순서 중요 (비밀번호, 순위)
orders = list(permutations([1, 2, 3, 4], 2))
print(len(orders))  # 12 = P(4,2)

print(comb(4, 2))  # 6
print(perm(4, 2))  # 12
```

## 경우의 수 폭발 예측

| 구조 | 공식 | n=10 | n=20 | n=30 |
| --- | --- | --- | --- | --- |
| 선형 | n | 10 | 20 | 30 |
| 이차 | n² | 100 | 400 | 900 |
| 조합 | C(n,2) | 45 | 190 | 435 |
| 지수 | 2^n | 1,024 | 1,048,576 | 1,073,741,824 |
| 팩토리얼 | n! | 3,628,800 | 2.4×10^18 | 2.6×10^32 |

n=20에서 2^n은 백만, n!은 2경이 넘습니다. "모든 경우를 탐색"하는 알고리즘은 n이 작을 때만 가능합니다.

## 비둘기집 원리와 해시 충돌

비둘기집 원리: n+1개의 비둘기가 n개의 집에 들어가면 적어도 하나의 집에 2마리 이상이 있습니다.

```python
# 해시 충돌: 가능한 키 > 버킷 수이면 충돌은 필연적
bucket_count = 1000
possible_keys = 10000  # 가능한 키 공간
# 비둘기집 원리: 충돌 불가피

import hashlib

def hash_collision_example():
    """생일 문제: 23명이면 같은 생일 확률 > 50%"""
    from math import exp
    n, days = 23, 365
    prob_no_collision = 1.0
    for i in range(n):
        prob_no_collision *= (days - i) / days
    return 1 - prob_no_collision

print(f"23명 중 같은 생일: {hash_collision_example():.2%}")  # ~50.7%
```

## AI 팁: 조합 폭발을 AI와 함께 관리하기

1. **"이 파라미터 조합의 수는 몇 개야?"** — 탐색 공간을 먼저 계산합니다.
2. **"페어와이즈 테스팅으로 테스트 케이스를 줄여줘"** — 조합 폭발을 억제합니다.
3. **"백트래킹 대신 가지치기를 추가해줘"** — 불필요한 탐색을 제거합니다.
4. **itertools.product, combinations, permutations**를 익혀두면 AI 코드 검토에 도움됩니다.

## 처음 질문으로 돌아가기

- **순열과 조합의 차이는 코드에서 어떻게 구분할까요?**
  순서가 중요하면 순열(P), 중요하지 않으면 조합(C)입니다. 팀 구성은 C, 비밀번호는 P입니다.

- **지수적 증가가 왜 알고리즘 설계의 핵심 제약일까요?**
  n=30이면 2^n은 10억이 넘어 현실적인 시간 내 처리 불가입니다. 설계 단계에서 탐색 공간을 먼저 계산해야 합니다.

- **비둘기집 원리는 해시 충돌과 어떻게 연결될까요?**
  키 공간이 버킷 수보다 크면 충돌은 수학적으로 필연입니다. 생일 문제가 실용적 예시입니다.
