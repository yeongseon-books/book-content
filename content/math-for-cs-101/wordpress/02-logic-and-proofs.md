# 바이브코딩을 위한 CS 수학 (2/10): 논리와 증명

이 글은 **바이브코딩을 위한 CS 수학** 시리즈의 2편입니다. 논리와 증명이 코드 설계와 디버깅에서 어떤 역할을 하는지 바이브코딩 관점에서 살펴봅니다.

---

"이 코드가 항상 맞는다"고 말할 수 있는 근거는 무엇일까요? 테스트를 통과했다는 사실만으로는 충분하지 않습니다. 테스트는 일부 케이스를 확인할 뿐, 가능한 모든 입력에 대한 보장이 아닙니다. 논리와 증명은 바로 이 간극을 메우는 도구입니다.

바이브코딩 환경에서 AI가 코드를 제안할 때, "이 조건이 항상 성립하는가"를 따지는 능력이 있으면 버그를 훨씬 빠르게 잡을 수 있습니다. AI는 주어진 예시에는 맞는 코드를 쉽게 내놓지만, 경계 조건에서 깨지는 경우를 놓치는 일이 많습니다.

> "논리는 조건과 결론의 연결을 정리합니다. 증명은 그 연결이 항상 성립함을 보장합니다."

## 이 글에서 다룰 질문들

- 명제, 함의, 대우는 코드에서 어떻게 나타날까요?
- 귀류법과 귀납법은 언제 쓰는 증명 방식일까요?
- 불변식이란 무엇이고 왜 디버깅에 도움이 될까요?
- AI가 제안한 코드의 논리적 오류를 어떻게 찾을까요?
- 진리표 없이 동치 조건을 빠르게 확인하는 방법은?

---

## 논리의 기본 문법: 명제와 함의

명제는 참 또는 거짓으로 판단할 수 있는 문장입니다. 코드에서는 조건식이 명제입니다.

함의(P → Q)는 "P이면 Q이다"입니다. 핵심은 P가 거짓일 때는 Q의 참거짓과 관계없이 함의 자체는 참이라는 점입니다. 이것이 코드에서 조건이 성립하지 않는 경우를 처리할 때 헷갈리는 원인입니다.

대우(¬Q → ¬P)는 함의와 동치입니다. "입력이 양수이면 결과가 양수이다"를 증명하기 어렵다면 "결과가 음수이면 입력이 음수였다"를 증명해도 됩니다.

### Before: 논리 구조를 모르고 조건 작성

```python
# 의도: x가 양수이고 y가 음수일 때만 처리
def process(x, y):
    if not (x <= 0 or y >= 0):  # 드모르간 법칙 모름
        return x * y
    return None
```

### After: 드모르간 법칙으로 명확하게

```python
# not (A or B) == (not A) and (not B)
def process(x, y):
    if x > 0 and y < 0:  # 직관적으로 동치임을 알고 사용
        return x * y
    return None
```

## 세 가지 증명 방식

| 방식 | 핵심 아이디어 | 코드 적용 예시 | 적합한 상황 |
| --- | --- | --- | --- |
| 직접 증명 | 가정 → 결론을 단계적으로 | 알고리즘 정확성 증명 | 연결 관계가 명확할 때 |
| 귀류법 | 결론 부정 → 모순 도출 | 최적해 존재 증명 | 직접 보이기 어려울 때 |
| 수학적 귀납법 | 기저 + 귀납 단계 | 재귀 알고리즘 정확성 | 자연수 범위 반복 구조 |

## 불변식: 증명을 코드로 표현하기

불변식은 루프나 재귀에서 항상 유지되어야 하는 조건입니다. 이것을 명시하면 코드의 정확성을 단계적으로 추론할 수 있습니다.

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        # 불변식: arr[lo] <= target <= arr[hi] (정렬된 배열 가정)
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1  # 불변식 유지: 왼쪽 절반 제거
        else:
            hi = mid - 1  # 불변식 유지: 오른쪽 절반 제거
    return -1
```

불변식이 명시된 코드는 AI에게 리뷰를 요청할 때도 더 정확한 피드백을 얻을 수 있습니다.

## AI 팁: 논리 오류를 AI와 함께 찾는 법

1. **"이 함수의 불변식을 찾아줘"** — AI가 제안한 루프 구조의 논리를 검증하세요.
2. **"경계 조건에서 이 코드가 맞는지 확인해줘"** — 반례를 요청하세요.
3. **"이 조건식과 동치인 더 단순한 표현은?"** — 드모르간, 대우를 활용하세요.
4. **assert로 불변식을 코드에 삽입하면** 런타임에서 논리 오류를 조기에 발견할 수 있습니다.

## 처음 질문으로 돌아가기

- **명제, 함의, 대우는 코드에서 어떻게 나타날까요?**
  조건식이 명제이고, if-then 구조가 함의입니다. 대우는 함수의 역방향 보장을 증명할 때 씁니다.

- **불변식이란 무엇이고 왜 디버깅에 도움이 될까요?**
  불변식은 루프 내에서 항상 성립해야 하는 조건입니다. 이것이 깨지는 지점이 버그의 위치입니다.

- **AI가 제안한 코드의 논리적 오류를 어떻게 찾을까요?**
  불변식을 찾고, 경계 조건에서 그것이 유지되는지 확인합니다. assert로 런타임 검증도 병행하세요.

## 정리

논리와 증명은 코드가 왜 맞는지 형식적으로 보여주는 도구입니다. 불변식을 명시하고 경계 조건을 따지는 습관은 바이브코딩에서 AI 코드를 더 신뢰성 있게 사용하는 기반이 됩니다. 다음 편에서는 집합과 함수로 데이터 모델을 설계하는 방법을 다룹니다.
