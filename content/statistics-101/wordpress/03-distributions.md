# 바이브코딩을 위한 통계 기초 (3/10): AI가 분포를 잘못 가정하면 생기는 일

이 글은 바이브코딩을 위한 통계 기초 시리즈의 3번째 글입니다.

AI에게 서버 응답 시간 데이터를 분석해달라고 했을 때, AI가 "평균 120ms, 표준편차 25ms로 정규분포에 가깝습니다"라고 보고했습니다. 그 결과를 바탕으로 SLA를 평균 ± 2σ 구간으로 설정했는데, 실제 운영에서 예상보다 훨씬 많은 사용자가 SLA를 초과했습니다. 나중에 확인해보니 응답 시간 데이터는 긴 꼬리를 가진 분포였고, AI가 정규분포를 기본값으로 가정해 계산한 수치는 현실을 제대로 반영하지 못했습니다.

바이브코딩에서 AI가 저지르는 가장 흔한 통계 실수 중 하나는 데이터 모양을 확인하기 전에 정규분포를 가정하는 것입니다. 대부분의 통계 라이브러리가 정규분포 기반 방법을 기본으로 제공하고, AI는 그 기본값을 따라갑니다.

매출, 응답 시간, 결제 금액처럼 현실 데이터의 많은 부분은 정규분포가 아닌 긴 꼬리 분포나 지수 분포를 따릅니다. 분포 모양을 먼저 확인하지 않으면 평균, 신뢰구간, 이상치 판단이 모두 흔들립니다.

> 분포를 이해하면 AI가 내놓은 요약 통계 너머의 데이터 성격을 정확히 읽을 수 있습니다.

---

## 이 글에서 다룰 문제
- AI가 정규분포를 기본 가정으로 쓸 때 어떤 문제가 생길까요?
- 정규, 균등, 지수, 멱법칙 분포는 실무에서 어떻게 나타날까요?
- 히스토그램과 분위수만으로 분포 모양을 어떻게 빠르게 읽을 수 있을까요?
- AI에게 분포 확인을 먼저 시키려면 어떻게 요청해야 할까요?
- 왜도와 첨도가 높은 데이터에서 평균과 SLA를 어떻게 다뤄야 할까요?

## 실무에서 자주 만나는 분포 유형

AI에게 분석을 요청하기 전에 어떤 분포 유형이 예상되는지 미리 알면 더 정확한 요청이 가능합니다.

| 분포 | 모양 | 실무 예시 | AI 요청 시 주의사항 |
|---|---|---|---|
| 정규분포 | 좌우 대칭, 종 모양 | 키, 시험 점수, 측정 오차 | 기본 가정이 맞는지 먼저 확인 |
| 균등분포 | 모든 값이 동일한 확률 | 난수, 무작위 배정 | 대표값보다 범위가 더 중요 |
| 지수분포 | 오른쪽으로 긴 꼬리 | 이벤트 간격, 서버 응답 시간 | 평균 대신 중앙값, p95 사용 |
| 멱법칙 분포 | 극단적으로 긴 꼬리 | 매출, 소셜 팔로워, 결제 금액 | 평균은 의미 없음, 분위수 중심으로 분석 |

AI에게 "이 데이터는 어떤 분포를 따르나요? 히스토그램과 왜도를 함께 보고해줘"라고 요청하면 분포 유형을 먼저 파악할 수 있습니다.

## 정규분포 가정의 함정

정규분포를 가정할 때 생기는 가장 큰 문제는 긴 꼬리를 가진 데이터에서 이상치 기준과 SLA가 현실과 멀어진다는 것입니다.

```python
import numpy as np
import scipy.stats as stats

# 지수분포를 따르는 응답 시간 데이터 (실제 서버 로그에 가까운 모양)
np.random.seed(42)
latency = np.random.exponential(scale=100, size=10000)

mean = latency.mean()
std = latency.std()
p95 = np.percentile(latency, 95)
p99 = np.percentile(latency, 99)

print(f"평균: {mean:.1f}ms")
print(f"표준편차: {std:.1f}ms")
print(f"정규분포 기준 이상치 임계값 (평균+2σ): {mean + 2*std:.1f}ms")
print(f"실제 p95: {p95:.1f}ms")
print(f"실제 p99: {p99:.1f}ms")
```

정규분포 기준의 이상치 임계값과 실제 p99가 크게 다릅니다. 이 데이터에 정규분포를 가정하고 SLA를 설정하면 실제 사용자 체감 문제를 놓칩니다.

## Before / After

**Before**: AI에게 서버 응답 시간을 분석해달라고 합니다. AI가 "평균 100ms, 표준편차 50ms, 정규분포 가정 하 99.7%가 250ms 이하"라고 보고합니다. 이 기준으로 SLA를 설정했는데 실제 운영에서 SLA 초과 건이 예상의 3배입니다.

**After**: AI에게 "응답 시간 데이터의 히스토그램과 왜도를 먼저 확인하고, 분포 유형에 맞는 방식으로 p95와 p99를 보고해줘. 정규분포 가정이 적합한지도 판단해줘"라고 요청합니다. AI가 "지수분포에 가까운 모양, 평균보다 p95와 p99를 기준으로 SLA를 설정하는 것이 적합"이라고 답합니다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 분포 확인 없이 평균과 표준편차로 SLA 설정 | 긴 꼬리 데이터에서 실제 극단값을 과소 추정 | 분포 확인 후 p95·p99 기준으로 SLA 설정 |
| AI 기본 설정(정규분포)을 그대로 사용 | 비정규 분포 데이터에 맞지 않는 방법이 적용됨 | 분포 유형 명시 후 분석 방법 지정 |
| 히스토그램 없이 숫자만 보고 | 왜도와 긴 꼬리를 표에서 바로 확인 못 함 | AI에게 시각화도 함께 요청 |
| 매출 데이터에 정규 분포 통계 적용 | 멱법칙 분포에서 평균이 의미 없을 수 있음 | 분위수 기반 분석으로 전환 |

## AI에게 통계 관련 질문하는 팁

분포 분석을 AI에게 요청할 때 이 순서로 프롬프트를 구성하면 분포 가정 오류를 줄일 수 있습니다:

1. **시각화 먼저**: "히스토그램과 박스플롯을 먼저 그려줘"
2. **왜도·첨도 확인**: "왜도와 첨도를 계산하고 분포 모양을 설명해줘"
3. **분포 유형 판단**: "이 데이터가 정규분포를 따르는지 확인해줘"
4. **적합한 요약 지표 선택**: "분포 유형에 맞는 대표값과 퍼짐 지표를 선택해줘"
5. **SLA/임계값 설정 시**: "평균+2σ 대신 p95와 p99를 기준으로 잡아줘"

## 운영 체크리스트
- [ ] AI 분석 전에 히스토그램으로 분포 모양을 먼저 확인합니다
- [ ] 왜도가 높은 데이터에는 p95·p99를 SLA 기준으로 사용합니다
- [ ] 정규분포 가정이 적합한지 AI에게 명시적으로 확인 요청합니다
- [ ] 매출·결제 금액 데이터에는 중앙값과 분위수를 우선합니다
- [ ] AI 보고서에 분포 유형 정보가 포함되어 있는지 확인합니다
- [ ] 긴 꼬리 분포에서는 평균 대신 분위수 기반 요약을 요청합니다

## 처음 질문으로 돌아가기

"AI가 정규분포를 기본 가정으로 쓸 때 어떤 문제가 생기나요?"

응답 시간이나 매출처럼 긴 꼬리를 가진 데이터에 정규분포를 가정하면, 평균과 표준편차 기반의 이상치 임계값과 SLA가 실제 데이터보다 훨씬 낙관적으로 계산됩니다. 그 기준으로 운영하면 예상보다 많은 사용자가 SLA를 초과하는 상황이 생깁니다. AI에게 분포 확인을 먼저 요청하는 것이 이 문제를 막는 가장 빠른 방법입니다.

## 정리

분포는 AI가 어떤 통계 방법을 적용해야 하는지의 출발점입니다. AI가 기본값으로 정규분포를 가정하지 않도록, 분석 전에 "히스토그램과 왜도를 먼저 확인하고 분포 유형에 맞는 방법을 선택해줘"라는 지시를 습관으로 만드세요. 다음 글에서는 AI에게 표본을 넘길 때 편향이 어떻게 숨어드는지 다룹니다.
