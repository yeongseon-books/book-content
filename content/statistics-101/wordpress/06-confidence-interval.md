# 바이브코딩을 위한 통계 기초 (6/10): 95% 신뢰구간을 AI가 잘못 해석하지 않게 하려면

이 글은 바이브코딩을 위한 통계 기초 시리즈의 6번째 글입니다.

A/B 테스트 결과를 AI에게 분석해달라고 했더니 이렇게 답했습니다. "B 버전의 전환율이 더 높고, 95% 신뢰구간이 [11.2%, 13.4%]이므로 이 구간 안에 참 전환율이 있을 확률이 95%입니다." 이 설명은 그럴듯하게 들리지만 통계적으로 틀렸습니다.

95% 신뢰구간은 "이 구간 안에 참값이 있을 확률이 95%"가 아닙니다. 정확한 의미는 "같은 방식으로 100번 실험하면 그 중 95번은 이런 구간이 참값을 포함하게 되는 절차의 성질"입니다. 미묘해 보이지만, 이 차이를 혼동하면 신뢰구간을 잘못 활용하게 됩니다.

바이브코딩 환경에서 AI는 신뢰구간을 계산하는 데는 탁월하지만, 그 의미를 정확하게 해석하는 데서 자주 실수합니다. AI가 신뢰구간을 어떻게 설명하는지 검토하고, 잘못된 해석을 바로잡을 수 있어야 합니다.

> 신뢰구간이 좁을수록 추정이 더 정확하고, 운영 결정도 더 분명해집니다.

---

## 이 글에서 다룰 문제
- 95% 신뢰구간은 정확히 무엇을 의미하나요?
- AI가 신뢰구간을 잘못 설명할 때 어떻게 판별할 수 있을까요?
- 신뢰구간의 폭이 넓다는 것은 어떤 의미일까요?
- A/B 테스트에서 신뢰구간을 어떻게 활용해야 할까요?
- 표본이 작을 때 t-분포를 써야 하는 이유는 무엇일까요?

## 신뢰구간의 바이브코더 관점

AI에게 신뢰구간을 요청할 때 해석 방법까지 함께 요청하지 않으면 잘못된 설명이 따라오는 경우가 있습니다.

| 해석 | 맞는가? | 올바른 설명 |
|---|---|---|
| "이 구간에 참값이 있을 확률이 95%" | 틀림 | 이 절차가 100번 중 95번 참값을 포함하는 구간을 만든다 |
| "구간이 0을 포함하지 않으면 효과가 있다" | 맞음 | 0 포함 여부가 유의성의 핵심 기준 |
| "구간이 좁을수록 추정이 정확하다" | 맞음 | 표본이 클수록 구간이 좁아짐 |
| "구간이 겹치면 두 그룹에 차이가 없다" | 대체로 맞음 | 완전 겹침은 유의하지 않음의 신호 |

## 신뢰구간 계산과 해석

```python
import numpy as np
from scipy import stats

# A/B 테스트 데이터
np.random.seed(42)
control = np.random.binomial(1, 0.10, 1000)  # A 버전: 전환율 10%
treatment = np.random.binomial(1, 0.124, 1000)  # B 버전: 전환율 12.4%

# 각 그룹의 전환율과 신뢰구간
def proportion_ci(data, confidence=0.95):
    n = len(data)
    p = data.mean()
    se = np.sqrt(p * (1 - p) / n)
    z = stats.norm.ppf((1 + confidence) / 2)
    return p, p - z * se, p + z * se

p_a, ci_a_low, ci_a_high = proportion_ci(control)
p_b, ci_b_low, ci_b_high = proportion_ci(treatment)

print(f"A 버전: {p_a:.3f} [{ci_a_low:.3f}, {ci_a_high:.3f}]")
print(f"B 버전: {p_b:.3f} [{ci_b_low:.3f}, {ci_b_high:.3f}]")
print()

# 두 구간이 겹치는지 확인
overlap = ci_a_high > ci_b_low
print(f"신뢰구간 겹침: {overlap}")
print("겹치지 않으면 두 그룹 차이가 통계적으로 유의할 가능성 높음")
```

신뢰구간이 0을 포함하지 않거나 두 그룹의 구간이 겹치지 않으면 차이가 통계적으로 의미 있다는 신호입니다. AI에게 "두 그룹의 신뢰구간이 겹치는지 확인하고 배포 여부를 판단해줘"라고 요청하면 신뢰구간을 실제 의사결정에 활용할 수 있습니다.

## t-분포 — 표본이 작을 때 더 보수적인 구간

표본이 작을 때 정규분포 대신 t-분포를 사용해야 합니다. t-분포는 꼬리가 더 두꺼워서 불확실성을 더 보수적으로 반영합니다.

```python
# 작은 표본에서 t-분포 기반 신뢰구간
small_sample = np.array([12.4, 11.8, 13.2, 12.1, 11.5, 12.8, 13.5, 11.2])
n = len(small_sample)

mean = small_sample.mean()
se = small_sample.std(ddof=1) / np.sqrt(n)
t_critical = stats.t.ppf(0.975, df=n-1)

ci_low = mean - t_critical * se
ci_high = mean + t_critical * se

print(f"표본 크기: {n}")
print(f"평균: {mean:.2f}")
print(f"95% CI (t-분포): [{ci_low:.2f}, {ci_high:.2f}]")
print(f"구간 폭: {ci_high - ci_low:.2f}")
```

표본이 30개 미만이면 AI에게 "정규분포 대신 t-분포를 사용해서 신뢰구간을 계산해줘"라고 명시하는 것이 좋습니다.

## Before / After

**Before**: AI에게 A/B 테스트 결과를 분석해달라고 합니다. AI가 "B 버전의 95% 신뢰구간 [11.2%, 13.4%]에 참 전환율이 있을 확률이 95%이므로 B 버전이 우수합니다"라고 보고합니다. 이 해석이 틀렸다는 것을 모르고 B 버전을 배포합니다.

**After**: AI에게 "A/B 테스트 결과를 분석하고 95% 신뢰구간을 계산해줘. 단, 신뢰구간을 '이 구간에 참값이 있을 확률 95%'로 해석하지 말고 정확한 의미로 설명해줘. 두 그룹의 신뢰구간이 겹치는지 확인하고 배포 여부를 추천해줘"라고 요청합니다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| "구간에 참값이 있을 확률 95%" 해석 | 신뢰구간의 정확한 정의가 아님 | AI에게 정확한 해석 명시 요청 |
| 표본이 작은데 정규분포로 구간 계산 | 구간이 실제보다 좁게 추정됨 | 표본 30개 미만 시 t-분포 사용 지시 |
| 구간 폭 무시하고 점 추정만 활용 | 불확실성 정도를 모르고 결정 | 구간 폭도 의사결정 기준에 포함 |
| 두 신뢰구간이 겹쳐도 차이 있다고 판단 | 통계적으로 유의하지 않은 차이일 수 있음 | 구간 겹침 여부를 먼저 확인 |

## AI에게 통계 관련 질문하는 팁

신뢰구간을 AI에게 요청할 때 해석 오류를 방지하는 프롬프트 구조입니다:

1. **표본 크기 확인 먼저**: "표본 크기를 알려주고 t-분포와 정규분포 중 어떤 것을 사용할지 판단해줘"
2. **계산과 해석 분리**: "신뢰구간을 계산하고, 올바른 통계적 해석도 함께 설명해줘"
3. **겹침 여부 확인**: "두 그룹의 신뢰구간이 겹치는지 확인해줘"
4. **구간 폭 해석**: "이 구간 폭이 실무 의사결정에 충분히 좁은지 판단해줘"
5. **의사결정 연결**: "이 신뢰구간을 근거로 배포/중단 여부를 추천해줘"

## 처음 질문으로 돌아가기

"95% 신뢰구간은 정확히 무엇을 의미하나요?"

같은 방식으로 실험을 100번 반복하면 그 중 95번은 이런 방식으로 만든 구간이 참값을 포함합니다. "이 구간 안에 참값이 있을 확률이 95%"가 아닙니다. 이 차이를 이해하면 AI가 신뢰구간을 잘못 설명할 때 바로 발견하고 바로잡을 수 있습니다.

## 정리

신뢰구간은 불확실성을 가장 직접적으로 보여주는 통계 도구입니다. AI가 신뢰구간을 계산하는 것은 잘 하지만 해석에서 오류를 낼 수 있습니다. "신뢰구간의 올바른 통계적 해석도 함께 설명해줘"라는 요청 하나가 AI 분석 결과의 신뢰도를 크게 높여줍니다. 다음 글에서는 AI에게 A/B 테스트를 맡기기 전에 알아야 할 가설검정을 다룹니다.
