# Data Science Career 101 (3/10): 학습 경로 설계

데이터 직무를 준비하는 입문자가 가장 자주 빠지는 함정은 열심히 공부하는데도 순서가 없다는 사실입니다. 강의를 몇 개 듣고, 책을 몇 권 사고, Kaggle 노트북을 따라 해 봐도 어느 순간 "그래서 지금 나는 무엇을 쌓고 있는가?"라는 질문 앞에서 멈추게 됩니다.

좋은 학습 경로는 더 많은 자료를 소비하게 만드는 계획이 아니라, 다음 단계로 넘어가기 위한 기준을 만들어 주는 계획입니다. 무엇을 먼저 익히고, 어떤 결과물을 남기고, 어느 시점에 회고할지 정해 두어야 공부가 취미가 아니라 자산으로 남습니다.

이 글은 Data Science Career 101 시리즈의 세 번째 글입니다.

![Data Science Career 101 3장 흐름 개요](https://yeongseon-books.github.io/book-public-assets/assets/data-science-career-101/03/03-01-concept-at-a-glance.ko.png)
*Data Science Career 101 3장 흐름 개요*

> 학습 로드맵에서 가장 중요한 기준은 '매주 산출물을 남기면서 다음 단계로 넘어간다'는 원칙입니다.

## 이 글에서 다룰 문제

- 데이터 직무 입문자는 무엇을 어떤 순서로 배워야 하는가
- 12주 로드맵을 기초, 분석, 모델링 단계로 나누는 이유는 무엇인가
- 매주 남기는 산출물이 왜 중요한가
- 학습 정체를 막는 주간 회고를 어떻게 운영하는가
- 12주 이후 다음 분기 계획을 어떻게 짜는가

## 왜 순서가 중요한가

입문 단계에서는 이 순서가 결정적입니다. 기초가 받쳐 줘야 분석이 흔들리지 않고, 분석 감각이 있어야 모델링 결과를 해석할 수 있습니다. 반대 방향으로 가면 모델을 만들었는데 왜 그 성능이 나오는지 설명하지 못하고, SQL을 배웠는데 어떤 질문에 써야 하는지 모르는 상황이 생깁니다.

모든 데이터 직무에 공통으로 필요한 기반이 있습니다.

- **SQL**: 어떤 역할이든 데이터를 꺼내는 공용어입니다
- **Python 기초**: 분석과 자동화의 출발점입니다
- **통계 기초**: 숫자의 의미를 판단하는 사고 틀입니다
- **문서화 습관**: 결과를 자산으로 남기는 행동입니다

이 네 가지를 먼저 확보하면 이후 Analyst, Scientist, Engineer 어느 방향으로 이동해도 이동 비용이 적습니다.

## 12주 학습 로드맵

### 1-4주차: 기초 구간

```text
- Python 문법, pandas 기본
- SQL JOIN, GROUP BY, 집계
- 통계 기초 (평균, 분산, p-value)
- matplotlib 기본 시각화
```

처음 4주는 화려하지 않아도 괜찮습니다. 이 구간을 건너뛰면 뒤에서 더 큰 비용을 치르게 됩니다. SQL을 정확하게 쓰고, 판다스로 데이터를 다루고, 기본 통계 개념을 설명할 수 있으면 충분합니다.

**주간 산출물 예시:**
- 1주차: Python으로 CSV 파일을 읽고 기본 집계 수행한 노트북
- 2주차: 두 테이블을 JOIN해 사용자별 구매 합계를 계산한 SQL 파일
- 3주차: 샘플 데이터의 평균/분산/분포를 시각화한 분석 노트
- 4주차: 하나의 질문을 SQL로 풀고 해석을 3문장으로 쓴 메모

### 5-8주차: 분석 구간

```text
- 데이터 정리 (결측, 이상치, 타입 변환)
- A/B 테스트 설계 기초
- 대시보드 하나 만들기
- 케이스 스터디 하나 완성하기
```

분석 단계에서는 질문을 구조화하고 결과를 설명하는 연습이 필요합니다. 완벽한 분석보다 처음부터 끝까지 완결된 분석이 더 중요합니다.

**주간 산출물 예시:**
- 5주차: 공개 데이터셋에서 결측치와 이상치를 처리한 정리 노트
- 6주차: A/B 테스트 결과 해석 문서 (가설, 지표, 결론, 한계 포함)
- 7주차: 하나의 비즈니스 질문에 답하는 대시보드와 해석 메모
- 8주차: 퍼널 또는 코호트 분석 케이스 스터디 완성본

### 9-12주차: 모델링 구간

```text
- 회귀 모델 하나, 분류 모델 하나
- scikit-learn 파이프라인 기초
- 모델 평가 지표 (RMSE, Precision, Recall, AUC)
- 미니 프로젝트 하나 완성
```

모델링은 기초와 분석 위에 올라갑니다. 이 단계에서는 모델 자체보다 문제 정의와 평가 지표를 함께 보는 습관이 중요합니다.

**주간 산출물 예시:**
- 9주차: 수치 예측 회귀 모델 코드와 RMSE 기준선 비교
- 10주차: 이진 분류 모델과 Precision-Recall 트레이드오프 설명
- 11주차: scikit-learn 파이프라인으로 전처리와 모델을 묶은 코드
- 12주차: 하나의 문제를 처음부터 끝까지 푼 미니 프로젝트 README

### 주간 회고 템플릿

```text
이번 주 목표:
달성한 것:
막혔던 부분:
다음 주 우선순위:
```

회고는 의욕을 다지는 의식이 아니라 방향을 조정하는 장치입니다. 매주 금요일에 10분만 써도 성장 속도가 달라집니다.

## 실제 학습 시나리오

**시나리오 A: 직장인 주말 학습자**

사무직으로 일하면서 데이터 직무 전환을 준비하는 지현은 주말 6시간과 평일 저녁 30분을 학습에 씁니다. 1-4주차에는 Mode SQL Tutorial을 따라가며 매주 쿼리 하나를 Notion에 정리했습니다. 5-8주차에는 공개 쇼핑몰 데이터로 코호트 분석을 완성했고, 9-12주차에는 이탈 예측 모델을 만들어 README에 결과를 기록했습니다. 12주 후 그가 제출한 포트폴리오는 "각 프로젝트마다 문제, 데이터, 접근, 결과, 재현 방법이 있는 저장소" 3개였습니다.

**시나리오 B: 부트캠프 병행 학습자**

비전공 졸업생 민우는 5개월 부트캠프를 다니면서 이 로드맵을 병행했습니다. 부트캠프에서는 개념을 빠르게 배우고, 이 로드맵에서는 스스로 문제를 정의해 프로젝트를 완성하는 연습을 했습니다. 부트캠프가 가르쳐 주지 않는 "문제 정의와 해석 문서화"를 직접 채운 덕분에 면접에서 자신의 프로젝트를 명확하게 설명할 수 있었습니다.

## 자주 하는 실수

| 실수 유형 | 구체적 사례 | 개선 방향 |
| --- | --- | --- |
| 책을 다 읽고 나서 시작하려 함 | "이 책 다 읽으면 프로젝트 시작할게" | 1주차부터 작은 산출물을 남기며 병행 |
| 모델링부터 먼저 시작함 | Kaggle 노트북 따라 하다가 SQL도 모름 | SQL과 통계 기초를 4주 먼저 확보 |
| 산출물을 남기지 않음 | 영상을 봤는데 아무것도 없음 | 매주 쿼리 1개 + 해석 1문단 최소 기준 설정 |
| 회고를 건너뜀 | 바빠서 그냥 다음 주제로 넘어감 | 주간 4줄 회고를 고정 루틴으로 만들기 |
| 도구를 자주 바꿈 | pandas 쓰다가 PySpark로, 다시 R로 | 12주 동안 도구를 고정하고 깊이를 쌓기 |

## 12주 이후 다음 분기 계획

12주를 마친 뒤에는 "무엇을 더 공부할까"보다 "어떤 스킬이 아직 약한가"를 먼저 진단해야 합니다.

| 역량 영역 | 1점 기준 | 3점 기준 | 5점 기준 |
| --- | --- | --- | --- |
| SQL | 기본 조회 가능 | 윈도우/CTE로 문제 해결 | 성능과 정합성까지 설명 |
| 통계 | 용어 이해 | 실험 설계 가능 | 해석 리스크까지 제어 |
| Python | 노트북 분석 | 함수화/모듈화 | 재현 가능한 파이프라인 |
| 커뮤니케이션 | 결과 공유 | 의사결정 문장 제시 | 이해관계자 정렬 주도 |

가장 낮은 2개 영역을 다음 분기에 집중 보강하십시오. 모든 영역을 동시에 끌어올리려는 전략은 지속되지 않습니다.

## 프로젝트 유형별 선택 기준

| 프로젝트 유형 | 목표 직무 | 핵심 질문 | 최소 검증 기준 |
| --- | --- | --- | --- |
| 퍼널/코호트 분석 | Analyst | 전환이 어디서 떨어지는가 | 지표 정의와 세그먼트 비교 포함 |
| A/B 테스트 분석 | Analyst/Scientist | 변화가 유의미한가 | 가정/한계/후속 액션 명시 |
| 수요 예측 모델 | Scientist | 다음 기간 값을 얼마나 잘 예측하는가 | 기준선 대비 개선 수치 제시 |
| 이탈 예측 모델 | Scientist | 어떤 사용자가 이탈 위험이 높은가 | precision-recall 트레이드오프 설명 |
| ELT 파이프라인 | Engineer | 데이터 적재와 변환이 안정적인가 | 재실행 가능성과 장애 복구 절차 |

한 번에 세 개를 병렬로 하지 말고, 하나를 끝까지 닫는 경험을 먼저 만드는 것이 중요합니다. 완료의 경험이 쌓여야 다음 프로젝트 품질도 올라갑니다.

## 처음 질문으로 돌아가기

- **데이터 직무 입문자는 무엇을 어떤 순서로 배워야 하는가**
  - SQL, Python 기초, 통계 기초, 시각화 순서로 4주씩 확보한 뒤 분석과 모델링으로 넘어가십시오. 기초를 건너뛰면 뒤에서 더 큰 비용이 생깁니다.
- **12주 로드맵을 기초, 분석, 모델링 단계로 나누는 이유는 무엇인가**
  - 각 단계가 다음 단계의 기반이 되기 때문입니다. 분석 감각 없이 모델링을 하면 결과를 해석하지 못하고, 기초 없이 분석하면 숫자를 신뢰할 수 없습니다.
- **매주 남기는 산출물이 왜 중요한가**
  - 배운 것이 아니라 만든 것이 포트폴리오가 됩니다. 주간 산출물이 쌓이면 면접에서 "이 프로젝트를 어떻게 풀었는지"를 구체적으로 말할 수 있습니다.
- **학습 정체를 막는 주간 회고를 어떻게 운영하는가**
  - 매주 금요일에 "이번 주 목표 / 달성한 것 / 막힌 부분 / 다음 주 우선순위" 네 항목을 10분 안에 씁니다. 연속 2주 같은 막힘이 반복되면 접근 방식을 바꿔야 한다는 신호입니다.
- **12주 이후 다음 분기 계획을 어떻게 짜는가**
  - 스킬 매트릭스를 채우고 가장 낮은 두 영역을 선택해 집중 보강합니다. 계획은 "배울 것" 목록보다 "만들고 검증할 것" 행동 단위로 적어야 실행됩니다.

## 운영 체크리스트

- [ ] 12주 학습 캘린더를 만들었다
- [ ] 주간 산출물 템플릿을 만들었다
- [ ] 역할에 맞는 프로젝트 주제를 하나 정했다
- [ ] 최소 네 번의 회고 시점(4주차, 8주차, 12주차, 분기말)을 잡았다
- [ ] 스킬 매트릭스를 작성해 가장 약한 두 영역을 파악했다

## 정리

좋은 학습 계획은 더 많은 자료를 소비하는 계획이 아니라, 매주 작은 결과물을 만들며 다음 단계로 넘어가는 계획입니다. 기초, 분석, 모델링을 순서대로 밟고 매주 흔적을 남기면 공부가 자산으로 바뀝니다. 12주가 끝났을 때 "내가 무엇을 할 수 있게 되었는가"를 산출물로 증명할 수 있어야 합니다.

다음 글에서는 이렇게 쌓은 결과물을 어떻게 포트폴리오로 구성해야 하는지 봅니다.
