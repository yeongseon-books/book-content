# 바이브코딩을 위한 Data Science Career 기초 (7/10): 케이스 인터뷰

이 글은 "바이브코딩을 위한 Data Science Career 기초" 시리즈의 7번째 글입니다.

---

케이스 인터뷰는 많은 지원자에게 가장 추상적으로 느껴지는 단계입니다. SQL처럼 정답 형태가 명확하지도 않고, 머신러닝처럼 알고리즘 이름을 기준으로 준비할 수도 없기 때문입니다. 그래서 질문을 들으면 곧바로 아이디어를 던지다가 구조 없이 끝나는 경우가 많습니다.

면접관이 보고 싶은 것은 아이디어의 양이 아니라 사고의 질입니다. 문제를 어떻게 명확히 하고, 어떤 지표를 중심에 둘지 정하고, 어떤 가설을 세운 뒤, 어떤 데이터로 검증하고, 마지막에 어떤 결정을 내릴지까지 보여 줘야 답변이 단단해집니다.

실무에서도 문제 정의가 늘 불완전한 상태에서 시작합니다. 숫자 하나가 떨어졌을 때도 세그먼트, 기간, 최근 변경 사항, 지표의 의미를 먼저 정리해야 합니다. 케이스 인터뷰는 바로 그 초기 구조화 능력을 압축해서 보는 방식입니다.

케이스 유형, 답변 프레임, 지표 설계, 가설 검증, 의사결정 제안을 하나의 흐름으로 정리합니다.

> **핵심 인사이트:** 케이스 인터뷰에서 가장 중요한 것은 무엇을 할 수 있는가가 아니라 무엇을 먼저 물어봐야 하는가입니다. 명확화 질문 없이 분석을 시작하면 방향이 어긋납니다.

## 이 글에서 다룰 문제

- 케이스 인터뷰가 실제로 무엇을 평가할까요?
- 문제를 들었을 때 왜 먼저 명확화 질문을 해야 할까요?
- 북극성 지표와 보조 지표는 어떻게 고를까요?
- 가설 검증과 의사결정 제안은 어떻게 연결될까요?
- 케이스 답변에서 구조를 잃지 않으려면 어떻게 해야 할까요?

## 케이스 인터뷰 핵심 패턴

```text
5단계 답변 프레임:
1. 명확화: "이 지표가 떨어진 기간은 언제부터인가요? 어떤 시장인가요?"
2. 지표 선정: North Star + 보조 지표 (전환율, 리텐션, LTV)
3. 가설: "프로모션 종료 → 신규 유입 감소 → 전환율 하락"
4. 데이터 계획: 코호트 분석, A/B 테스트, 세그먼트 비교
5. 의사결정: "데이터가 가설을 지지하면 X를 권장, 아니면 Y 추가 조사"
```

```sql
-- 케이스: 일별 활성 사용자 하락 원인 분석
SELECT
    date_trunc('day', event_time) AS day,
    user_segment,
    COUNT(DISTINCT user_id) AS dau,
    COUNT(DISTINCT CASE WHEN action='purchase' THEN user_id END) AS buyers
FROM events
WHERE event_time >= '2026-05-01'
GROUP BY 1, 2
ORDER BY 1, 2;
```

## 변경 전후 비교

**Before: 구조 없이 아이디어 나열**
```text
- 문제를 듣자마자 여러 아이디어를 던짐
- 지표 정의 없이 "DAU가 떨어졌다"만 반복
- 가설과 데이터 계획이 연결되지 않음
- 결론 없이 "더 살펴봐야 할 것 같습니다"로 마무리
```

**After: 5단계 프레임 적용**
```text
- "기간과 세그먼트를 먼저 확인하겠습니다" (명확화)
- North Star 지표 + 2-3개 보조 지표 선정
- 검증 가능한 가설 1-2개 제시
- 데이터 계획과 의사결정 기준까지 연결
```

## 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 방법 |
|------|-------------|-----------|
| 명확화 질문 없이 분석 시작 | 방향이 어긋나도 인지하지 못함 | 항상 범위와 정의를 먼저 확인 |
| 너무 많은 지표 나열 | 무엇이 핵심인지 불분명 | North Star 1개 + 보조 2-3개 |
| 가설과 데이터 계획 미연결 | "이런 거 보면 알 수 있지 않나요"로 끝남 | 가설 → 어떤 데이터로 검증할지 명시 |
| 결론 없이 마무리 | 의사결정 역량이 보이지 않음 | "데이터가 X이면 Y를 권장"까지 제시 |
| 면접관 반응 무시 | 방향을 놓쳐도 계속 진행 | 중간에 "맞는 방향인가요?" 확인 |

## AI 활용 팁

```
# AI에게 이렇게 요청하세요:
"DAU가 지난주 대비 20% 떨어졌습니다.
이 케이스 인터뷰 문제를 5단계 프레임으로
풀어주세요: 명확화 → 지표 → 가설 → 데이터 계획 → 의사결정"

# 케이스 답변 자가 점검:
# - 명확화 질문을 먼저 했는가?
# - North Star 지표를 한 개 골랐는가?
# - 가설이 검증 가능한가 (데이터로)?
# - 결론과 다음 액션이 명확한가?
```

## 운영 체크리스트

- [ ] 5단계 프레임(명확화→지표→가설→데이터→결정)을 말하지 않고 써볼 수 있다
- [ ] North Star 지표와 보조 지표를 구분할 수 있다
- [ ] 가설을 검증 가능한 형태로 표현할 수 있다
- [ ] 3개 이상의 케이스 유형(지표 하락, 기능 론칭, A/B 설계)을 연습했다
- [ ] 10분 안에 완결된 답변을 구조화할 수 있다

## 처음 질문으로 돌아가기

- **케이스 인터뷰가 평가하는 것은?** 아이디어 양이 아니라 모호한 상황에서 구조화하는 능력입니다. 명확화 → 지표 → 가설 → 검증 → 결정 순서가 그 능력을 보여줍니다.
- **명확화 질문이 먼저여야 하는 이유는?** 문제를 정의하지 않으면 뒤의 지표와 가설이 모두 흔들립니다. 명확화 없이 시작하는 분석은 방향을 잃기 쉽습니다.
- **North Star 지표와 보조 지표를 어떻게 구분하나요?** North Star는 제품의 핵심 가치를 대표하는 지표(예: DAU, LTV), 보조 지표는 North Star를 설명하는 세부 지표(전환율, 리텐션, 이탈률)입니다.

## 정리

케이스 인터뷰는 기술 역량이 아니라 불완전한 문제 상황에서 구조를 만드는 능력을 평가합니다. 5단계 프레임을 반복 연습해서 명확화 → 지표 → 가설 → 검증 → 결정 순서가 자연스럽게 나오도록 준비하세요. 다음 글에서는 첫 직장 적응 전략을 다룹니다.
