# 바이브코딩을 위한 데이터 사이언스 커리어 (2/10): 분석가 vs 사이언티스트 vs 엔지니어

이 글은 **바이브코딩을 위한 데이터 사이언스 커리어** 시리즈의 두 번째 글입니다.

---

AI 코딩 도구로 포트폴리오를 만들다 보면 이런 상황이 생깁니다. 대시보드도 만들고, 머신러닝 모델도 학습시키고, 데이터 파이프라인도 구축했는데, 막상 취업 준비를 할 때 "저는 어떤 직무에 어울리나요?"라는 질문 앞에서 멈추게 됩니다.

바이브코딩 환경에서는 AI 덕분에 기술 장벽이 낮아졌습니다. 하지만 "무엇이든 할 수 있게 됐다"와 "어떤 역할을 맡아야 하는가"는 전혀 다른 문제입니다. 오히려 할 수 있는 것이 많아질수록 어느 방향에 집중해야 하는지 더 명확히 알아야 합니다.

실제로 분석가, 사이언티스트, 엔지니어는 같은 Python과 SQL을 쓰더라도 목적과 산출물이 완전히 다릅니다. 이 차이를 모르면 바이브코딩으로 만든 포트폴리오가 넓기만 하고 깊이가 없다는 평가를 받게 됩니다.

> 세 역할을 구분하는 가장 빠른 기준은 도구가 아니라 목적과 산출물을 보는 것입니다.

## 이 글에서 다룰 문제

- 분석가, 사이언티스트, 엔지니어가 각각 어떤 목적을 중심에 두는지 비교하면 무엇이 보이는가
- 세 역할이 만드는 대표 산출물은 어떻게 다른가
- 주요 도구와 성과 지표가 왜 역할마다 달라지는가
- 바이브코딩으로 포트폴리오를 만들 때 역할 차이를 모르면 어떤 문제가 생기는가
- AI와 함께 일하는 환경에서 각 역할의 강점은 어디서 드러나는가

## 세 역할의 핵심 차이

분석가는 질문에 답하는 사람입니다. "지난달 전환율이 왜 떨어졌지?"라는 질문을 받으면, SQL로 퍼널을 분해하고 세그먼트를 비교해 원인을 찾습니다. 바이브코딩으로 이 작업을 하면 AI에게 "결제 퍼널 단계별 이탈률 계산하는 SQL 써 줘"라고 프롬프트를 씁니다.

사이언티스트는 가설을 검증하는 사람입니다. "이 기능을 바꾸면 리텐션이 오를까?"를 A/B 테스트로 설계하고 통계적으로 검증합니다. AI에게는 "실험 설계서 초안 작성하고 샘플 사이즈 계산해 줘"라고 요청합니다.

엔지니어는 데이터 흐름을 보장하는 사람입니다. 파이프라인이 안 터지게 만들고, 스키마 변경에도 흔들리지 않게 합니다. AI에게 "idempotent 배치 파이프라인 DAG 작성해 줘"라고 요청합니다.

|---|---|---|
| 포트폴리오 구성 | 세 종류를 모두 얕게 | 목표 역할 산출물을 깊게 |
| AI 프롬프트 방향 | "데이터 분석 코드 짜 줘" | "DA 포지션 위한 퍼널 분석 리포트 구조 잡아 줘" |
| 면접 준비 | 모든 기술 외우기 | 역할별 핵심 판단 기준 연습 |

## 역할별 실습 관점

### Analyst — 바이브코딩으로 할 수 있는 것

```sql
-- AI에게: "주간 신규/복귀 사용자를 구분하는 CTE 기반 SQL 써 줘"
WITH weekly_users AS (
    SELECT user_id,
           DATE_TRUNC('week', event_date) AS week,
           MIN(DATE_TRUNC('week', event_date)) OVER (PARTITION BY user_id) AS first_week
    FROM events
    WHERE event = 'login'
)
SELECT week,
       COUNT(DISTINCT CASE WHEN week = first_week THEN user_id END) AS new_users,
       COUNT(DISTINCT CASE WHEN week != first_week THEN user_id END) AS returning_users
FROM weekly_users
GROUP BY week ORDER BY week;
```

### Scientist — 바이브코딩으로 할 수 있는 것

```python
# AI에게: "A/B 테스트 결과 유의성 검정하는 코드 써 줘"
from scipy import stats
import numpy as np

control = np.array([0.12, 0.11, 0.13])  # 전환율 샘플
treatment = np.array([0.14, 0.15, 0.13])

t_stat, p_value = stats.ttest_ind(control, treatment)
print(f"p-value: {p_value:.4f}")
print("유의미한 차이" if p_value < 0.05 else "유의미하지 않음")
```

## 자주 하는 실수

| 실수 | 문제 | 바이브코딩 해결책 |
|---|---|---|
| 도구만 보고 직무 분류 | SQL 쓴다고 같은 역할 아님 | AI에게 "이 JD의 핵심 산출물이 뭐야?" 물어보기 |
| 산출물 없이 기술 나열 | 포트폴리오 임팩트 약함 | AI와 함께 "결과 + 의사결정 연결" 문서화 |
| 세 역할 동시 준비 | 깊이 없는 포트폴리오 | 한 역할 먼저 깊게, 나머지는 보완 |
| 성과 지표 정의 안 함 | 면접에서 "결과가 뭐였나요?" 막힘 | AI에게 "이 프로젝트 성과 지표 뭐가 적절해?" 확인 |
| 협업 상대 모름 | 직무 적합성 어필 못함 | JD에서 협업 상대 분석하기 |

## AI 활용 팁

역할이 확실해진 뒤에 AI를 쓰는 방법:

- **DA 역할 확인**: "이 채용 공고가 DA인지 DS인지 산출물 기준으로 분류해 줘"
- **포트폴리오 정렬**: "내 프로젝트 3개를 DA 관점에서 강점과 약점 분석해 줘"
- **면접 준비**: "DA 면접에서 '전환율이 떨어졌다'는 질문에 어떤 구조로 답해야 해?"
- **스킬 갭 분석**: "DA 포지션 JD 5개 분석해서 공통 요구 스킬 정리해 줘"

## 체크리스트

- [ ] 세 역할의 목적을 각각 설명할 수 있다
- [ ] 각 역할의 대표 산출물을 하나씩 안다
- [ ] 역할별 AI 프롬프트를 다르게 작성해 봤다
- [ ] 목표 역할의 핵심 평가 지표를 하나 이상 정의했다
- [ ] 바이브코딩 포트폴리오를 한 역할 중심으로 정렬했다

## 처음 질문으로 돌아가기

- **세 역할이 각각 어떤 목적을 중심에 두는가** — 분석가는 질문에 답하고, 사이언티스트는 가설을 검증하고, 엔지니어는 흐름을 보장합니다.
- **대표 산출물이 어떻게 다른가** — 대시보드/리포트, 실험 결과/모델, 파이프라인/스키마로 구분됩니다.
- **도구와 성과 지표가 왜 달라지는가** — 목적이 도구를 결정하고, 성과 지표는 그 목적을 측정하기 때문입니다.

## 정리

세 역할은 경쟁 관계가 아니라 분업 구조입니다. 바이브코딩 환경에서 AI로 뭐든 만들 수 있게 됐다고 해서 방향이 생기는 것은 아닙니다. 목표 역할의 산출물과 성과 지표를 먼저 고정하고, 그에 맞는 AI 프롬프트를 개발하는 것이 바이브코딩을 커리어 자산으로 바꾸는 방법입니다.
