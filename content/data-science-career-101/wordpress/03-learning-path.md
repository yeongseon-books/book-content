# 바이브코딩을 위한 데이터 사이언스 커리어 (3/10): 학습 경로 설계

이 글은 **바이브코딩을 위한 데이터 사이언스 커리어** 시리즈의 세 번째 글입니다.

---

바이브코딩 환경에서 데이터 직무를 준비하는 사람들이 가장 많이 하는 말이 있습니다. "AI가 코드를 바로 써 주니까 기초는 빨리 넘어가도 되지 않을까요?" 그 결과 SQL 기초도 모르는 상태에서 Kaggle 컴피티션에 도전하고, 모델 평가 지표도 이해 못한 채 XGBoost를 튜닝하다가 멈추게 됩니다.

AI는 코드 생성 속도를 높여 주지만, 코드를 이해하고 검증하는 능력은 여전히 사람이 가져야 합니다. 기초 없이 AI가 뱉는 코드를 그냥 제출하면, 면접에서 "이 코드에서 NULL은 어떻게 처리했나요?"라는 질문에 말문이 막힙니다.

바이브코딩을 오래 써온 사람들이 공통적으로 말하는 것은 "기초를 알아야 AI를 제대로 검증할 수 있다"입니다. 순서가 있습니다. 기초가 있어야 모델링도 흔들리지 않고, 분석 감각이 있어야 AI가 만든 결과를 해석할 수 있습니다.

> 학습 로드맵에서 가장 중요한 기준은 매주 산출물을 남기면서 다음 단계로 넘어간다는 원칙입니다.

## 이 글에서 다룰 문제

- 바이브코딩으로 빠르게 배우려 할 때 기초를 건너뛰면 어떤 문제가 생기는가
- 12주 로드맵을 기초, 분석, 모델링 단계로 나누는 이유는 무엇인가
- AI와 함께 공부할 때 매주 산출물을 남기는 것이 왜 중요한가
- 바이브코딩으로 학습하면서 자주 빠지는 함정은 무엇인가
- 회고를 통해 AI 활용 학습을 어떻게 개선할 수 있는가

## 12주 학습 경로 (바이브코딩 버전)

### 1단계 — 기초 (1-4주차)

AI에게 "이 개념 설명해 줘"를 쓰기 전에 먼저 직접 해봐야 하는 것들:

```python
# 직접 짜 봐야 하는 기초 코드
import pandas as pd

df = pd.read_csv("orders.csv")
print(df.groupby("user_id")["amount"].sum().sort_values(ascending=False))
```

```sql
-- AI 도움 받아도 되지만 원리를 알아야 하는 SQL
SELECT user_id, COUNT(*) AS order_count, SUM(amount) AS total
FROM orders
WHERE status = 'completed'
GROUP BY user_id
HAVING COUNT(*) >= 3;
```

### 2단계 — 분석 (5-8주차)

AI와 함께 하되 해석은 본인이:

```python
# AI에게 "퍼널 분석 코드 작성" 후 직접 해석 작성
# What: 방문 -> 가입 -> 결제 단계별 전환율
# Why: 어느 단계에서 이탈이 가장 많은가
# Next: 가입 -> 결제 전환율이 낮으면 가격 또는 UI 문제 가설
```

### 3단계 — 모델링 (9-12주차)

```python
# AI에게 코드를 받아도 평가 지표는 직접 해석
from sklearn.metrics import classification_report

# AI가 써준 코드
report = classification_report(y_test, y_pred)
# 직접 해야 하는 해석
# precision이 중요한가, recall이 중요한가? 이 비즈니스 문제에서 FP와 FN 중 뭐가 더 비싼가?
```

## Before / After 비교

| 구분 | Before (기초 건너뜀) | After (순서 지킴) |
|---|---|---|
| AI 활용 | 코드 복붙 | 코드 이해 후 수정 |
| 산출물 | 실행만 되는 노트북 | 해석 문서가 있는 노트북 |
| 면접 대비 | "AI가 써줘서 잘 모름" | 모든 코드 라인 설명 가능 |
| 포트폴리오 | 기술 목록 나열 | 문제 정의 → 결론 서사 |

## 주간 산출물 템플릿

바이브코딩으로 공부할 때 매주 이것만 남기면 됩니다:

```markdown

- 이번 주에 푼 비즈니스/기술 문제: [한 문장]

### 결과
- 주요 발견: [숫자 포함 1-2문장]
- 다음 질문: [후속으로 봐야 할 것]

### 회고
- 잘 된 것:
- 개선할 것:
- 다음 주 집중 포인트:
```

## 자주 하는 실수

| 실수 | 바이브코딩 상황 | 해결 |
|---|---|---|
| 기초 건너뜀 | AI 코드 의미 모름 | SQL, pandas 기초 먼저 손으로 익히기 |
| 모델부터 시작 | 데이터 정제도 못함 | 1-4주 기초 구간 무조건 이수 |
| 산출물 없음 | 공부했지만 증거 없음 | 매주 GitHub에 노트북 1개 |
| 회고 건너뜀 | 같은 실수 반복 | 매주 금요일 15분 회고 |
| 도구 자주 바꿈 | 깊이 없이 표면만 | 12주 동안 Python + SQL 고정 |

## AI 활용 팁

학습 단계별 효과적인 AI 프롬프트:

- **기초 단계**: "이 SQL 쿼리를 단계별로 설명해 줘. 내가 이해했는지 퀴즈 내줘."
- **분석 단계**: "이 분석 결과에서 비즈니스 인사이트 3개와 후속 질문 2개 뽑아 줘."
- **모델링 단계**: "이 모델의 feature importance를 비즈니스 언어로 해석해 줘."
- **회고 단계**: "이번 주 내가 한 분석의 약점과 개선 방향을 피드백해 줘."

## 처음 질문으로 돌아가기

- **기초를 건너뛰면 어떤 문제가 생기는가** — AI가 쓴 코드의 오류를 발견 못하고, 면접에서 원리 설명이 불가능해집니다.
- **12주를 단계로 나누는 이유** — 기초 없이 분석 못하고, 분석 없이 모델 결과 해석 못하기 때문에 순서가 중요합니다.
- **매주 산출물이 중요한 이유** — "공부했다"가 아니라 "남겼다"는 증거가 포트폴리오가 되기 때문입니다.

## 정리

바이브코딩은 학습 속도를 높여 주지만 순서를 바꿔 주지는 않습니다. AI와 함께 공부하더라도 기초 → 분석 → 모델링 순서는 지켜야 하고, 매주 산출물을 남겨야 공부가 자산으로 쌓입니다. AI 프롬프트 노트와 주간 회고를 함께 운영하면 바이브코딩 학습의 질이 크게 올라갑니다.
