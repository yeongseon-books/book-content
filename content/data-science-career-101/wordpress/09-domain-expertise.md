# 바이브코딩을 위한 Data Science Career 기초 (9/10): 도메인 전문성 쌓기

이 글은 "바이브코딩을 위한 Data Science Career 기초" 시리즈의 9번째 글입니다.

---

데이터 직무에서 어느 순간부터는 기술만으로 설명되지 않는 차이가 벌어집니다. 같은 대시보드를 보고도 어떤 사람은 "숫자가 조금 흔들렸네"에서 멈추고, 어떤 사람은 "이건 프로모션 구조와 환불 정책 변화까지 같이 봐야 한다"는 식으로 더 좋은 질문을 던집니다. 그 차이를 만드는 축이 바로 도메인 전문성입니다.

입문자일수록 기술 학습만으로도 바쁘기 때문에 도메인 공부를 나중으로 미루기 쉽습니다. 하지만 실제로는 용어, KPI, 현장 흐름을 조금만 이해해도 질문 수준과 해석 품질이 빠르게 달라집니다.

도메인은 나중에 붙는 장식이 아니라, 기술을 실제 가치로 연결하는 번역기입니다. 특히 KPI는 업종에 따라 정상 범위와 의미가 다릅니다. 게임의 리텐션과 핀테크의 리텐션은 해석 기준이 다르고, 헬스케어의 전환율과 커머스의 전환율도 위험과 비용 구조가 전혀 다릅니다.

도메인의 정의, 용어집 학습, 핵심 지표 이해, 현장 관찰, 지속적 학습 루프를 중심으로 정리합니다.

> **핵심 인사이트:** 도메인을 알아야 숫자를 읽는 해상도가 올라갑니다. 용어를 알아야 회의가 들리고, 지표를 알아야 숫자가 읽히고, 현장을 알아야 왜 그런 숫자가 나오는지 감이 생깁니다.

## 이 글에서 다룰 문제

- 데이터 직무에서 도메인 전문성이 왜 중요할까요?
- 용어집과 KPI는 어떻게 익히면 좋을까요?
- 현장 관찰이 숫자 해석 능력을 어떻게 높일까요?
- 도메인 학습은 어떤 순서로 쌓아가야 할까요?
- 기술과 도메인을 어떻게 함께 성장시킬까요?

## 도메인 전문성 핵심 패턴

```text
도메인 학습 순서:
1. 용어집 만들기: 업종 고유 단어와 정의 정리
   예) 커머스: GMV, AOV, CAC, LTV, 장바구니 이탈율
       게임: DAU, MAU, ARPU, D1/D7/D30 리텐션
       핀테크: NPL, 연체율, 한도 소진율, LTV

2. 핵심 KPI 파악: 팀이 가장 중요하게 보는 지표
   - North Star Metric (예: 월 활성 결제자 수)
   - Leading Indicators (전환율, 재구매율)
   - 정상 범위 파악 (업종별 기준치)

3. 현장 관찰: 실제 사용자/업무 흐름 직접 보기
   - 현장팀(세일즈, CS, 운영) 인터뷰
   - 사용자 인터뷰 동행
   - 실제 서비스 직접 사용

4. 지속적 갱신: 업종 뉴스, 경쟁사 분석, 트렌드
```

```python
# 도메인 KPI 계산 예시 (커머스)
def calculate_ltv(avg_order_value, purchase_frequency, customer_lifespan):
    """고객 생애 가치 = 평균 주문액 × 구매 빈도 × 고객 수명"""
    return avg_order_value * purchase_frequency * customer_lifespan

def calculate_cac(marketing_spend, new_customers):
    """고객 획득 비용 = 마케팅 지출 / 신규 고객 수"""
    return marketing_spend / new_customers if new_customers > 0 else 0

# LTV/CAC > 3이면 건강한 비즈니스 (업종마다 기준 다름)
ltv = calculate_ltv(avg_order_value=50000, purchase_frequency=4, customer_lifespan=2)
cac = calculate_cac(marketing_spend=1000000, new_customers=200)
print(f"LTV: {ltv:,}원, CAC: {cac:,}원, LTV/CAC: {ltv/cac:.1f}x")
```

## 변경 전후 비교

**Before: 기술만 있고 도메인 없음**
```text
- "전환율이 3.2%입니다" (좋은 건지 나쁜 건지 모름)
- 회의에서 업종 용어를 모르고 맥락을 놓침
- 숫자 이상을 발견해도 왜인지 설명 못함
- 이해관계자가 원하는 분석과 방향이 다름
```

**After: 기술 + 도메인 조합**
```text
- "커머스 평균 3%이고 저희는 3.2%이지만, 경쟁사 대비 낮은 편입니다"
- 회의에서 업종 용어를 이해하고 적절한 질문
- 숫자 이상의 원인을 도메인 지식으로 가설화
- 이해관계자가 중요하게 보는 지표 중심으로 분석
```

## 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 방법 |
|------|-------------|-----------|
| 도메인 학습을 "나중에" 미룸 | 기술만으로는 비즈니스 가치를 전달 못함 | 입사 첫 달에 용어집 작성 시작 |
| 업종 기준치 모르고 분석 | "좋은지 나쁜지" 판단 불가 | 경쟁사/업종 벤치마크 수집 |
| 현장팀과 소통 안 함 | 숫자 뒤의 맥락을 모름 | 월 1회 CS/운영팀 인터뷰 |
| 용어를 추측으로 사용 | 다른 의미로 쓰면 신뢰 저하 | 팀 공식 용어집 참조 |
| 한 도메인만 깊게 | 이동 시 처음부터 시작 | 학습 방법을 포터블하게 유지 |

```
# 도메인 학습 가속화 방법:

# - 경쟁사 IR 자료 / 투자자 프레젠테이션 읽기
# - 현장팀 인터뷰 월 1회 이상
# - 팀 내 도메인 전문가와 페어 작업
```

## 운영 체크리스트

- [ ] 업종 핵심 용어 20개 이상을 정의와 함께 정리했다
- [ ] 팀의 North Star KPI와 정상 범위를 알고 있다
- [ ] 현장팀(CS, 운영, 세일즈)과 월 1회 이상 소통한다
- [ ] 분석 결과를 비즈니스 언어로 설명할 수 있다
- [ ] 경쟁사 또는 업종 벤치마크 데이터를 파악하고 있다

## 처음 질문으로 돌아가기

- **도메인 전문성이 중요한 이유는?** 도메인을 알아야 숫자를 올바르게 해석하고, 이해관계자가 원하는 방향으로 분석할 수 있습니다. 기술은 도메인이 있어야 가치로 연결됩니다.
- **용어집을 왜 먼저 만들어야 하나요?** 용어를 알아야 회의가 들립니다. 팀이 쓰는 언어를 모르면 맥락을 놓치고 엉뚱한 분석을 할 수 있습니다.
- **현장 관찰이 숫자 해석에 왜 도움이 되나요?** 숫자 이상이 발생했을 때 "프로모션 구조 때문인가, 시스템 이슈인가"를 판단하는 능력이 현장 이해에서 나옵니다.

## 정리

기술 역량이 성장할수록 도메인 전문성이 차별화 요소가 됩니다. 용어집 작성부터 시작해서 KPI 기준치를 파악하고, 현장팀과 소통하는 루프를 만들어 두세요. 도메인은 한 번에 쌓이지 않지만 꾸준히 쌓이면 분석의 해상도가 완전히 달라집니다. 다음 글에서는 시니어 데이터 직무로 가는 길을 정리합니다.
