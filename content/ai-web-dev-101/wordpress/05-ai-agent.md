# 바이브코딩을 위한 AI 웹 개발 (5/7): AI 에이전트

> 이 글은 **바이브코딩을 위한 AI 웹 개발** 시리즈 5편입니다. Tool Use와 Function Calling으로 모델이 외부 기능을 호출하는 에이전트 구조를 다룹니다.

바이브코딩으로 AI 앱을 만들다 보면 "모델이 스스로 검색하거나 계산기를 쓸 수 있으면 좋겠다"는 생각이 든다. AI 에이전트는 바로 이 아이디어다. 모델이 도구를 선택하고 호출해서, 그 결과를 바탕으로 최종 답변을 만든다.

Function Calling(Tool Use)은 모델에게 사용 가능한 도구 목록을 JSON 스키마로 제공하고, 모델이 필요할 때 그 도구를 호출하도록 만드는 구조다. 핵심은 "모델이 무엇을 해야 하는지 판단 → 도구 호출 → 결과 관찰 → 다음 판단" 루프다.

안전한 도구 실행이 중요하다. 모델이 요청한 도구 이름이 실제로 등록된 도구인지 확인하고, 허용되지 않은 도구 호출은 거부해야 한다. `safe_tool_dispatch` 패턴으로 화이트리스트 방식으로 도구를 실행한다.

멀티 도구 예시: 환율 API와 계산기를 동시에 등록하면, 모델이 "100달러를 원화로 환산하면?"이라는 질문에 환율 API를 호출해 환율을 얻고, 계산기로 곱셈을 수행하는 두 단계를 자동으로 처리한다.

에이전트 평가는 일반 챗봇보다 복잡하다. 최종 답변뿐 아니라 도구 선택이 적절했는지, 불필요한 도구를 과도하게 호출하지 않았는지, 루프가 무한히 돌지 않는지를 함께 봐야 한다.

> AI 에이전트는 모델이 도구를 선택하고 실행하는 능력입니다. 도구 계약을 명확히 정의하고, 실행을 안전하게 제어하면 모델이 훨씬 더 많은 일을 할 수 있습니다.

## 이 글에서 다룰 문제

- Tool Use와 단순 API 호출은 어떻게 다른가요?
- Function Calling의 JSON 스키마는 어떻게 설계해야 할까요?
- 에이전트 루프는 어떤 구조로 작동하나요?
- 도구 실행을 안전하게 제어하는 방법은 무엇인가요?
- 에이전트를 어떻게 평가해야 할까요?

## Before / After: AI 에이전트 전후

| 상황 | 에이전트 없이 | 에이전트 적용 후 |
|------|--------------|----------------|
| 실시간 데이터 필요 | 모델이 모름 | 도구로 실시간 조회 |
| 다단계 계산 | 모델 추론 오류 발생 | 계산기 도구로 정확히 계산 |
| 도구 선택 | 개발자가 하드코딩 | 모델이 컨텍스트 보고 선택 |
| 안전성 | 검증 없이 실행 | safe_tool_dispatch 화이트리스트 |

## 흔한 실수

| 실수 | 결과 | 올바른 접근 |
|------|------|------------|
| 도구를 검증 없이 실행 | 임의 코드 실행 위험 | 화이트리스트 기반 safe_tool_dispatch |
| 도구 스키마를 너무 느슨하게 정의 | 모델이 잘못된 파라미터 전달 | 필수 파라미터와 타입 명시 |
| 루프 반복 횟수 제한 없음 | 무한 루프로 비용 폭증 | max_iterations 설정 |
| 최종 답변만 평가 | 도구 선택 오류 놓침 | 도구 선택 경로도 평가 |

## AI 팁: AI 에이전트 빠르게 만드는 방법

Claude나 GPT-4에 "Python으로 OpenAI Function Calling을 사용한 에이전트를 만들어줘. 환율 조회와 계산기 두 가지 도구를 등록하고, 화이트리스트로 안전하게 실행하며, 최대 5번 루프를 도는 구조로 만들어줘"라고 요청하면 작동하는 코드를 얻을 수 있다. tools 파라미터에 JSON 스키마를 정의하고, 모델 응답에 `tool_calls`가 있으면 실행하고 결과를 다시 messages에 추가하는 루프가 핵심이다.

## 운영 체크리스트

- [ ] 도구를 화이트리스트 방식으로 등록하고 안전하게 실행하는가
- [ ] max_iterations를 설정해 무한 루프를 방지하는가
- [ ] 도구 스키마에 필수 파라미터와 타입을 명시했는가
- [ ] 도구 호출 이력을 로깅해 에이전트 동작을 추적하는가
- [ ] 최종 답변과 도구 선택 경로를 함께 평가하는가

## 처음 질문으로 돌아가기

- **Tool Use vs 단순 API 호출 차이는?** Tool Use는 모델이 어떤 도구를 언제 사용할지 스스로 판단한다. 단순 API 호출은 개발자가 하드코딩한 순서대로 실행된다.
- **에이전트 루프 구조는?** 판단(모델이 다음 단계 결정) → 도구 호출(safe_tool_dispatch) → 관찰(결과를 messages에 추가) → 판단... 반복.
- **안전한 도구 실행은?** 모델이 요청한 도구 이름이 등록된 화이트리스트에 있는지 확인하고, 없으면 거부한다.

## 정리

AI 에이전트는 모델이 도구를 선택하고 실행하는 능력이다. 도구 계약을 명확히 정의하고, 실행을 안전하게 제어하면 모델이 실시간 데이터 조회, 계산, 외부 서비스 호출을 자동으로 처리할 수 있다. 바이브코딩 환경에서 에이전트는 한 번 구조를 잡으면 도구만 추가하면 되므로 확장이 빠르다.
