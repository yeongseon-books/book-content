# 바이브코딩을 위한 자료구조 기초 (9/10): 그래프

이 글은 바이브코딩을 위한 자료구조 기초 시리즈의 9번째 글입니다.

팔로우/팔로잉 기능을 만들고 있습니다. AI에게 "특정 사용자가 팔로우하는 사람들과, 그 사람들이 팔로우하는 사람들까지 2단계 추천을 만들어줘"라고 했습니다. AI가 이렇게 줬습니다.

```python
follows = {
    "alice": ["bob", "carol"],
    "bob": ["dave"],
    "carol": ["dave", "eve"],
}

def get_suggestions(user):
    level1 = follows.get(user, [])
    level2 = []
    for f in level1:
        level2.extend(follows.get(f, []))
    return [u for u in set(level2) if u not in level1 and u != user]
```

2단계까지는 동작합니다. 그런데 "3단계, 4단계까지 확장해줘"라고 하자 AI 코드가 점점 복잡해졌고, 사이클(서로 팔로우)이 있는 경우를 제대로 처리하지 못했습니다.

소셜 네트워크, 의존성 관리, 경로 찾기 같은 문제는 그래프 모델이 필요합니다. 그래프를 이해하면 AI에게 "BFS로 k단계 이내 연결 노드를 찾아줘"라고 명확하게 요청할 수 있습니다.

> 트리는 가장 단순한 관계이고, 현실 세계의 대부분은 그래프로 설명하는 편이 더 정확합니다.

## 이 글에서 다룰 문제
- 그래프의 정점, 간선, 방향, 가중치 개념을 어떻게 코드로 표현할까요?
- 인접 리스트와 인접 행렬의 트레이드오프는 무엇인가요?
- BFS는 어떤 문제에, DFS는 어떤 문제에 적합한가요?
- AI가 준 그래프 탐색 코드에서 사이클 처리 누락을 어떻게 발견할까요?
- 의존성 관리, 최단 경로 같은 실무 문제를 그래프로 어떻게 모델링할까요?

## 핵심 개념: 정점과 간선, 표현 방식

그래프 `G = (V, E)`는 정점(V) 집합과 간선(E) 집합으로 정의됩니다.

```text
인접 리스트 (메모리 효율적, 간선이 적을 때):
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}

인접 행렬 (두 노드 간 간선 O(1) 확인, 노드가 많으면 비효율):
    A  B  C  D
A [ 0  1  1  0 ]
B [ 0  0  0  1 ]
C [ 0  0  0  1 ]
D [ 0  0  0  0 ]
```

대부분의 실무 그래프는 간선이 드문드문합니다(희소 그래프). 인접 리스트가 기본 선택입니다.

## Before / After

**Before — 레벨별 하드코딩:**

```python
def get_level2(user):
    level1 = follows.get(user, [])
    level2 = []
    for f in level1:
        level2.extend(follows.get(f, []))
    return set(level2) - set(level1) - {user}
# 레벨이 바뀌면 코드를 다시 짜야 함, 사이클 처리 없음
```

**After — BFS로 k단계 탐색:**

```python
from collections import deque

def get_within_k_hops(graph, start, k):
    visited = {start}
    queue = deque([(start, 0)])
    result = []

    while queue:
        node, depth = queue.popleft()
        if depth > 0:
            result.append(node)
        if depth < k:
            for neighbor in graph.get(node, []):
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append((neighbor, depth + 1))
    return result
# k를 바꾸면 되고, 사이클도 visited로 자동 처리
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| visited 집합 없이 BFS/DFS 구현 | 사이클에서 무한 루프 | enqueue 시점에 즉시 visited 표시 |
| visited를 dequeue 시점에 표시 | 중복 방문으로 O(n²) 가능 | enqueue 시점에 표시 |
| 인접 행렬로 희소 그래프 표현 | O(V²) 메모리 낭비 | 인접 리스트 사용 |
| BFS/DFS 목적 혼동 | BFS: 최단 거리, DFS: 경로 탐색 | 목적에 맞는 방식 선택 |
| 방향 그래프/무방향 그래프 혼동 | 간선 방향이 의미를 결정 | AI에게 방향성 명시 |

## AI에게 자료구조 관련 질문하는 팁

1. **관계의 방향성을 알려주세요.** "팔로우는 단방향이야" vs "친구는 양방향이야"
2. **BFS vs DFS를 목적으로 선택하세요.** "최단 거리가 필요해" → BFS / "연결 여부만 확인해" → DFS
3. **사이클 처리를 명시하세요.** "순환 의존성이 있을 수 있어, 방어 처리 해줘"
4. **가중치 여부를 알려주세요.** "이동 비용이 다 달라" → 가중치 그래프 + 다익스트라
5. **의존성 정렬이 필요하면.** "이 작업 순서를 의존성 순으로 정렬해야 해" → 위상 정렬

## 운영 체크리스트
- [ ] 인접 리스트와 인접 행렬의 트레이드오프를 설명할 수 있습니다
- [ ] BFS는 최단 거리, DFS는 경로 탐색에 적합하다는 차이를 이해했습니다
- [ ] visited 처리 없는 BFS/DFS 코드를 발견하고 수정을 요청할 수 있습니다
- [ ] 방향 그래프와 무방향 그래프의 차이를 AI 요청에 반영할 수 있습니다
- [ ] 소셜 네트워크, 의존성 관리, 최단 경로가 그래프 문제라는 것을 인식합니다
- [ ] 위상 정렬이 언제 필요한지 이해했습니다

## 처음 질문으로 돌아가기

팔로우 추천에서 레벨별 하드코딩이 왜 한계에 부딪혔는지 이제 명확합니다. 단계가 늘어날수록 코드가 기하급수적으로 복잡해지고, 사이클 처리가 없어 오류가 발생합니다. BFS로 구현하면 k 값만 바꾸면 몇 단계든 처리 가능하고, visited 집합이 사이클을 자동으로 방어합니다. AI에게 처음부터 "BFS로 k단계 이내 연결 노드를 찾아줘, 사이클 처리도 포함해"라고 하면 올바른 코드를 받을 수 있습니다.

## 정리

그래프는 정점과 간선으로 임의의 관계를 표현하는 가장 일반적인 자료구조입니다. 인접 리스트가 희소 그래프에서 기본 선택이고, BFS는 최단 거리, DFS는 경로 탐색에 적합합니다. 바이브코딩에서 관계형 데이터가 나오면 그래프 모델을 요청하는 것, 그리고 AI BFS/DFS 코드에서 visited 처리와 사이클 방어를 확인하는 것이 핵심 활용법입니다.
