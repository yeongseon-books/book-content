# 바이브코딩을 위한 자료구조 기초 (6/10): 트리

이 글은 바이브코딩을 위한 자료구조 기초 시리즈의 6번째 글입니다.

회사 조직도를 관리하는 기능을 만들고 있습니다. AI에게 "부서와 하위 부서를 관리하고, 특정 부서의 모든 하위 조직을 가져오는 코드 짜줘"라고 했습니다. AI가 이렇게 줬습니다.

```python
departments = [
    {"id": 1, "name": "전사", "parent": None},
    {"id": 2, "name": "개발", "parent": 1},
    {"id": 3, "name": "백엔드", "parent": 2},
    {"id": 4, "name": "프론트", "parent": 2},
]

def get_children(parent_id):
    return [d for d in departments if d["parent"] == parent_id]
```

작동은 합니다. 그런데 "개발팀 전체 하위 조직"을 가져오려면 재귀적으로 호출해야 하고, 깊이가 깊어질수록 전체 리스트를 반복해서 스캔합니다. 구조가 점점 복잡해지면서 AI도 점점 어색한 코드를 주기 시작합니다.

계층 관계를 다루는 데이터에는 트리가 자연스러운 모델입니다. 트리를 이해하면 AI에게 "트리 구조로 구현해줘"라고 요청하고, 그 코드가 올바른지 판단할 수 있습니다.

> 트리는 재귀가 가장 자연스럽게 느껴지는 구조입니다. 계층형 데이터라면 트리 모델부터 생각하세요.

## 이 글에서 다룰 문제
- 루트, 리프, 깊이, 높이 같은 트리 용어를 어떻게 정확히 이해할까요?
- 전위/중위/후위 순회는 각각 어떤 상황에서 유용할까요?
- 재귀와 트리가 왜 자연스럽게 연결되는지 이해할 수 있나요?
- AI가 계층형 데이터를 flat list로 관리하는 코드를 줄 때 개선을 어떻게 요청할까요?
- 트리 코드에서 흔한 버그(빈 트리, 리프 노드 처리 실수)를 어떻게 발견할까요?

## 핵심 개념: 계층 구조와 순회

트리는 연결되어 있고 사이클이 없는 계층 구조입니다. 이진 트리는 각 노드가 자식을 최대 두 개 가집니다.

```text
        전사          ← 루트(root), 깊이 0
       /    \
    개발      마케팅    ← 깊이 1
   /    \
백엔드  프론트         ← 깊이 2 (리프)

높이: 2, 노드 수: 5
```

순회 방식:
- **전위(pre-order)**: 루트 → 왼쪽 → 오른쪽 (부모를 먼저, 파일 시스템 출력에 유용)
- **중위(in-order)**: 왼쪽 → 루트 → 오른쪽 (정렬 순서, BST에서 주로 사용)
- **후위(post-order)**: 왼쪽 → 오른쪽 → 루트 (자식을 먼저, 파일/폴더 삭제에 유용)

## Before / After

**Before — flat list로 계층 관계 표현:**

```python
departments = [
    {"id": 1, "name": "전사", "parent": None},
    {"id": 2, "name": "개발", "parent": 1},
]

# 하위 조직 모두 가져오기: 매번 전체 스캔
def get_all_children(parent_id):
    result = []
    queue = [parent_id]
    while queue:
        current = queue.pop()
        children = [d for d in departments if d["parent"] == current]  # O(n) 반복
        result.extend(children)
        queue.extend([c["id"] for c in children])
    return result
```

**After — 트리 구조로 표현:**

```python
class DeptNode:
    def __init__(self, name):
        self.name = name
        self.children = []

    def add_child(self, child):
        self.children.append(child)

    def get_all_descendants(self):
        result = []
        for child in self.children:
            result.append(child)
            result.extend(child.get_all_descendants())
        return result

# 전체 스캔 없이 구조 자체를 따라가며 순회
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 계층 관계를 flat list로만 관리 | 하위 조직 조회마다 전체 스캔 | 트리 노드 구조로 모델링 요청 |
| 빈 트리(None) 처리 누락 | None 참조로 AttributeError | `if node is None: return` 기본 패턴 |
| 리프 노드와 내부 노드 처리 혼동 | 자식 없는 노드에서 오류 | 자식 리스트가 비었으면 리프로 처리 |
| 재귀 깊이 무시 | 깊은 트리에서 RecursionError | 깊이가 깊으면 반복(BFS) 방식으로 변환 |
| 순회 방식을 잘못 선택 | 원하는 순서로 결과 못 얻음 | 삭제/합계에는 후위, 출력에는 전위 |

## AI에게 자료구조 관련 질문하는 팁

1. **계층 구조임을 명시하세요.** "이 데이터는 부모-자식 관계야, 트리로 모델링해줘"
2. **순회 방식을 지정하세요.** "부모부터 출력해야 해" → 전위 / "하위 합계를 먼저 계산해야 해" → 후위
3. **재귀 깊이를 알려주세요.** "최대 몇 단계 깊이가 될 수 있어" → 깊으면 반복 방식 요청
4. **flat list 코드 개선을 요청하세요.** "이 parent_id 기반 코드를 트리 노드 구조로 바꿔줘"
5. **None 처리 확인하세요.** "빈 트리나 리프 노드 케이스도 처리해줘"

## 처음 질문으로 돌아가기

조직도에서 flat list를 반복 스캔하는 방식이 왜 문제인지 이제 명확합니다. 하위 조직을 찾으려면 전체 리스트를 여러 번 스캔해야 합니다. 트리 노드 구조로 바꾸면 구조를 따라 내려가기만 하면 되어 훨씬 자연스럽고 효율적입니다. AI에게 "계층 관계는 트리 노드로 구현해줘"라고 요청하면 처음부터 올바른 모델을 받을 수 있습니다.

## 정리

트리는 계층 구조를 표현하는 자연스러운 자료구조입니다. 파일 시스템, 조직도, JSON, DOM 같은 구조가 모두 트리 모델로 잘 표현됩니다. 바이브코딩에서는 AI가 flat list로 계층 관계를 표현하는 코드를 줄 때 트리 노드 구조를 요청하는 것, 그리고 재귀 기반 코드에서 빈 노드 처리를 확인하는 것이 핵심 활용법입니다.
