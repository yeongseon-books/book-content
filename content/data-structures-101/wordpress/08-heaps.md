# 바이브코딩을 위한 자료구조 기초 (8/10): 힙

이 글은 바이브코딩을 위한 자료구조 기초 시리즈의 8번째 글입니다.

고객 지원 티켓 시스템을 만들고 있습니다. 티켓마다 긴급도가 있고, 항상 가장 긴급한 티켓을 먼저 처리해야 합니다. AI에게 요청하니 이런 코드가 나왔습니다.

```python
tickets = []

def add_ticket(priority, content):
    tickets.append((priority, content))
    tickets.sort()   # 매번 정렬

def get_next():
    return tickets.pop(0)
```

10개 티켓에서는 완벽합니다. 그런데 시스템이 성장해서 티켓이 계속 쌓이고 초당 수백 건이 들어오자 서버 CPU가 치솟기 시작했습니다. `tickets.sort()`가 매 삽입마다 O(n log n)이기 때문입니다.

힙은 이런 문제를 위한 자료구조입니다. 항상 최솟값(또는 최댓값)을 O(1)에 꺼낼 수 있고, 삽입은 O(log n)입니다. 전체 정렬이 필요 없고 "현재 가장 중요한 것"만 빠르게 꺼내면 되는 상황에 최적입니다.

> 힙은 우선순위 큐의 사실상 표준 구현입니다. 매번 sort를 부르는 코드를 발견하면 힙을 검토하세요.

## 이 글에서 다룰 문제
- 힙이 왜 배열 하나만으로 트리를 표현할 수 있는지 이해할 수 있나요?
- sift up과 sift down이 무엇이고 O(log n)인 이유는?
- 파이썬 `heapq`를 실제로 어떻게 사용하는지 알 수 있나요?
- AI가 `sort()`를 남용하는 코드에서 힙으로 바꿔야 할 패턴을 어떻게 발견할까요?
- 최대 힙이 필요할 때 파이썬 heapq를 어떻게 활용할까요?

## 핵심 개념: 완전 이진 트리와 배열 매핑

힙은 완전 이진 트리로, 마지막 레벨을 제외하면 모두 채워져 있고 마지막 레벨도 왼쪽부터 채웁니다. 이 덕분에 포인터 없이 배열 하나로 표현할 수 있습니다.

```text
인덱스: 0  1  2  3  4  5  6
값:    [1, 3, 2, 7, 5, 8, 4]

트리:      1
          / \
         3   2
        / \ / \
       7  5 8  4

부모(i) = (i-1) // 2
왼쪽 자식(i) = 2*i + 1
오른쪽 자식(i) = 2*i + 2
```

힙 불변식: 최소 힙에서 부모는 항상 자식보다 작거나 같습니다. 그래서 `heap[0]`이 항상 최솟값입니다.

## Before / After

**Before — 매번 sort (O(n log n) 삽입):**

```python
tickets = []
def add(priority, content):
    tickets.append((priority, content))
    tickets.sort()            # O(n log n)

def get_next():
    return tickets.pop(0)     # O(n) 이동
```

**After — heapq 사용 (O(log n) 삽입, O(log n) 삭제):**

```python
import heapq

tickets = []
def add(priority, content):
    heapq.heappush(tickets, (priority, content))   # O(log n)

def get_next():
    return heapq.heappop(tickets)                  # O(log n)
```

삽입 100만 번: sort 방식 ~10분 vs heapq 방식 ~수 초.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 우선순위 처리에 sort() 남용 | O(n log n) × n = O(n² log n) | heapq로 교체 |
| 최댓값이 필요한데 최솟값 힙만 씀 | 원하는 값의 반대가 나옴 | 값에 -1 곱해서 최소 힙에 저장 |
| heapq로 특정 항목 수정 시도 | heapq는 O(1) 최소값 접근만 지원 | 항목 수정 필요하면 삭제+재삽입 또는 lazy deletion |
| heapify 없이 기존 list를 힙처럼 사용 | 힙 불변식이 유지되지 않음 | `heapq.heapify(list)` 먼저 호출 |
| 같은 우선순위 항목의 순서를 기대 | 힙은 순서를 보장하지 않음 | 타이브레이커 필드 추가 (삽입 시간 등) |

## AI에게 자료구조 관련 질문하는 팁

1. **"가장 큰/작은 것을 빠르게"면 heapq 요청하세요.** "항상 우선순위 높은 것 먼저 처리해야 해" → heapq
2. **sort 패턴 발견 시 물어보세요.** "이 sort가 루프 안에 있는데 heapq로 바꾸면 빨라지지 않아?"
3. **최대 힙이 필요하면 명시하세요.** "가장 큰 값을 꺼내야 해" → "음수로 저장해서 최소 힙으로 구현해줘"
4. **n개 중 상위 k개가 필요하면.** "상위 5개만 빠르게 가져와야 해" → `heapq.nlargest(5, data)`
5. **다익스트라, 이벤트 시뮬레이션 언급 시.** "최단 경로 찾아야 해" → heapq 기반 다익스트라 요청

## 운영 체크리스트
- [ ] 힙 불변식(부모 ≤ 자식)이 O(1) 최솟값 접근을 가능하게 하는 이유를 이해했습니다
- [ ] 완전 이진 트리가 왜 배열로 표현 가능한지 알고 있습니다
- [ ] AI 코드에서 sort() 남용 패턴을 발견하고 heapq 교체를 요청할 수 있습니다
- [ ] 최대 힙이 필요할 때 -1 곱하기 트릭을 알고 있습니다
- [ ] `heapq.nlargest`, `heapq.nsmallest`를 활용할 수 있습니다
- [ ] heapq의 한계(특정 항목 수정 불편)를 알고 있습니다

## 처음 질문으로 돌아가기

티켓 시스템에서 `tickets.sort()`가 왜 CPU를 치솟게 했는지 이제 명확합니다. 삽입마다 O(n log n) 정렬을 하면 전체 O(n² log n)이 됩니다. `heapq.heappush`로 바꾸면 삽입 O(log n), 최우선 항목 꺼내기 O(log n)으로 훨씬 효율적입니다. AI에게 "우선순위가 있어, heapq로 구현해줘"라고 처음부터 명시하면 sort 남용을 피할 수 있습니다.

## 정리

힙은 완전 이진 트리를 배열로 표현하여 최솟값/최댓값을 O(1)에 접근하고, 삽입/삭제를 O(log n)에 처리합니다. 파이썬의 `heapq`가 이 구조입니다. 바이브코딩에서 핵심은 AI 코드에서 루프 안의 `sort()` 패턴을 발견하면 `heapq`로 교체를 요청하는 것, 그리고 우선순위 처리가 필요하면 처음부터 heapq를 요청하는 것입니다.
