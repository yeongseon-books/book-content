# 바이브코딩을 위한 SQL 기초 (1/10): AI에게 DB 쿼리 시키기 전에 알아야 할 것

이 글은 바이브코딩을 위한 SQL 기초 시리즈의 1번째 글입니다.

"AI야, DB에서 지난달 매출 상위 고객 뽑아줘."

바이브코딩을 시작하면서 누구나 한 번쯤 이런 요청을 해봤을 것이다. 그런데 AI가 뱉어낸 SQL을 보고 멍해진 경험이 있다면, 또는 그 SQL을 실행했더니 뭔가 이상한 숫자가 나왔다면 이 글을 읽을 이유가 충분하다.

문제는 AI가 못 만드는 게 아니다. AI는 SQL을 잘 만든다. 문제는 내가 그 SQL이 맞는지 틀린지, 왜 느린지, 어떤 테이블을 건드리는지 전혀 모른다는 점이다. AI는 코파일럿이지 대신 생각해주는 기계가 아니다. 쿼리의 의도와 결과를 내가 이해하지 못하면, AI가 만든 SQL은 언제든 조용히 틀린 결과를 낼 수 있다.

이 시리즈는 SQL을 처음부터 배우는 게 아니다. AI가 만든 SQL을 내가 읽고, 검증하고, 필요할 때 고칠 수 있는 최소한의 감각을 키우는 것이 목표다.

첫 번째 질문부터 시작한다. SQL이 뭔지, 왜 수십 년째 살아남았는지 모르면 AI와 대화도 어렵다.

> AI에게 SQL을 시키는 것과, 그 SQL이 맞는지 판단하는 것은 완전히 다른 능력이다. 후자는 내가 직접 가져야 한다.

## 이 글에서 다룰 문제
- SQL은 정확히 어떤 종류의 언어이고 왜 아직도 쓰일까요?
- 관계형 모델을 모르면 AI가 만든 JOIN이 왜 위험할까요?
- 선언형 언어라는 뜻이 바이브코딩에서 어떤 의미일까요?
- AI에게 SQL 짜달라고 할 때 뭘 알고 있어야 할까요?
- 초보자가 가장 자주 놓치는 SQL의 본질적인 개념은 무엇일까요?

SQL은 데이터가 스프레드시트 범위를 넘는 순간부터 필수 도구다. 사용자 수를 세고, 주문 합계를 계산하고, 로그에서 이상 징후를 찾는 일은 결국 SQL 한두 줄에서 시작한다. 바이브코딩으로 앱을 만들 때도, 데이터를 분석할 때도 DB는 빠지지 않는다. SQL을 모르면 AI와의 대화에서 항상 수동적인 수신자가 된다.

PostgreSQL, MySQL, SQLite, BigQuery 어느 것을 쓰든 핵심 SQL은 크게 다르지 않다. 한 번 제대로 익히면 여러 환경으로 옮겨 갈 수 있다는 것도 SQL의 강점이다.

## SQL이란 무엇인가

### 관계형 모델: AI가 만든 테이블 구조를 읽는 기초

관계형 모델의 기본 단위는 테이블이다. 테이블은 행과 열로 이루어지고, 각 행은 하나의 사실을, 각 열은 그 사실의 속성을 나타낸다. 예를 들어 사용자 테이블이라면 한 행은 한 명의 사용자이고, `name`, `signup_at` 같은 열이 그 사용자의 속성이다.

AI가 CREATE TABLE 문을 만들어줄 때, 이 구조를 이해하지 못하면 그냥 복붙할 수밖에 없다. 어떤 값이 이름인지, 어떤 값이 날짜인지, 어떤 열이 기본 키인지가 명확해야 JOIN, 집계, 정렬, 필터가 안정적으로 동작한다.

### 선언형 언어: AI에게 SQL을 시킬 수 있는 이유

SQL이 선언형이라는 말의 뜻은 간단하다. **어떻게**가 아니라 **무엇을** 원하는지만 쓴다. 파이썬에서 루프를 돌리고 조건을 체크하는 대신, SQL에서는 그냥 원하는 결과를 선언한다.

```sql
SELECT name FROM users WHERE signup_at >= '2026-02-01';
```

이 한 줄이 선언이다. 인덱스를 어떻게 쓸지, 어떤 순서로 읽을지는 데이터베이스가 알아서 결정한다. AI가 SQL을 잘 만드는 이유도 여기에 있다. 의도를 말로 쓰면 되는 형태가 AI가 처리하기 좋다.

### SQL의 큰 분류

| 분류 | 의미 | 대표 문장 |
| --- | --- | --- |
| DDL | 구조를 정의 | `CREATE`, `ALTER`, `DROP` |
| DML | 데이터를 읽고 바꿈 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL | 권한을 다룸 | `GRANT`, `REVOKE` |

바이브코딩 초반에는 DML, 그중에서도 `SELECT`가 중심이다. 하지만 AI에게 데이터 수정을 시킬 때는 DML의 위험성도 알아야 한다.

## Before / After

**Before: AI에게 막연하게 요청**
```
"사용자 테이블에서 데이터 뽑아줘"
```
AI가 `SELECT *`를 돌려준다. 컬럼이 50개인 테이블을 통째로 읽는다.

**After: SQL 기초를 알고 요청**
```
"users 테이블에서 2026년 2월 이후 가입한 사용자의 name과 signup_at만 가져와줘"
```
```sql
SELECT name, signup_at FROM users WHERE signup_at >= '2026-02-01';
```
원하는 데이터만, 원하는 열만 가져온다.

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
| --- | --- | --- |
| AI가 만든 SQL을 확인 없이 실행 | 조건이 빠졌을 때 전체 데이터에 영향 | 실행 전 SELECT로 대상 확인 |
| `SELECT *`를 그대로 쓰기 | 불필요한 컬럼까지 읽어 성능 저하 | 필요한 컬럼만 명시하도록 AI에게 요청 |
| NULL을 `= NULL`로 비교 | 항상 빈 결과를 돌려줌 | `IS NULL` / `IS NOT NULL` 사용 |
| 테이블 구조 모르고 쿼리 실행 | 의도와 다른 결과 | AI에게 먼저 스키마 설명 요청 |

## AI에게 SQL 요청하는 팁

- 테이블 스키마(컬럼 목록)를 함께 붙여서 요청하면 AI가 더 정확한 쿼리를 만든다
- "어떤 컬럼이 있는지 먼저 알려줘"로 시작해서 구조를 파악한 뒤 요청하라
- AI가 만든 쿼리에서 `WHERE`가 빠졌는지 반드시 확인하라
- 결과 행 수가 예상과 크게 다르면 쿼리 의도를 다시 확인하라

## 운영 체크리스트
- [ ] SQL이 선언형 언어라는 뜻을 말로 설명할 수 있다
- [ ] 테이블, 행, 열의 차이를 알고 있다
- [ ] `SELECT`, `FROM`, `WHERE`의 역할을 구분할 수 있다
- [ ] DDL과 DML의 차이를 알고 있다
- [ ] `NULL`이 별도 상태라는 점을 이해하고 있다

## 처음 질문으로 돌아가기

AI에게 "DB에서 데이터 뽑아줘"라고 말하기 전에 알아야 할 것은 SQL 문법이 아니다. 내가 원하는 게 무엇인지, 그 결과가 어떤 모양이어야 하는지, 조건이 정확히 무엇인지를 먼저 생각해야 한다. SQL의 선언형 특성이 AI와의 대화를 자연스럽게 만드는 이유도 바로 여기에 있다.

## 정리

SQL은 AI에게 데이터 작업을 시킬 때 공통으로 쓰는 언어다. 핵심은 절차를 세세하게 적는 것이 아니라 원하는 결과를 선언하는 데 있다. 관계형 모델, 선언형 사고방식, 기본 문장 구조를 여기서 잡아 두면 이후의 SELECT, WHERE, JOIN, 집계 문장이 모두 더 자연스럽게 이어진다.
