# 바이브코딩을 위한 인시던트 대응 (9/10): 재발 방지

이 글은 바이브코딩을 위한 인시던트 대응 시리즈의 9번째 글입니다.

바이브코딩 시대에 재발 방지을 이해하는 것은 AI와 더 효과적으로 협업하는 기반이 됩니다. AI에게 이 주제로 질문할 때, 기본 개념을 알고 있으면 훨씬 정확한 답변을 받을 수 있고, 받은 답변을 올바르게 평가할 수 있습니다.

이 글에서는 재발 방지의 핵심 개념을 이해하고, AI와 이 주제에 대해 효과적으로 대화할 수 있는 언어를 갖추는 것을 목표로 합니다.

> 재발 방지을 이해하면 AI에게 더 정확한 질문을 할 수 있고, AI의 답변을 더 잘 이해하고 검증할 수 있습니다.

---

## 이 글에서 다룰 문제

- 재발 방지이란 무엇이며 왜 중요할까요?
- 바이브코딩에서 이 개념이 어떻게 활용될까요?
- AI에게 이 주제로 어떤 질문을 할 수 있을까요?
- 자주 하는 실수와 그 해결책은 무엇일까요?
- 이 개념을 실무에 적용하는 방법은 무엇일까요?

재발 방지의 핵심 개념을 알면 AI와 이 주제로 더 깊이 있는 대화를 할 수 있습니다. AI가 제안하는 코드나 설계의 장단점을 직접 판단할 수 있게 됩니다.

## Before / After

**Before — AI에게 컨텍스트 없이 질문:**

```
Q: "재발 방지에 대해 코드 만들어줘"
→ 막연한 요청으로 범용적인 답변 수령
→ 내 상황에 맞지 않을 수 있음
```

**After — 개념을 이해하고 구체적으로 질문:**

```
Q: "[구체적인 상황]에서 재발 방지을 어떻게 적용해야 해?
    [제약 조건]을 고려해서 [원하는 결과]를 만들어줘"
→ 내 상황에 맞는 정확한 코드와 설명 수령
→ 이유를 이해하고 수정·개선 가능
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 개념 없이 AI 코드 복사 | 버그 발생 시 해결 불가 | 핵심 개념 먼저 이해 |
| AI 설명을 그대로 수용 | 내 상황에 맞지 않을 수 있음 | 맥락을 함께 제공하고 검토 |
| 너무 넓은 질문 | 막연한 답변 수령 | 구체적인 상황과 제약 조건 명시 |
| 한 번 물어보고 끝 | 최적 답변이 아닐 수 있음 | 후속 질문으로 개선 |
| 예외 케이스 확인 생략 | 엣지 케이스에서 실패 | "예외 케이스도 처리해줘" 추가 |

## AI 협업 팁

재발 방지 관련 효과적인 AI 프롬프트 패턴:

1. **배경 설명**: 내가 하려는 것의 맥락을 먼저 제공
2. **구체적인 요청**: 추상적 질문보다 구체적인 예시와 함께
3. **검증 요청**: "이 접근의 장단점도 설명해줘"

예시 프롬프트:
> "[상황 설명]. 재발 방지 관점에서 가장 좋은 접근은 뭐야? 코드 예시와 함께 알려줘."

## 운영 체크리스트

- [ ] 재발 방지의 핵심 개념을 한 문장으로 설명할 수 있는가?
- [ ] AI에게 이 주제로 구체적인 질문을 만들 수 있는가?
- [ ] 실무 적용 시 발생할 수 있는 주요 이슈를 파악했는가?
- [ ] Before/After 코드의 차이를 설명할 수 있는가?
- [ ] 이 개념이 시리즈의 다른 주제와 어떻게 연결되는지 이해하는가?

## 처음 질문으로 돌아가기

재발 방지을 배운 지금, AI에게 이 주제로 더 정확한 질문을 할 수 있게 되었습니다. 더 나은 질문이 더 나은 코드를 만들고, 더 나은 이해가 더 나은 판단을 만듭니다.

## 정리

재발 방지은 바이브코딩을 위한 인시던트 대응의 중요한 주제입니다. 이 개념을 이해하면 AI와 더 정확하게 대화하고, 더 좋은 결과를 얻을 수 있습니다.
