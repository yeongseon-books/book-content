# 바이브코딩을 위한 테스팅 기초 (8/10): 회귀 테스트

이 글은 **바이브코딩을 위한 테스팅 기초** 시리즈의 여덟 번째 글입니다. AI에게 코드 수정을 맡길 때마다 이전에 고친 버그가 다시 돌아오는 문제를 막는 회귀 테스트를 설명합니다.

---

AI에게 코드 수정을 요청하면 의도하지 않은 부분이 함께 바뀌는 경우가 있습니다. 한 달 전에 고친 버그가 AI가 리팩토링을 하면서 다시 돌아오는 일이 바이브코딩 환경에서 반복됩니다. AI는 이전 수정의 맥락을 기억하지 못하기 때문입니다.

회귀 테스트는 이 맥락을 코드로 얼려 두는 방법입니다. 버그를 테스트로 남기면 AI가 코드를 어떻게 바꾸든 같은 버그가 다시 나타나는 순간 테스트가 즉시 실패합니다.

> 회귀 테스트는 AI가 코드를 수정할 때 이전에 고친 버그가 다시 살아나는 것을 막는 안전망입니다.

## 이 글에서 다룰 문제

- 회귀 테스트는 무엇을 막는 테스트일까요?
- 버그를 재현하고 테스트로 남기는 순서는 어떻게 될까요?
- AI에게 코드 수정을 맡길 때 회귀 테스트를 어떻게 활용할까요?
- 최소 재현 케이스는 왜 중요할까요?
- 바이브코딩 팀에서 회귀 테스트를 PR 기준으로 만드는 방법은?

바이브코딩에서 AI는 코드를 빠르게 많이 만들고 수정합니다. 회귀 테스트 없이 AI에게 수정을 맡기면 어느 순간 이전에 고쳤던 버그가 다시 나타납니다. 회귀 테스트는 팀의 기억을 AI가 덮어쓰지 못하도록 코드로 잠근 자물쇠입니다.

## 한눈에 보는 구조

좋은 회귀 테스트 흐름은 버그 보고에서 끝나지 않습니다. 먼저 실패하는 재현 테스트를 만들고, 그 테스트를 통과하도록 AI에게 수정을 요청한 뒤, CI에 넣어 다시는 조용히 돌아오지 못하게 만듭니다.

- **회귀(regression)**: 한 번 고친 동작이 나중에 다시 깨지는 현상입니다.
- **재현 테스트(repro test)**: 버그를 최소한의 입력으로 다시 일으키는 테스트입니다.
- **버그 ID**: 이슈 트래커에서 쓰는 고유 식별자입니다.
- **최소 재현 케이스**: 버그를 드러내는 가장 단순한 입력 조합입니다.

## 바이브코딩에서 회귀가 자주 발생하는 패턴

| 트리거 상황 | 바이브코딩에서의 실제 상황 |
|---|---|
| AI 리팩토링 요청 | "이 함수를 더 깔끔하게 만들어 줘" → 예외 처리 로직 사라짐 |
| AI 기능 추가 요청 | "할인 쿠폰 기능을 추가해 줘" → 기존 할인 로직 덮어씀 |
| AI 버그 수정 요청 | "이 버그를 고쳐 줘" → 다른 버그가 다시 생김 |
| AI 성능 개선 요청 | "이 쿼리를 최적화해 줘" → 페이지네이션 버그 재발 |

## 바꾸기 전과 후

**바꾸기 전 — AI에게 수정을 맡기고 구두 약속만 있는 상태**

```text
- "이 버그 고쳤습니다"라고 기록
- AI에게 다른 기능 추가 요청
- AI 리팩토링 과정에서 같은 버그 재발
- 발견까지 몇 주 소요
```

**바꾼 뒤 — 회귀 테스트를 추가한 상태**

```python
def test_regression_PROJ_1234_negative_total():
    cart = Cart()
    cart.add(Item(price=-1))
    with pytest.raises(ValueError):
        cart.total()
# AI가 코드를 수정할 때마다 이 테스트가 실행됨
# 버그가 다시 살아나면 즉시 실패
```

## 다섯 단계로 회귀 테스트 만들기

### 1단계 — 버그를 재현하기 (AI에게 수정 전 먼저 실행)

```python
# tests/test_regression.py
def test_repro_negative_price_breaks_total():
    cart = Cart()
    cart.add(Item(price=-1))
    assert cart.total() >= 0   # 현재는 실패해야 함
```

### 2단계 — 실패를 먼저 확인하기

```bash
pytest tests/test_regression.py -v
# FAILED ... assert -1 >= 0
# 이 실패를 확인해야 테스트가 실제로 버그를 감시함
```

### 3단계 — AI에게 수정 요청

```text
AI 프롬프트:
"tests/test_regression.py의 test_repro_negative_price_breaks_total
테스트가 실패하고 있어.
음수 가격의 Item을 Cart에 추가하면 ValueError를 발생시켜야 해.
Cart.add() 메서드를 수정해 줘."
```

### 4단계 — 의도를 담아 테스트 다듬기

```python
def test_regression_PROJ_1234_negative_price_rejected():
    """음수 가격의 상품 추가 시 ValueError 발생. (PROJ-1234)"""
    cart = Cart()
    with pytest.raises(ValueError, match="price must be >= 0"):
        cart.add(Item(price=-1))
```

### 5단계 — CI에 넣어 AI 수정 시 자동 검증

```bash
git add tests/test_regression.py src/cart.py
git commit -m "fix(cart): reject negative price (PROJ-1234)"
# 이후 AI가 cart.py를 수정할 때마다 CI에서 자동 실행
```

## AI 코드 수정 시 회귀 테스트 활용 흐름

```text
1. 버그 발생
2. 재현 테스트 작성 → 실패 확인
3. AI에게 수정 요청 (재현 테스트와 함께 제공)
4. AI가 수정한 코드로 테스트 통과 확인
5. CI에 포함 → 이후 AI 수정 시 자동 감시

"이 함수를 리팩토링해 줘. 단, 첨부한 회귀 테스트는 모두 통과해야 해."
```

## 자주 하는 실수

가장 흔한 실수는 버그를 고치고 테스트를 쓰지 않는 일입니다. 바이브코딩에서는 AI가 코드를 수시로 변경하기 때문에 회귀 테스트 없이는 같은 버그가 반드시 돌아옵니다.

두 번째 실수는 재현 테스트를 지나치게 크게 만드는 일입니다. E2E 수준의 재현 테스트는 느리고 유지비가 높습니다. 가능한 한 낮은 계층(단위 테스트)에 두는 것이 좋습니다.

세 번째 실수는 AI에게 수정을 요청하면서 기존 회귀 테스트를 함께 제공하지 않는 경우입니다. AI는 기존 제약 조건을 모르면 무시할 수 있습니다.

## AI 팁: 회귀 테스트와 함께 수정 요청하기

```text
효과적인 프롬프트:
"다음 회귀 테스트들이 모두 통과하면서
cart.py에 할인 쿠폰 기능을 추가해 줘:

[테스트 코드 첨부]

새 기능을 추가하면서 기존 회귀 테스트가 깨지면 안 돼."

확인 포인트:
1. AI 수정 전에 재현 테스트가 실패하는지 확인
2. AI 수정 후에 같은 테스트가 통과하는지 확인
3. 다른 기존 테스트도 모두 통과하는지 확인
```

## 운영 체크리스트

- [ ] 버그 수정 PR에 회귀 테스트를 함께 추가했습니다.
- [ ] 테스트 이름에 이슈 ID를 남겼습니다.
- [ ] 재현 테스트를 수정 전에 먼저 실패 확인했습니다.
- [ ] 가능한 한 낮은 테스트 계층에 회귀 테스트를 두었습니다.
- [ ] AI에게 수정 요청 시 기존 회귀 테스트를 함께 제공합니다.

## 처음 질문으로 돌아가기

- **회귀 테스트는 무엇을 막는 테스트일까요?**
  AI가 코드를 수정할 때 이전에 고친 버그가 다시 살아나는 것을 막습니다. AI는 이전 수정의 맥락을 모르기 때문에 회귀 테스트가 없으면 같은 버그가 반복됩니다.

- **최소 재현 케이스는 왜 중요할까요?**
  작고 결정적인 재현 케이스는 AI에게 수정 요청 시 문제를 정확히 설명하고, 실패 원인을 빠르게 파악할 수 있게 합니다.

- **AI에게 수정을 맡길 때 회귀 테스트를 어떻게 활용할까요?**
  수정 요청 시 기존 회귀 테스트를 함께 제공하면 AI가 기존 동작을 유지하면서 새 기능을 추가합니다.

## 정리

회귀 테스트는 AI가 코드를 수시로 바꾸는 바이브코딩 환경에서 특히 중요합니다. 버그를 고치는 일로 끝내지 않고, 테스트로 얼려 두어 AI가 다시 건드려도 안전하게 만드는 것이 바이브코딩 팀의 핵심 습관입니다. 다음 글에서는 이런 테스트들을 모든 AI 수정에 자동으로 실행하는 CI 흐름을 보겠습니다.
