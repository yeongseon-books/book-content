# 바이브코딩을 위한 캡스톤 프로젝트 (3/10): 문제 정의

이 글은 바이브코딩을 위한 캡스톤 프로젝트 시리즈의 3번째 글입니다.

캡스톤 프로젝트는 학과 과정의 총 결산이자 취업 포트폴리오의 핵심입니다. 바이브코딩 시대에는 AI를 잘 활용하는 것이 프로젝트 성공의 핵심 요소가 되었습니다. AI에게 "이 주제 어때?", "이 코드 고쳐줘", "발표 자료 만들어줘"라고 요청하면서도, 방향과 판단은 여러분이 내려야 합니다.

이 시리즈는 캡스톤 프로젝트의 기획부터 발표까지 전 과정에서 AI를 효과적으로 활용하는 방법을 다룹니다. AI가 할 수 있는 것과 여러분이 직접 결정해야 하는 것을 명확히 구분하는 것이 핵심입니다.

문제 정의에 대해 AI에게 올바른 질문을 하고, AI의 도움을 받아 더 빠르고 좋은 결과를 내는 방법을 배웁니다.

> AI는 도구입니다. 방향을 정하고 판단을 내리는 것은 여러분의 몫입니다. AI를 잘 활용하는 사람이 캡스톤을 성공시킵니다.

---

## 이 글에서 다룰 문제

- 문제 정의에서 가장 먼저 결정해야 할 것은 무엇일까요?
- AI에게 어떤 도움을 요청할 수 있을까요?
- 이 단계에서 자주 하는 실수는 무엇일까요?
- 팀 전체가 공통된 이해를 가지려면 어떻게 해야 할까요?
- 이 단계를 잘 마쳤다는 기준은 무엇일까요?

캡스톤 프로젝트에서 문제 정의 단계는 이후 모든 작업의 방향을 결정합니다. 이 단계를 잘 설계하면 AI와의 협업도 훨씬 효과적이 됩니다. AI에게 명확한 컨텍스트를 제공할수록 더 좋은 도움을 받을 수 있습니다.

## Before / After

**Before — 방향 없이 바로 시작:**

```
팀원들이 각자 생각하는 방향으로 작업 시작
→ 나중에 방향 충돌, 재작업 발생
→ AI에게도 일관성 없는 요청으로 일관성 없는 결과 수령
```

**After — 문제 정의을 먼저 명확히 정의:**

```
AI에게: "우리 팀의 캡스톤 프로젝트에서 문제 정의 단계를
체크리스트로 만들어줘. 우리 주제는 [주제]야."
→ 팀 전체가 공통된 이해를 가지고 시작
→ AI에게 일관된 컨텍스트 제공으로 더 좋은 도움 수령
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| AI에게 컨텍스트 없이 질문 | 엉뚱한 답변 수령 | 프로젝트 배경을 먼저 설명 |
| 팀 합의 없이 AI 결과 바로 적용 | 팀 내 혼선 발생 | AI 결과를 팀 논의의 출발점으로 사용 |
| 문제 정의 단계 문서화 생략 | 나중에 같은 논의 반복 | 결정 사항을 문서로 남기기 |
| AI 의견을 무조건 따름 | 프로젝트 방향 상실 | AI 제안을 검토하고 팀이 최종 결정 |
| 이 단계에서 너무 완벽 추구 | 진행이 막힘 | 80% 완성도로 다음 단계로 이동 |

## AI 협업 팁

문제 정의 단계에서 효과적인 AI 활용법:

1. **컨텍스트 먼저 제공**: 프로젝트 주제, 팀 규모, 일정을 먼저 설명
2. **구체적인 산출물 요청**: "체크리스트", "템플릿", "예시"를 요청
3. **팀 검토 포함**: AI 결과를 바로 적용하지 말고 팀이 함께 검토

예시 프롬프트:
> "우리 팀은 4명이고 8주 동안 [주제]로 캡스톤 프로젝트를 해. 문제 정의 단계에서 해야 할 일 목록과 각각의 예상 소요 시간을 알려줘."

## 운영 체크리스트

- [ ] 문제 정의의 목표와 산출물을 팀원 모두가 공유하는가?
- [ ] AI에게 프로젝트 컨텍스트를 충분히 제공했는가?
- [ ] 이 단계의 결정 사항을 문서로 남겼는가?
- [ ] 다음 단계로 넘어가는 기준을 정했는가?
- [ ] 팀원들의 동의를 확인했는가?

## 처음 질문으로 돌아가기

문제 정의 단계에서 AI를 잘 활용하면 혼자 고민할 때보다 빠르게 결론에 도달할 수 있습니다. 하지만 AI의 제안은 출발점이지 정답이 아닙니다. 팀의 맥락, 제약 조건, 목표를 가장 잘 아는 것은 여러분입니다.

## 정리

문제 정의는 캡스톤 프로젝트의 중요한 단계입니다. AI를 활용해 빠르게 초안을 만들고, 팀이 함께 검토하고 개선하는 워크플로가 효과적입니다. 다음 글에서는 요구사항 정리을 다룹니다.
