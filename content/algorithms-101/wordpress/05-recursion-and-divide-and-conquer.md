# 바이브코딩을 위한 알고리즘 기초 (5/10): 재귀와 분할 정복

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 5번째 글입니다.

파일 시스템을 탐색하는 기능을 AI에게 요청했습니다. 폴더 안의 모든 파일을 재귀적으로 찾는 코드였습니다. AI는 재귀 함수를 줬고, 작은 폴더 구조에서는 잘 동작했습니다.

프로덕션 서버의 깊은 디렉토리 구조에 적용했더니 `RecursionError: maximum recursion depth exceeded` 오류가 발생했습니다. Python 기본 재귀 한도인 1000을 초과한 것입니다.

AI에게 "왜 이런 에러가 나?"라고 물으면 재귀 한도를 올리는 코드를 줄 수도 있습니다. 하지만 그게 항상 올바른 해결책은 아닙니다. 때로는 재귀를 반복문으로 바꾸거나, 구조 자체를 분할 정복 방식으로 설계해야 합니다.

재귀가 어떻게 동작하는지, 왜 한계가 있는지를 알면 AI와의 대화가 훨씬 생산적이 됩니다.

> AI에게 "재귀를 반복문으로 바꿔줘"라고 말할 수 있으려면, 둘의 차이를 먼저 알아야 합니다.

---

## 이 글에서 다룰 문제
- 재귀 함수가 올바르게 동작하기 위한 세 가지 조건은 무엇인가?
- Python에서 RecursionError는 왜 발생하고 어떻게 피하는가?
- 분할 정복은 어떻게 O(n)을 O(log n)으로 만드는가?
- 재귀와 반복문 중 어떤 상황에서 무엇을 선택해야 하는가?
- AI가 재귀 코드를 줬을 때 어떻게 점검해야 하는가?

재귀는 트리, 그래프, 동적 계획법, 분할 정복의 기반입니다. AI가 생성하는 많은 코드가 재귀를 사용하며, 이를 이해하지 못하면 오류 대응이 어렵습니다.

## Before / After

**Before — AI가 만든 재귀 (깊은 입력에서 RecursionError):**

```python
def factorial(n):
    return n * factorial(n - 1)
# RecursionError: 베이스 케이스 없음, n=0에서 무한 재귀
```

**After — 베이스 케이스를 포함한 올바른 재귀:**

```python
def factorial(n):
    if n <= 1:          # 베이스 케이스 — 반드시 필요
        return 1
    return n * factorial(n - 1)

# 깊은 재귀가 우려된다면 반복문으로:
def factorial_iterative(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 베이스 케이스 없이 재귀 사용 | 무한 재귀 → RecursionError | AI에게 "베이스 케이스 포함해줘" 명시 |
| RecursionError를 재귀 한도 높이기로 해결 | 근본 원인 미해결, 메모리 폭발 가능 | 반복문으로 전환 검토 |
| 깊은 트리에 재귀 순회 사용 | 깊이 1000 초과 시 오류 | 명시적 스택을 사용한 반복 순회로 전환 |
| 반복되는 부분 문제를 캐싱 없이 재귀 | O(2^n) 지수 시간 폭발 | `@lru_cache` 또는 메모이제이션 추가 |
| 재귀 vs 반복 선택 기준 없음 | 상황에 맞지 않는 구현 선택 | 트리 구조 → 재귀, 선형 체인 → 반복 |

## AI에게 알고리즘 관련 질문하는 팁

재귀 관련 요청 시 Python 환경 특수성을 함께 전달하세요.

**안전한 재귀 요청**:
> "파일 시스템을 재귀 순회하는 코드를 만들어줘. 디렉토리 깊이가 1000을 넘을 수 있어. Python RecursionError를 피해야 해."

AI는 명시적 스택을 사용한 반복 방식 또는 `os.walk()`를 제안할 것입니다.

**분할 정복 최적화 요청**:
> "2의 n승을 계산하는 함수를 만들어줘. 단순 곱셈 반복 O(n) 말고, 분할 정복으로 O(log n)에 구현해줘."

AI는 빠른 거듭제곱(fast exponentiation) 알고리즘을 제안할 것입니다.

**중복 재귀 최적화**:
> "피보나치 함수가 있는데 fib(40)이 너무 느려. 메모이제이션을 추가해서 O(n)으로 바꿔줘."

## 재귀 코드 점검 체크리스트

AI가 재귀 코드를 줬을 때 확인할 사항:

```
1. 베이스 케이스가 있는가?
2. 베이스 케이스에 실제로 도달하는가? (무한 재귀 없는가?)
3. 최대 재귀 깊이가 Python 한도(기본 1000)를 넘지 않는가?
4. 같은 부분 문제가 반복 계산되는가? (캐싱 필요)
5. 반복문이 더 적합한 상황은 아닌가?
```

## 운영 체크리스트
- [ ] AI가 만든 재귀 코드에 베이스 케이스가 있는가?
- [ ] 최대 입력 크기에서 재귀 깊이가 안전한가?
- [ ] RecursionError가 발생했을 때 반복문 전환을 고려했는가?
- [ ] 반복 계산되는 부분 문제에 캐싱을 추가했는가?
- [ ] 분할 정복으로 복잡도를 낮출 기회를 확인했는가?
- [ ] 트리 구조 문제인지 선형 구조 문제인지 구분했는가?

## 처음 질문으로 돌아가기

AI가 재귀 코드를 줬을 때, 우리는 "이 재귀의 최대 깊이는 얼마야? Python 한도 넘지 않아?"라고 물을 수 있어야 합니다. 그리고 필요하다면 "반복문으로 바꿔줘" 또는 "메모이제이션 추가해줘"라고 요청할 수 있어야 합니다. 재귀를 이해하면 이런 대화가 가능해집니다.

## 정리

재귀는 문제를 더 작은 자기 자신으로 표현하는 방식입니다. AI가 재귀 코드를 생성할 때 베이스 케이스, 재귀 깊이, 중복 계산을 확인하는 습관이 중요합니다. 분할 정복은 재귀의 가장 강력한 패턴으로, O(n)을 O(log n)으로 줄이는 핵심 아이디어를 담고 있습니다.

다음 글에서는 동적 계획법을 다룹니다. AI가 피보나치를 O(2^n)으로 구현했을 때 O(n)으로 바꾸는 메모이제이션 패턴을 봅니다.
