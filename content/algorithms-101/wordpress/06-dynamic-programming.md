# 바이브코딩을 위한 알고리즘 기초 (6/10): 동적 계획법

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 6번째 글입니다.

여행 앱을 만들면서 AI에게 "n개의 도시 중 예산 내에서 방문할 수 있는 최대 도시 수를 찾아줘"라는 요청을 했습니다. AI는 재귀로 모든 경우의 수를 탐색하는 코드를 줬습니다.

도시 10개에서 테스트하니 빠르게 동작했습니다. 도시 30개로 늘리자 응답이 30초 이상 걸렸습니다. 도시 50개에서는 사실상 무한 대기였습니다.

이유가 뭘까요? AI가 만든 코드는 같은 부분 문제를 반복해서 계산하고 있었습니다. 도시 A, B, C의 최적 조합을 계산했는데, 나중에 또 같은 조합을 다시 계산합니다. 이게 O(2^n) 지수 시간의 정체입니다.

동적 계획법(DP)은 이 문제를 "한 번 계산한 결과를 저장해서 두 번 다시 풀지 않는다"는 원칙으로 해결합니다. 같은 문제를 O(n·예산)으로 풀 수 있습니다.

> 같은 부분 문제를 두 번 이상 계산하는 코드를 보면, 동적 계획법이 필요하다는 신호입니다.

---

## 이 글에서 다룰 문제
- 동적 계획법이 적용되는 두 조건은 무엇인가?
- AI가 만든 코드가 O(2^n)인지 어떻게 알아채는가?
- 메모이제이션과 타뷸레이션은 어떻게 다른가?
- AI에게 DP 최적화를 어떻게 요청하는가?
- 상태 정의가 왜 DP 풀이의 핵심인가?

동적 계획법은 면접 단골 주제이기도 하지만, 실무에서도 최적화, 스케줄링, 문자열 비교, 추천 시스템에 직접 등장합니다.

## Before / After

**Before — AI가 만든 지수 시간 재귀 (같은 부분 문제 반복 계산):**

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# fib(40): 약 3억 번 호출 — 수 초 걸림
# fib(50): 약 2조 번 호출 — 사실상 무한 대기
```

**After — 메모이제이션으로 O(n):**

```python
from functools import lru_cache

# 프롬프트: "이 재귀에 메모이제이션 추가해서 O(n)으로 최적화해줘"
@lru_cache(maxsize=None)
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
# fib(100): 즉시 반환 — 각 상태 한 번씩만 계산
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 같은 입력에 재귀가 여러 번 호출됨을 인식 못 함 | O(2^n) 폭발 | 중복 호출 패턴 보이면 DP 적용 검토 |
| 상태 정의 없이 바로 코딩 | 점화식이 흐려져 버그 발생 | AI에게 "상태 정의 먼저 설명해줘" 요청 |
| 메모이제이션 추가를 잊음 | O(n) 가능한 문제를 O(2^n)으로 풀기 | `@lru_cache` 습관적으로 추가 |
| 2차원 DP에서 메모리 폭발 | 큰 입력에서 OOM | rolling array로 차원 줄이기 요청 |
| 중복 부분 문제가 없는데 DP 적용 | 불필요한 복잡성 | 부분 문제가 정말 반복되는지 먼저 확인 |

## AI에게 알고리즘 관련 질문하는 팁

DP 최적화를 요청할 때는 문제 구조를 설명하는 것이 핵심입니다.

**중복 계산 최적화 요청**:
> "이 재귀 함수가 fib(40)에서 너무 느려. 같은 n에 대해 중복 계산이 발생하고 있어. `@lru_cache`로 메모이제이션을 추가해서 O(n)으로 만들어줘."

**DP 변환 요청**:
> "이 문제는 '부분 문제가 반복되는 구조'인 것 같아. 메모이제이션 방식(top-down)과 타뷸레이션 방식(bottom-up) 둘 다 구현해줘. 상태 정의도 설명해줘."

**메모리 최적화 요청**:
> "2차원 DP 테이블이 너무 커. rolling array로 줄일 수 있어?"

## DP 적용 신호 감지하기

코드나 문제에서 이런 패턴이 보이면 DP가 필요하다는 신호입니다.

```
신호 1: 같은 인자로 재귀 함수가 여러 번 호출됨
신호 2: "최대", "최소", "몇 가지 방법" 같은 최적화/카운팅 문제
신호 3: 문제가 더 작은 같은 형태의 문제로 분해됨
신호 4: "앞에서부터 결정하면 뒤가 영향받는" 구조
```

AI에게 물어보는 방법:
> "이 문제가 동적 계획법으로 풀릴 수 있어? 중복 부분 문제와 최적 부분 구조가 있는지 확인해줘."

## 운영 체크리스트
- [ ] AI가 만든 재귀 코드에서 중복 호출 패턴을 확인했는가?
- [ ] `@lru_cache`로 메모이제이션을 추가할 수 있는가?
- [ ] 상태 정의를 한 문장으로 설명할 수 있는가?
- [ ] top-down과 bottom-up 방식의 차이를 이해하는가?
- [ ] 2차원 DP가 메모리 효율적인지 확인했는가?
- [ ] DP 적용 조건(중복 부분 문제, 최적 부분 구조)을 확인했는가?

## 처음 질문으로 돌아가기

AI가 만든 코드가 n=40에서 느리다는 것을 알았을 때, "이 함수에 중복 계산이 있어? 있다면 메모이제이션으로 최적화해줘"라고 물을 수 있어야 합니다. 그리고 AI의 답변을 보고 O(2^n)이 O(n)으로 개선됐는지 복잡도를 확인할 수 있어야 합니다.

## 정리

동적 계획법은 "같은 부분 문제를 두 번 풀지 않는다"에서 출발합니다. AI가 만든 재귀 코드에서 중복 호출이 보이면 DP가 필요하다는 신호입니다. `@lru_cache`로 시작해서 필요하면 bottom-up 타뷸레이션으로 전환하는 패턴이 가장 실용적입니다.

다음 글에서는 그리디 알고리즘을 다룹니다. AI가 항상 욕심쟁이처럼 가장 좋아 보이는 선택을 해줄 때, 그게 실제로 최적인지 판단하는 방법을 봅니다.
