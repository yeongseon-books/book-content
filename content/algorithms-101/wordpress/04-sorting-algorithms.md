# 바이브코딩을 위한 알고리즘 기초 (4/10): 정렬 알고리즘

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 4번째 글입니다.

고객 데이터를 날짜 순으로 정렬해서 보여주는 기능을 AI에게 요청했습니다. AI는 quicksort를 직접 구현해서 줬습니다. 테스트 데이터 1000건, 랜덤으로 섞인 데이터에서는 완벽하게 동작했습니다.

실제 운영 데이터를 넣었을 때 문제가 생겼습니다. 실제 데이터는 이미 날짜 순으로 거의 정렬된 상태였습니다. AI가 만든 quicksort는 첫 번째 원소를 pivot으로 썼기 때문에, 이미 정렬된 입력에서 O(n²)으로 무너졌습니다. 10만 건을 정렬하는 데 수 분이 걸렸습니다.

이건 AI의 실수가 아닙니다. AI는 유효한 quicksort를 줬습니다. 하지만 "이미 정렬된 입력이 들어올 수 있어"라는 정보가 없었기 때문에 pivot 선택 전략을 최적화하지 않았습니다. 그리고 사실, 이 상황의 정답은 quicksort가 아니라 그냥 Python의 `sorted()`입니다.

> AI가 만든 정렬 코드보다 Python 표준 라이브러리가 거의 항상 더 낫습니다.

---

## 이 글에서 다룰 문제
- Python `sorted()`는 왜 그렇게 빠르고 안정적인가?
- AI가 구현한 quicksort가 특정 입력에서 무너지는 이유는 무엇인가?
- 비교 기반 정렬의 하한이 O(n log n)인 이유는 무엇인가?
- 안정 정렬과 비안정 정렬의 차이가 언제 중요한가?
- 전체 정렬이 필요한지 먼저 확인해야 하는 이유는 무엇인가?

정렬은 거의 모든 다른 알고리즘의 전처리 단계입니다. 이진 탐색, 데이터 조인, 집계, 시각화 모두 정렬된 데이터를 가정합니다. 어떤 정렬을 선택하느냐가 뒤쪽 파이프라인 전체 비용을 좌우합니다.

## Before / After

**Before — AI가 직접 구현한 quicksort (이미 정렬된 입력에 취약):**

```python
def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[0]  # 첫 번째 원소를 pivot으로 — 이미 정렬된 입력에서 O(n²)
    left = [x for x in arr[1:] if x < pivot]
    right = [x for x in arr[1:] if x >= pivot]
    return quicksort(left) + [pivot] + quicksort(right)
```

**After — Python 표준 라이브러리 사용 (Timsort, 이미 정렬된 입력에서 O(n)):**

```python
# 대부분의 상황에서 이것이 정답입니다
sorted_data = sorted(data, key=lambda x: x["date"])
# 또는 제자리 정렬
data.sort(key=lambda x: x["date"])
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| AI에게 정렬 함수를 직접 구현하게 함 | 표준 라이브러리보다 느리고 버그 위험 | "Python sorted() 사용해줘" 명시 |
| 안정성 확인 없이 다중 키 정렬 | 정렬 결과가 비결정적이 될 수 있음 | "안정 정렬이 필요해" 명시 |
| 전체 정렬 불필요한데 항상 정렬 | 상위 k개만 필요할 때 O(n log n) 낭비 | "상위 5개만 필요해" → heap 사용 |
| 메모리 한계 무시 | 대용량 데이터 OOM 발생 | 데이터 크기와 메모리 제약 AI에게 전달 |
| 부작용 있는 key 함수 사용 | 비교 결과 불일치 | key 함수는 순수 함수로 유지 |

## AI에게 알고리즘 관련 질문하는 팁

정렬 요청 시 세 가지를 명시하면 최적의 코드를 받을 수 있습니다.

1. **정렬 키 명시**: "날짜 기준으로 내림차순 정렬"
2. **안정성 요구사항**: "같은 날짜면 이름 순서 유지해줘 (안정 정렬)"
3. **전체 정렬 필요 여부**: "전체 정렬 말고 상위 10개만 필요해"

**전체 정렬 대신 상위 k개 요청 예시**:
> "100만 개의 상품 중 가격이 가장 낮은 5개만 효율적으로 추출해줘. 전체를 정렬할 필요 없어."

AI는 `heapq.nsmallest(5, products, key=lambda x: x["price"])`를 제안할 것입니다. 이는 O(n log k)로 전체 정렬 O(n log n)보다 훨씬 빠릅니다.

## 정렬 알고리즘 비교표

| 알고리즘 | 시간 복잡도 | 안정성 | 메모리 | Python에서 |
|---------|-----------|--------|--------|-----------|
| Timsort | O(n log n) 최악, O(n) 거의 정렬됨 | 안정 | O(n) | `sorted()`, `list.sort()` |
| mergesort | O(n log n) 보장 | 안정 | O(n) | — |
| quicksort | O(n log n) 평균, O(n²) 최악 | 비안정 | O(log n) | — |
| heapsort | O(n log n) 보장 | 비안정 | O(1) | `heapq` |

결론: 바이브코딩에서 정렬은 거의 항상 `sorted()` 또는 `.sort()`를 쓰면 됩니다.

## 처음 질문으로 돌아가기

AI가 quicksort를 직접 구현해줬을 때 "이거 이미 정렬된 입력에서 괜찮아?"라고 물어볼 수 있었다면 문제를 사전에 잡을 수 있었습니다. 또는 처음부터 "Python sorted() 써줘"라고 했다면 Timsort가 이미 정렬된 입력을 O(n)에 처리해줬을 것입니다.

## 정리

같은 O(n log n) 울타리 안에서도 정렬 알고리즘은 안정성, 메모리, 입력 적응성에서 크게 다릅니다. 바이브코딩에서 기본 선택은 항상 `sorted()`이고, 특별한 이유가 있을 때만 다른 방법을 검토합니다. 전체 정렬이 필요한지도 먼저 물어보는 습관이 중요합니다.
