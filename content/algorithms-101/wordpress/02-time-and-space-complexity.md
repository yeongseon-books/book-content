# 바이브코딩을 위한 알고리즘 기초 (2/10): 시간 복잡도와 공간 복잡도

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 2번째 글입니다.

AI에게 "사용자 리스트에서 중복을 제거해줘"라고 했더니 이런 코드가 나왔습니다.

```python
def remove_duplicates(items):
    result = []
    for item in items:
        if item not in result:
            result.append(item)
    return result
```

로컬에서 테스트했을 때 1000개짜리 리스트는 0.01초. 문제없어 보였습니다. 프로덕션에 올렸는데 10만 개짜리 리스트가 들어오자 응답 시간이 10초로 폭발했습니다.

코드는 맞습니다. 중복도 잘 제거합니다. 그런데 `item not in result`가 매번 결과 리스트 전체를 훑기 때문에, 전체 복잡도가 O(n²)입니다. 10만 개면 100억 번의 비교가 발생합니다.

이 문제를 사전에 막으려면 코드를 보자마자 "이게 O(n²)이네"라고 읽을 수 있어야 합니다. 그게 Big-O 표기법이 바이브코더에게 필요한 이유입니다.

> AI 코드를 신뢰하려면, 그 코드의 비용을 읽을 수 있어야 합니다.

---

## 이 글에서 다룰 문제
- Big-O, Big-Omega, Big-Theta는 각각 무엇을 뜻하는가?
- 코드 조각만 보고 복잡도를 어떻게 추정할 수 있는가?
- AI가 생성한 코드에서 O(n²) 패턴을 어떻게 찾는가?
- 입력 크기로 성능을 미리 예측하는 방법은 무엇인가?
- 공간 복잡도는 왜 따로 확인해야 하는가?

점근 분석은 엔지니어가 성능을 논의할 때 쓰는 공통 언어입니다. AI와 대화할 때도 "O(n log n)으로 구현해줘"처럼 쓸 수 있고, AI도 이 언어를 이해합니다.

## Before / After

**Before — AI가 자연스럽게 O(n²)을 선택한 코드:**

```python
def has_duplicates(arr):
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False
# n=10^5일 때 약 5×10^9 번 비교 — 수 분 걸림
```

**After — AI에게 복잡도 요구사항을 명시하고 받은 코드:**

```python
# 프롬프트: "O(n) 시간 복잡도로 중복 여부 확인 함수 만들어줘"
def has_duplicates(arr):
    return len(arr) != len(set(arr))
# O(n) — 해시 셋 활용, 10^5에서도 즉시 반환
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 작은 입력으로만 테스트 | 로컬에서 빠른 건 의미 없음 | 10배, 100배 데이터로 재측정 |
| 중첩 루프를 당연하게 수용 | 대부분 O(n²)이고 대안이 있음 | 중첩 루프 보이면 "더 좋은 방법?"을 AI에게 질문 |
| 상수를 완전히 무시 | 작은 n에서 상수가 결과를 뒤집음 | 계층과 상수 둘 다 보기 |
| 공간 복잡도 무시 | 메모리 한계 초과 가능 | AI에게 메모리 제약도 함께 명시 |
| 평균과 최악 혼동 | 운영에서 최악이 반드시 나타남 | 지연 민감한 시스템은 최악 기준으로 판단 |

## AI에게 알고리즘 관련 질문하는 팁

복잡도를 명시하면 AI 응답의 품질이 달라집니다.

**효과 없는 프롬프트**: "빠른 코드 만들어줘"

**효과 있는 프롬프트**:
> "입력 크기 n=10^6일 때 1초 안에 동작해야 해. 시간 복잡도는 O(n) 또는 O(n log n)이어야 하고, 공간 복잡도는 O(n) 이하여야 해."

또한 AI가 준 코드에 대해 이렇게 확인하는 습관을 들이세요:
> "이 코드의 시간 복잡도와 공간 복잡도를 Big-O로 설명해줘. 최악의 경우도 포함해서."

## 비용 계층 빠른 참고표

```
O(1)       — 해시 조회, 배열 인덱싱
O(log n)   — 이진 탐색, 균형 트리
O(n)       — 한 번 순회
O(n log n) — 효율적인 정렬 (mergesort, Timsort)
O(n²)      — 중첩 루프, 버블 정렬
O(2^n)     — 모든 부분집합 탐색
```

입력 크기 가이드:
- n ≤ 10^3: O(n²)까지 허용
- n ≤ 10^5: O(n log n) 필요
- n ≤ 10^7: O(n) 필요
- n ≥ 10^8: O(log n) 또는 스트리밍

## 처음 질문으로 돌아가기

AI가 만들어준 중복 제거 코드가 O(n²)인 것을 배포 전에 발견할 수 있었을까요? Big-O를 읽을 줄 알았다면 가능했습니다. 중첩 `for` 루프가 보이는 순간 "이건 O(n²)이야, `set()`으로 O(n)에 할 수 있지 않을까?"라고 AI에게 물어볼 수 있었을 것입니다.

## 정리

Big-O는 성능을 논의하는 공통 언어입니다. 바이브코더에게는 두 가지가 필요합니다. 첫째, 코드를 보고 복잡도 계층을 읽는 눈. 둘째, AI에게 복잡도를 명시해서 요청하는 습관. 이 두 가지가 갖춰지면 AI가 만든 코드를 훨씬 더 잘 활용할 수 있습니다.

다음 글에서는 탐색 알고리즘을 다룹니다. AI가 O(n)으로 만든 탐색 코드를 O(log n)으로 바꾸는 구체적인 시나리오를 봅니다.
