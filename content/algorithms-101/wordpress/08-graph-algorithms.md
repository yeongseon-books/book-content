# 바이브코딩을 위한 알고리즘 기초 (8/10): 그래프 알고리즘

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 8번째 글입니다.

소셜 네트워크 앱에서 두 사용자 사이의 최단 연결 경로를 찾는 기능이 필요했습니다. "사용자 A에서 B까지 친구 관계로 연결되는 가장 짧은 경로 찾아줘"라고 AI에게 요청했습니다.

AI는 다익스트라 알고리즘을 구현해줬습니다. 테스트에서는 잘 동작했습니다. 그런데 조금 더 생각해보니 이 문제는 모든 친구 관계의 가중치가 1로 동일합니다. 다익스트라는 BFS보다 구현이 복잡하고 느립니다. 가중치가 없는 최단 경로는 BFS가 더 적합하고 단순합니다.

반대 케이스도 있습니다. 물류 시스템에서 경로 비용을 최소화하는 기능을 만들었는데, 할인 경로에 음수 가중치가 있었습니다. AI가 준 다익스트라 코드는 이 경우 틀린 결과를 줬습니다. 음수 가중치에는 Bellman-Ford가 필요합니다.

어떤 알고리즘을 언제 써야 하는지 알면, AI에게 더 정확한 요청을 할 수 있습니다.

> 그래프 문제는 "무엇이 노드이고 무엇이 간선인가"를 정의하는 순간 풀이가 시작됩니다.

---

## 이 글에서 다룰 문제
- BFS와 DFS는 각각 어떤 문제에 적합한가?
- 다익스트라는 어떤 조건에서 쓰고, 어떤 조건에서 실패하는가?
- 인접 리스트와 인접 행렬의 차이는 언제 중요한가?
- AI가 만든 그래프 코드에서 어떤 점을 점검해야 하는가?
- 그래프 탐색 코드의 성능을 어떻게 판단하는가?

실무 문제는 의외로 많이 그래프로 환원됩니다. 마이크로서비스 의존성, 소셜 네트워크, 배달 경로, 작업 스케줄링이 모두 그래프 문제입니다.

## Before / After

**Before — AI가 기본으로 선택한 인접 행렬 (희소 그래프에 메모리 낭비):**

```python
# 노드 10000개, 간선 30000개인 희소 그래프
adj = [[0] * 10000 for _ in range(10000)]  # 1억 셀 — 대부분 0
```

**After — 인접 리스트로 O(V+E) 메모리:**

```python
# 프롬프트: "노드 10000개, 간선 30000개인 희소 그래프. 인접 리스트로 구현해줘."
from collections import defaultdict
adj = defaultdict(list)
# 메모리 O(V+E) — 실제 간선만 저장
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 희소 그래프에 인접 행렬 사용 | 메모리 O(V²) 낭비 → OOM | "희소 그래프야. 인접 리스트 써줘" 명시 |
| 가중치 없는 최단 경로에 다익스트라 사용 | BFS가 더 단순하고 빠름 | "가중치 없는 최단 경로야. BFS 써줘" 명시 |
| 음수 가중치에 다익스트라 사용 | 틀린 결과 반환 | "음수 가중치 있어. Bellman-Ford 써줘" 명시 |
| BFS에 `list` 대신 `deque` 미사용 | O(1) vs O(n) 큐 연산 차이 | `from collections import deque` 사용 |
| 사이클 그래프에 위상 정렬 사용 | None 반환되는데 확인 안 함 | 결과 길이로 사이클 존재 여부 확인 |

## AI에게 알고리즘 관련 질문하는 팁

그래프 문제를 AI에게 요청할 때는 그래프의 속성을 명시하는 것이 핵심입니다.

**속성 명시 체크리스트**:
- 방향 그래프 / 무방향 그래프?
- 가중치 있음 / 없음?
- 가중치에 음수 있음 / 없음?
- 사이클 있음 / 없음?
- 희소 (간선 수 << 노드²) / 밀집?
- 노드와 간선 수 규모?

**예시 프롬프트**:
> "무방향 그래프, 가중치 없음, 노드 10^5개, 간선 3×10^5개. 두 노드 사이 최단 경로(홉 수)를 구해줘."

이 정보가 있으면 AI는 확신을 가지고 BFS를 선택합니다.

**음수 가중치 시나리오**:
> "가중치가 있고 일부 가중치가 음수일 수 있어. 최단 경로 구해줘. 다익스트라 말고 음수도 처리되는 알고리즘 써줘."

## 그래프 알고리즘 선택 가이드

```
최단 경로:
  가중치 없음                → BFS, O(V+E)
  가중치 있음, 음수 없음     → 다익스트라, O((V+E) log V)
  가중치 있음, 음수 있음     → Bellman-Ford, O(VE)
  모든 쌍 최단 경로          → Floyd-Warshall, O(V³)

연결성/순회:
  연결 요소 찾기             → BFS 또는 DFS
  사이클 탐지                → DFS
  위상 정렬                  → Kahn 알고리즘 (BFS 기반)

최소 신장 트리:
  희소 그래프                → Kruskal (간선 정렬)
  밀집 그래프                → Prim (우선순위 큐)
```

## 운영 체크리스트
- [ ] 그래프의 방향성, 가중치, 음수 여부를 AI에게 명시했는가?
- [ ] 희소/밀집 여부에 따라 인접 리스트/행렬을 선택했는가?
- [ ] 가중치 없는 최단 경로에 BFS를 쓰는가 (다익스트라 아닌)?
- [ ] 음수 가중치에 다익스트라를 쓰지 않는가?
- [ ] BFS 구현에 `deque`를 사용하는가?
- [ ] 위상 정렬 결과에서 사이클 여부를 확인하는가?

## 처음 질문으로 돌아가기

AI가 다익스트라를 줬을 때, "가중치 없는 그래프야. BFS가 더 단순하고 빠르지 않아?"라고 물을 수 있어야 합니다. 음수 가중치가 있을 때 "다익스트라는 음수에서 틀려. Bellman-Ford로 바꿔줘"라고 말할 수 있어야 합니다. 그래프 알고리즘 선택 기준을 아는 것이 이 판단을 가능하게 합니다.

## 정리

그래프 알고리즘은 문제를 노드와 간선으로 프레임하는 순간 강력해집니다. AI에게 그래프 속성을 명확히 전달하면 적절한 알고리즘을 선택해줍니다. BFS, DFS, 다익스트라, MST만 이해해도 실무의 많은 그래프 문제를 다룰 수 있습니다.

다음 글에서는 문자열 알고리즘을 다룹니다. AI가 만든 정규식이 특정 입력에서 서버를 멈출 수 있는 ReDoS 취약점을 어떻게 피하는지 봅니다.
