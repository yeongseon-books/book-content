# 바이브코딩을 위한 알고리즘 기초 (7/10): 그리디 알고리즘

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 7번째 글입니다.

결제 시스템에 거스름돈을 계산하는 함수가 필요했습니다. AI에게 요청했고, AI는 그리디 알고리즘으로 구현했습니다. 가장 큰 단위부터 거슬러 주는 방식입니다.

```python
def make_change(coins, amount):
    coins = sorted(coins, reverse=True)
    result = []
    for coin in coins:
        while amount >= coin:
            result.append(coin)
            amount -= coin
    return result
```

한국 화폐 시스템(500, 100, 50, 10원)에서는 완벽하게 동작했습니다. 그런데 글로벌 서비스를 위해 임의의 코인 시스템을 지원하도록 확장했을 때 문제가 생겼습니다. `coins = [1, 3, 4]`, `amount = 6`에서 그리디는 `[4, 1, 1]` (3개)를 반환했지만, 실제 최소 동전 수는 `[3, 3]` (2개)입니다.

AI는 틀린 코드를 준 게 아닙니다. 그리디는 "동전 시스템이 canonical할 때" 최적입니다. 임의의 동전 집합에서는 동적 계획법이 필요합니다. 이 조건을 알아야 AI 코드를 신뢰할 수 있는지 판단할 수 있습니다.

> 그리디 코드가 동작하는 것처럼 보여도, 모든 입력에서 최적인지는 별개의 문제입니다.

---

## 이 글에서 다룰 문제
- 그리디 알고리즘이 옳으려면 어떤 두 조건이 필요한가?
- AI가 그리디로 만든 코드가 틀릴 수 있는 상황은 무엇인가?
- 교환 논증은 그리디의 정확성을 어떻게 검증하는가?
- 그리디처럼 보이는데 실제로는 DP가 필요한 문제를 어떻게 구별하는가?
- 그리디가 확실히 최적인 경우는 어떤 상황인가?

그리디 알고리즘은 빠르고 단순합니다. 맞을 때는 O(n log n) 이하로 처리됩니다. 하지만 틀릴 때는 조용히 틀립니다. 그래서 더 위험합니다.

## Before / After

**Before — AI가 그리디로 만든 코드 (임의 동전에서 틀림):**

```python
def min_coins_greedy(coins, amount):
    coins = sorted(coins, reverse=True)
    count = 0
    for coin in coins:
        count += amount // coin
        amount %= coin
    return count if amount == 0 else -1

# coins=[1,3,4], amount=6
# 그리디: 4+1+1 = 3개 (틀림)
# 정답: 3+3 = 2개
```

**After — 동적 계획법으로 항상 최적 보장:**

```python
# 프롬프트: "임의의 동전 시스템에서 최소 동전 수 DP로 구현해줘. 그리디는 일반적으로 틀려."
def min_coins_dp(coins, amount):
    INF = amount + 1
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1

# coins=[1,3,4], amount=6 → 2 (3+3, 정답)
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 그리디가 직관적으로 맞아 보여서 검증 생략 | 특정 입력에서 조용히 틀림 | 반례를 직접 만들어서 확인 |
| AI 코드가 돌아가니 맞다고 가정 | 테스트 케이스가 운 좋게 맞았을 수 있음 | "이 코드가 모든 입력에서 최적인가?" AI에게 질문 |
| 그리디 적용 조건 확인 없이 배포 | 운영에서 잘못된 계산 결과 | "canonical coin system에서만 맞다" 같은 조건을 명시 |
| 정렬 키를 잘못 선택 | 거의 맞지만 미묘하게 틀림 | AI에게 "왜 이 정렬 키가 최적인가?" 설명 요청 |
| 우선순위 큐 없이 그리디 구현 | O(n²) → O(n log n) 기회 놓침 | heapq 활용 가능한지 확인 |

## AI에게 알고리즘 관련 질문하는 팁

그리디 코드를 받았을 때 정확성을 검증하는 질문이 중요합니다.

**정확성 검증 요청**:
> "이 그리디 알고리즘이 모든 입력에서 최적 결과를 보장하는가? 교환 논증으로 설명해줘. 반례가 있다면 DP로 바꿔줘."

**그리디 vs DP 판단 요청**:
> "이 문제가 그리디로 풀리는지 DP로 풀어야 하는지 판단해줘. 판단 근거도 설명해줘."

**안전한 시나리오 명시**:
> "한국 화폐 단위(10, 50, 100, 500, 1000원)에 한정된 거스름돈 계산이야. 이 경우 그리디가 최적인지 확인해줘."

## 그리디가 안전한 경우 vs 위험한 경우

```
그리디가 안전한 경우:
  - 활동 선택 문제 (가장 빨리 끝나는 것 선택)
  - Huffman 인코딩 (빈도 기반 압축)
  - canonical 화폐 시스템 (한국, 미국 동전)
  - fractional knapsack (분수로 쪼갤 수 있는 배낭)

그리디가 위험한 경우 (DP 필요):
  - 임의의 동전 집합 거스름돈
  - 0/1 knapsack (쪼갤 수 없는 배낭)
  - 일반 그래프 최단 경로 (음수 가중치)
  - 직관적으로 "욕심" 부리면 될 것 같은 문제들
```

## 처음 질문으로 돌아가기

AI가 그리디 알고리즘을 줬을 때, 우리는 "이게 모든 경우에 최적이야? 반례 없어?"라고 물을 수 있어야 합니다. 그리디가 항상 동작하는 건지, 특정 조건에서만 동작하는 건지 판단하는 것이 알고리즘 지식의 핵심 역할입니다.

## 정리

그리디는 단순하고 빠르지만, 정확성 부담이 큽니다. AI가 그리디 코드를 줬을 때 "이게 항상 맞아?"라는 질문을 해야 합니다. 그리디 선택 속성과 최적 부분 구조가 없으면 DP로 전환하는 것이 안전합니다.

다음 글에서는 그래프 알고리즘을 다룹니다. AI에게 "최단 경로 찾아줘"라고 했을 때 나온 코드가 음수 가중치에서 왜 틀리는지, 그리고 BFS와 다익스트라의 차이를 봅니다.
