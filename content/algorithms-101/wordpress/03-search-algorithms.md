# 바이브코딩을 위한 알고리즘 기초 (3/10): 탐색 알고리즘

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 3번째 글입니다.

이커머스 플랫폼을 바이브코딩으로 만들었습니다. 상품 카탈로그에서 특정 상품 ID를 찾는 함수를 AI에게 요청했습니다. AI는 이렇게 줬습니다.

```python
def find_product(products, product_id):
    for product in products:
        if product["id"] == product_id:
            return product
    return None
```

상품이 1000개일 때는 문제없었습니다. 런칭 후 상품이 100만 개로 늘어났습니다. 상품 조회 API가 평균 0.5초로 느려졌고, 동시 요청이 몰리자 타임아웃이 발생했습니다.

AI가 문제였을까요? 아닙니다. AI는 여러분이 "정렬된 리스트"라는 정보를 주지 않았기 때문에 가장 범용적인 방법을 선택했습니다. 만약 "상품 ID가 오름차순으로 정렬된 리스트에서 O(log n)으로 찾아줘"라고 했다면 이진 탐색 코드가 나왔을 것입니다.

100만 개 리스트에서 선형 탐색은 최대 100만 번 비교, 이진 탐색은 최대 20번 비교입니다. 이 차이가 0.5초와 0.0001초의 차이입니다.

> 정렬된 데이터를 갖고 있다면, 선형 탐색은 기회를 버리는 것과 같습니다.

---

## 이 글에서 다룰 문제
- 선형 탐색과 이진 탐색의 비용 차이는 실제로 얼마나 큰가?
- 이진 탐색이 동작하려면 어떤 전제 조건이 필요한가?
- Python `bisect` 모듈을 어떻게 활용하는가?
- AI에게 탐색 최적화를 어떻게 요청하는가?
- lower bound와 upper bound는 어디에 쓰이는가?

탐색은 거의 모든 시스템의 기본 연산입니다. 데이터베이스 조회, 로그 검색, 사용자 찾기, 상품 목록 필터링이 모두 탐색 문제입니다. 탐색 알고리즘을 이해하면 AI에게 훨씬 정확한 요청을 할 수 있습니다.

## Before / After

**Before — AI가 기본으로 생성하는 선형 탐색:**

```python
def find_by_id(items, target_id):
    for item in items:
        if item.id == target_id:
            return item
    return None
# O(n) — 100만 건에서 최대 100만 번 비교
```

**After — 정렬 조건을 명시하고 AI에게 받은 이진 탐색:**

```python
import bisect

# 프롬프트: "ID가 정렬된 리스트에서 bisect로 O(log n) 탐색 만들어줘"
def find_by_id(sorted_ids, id_list, target_id):
    i = bisect.bisect_left(sorted_ids, target_id)
    if i < len(sorted_ids) and sorted_ids[i] == target_id:
        return id_list[i]
    return None
# O(log n) — 100만 건에서 최대 20번 비교
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 정렬된 데이터에도 선형 탐색 사용 | O(n) vs O(log n) 차이를 놓침 | "이 데이터 정렬돼 있어. 이진 탐색 써줘" |
| 매번 이진 탐색을 직접 구현 | off-by-one 버그 발생 빈번 | `bisect` 모듈 우선 사용 |
| 정렬 전제를 코드에 명시하지 않음 | 이후 유지보수에서 사고 발생 | 주석 또는 타입 힌트로 명시 |
| 반복 탐색에 매번 선형 탐색 | 누적 비용 폭발 | "한 번 정렬 + 여러 번 이진 탐색"으로 설계 변경 |
| 정렬되지 않은 데이터에 이진 탐색 적용 | 잘못된 결과 반환 | 정렬 여부를 항상 먼저 확인 |

## AI에게 알고리즘 관련 질문하는 팁

탐색 최적화를 요청할 때는 데이터의 상태를 명시하는 것이 핵심입니다.

**데이터 상태 명시 예시**:
> "정렬된 정수 배열에서 특정 값의 첫 번째 위치를 O(log n)으로 찾아줘. Python bisect 모듈을 활용해도 좋아."

**반복 탐색 최적화 요청**:
> "같은 리스트에서 탐색을 1000번 반복해야 해. 전처리를 포함한 전체 비용이 최소가 되도록 설계해줘."

**lower/upper bound 요청**:
> "정렬된 배열에서 특정 값이 처음 나타나는 위치와 마지막으로 나타나는 위치를 각각 반환하는 함수를 만들어줘."

AI는 `bisect_left`와 `bisect_right`를 활용한 깔끔한 코드를 즉시 제안할 것입니다.

## 탐색 알고리즘 선택 기준

```
데이터가 정렬되어 있고, 탐색을 한 번만 함
  → 이진 탐색 (O(log n))

데이터가 정렬되어 있고, 탐색을 반복함
  → 한 번 정렬 후 이진 탐색 반복 (전처리 O(n log n) + 탐색 O(log n))

데이터가 정렬되지 않음
  → 해시 딕셔너리 변환 후 O(1) 조회
  → 또는 정렬 후 이진 탐색

"X 이상인 첫 번째 값" 같은 조건
  → bisect_left / bisect_right
```

- [ ] 같은 리스트에서 탐색이 반복된다면 전처리를 고려했는가?

- [ ] AI에게 데이터의 정렬 여부를 명시해서 요청했는가?
- [ ] 정렬 전제를 코드나 주석에 명시했는가?

## 처음 질문으로 돌아가기

AI가 선형 탐색 코드를 줬을 때, 우리는 "정렬된 데이터야. 이진 탐색으로 바꿔줘"라고 말할 수 있어야 합니다. 그리고 "O(n)이 O(log n)이 됐으니 100만 건 기준으로 100만 번 비교가 20번이 됐어"라고 확인할 수 있어야 합니다. 그게 탐색 알고리즘을 아는 것의 가치입니다.

## 정리

탐색 비용은 데이터에 구조가 있는지에 따라 극적으로 달라집니다. 정렬이 있으면 O(n)을 O(log n)으로 줄일 수 있고, 이 발상은 데이터베이스 인덱스, 시계열 조회, 게임 매칭 등 실제 시스템 전반에 적용됩니다.

다음 글에서는 정렬 알고리즘을 다룹니다. AI가 만든 정렬 코드가 어떤 조건에서 느려지는지, Python `sorted()`가 왜 Timsort를 쓰는지 봅니다.
