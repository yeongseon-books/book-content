# 바이브코딩을 위한 알고리즘 기초 (10/10): 알고리즘 문제 풀이 전략

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 10번째 글입니다.

이 시리즈를 통해 우리는 AI 코드에서 O(n²)을 발견하고, ReDoS 취약 정규식을 걸러내고, 재귀 깊이 문제를 사전에 감지하는 방법을 배웠습니다. 이제 마지막으로 이 모든 판단을 체계화하는 방법을 정리합니다.

바이브코딩에서 알고리즘 지식의 실제 가치는 특정 알고리즘을 암기하는 것이 아닙니다. 새로운 문제가 들어왔을 때 다섯 가지 질문을 빠르게 처리하는 능력입니다.

1. 입력 크기는 얼마인가?
2. 어떤 복잡도가 허용되는가?
3. 이 문제의 구조는 어떤 패턴인가?
4. 어떤 알고리즘 도구가 적합한가?
5. AI의 코드가 이 기준에 맞는가?

이 절차가 있으면 AI가 최선의 선택을 하지 않았을 때를 감지할 수 있고, 더 나은 코드를 요청할 수 있습니다.

> 바이브코딩의 한계는 AI가 아니라, AI에게 무엇을 요청해야 할지 모르는 데서 옵니다.

---

## 이 글에서 다룰 문제
- 어떤 알고리즘 문제에도 적용할 수 있는 표준 사고 절차는 무엇인가?
- 입력 크기만 보고 허용 복잡도를 어떻게 추정하는가?
- 문제의 신호에서 어떤 알고리즘 도구를 떠올릴 수 있는가?
- AI와 알고리즘을 논의할 때 어떤 언어로 소통하면 좋은가?
- 이 시리즈에서 배운 내용을 실무에 어떻게 적용하는가?

알고리즘을 배운 목적은 풀이를 암기하는 게 아니라 문제를 분해하는 능력을 갖추는 것입니다. 이 능력이 있으면 처음 보는 문제도 체계적으로 접근할 수 있습니다.

## Before / After

**Before — AI 코드를 이해 없이 그대로 사용:**

```text
"이거 잘 되겠지" → 복붙 → 로컬 테스트 통과 → 배포
→ 규모 커지면 병목, 예외 상황에서 오류
```

**After — 5단계 절차로 AI 코드를 검토하고 활용:**

```text
1단계: 문제를 자기 말로 다시 쓰기 — "이게 정말 내가 원하는 거 맞아?"
2단계: 입력, 출력, 제약 조건 명시 — 크기, 형식, 엣지 케이스
3단계: 입력 크기로 허용 복잡도 추정 — "n=10^6이면 O(n log n) 이하 필요"
4단계: 패턴 인식으로 도구 후보 좁히기 — "정렬된 배열 탐색 → 이진 탐색"
5단계: 작은 예제로 손 검증 후 배포 — 경계 케이스 포함
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 문제를 끝까지 읽지 않고 AI에게 바로 요청 | 잘못된 방향의 최적화 | 자기 말로 다시 쓴 뒤 요청 |
| 입력 크기와 제약 없이 요청 | AI가 최악의 경우를 고려 못 함 | 크기, 형식, 시간 예산 항상 명시 |
| AI 코드 복잡도 확인 생략 | 규모에서 무너짐 | "이 코드의 시간 복잡도는?" 반드시 물어보기 |
| 경계 케이스 무시 | 간헐적 오류 발생 | 빈 입력, 단일 원소, 극단값 항상 테스트 |
| 알고리즘 선택을 전적으로 AI에 맡김 | AI가 최선이 아닌 선택을 할 수 있음 | 패턴 인식으로 후보를 좁힌 뒤 확인 |

## AI에게 알고리즘 관련 질문하는 팁

이 시리즈에서 배운 패턴 인식 신호표를 AI와의 대화에 활용하세요.

```python
# 이 신호가 보이면 이 알고리즘을 요청하세요
signals = {
    "정렬된 배열에서 탐색":           "이진 탐색 / bisect",
    "가장 크거나 작은 k개":           "heapq.nlargest / nsmallest",
    "연속 부분 배열 최적":            "슬라이딩 윈도우 / 투 포인터",
    "같은 부분 문제 반복":            "동적 계획법 / @lru_cache",
    "가중치 없는 최단 경로":          "BFS",
    "가중치 있는 최단 경로 (음수 없음)": "다익스트라",
    "작업 순서 / 의존성":             "위상 정렬",
    "prefix 공유 / 자동완성":         "트라이",
    "대용량 텍스트 패턴 매칭":        "KMP / str.find()",
    "최적 선택 + 증명 가능":          "그리디 (교환 논증 확인 필요)",
}
```

**입력 크기 기반 복잡도 요청 방법**:
> "n=10^6이고 시간 제한 1초야. 이 알고리즘이 O(n) 또는 O(n log n) 이하로 동작하는지 확인해줘."

## 입력 크기 기반 허용 복잡도 표

```
n ≤ 10         : O(2^n), 백트래킹 가능
n ≤ 20         : O(2^n), 비트마스크 DP 가능
n ≤ 500        : O(n³) 가능 (Floyd-Warshall 등)
n ≤ 5,000      : O(n²) 가능
n ≤ 10^5~10^6  : O(n log n) 필요
n ≥ 10^7       : O(n) 또는 O(log n) 필요
```

이 표를 기억하면 AI에게 복잡도를 명시할 때 자신감이 생깁니다.

## 처음 질문으로 돌아가기

"AI한테 맡기면 되지 않나요?"라는 질문으로 이 시리즈를 시작했습니다.

맞습니다. AI에게 맡기면 됩니다. 그런데 "어떻게 맡기느냐"가 결과를 결정합니다. 입력 크기를 명시하고, 복잡도를 요구하고, 생성된 코드를 패턴으로 검증하는 사람은 AI로부터 훨씬 더 나은 코드를 받습니다.

이 시리즈에서 배운 것들, Big-O 읽기, 탐색과 정렬 선택 기준, 재귀 점검, DP 신호 인식, 그리디 검증, 그래프 속성 명시, 정규식 보안이 모두 그 도구입니다.

## 정리

알고리즘 학습의 본질은 풀이 암기가 아니라 문제 분해 절차를 갖추는 것입니다. 입력 크기에서 복잡도를 추정하고, 신호에서 도구를 좁히고, AI 코드를 검증하는 5단계 루프는 면접과 실무, 그리고 바이브코딩 모두에서 동작합니다.

이로써 바이브코딩을 위한 알고리즘 기초 시리즈를 마칩니다. 여기서 익힌 판단 프레임은 자료구조 심화, 시스템 설계, 성능 최적화로 확장될 때도 그대로 적용됩니다.
