# 바이브코딩을 위한 알고리즘 기초 (1/10): 알고리즘이란 무엇인가?

이 글은 바이브코딩을 위한 알고리즘 기초 시리즈의 1번째 글입니다.

"AI한테 맡기면 되지 않나요?"라는 질문을 자주 받습니다. 맞습니다. ChatGPT나 Claude에게 "사용자 목록에서 특정 이름을 찾는 함수 만들어줘"라고 하면 코드가 뚝딱 나옵니다. 그런데 그 코드를 프로덕션에 올렸더니, 사용자가 1만 명일 때는 괜찮았는데 100만 명이 되자 API 응답이 수 초씩 걸리기 시작했습니다.

AI가 잘못 짠 걸까요? 아닙니다. AI는 동작하는 코드를 줬습니다. 문제는 "동작함"과 "빠름"은 다른 이야기라는 점입니다. AI는 여러분이 요청하지 않은 이상 성능 최적화를 우선하지 않습니다. 그리고 여러분이 "O(n) 탐색 말고 O(log n)으로 바꿔줘"라고 말하려면, 먼저 그 언어를 알아야 합니다.

바이브코딩 시대에 알고리즘을 배우는 이유는 코드를 외우려는 게 아닙니다. AI와 대화할 때 "이 코드의 시간 복잡도는 뭐야?", "더 빠른 방법 있어?"라고 물을 수 있는 판단력을 갖추기 위해서입니다.

> AI에게 더 나은 코드를 받으려면, 먼저 어떤 코드가 더 나은지 판단할 수 있어야 합니다.

---

## 이 글에서 다룰 문제
- 알고리즘이 반드시 만족해야 하는 세 가지 조건은 무엇인가?
- 알고리즘과 프로그램은 어떻게 다른가?
- AI가 생성한 코드에서 알고리즘을 어떻게 읽을 수 있는가?
- 의사코드는 왜 AI와의 소통 도구가 될 수 있는가?
- 실무에서 알고리즘 지식이 없을 때 어떤 문제가 생기는가?

운영에서 "시스템이 느리다"로 보이는 문제의 상당수는 사실 "알고리즘이 입력 크기에 맞게 확장되지 않는다"는 문제입니다. 테스트 데이터에서는 괜찮았던 선형 탐색 하나가, 실제로 수천만 건을 만나는 순간 병목이 됩니다.

## Before / After

**Before — AI가 생성한 "동작하는" 코드:**

```python
def find_user(users, name):
    for user in users:
        if user["name"] == name:
            return user
    return None
# 사용자 100명: 괜찮음. 사용자 100만명: 병목.
```

**After — AI에게 조건을 명시하고 받은 코드:**

```python
# 프롬프트: "이름으로 정렬된 리스트에서 O(log n)으로 찾는 함수 만들어줘"
import bisect

def find_user(sorted_names, name):
    i = bisect.bisect_left(sorted_names, name)
    return sorted_names[i] if i < len(sorted_names) and sorted_names[i] == name else None
# O(log n) — 100만 명에서도 약 20번 비교로 끝남
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| AI 코드를 바로 복붙 | 동작은 하지만 규모에서 무너짐 | "이 코드의 복잡도는?" 반드시 물어보기 |
| "빠르게 만들어줘"만 요청 | AI가 뭘 기준으로 빠르게 할지 모름 | 입력 크기와 시간 예산을 함께 명시 |
| 로컬 테스트만 믿음 | 소규모 데이터는 무조건 빠름 | 10배, 100배 데이터로도 테스트 |
| 알고리즘 대신 언어를 탓함 | Python이 느린 게 아니라 O(n²)이 느린 것 | 알고리즘 선택을 먼저 점검 |
| 코드만 보고 의사코드 생략 | 논리 오류를 나중에 발견 | AI에게 의사코드 먼저 요청 후 구현 |

## AI에게 알고리즘 관련 질문하는 팁

바이브코딩에서 알고리즘 관련 프롬프트를 잘 쓰려면 세 가지를 포함하면 됩니다.

1. **입력 크기 명시**: "사용자가 최대 100만 명일 때"
2. **성능 기대치 명시**: "1초 안에 응답해야 해"
3. **복잡도 질문 추가**: "이 코드의 시간 복잡도는 뭐야? 더 좋은 방법 있어?"

예시 프롬프트:
> "정렬된 정수 배열에서 특정 값을 찾는 함수를 만들어줘. 배열 크기가 최대 10^6이고 1초 안에 동작해야 해. 코드 옆에 시간 복잡도도 적어줘."

이렇게 하면 AI는 O(log n) 이진 탐색을 제안하고, 왜 O(n) 선형 탐색이 안 되는지도 설명해줍니다.

## 운영 체크리스트
- [ ] AI가 생성한 코드에서 루프 구조를 확인하고 복잡도를 추정했는가?
- [ ] 입력 크기가 커졌을 때 어떻게 동작할지 생각해봤는가?
- [ ] "이 알고리즘의 정확성 조건"을 한 문장으로 말할 수 있는가?
- [ ] 코딩 전에 복잡도를 추정했는가?
- [ ] 의사코드로 논리를 확인하고 구현했는가?
- [ ] 경계 입력(빈 배열, 단일 원소, 중복 값)으로 테스트했는가?

## 처음 질문으로 돌아가기

AI가 짜준 코드가 느릴 때, 우리는 "AI가 잘못했다"고 말하는 대신 "이 알고리즘은 O(n)인데 O(log n)으로 바꿀 수 있어?"라고 물을 수 있어야 합니다. 그 언어를 배우는 것이 이 시리즈의 목표입니다.

알고리즘은 정확성, 유한성, 효율성으로 정의됩니다. AI 코드를 읽을 때도, 프롬프트를 쓸 때도, 성능 이슈를 디버깅할 때도 이 세 가지 질문이 출발점입니다.

## 정리

알고리즘은 프로그램 뒤에 있는 추상적 절차입니다. AI는 프로그램을 만들지만, 어떤 알고리즘을 쓸지는 여러분이 판단해야 합니다. 의사코드를 쓸 줄 알고, 복잡도를 추정할 줄 알면, AI와의 협업 품질이 달라집니다.

다음 글에서는 시간 복잡도와 공간 복잡도를 다룹니다. "이 코드 빠른가요?"라는 질문에 Big-O로 답하는 방법을 배웁니다.
