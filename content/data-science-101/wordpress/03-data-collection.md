# 바이브코딩을 위한 데이터 사이언스 기초 (3/10): AI에게 줄 데이터를 어떻게 모을지

이 글은 바이브코딩을 위한 데이터 사이언스 기초 시리즈의 3번째 글입니다.

AI 코딩 도구로 데이터 분석을 하다 보면 이런 상황이 생깁니다. 동료가 카카오톡으로 엑셀 파일을 보내줍니다. 언제 추출했는지, 어떤 기준으로 필터링했는지, 중간에 손으로 수정했는지 아무것도 모릅니다. 그 파일을 AI에게 넘겨 분석을 시킵니다. 분석 결과를 보고서로 냈는데, 나중에 같은 분석을 다시 해달라는 요청이 옵니다. 그런데 원래 파일이 어디 있는지, 어떤 버전이었는지 알 수 없습니다.

바이브코딩에서 데이터 수집 단계는 단순히 "AI에게 넘길 파일을 구하는 것"이 아닙니다. 나중에 같은 분석을 재현할 수 있도록 출처를 기록하는 단계입니다. AI는 코드를 잘 씁니다. 하지만 AI에게 넘긴 데이터가 어디서 왔는지 설명할 수 없다면, 아무리 정교한 분석도 신뢰를 얻기 어렵습니다.

데이터 수집의 핵심은 재현성입니다. 두 달 뒤에 팀원이 "이 분석 다시 해줄 수 있어?"라고 했을 때, 같은 데이터로 같은 분석을 다시 할 수 있어야 합니다. 이를 위해 필요한 것이 출처, 추출 시각, 데이터 버전을 함께 기록하는 습관입니다.

파일, API, 데이터베이스, 이벤트 로그라는 네 가지 경로 각각에서 데이터를 가져올 때 어떤 점을 주의해야 하는지, AI에게 수집 코드를 짜달라고 할 때 어떤 정보를 함께 요청해야 하는지를 이 글에서 정리합니다.

> 추적 가능한 데이터만 믿을 수 있고, 믿을 수 있는 데이터로만 좋은 분석이 나옵니다.

---

## 이 글에서 다룰 문제
- AI에게 분석을 맡길 때 데이터는 어디서 가져와야 할까요?
- 원본, 사본, 스냅샷을 왜 구분해야 할까요?
- 파일, API, 데이터베이스, 이벤트 로그는 각각 어떤 특성을 가질까요?
- 데이터 출처를 기록하지 않으면 어떤 문제가 생길까요?
- AI에게 수집 코드를 요청할 때 어떤 정보를 함께 줘야 할까요?

## 데이터 수집 경로 비교

| 경로 | 특징 | AI 요청 시 주의점 | 출처 기록 방법 |
|---|---|---|---|
| CSV/엑셀 파일 | 빠르지만 버전 혼선 위험 | 파일명에 날짜 포함, 원본 별도 보관 | 파일명 + 다운로드 일시 |
| REST API | 최신 데이터 접근 가능 | 인증키, rate limit, 스키마 변경 주의 | API 엔드포인트 + 호출 시각 |
| 데이터베이스 | 신뢰도 높지만 쿼리 필요 | 운영 DB 직접 조회 대신 복제본 사용 | SQL 쿼리 + 실행 시각 |
| 이벤트 로그 | 행동 데이터 풍부하지만 스키마 변경 빈번 | 이벤트 이름 변경 추적 필요 | 로그 파일 경로 + 기간 |

## AI에게 수집 코드 요청하기

AI에게 데이터 수집 코드를 짜달라고 할 때 다음 정보를 함께 줘야 합니다:

```python
# AI에게 이런 형태로 요청할 수 있습니다
"""
다음 조건으로 PostgreSQL에서 데이터를 가져오는 Python 코드를 작성해줘:
- 테이블: payments
- 기간: 2026-05-01 ~ 2026-05-31
- 조건: plan_type = 'paid', is_trial = 0
- 추가: 쿼리 실행 시각과 행 수를 메타데이터로 함께 저장
"""

import pandas as pd
from sqlalchemy import create_engine
import datetime as dt

query = """
SELECT user_id, plan, amount, paid_at
FROM payments
WHERE paid_at >= '2026-05-01' AND paid_at < '2026-06-01'
  AND plan_type = 'paid' AND is_trial = 0
"""

engine = create_engine("postgresql://reader:***@replica/warehouse")
df = pd.read_sql(query, engine)

# 출처 기록 — 이 부분이 핵심입니다
meta = {
    "source": "payments table @ replica",
    "query": query.strip(),
    "fetched_at": dt.datetime.utcnow().isoformat(),
    "row_count": len(df),
}
print(meta)
```

## 원본 보호의 원칙

바이브코딩에서 자주 생기는 문제 중 하나는 AI에게 넘긴 파일을 AI가 수정한 코드로 덮어쓰는 경우입니다. 원본과 작업본을 분리하는 것은 데이터 분석의 기본입니다:

- `data/raw/` — 절대 수정하지 않는 원본 디렉토리
- `data/processed/` — AI가 정제하고 변환한 작업본
- `data/snapshots/` — 특정 날짜 기준으로 고정한 스냅샷

AI에게 "data/raw 폴더의 파일은 수정하지 말고, data/processed에 결과를 저장해줘"라고 지시하는 것이 좋습니다.

## Before / After

**Before**: 팀원이 보낸 엑셀 파일을 AI에게 넘겨 분석했습니다. 6개월 뒤에 같은 분석을 요청받았는데, 원본 파일도 없고 어떤 기준으로 데이터를 뽑았는지도 모릅니다. 처음부터 다시 해야 합니다.

**After**: AI에게 수집 코드를 짜달라고 할 때 출처, 기간, 필터 조건, 실행 시각을 메타데이터로 함께 저장하게 했습니다. 6개월 뒤에 같은 조건으로 다시 실행하면 됩니다.

## 바이브코딩할 때 자주 하는 실수
| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 원본 파일을 AI가 수정하게 둠 | 되돌릴 방법 없음 | raw/processed 폴더 분리 |
| 데이터 출처를 기록하지 않음 | 재현 불가능 | fetched_at, source 항상 저장 |
| API 오류 처리 없이 요청 | 실패 시 데이터 손실 | 재시도 로직 포함하도록 요청 |
| 민감 데이터를 로컬에 저장 | 보안 사고 위험 | 마스킹 처리 요청 |

## AI에게 데이터 분석 요청하는 팁

데이터 수집을 AI에게 맡길 때 이 요소들을 프롬프트에 포함하면 좋습니다:

1. **데이터 출처**: 어떤 DB, API, 파일에서 가져올지
2. **필터 조건**: 어떤 기간, 어떤 집단을 포함/제외할지
3. **메타데이터 저장**: 출처, 시각, 행 수를 함께 기록하도록
4. **원본 보호**: 원본을 수정하지 않도록
5. **오류 처리**: 실패 시 어떻게 처리할지

## 운영 체크리스트
- [ ] 데이터 수집 시 원본 파일은 수정하지 않습니다
- [ ] 출처, 추출 시각, 행 수를 항상 메타데이터로 저장합니다
- [ ] raw/processed 디렉토리를 분리해서 관리합니다
- [ ] AI에게 수집 코드를 요청할 때 필터 조건을 구체적으로 명시합니다
- [ ] 민감 데이터는 마스킹 처리를 요청합니다

## 처음 질문으로 돌아가기

"AI에게 분석을 맡기기 전에 데이터 수집 단계가 왜 중요한가요?"

AI는 받은 데이터로만 분석합니다. 데이터가 어디서 왔는지, 어떤 기준으로 필터링됐는지 알 수 없으면 결과를 신뢰하기 어렵습니다. 또한 같은 분석을 나중에 다시 재현하려면 출처와 수집 조건이 기록되어 있어야 합니다. 재현 가능한 데이터 수집이 재현 가능한 분석의 기반입니다.

## 정리

데이터 수집은 단순히 AI에게 넘길 파일을 구하는 단계가 아닙니다. 나중에 같은 분석을 재현할 수 있도록 출처를 기록하는 단계입니다. 파일, API, DB, 로그 각 경로의 특성을 이해하고, 원본을 보호하고, 메타데이터를 저장하는 습관이 AI 기반 데이터 분석의 신뢰성을 만듭니다. 다음 글에서는 AI가 더러운 데이터로 분석하면 어떤 문제가 생기는지, 데이터 정제를 어떻게 AI에게 맡길지 다룹니다.
