# 바이브코딩을 위한 데이터 사이언스 기초 (9/10): AI가 준 결과를 비즈니스에 설명하려면

이 글은 바이브코딩을 위한 데이터 사이언스 기초 시리즈의 9번째 글입니다.

AI가 분석을 해줬습니다. 숫자도 나왔습니다. 이제 팀에 설명해야 합니다. 그런데 막상 발표 준비를 하다 보면 두 가지 함정 중 하나에 빠집니다. 첫 번째는 결과를 과장하는 것입니다. AI가 "전환율이 12% 상승했다"고 했는데, 그게 어떤 기간에 어떤 세그먼트에서 얼마나 확신할 수 있는 숫자인지 불분명한 채로 "우리 분석 결과 전환율 12% 상승 확인!"이라고 발표하는 경우입니다. 두 번째는 결과를 지나치게 약하게 말하는 것입니다. 불확실성이 있다는 이유로 "뭔가 좋아진 것 같긴 한데 확신하기 어렵습니다"라고만 말하면 아무 행동도 일어나지 않습니다.

좋은 결과 해석은 숫자를 더 크게 보이게 만드는 것이 아닙니다. 숫자와 함께 맥락, 불확실성, 행동 제안을 함께 보여주는 것입니다. AI는 숫자를 계산해줍니다. 신뢰구간을 계산해줍니다. 세그먼트별로 나눠줍니다. 하지만 "이 숫자가 의미 있는지, 우리가 무엇을 해야 하는지"는 사람이 판단해야 합니다.

바이브코딩에서 AI가 준 결과를 비즈니스에 설명할 때 이 구조를 쓰면 됩니다: 숫자 + 신뢰구간 + 대상 세그먼트 + 제한 사항 + 권장 행동. 이 다섯 가지가 한 단락 안에 있으면 설명이 과장도 아니고 지나치게 약하지도 않습니다.

> 좋은 결과 해석은 과장하지 않지만, 그래도 행동을 만들어냅니다.

---

## 이 글에서 다룰 문제
- AI가 준 숫자를 팀에 그대로 공유하면 왜 오해가 생길까요?
- 신뢰구간과 효과 크기는 왜 항상 함께 보고해야 할까요?
- "12% 상승"이라는 숫자를 어떻게 올바르게 해석할 수 있을까요?
- 결과를 과장하지 않으면서도 행동으로 연결하는 방법은 무엇인가요?
- AI가 선택적으로 좋은 결과만 보고했을 때 어떻게 확인하나요?

## 결과 해석 5단계 프레임

```text
1단계: 숫자를 정확히 적기
"전환율: 대조군 3.2% vs 실험군 3.6%, n=50,000"

2단계: 신뢰구간 함께 적기
"차이: +0.4pp (95% CI: +0.2pp ~ +0.6pp)"

3단계: 효과 크기 확인
"상대적 증가: +12.5%"

4단계: 맥락 추가하기
"기간: 2주, 대상: 유료 구독자, 디바이스: 데스크탑만"

5단계: 의사결정으로 닫기
"권장 행동: 유료 구독자 데스크탑 전체에 배포, 2주 후 모니터링"
```

## AI에게 결과 해석을 요청하는 방법

```python
# AI에게 해석을 포함한 결과 보고를 요청할 수 있습니다
"""
다음 A/B 테스트 결과를 5단계 해석 형식으로 정리해줘:
1. 정확한 수치와 표본 크기
2. 신뢰구간 (95%)
3. 효과 크기 (절대값과 상대값)
4. 분석의 제한 사항 (기간, 세그먼트, 환경)
5. 비즈니스 권장 행동
주의: 좋은 결과만 선택적으로 보고하지 말고 전체 결과를 보여줘
"""

import numpy as np
from scipy import stats

# A/B 테스트 결과 계산
control = {"conversions": 1600, "n": 50000}
variant = {"conversions": 1800, "n": 50000}

control_rate = control["conversions"] / control["n"]
variant_rate = variant["conversions"] / variant["n"]
diff = variant_rate - control_rate

# 신뢰구간 계산
se = np.sqrt(control_rate*(1-control_rate)/control["n"] + variant_rate*(1-variant_rate)/variant["n"])
ci_lower = diff - 1.96 * se
ci_upper = diff + 1.96 * se

print("=== A/B 테스트 결과 ===")
print(f"대조군 전환율: {control_rate:.2%}")
print(f"실험군 전환율: {variant_rate:.2%}")
print(f"차이: {diff:.4f} ({diff:.2%})")
print(f"95% CI: [{ci_lower:.4f}, {ci_upper:.4f}]")
print(f"상대적 증가: {diff/control_rate:.2%}")
print(f"\n제한 사항:")
print("- 데스크탑 사용자에게만 실험 진행")
print("- 분석 기간: 2주")
print(f"\n권장 행동:")
print("- 신뢰구간이 모두 양수 (+)이므로 효과 있음")
print("- 유료 구독자 데스크탑 전체에 배포 권장")
print("- 모바일 사용자 대상 별도 실험 필요")
```

## 결과를 Cherry-picking하지 않는 방법

AI에게 분석을 시키면 AI는 요청한 것만 분석합니다. 만약 "좋은 결과가 나온 세그먼트만 보여줘"라고 했다면 그게 Cherry-picking입니다. 비즈니스 설명 시 이를 방지하는 방법:

1. **사전에 분석 계획 고정**: "이 세그먼트들을 분석할 것"을 미리 정하기
2. **전체 결과 공개**: 좋지 않은 결과도 함께 보고
3. **반례 확인 요청**: AI에게 "이 해석이 틀릴 수 있는 경우를 찾아줘"라고 요청
4. **불확실성 명시**: "이 결과는 ±X% 범위의 불확실성이 있습니다"

## Before / After

**Before**: AI가 "전환율 12% 상승"이라는 결과를 줬습니다. 팀에 "우리 분석으로 전환율 12% 상승 확인!"이라고 발표했습니다. 나중에 확인해보니 신뢰구간이 -1% ~ +25%였고, 데스크탑 사용자에게만 해당되는 결과였습니다.

**After**: "전환율: 대조군 3.2% vs 실험군 3.6%, 95% CI +0.2~+0.6pp, 데스크탑 유료 구독자 n=50,000 기준, 2주 실험. 권장: 데스크탑 전체 배포, 모바일 별도 실험 필요"라고 발표했습니다. 팀이 결정을 바로 내릴 수 있었습니다.

## 바이브코딩할 때 자주 하는 실수
| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 신뢰구간 없이 숫자만 보고 | 불확실성을 숨김 | 항상 95% CI 포함 |
| 한 세그먼트를 전체로 일반화 | 과도한 일반화 | "X 세그먼트 기준" 명시 |
| 좋은 결과만 선택적 보고 | Cherry-picking | 전체 결과 공개 |
| 결정 제안 없이 숫자만 공유 | 팀이 행동하지 못함 | 5단계 해석 프레임 사용 |

## AI에게 데이터 분석 요청하는 팁

결과를 비즈니스에 설명할 때 AI에게 이 구조로 정리를 요청하면 좋습니다:

```
관찰: "[정확한 수치와 표본 크기]"
신뢰구간: "[95% CI 범위]"
효과 크기: "[절대값과 상대값]"
제한: "[기간, 세그먼트, 환경 등 한계]"
결정: "[권장 행동과 다음 검토 시점]"
```

이 구조로 AI에게 결과 정리를 요청하면 과장도 없고 지나치게 약하지도 않은 설명이 나옵니다.

## 운영 체크리스트
- [ ] 결과를 보고할 때 신뢰구간을 항상 포함합니다
- [ ] "X 기간, Y 세그먼트 기준"이라는 제한 조건을 명시합니다
- [ ] 좋지 않은 결과도 함께 공유합니다
- [ ] 숫자뿐만 아니라 권장 행동도 포함합니다
- [ ] 효과 크기(절대값과 상대값)를 모두 보고합니다
- [ ] 다음 검토 시점과 담당자를 지정합니다

## 처음 질문으로 돌아가기

"AI가 준 결과를 어떻게 비즈니스에 설명해야 하나요?"

숫자 + 신뢰구간 + 맥락 + 제한 사항 + 권장 행동. 이 다섯 가지를 한 단락에 담으면 됩니다. 과장하지 않지만 행동을 만들어내는 설명이 됩니다. AI에게 이 구조로 결과를 정리해달라고 요청하면 바로 비즈니스 설명에 쓸 수 있는 형태가 나옵니다.

## 정리

AI가 준 분석 결과를 비즈니스에 설명하는 것은 AI의 역할이 아닙니다. 사람이 해야 합니다. 숫자와 함께 신뢰구간, 분석 맥락, 제한 사항, 권장 행동을 함께 제시하면 팀이 과신하지도 않고 아무 행동도 안 하지도 않습니다. 다음 글에서는 AI와 함께 데이터 프로젝트를 처음부터 끝까지 완성하는 방법을 다룹니다.
