# 바이브코딩을 위한 데이터 사이언스 기초 (5/10): AI에게 EDA 시키기 전에 알아야 할 것

이 글은 바이브코딩을 위한 데이터 사이언스 기초 시리즈의 5번째 글입니다.

AI 코딩 도구에게 "이 데이터 EDA 해줘"라고 하면 즉시 수십 개의 차트와 통계가 나옵니다. 분포 히스토그램, 상관관계 히트맵, 결측치 현황, 기술 통계량. 보기엔 완벽해 보입니다. 그런데 이걸 팀에 공유했을 때 "그래서 이 데이터로 뭘 알 수 있어요?"라는 질문에 대답이 막히는 경우가 있습니다.

AI가 EDA 코드를 완벽하게 짜줬는데 왜 막힐까요? EDA는 코드의 문제가 아닙니다. AI가 낸 차트와 숫자를 사람이 해석하는 단계가 없었기 때문입니다. AI는 평균을 계산해줍니다. 하지만 "이 평균이 의미 있는 대표값인지, 아니면 이상치 때문에 왜곡된 것인지"는 사람이 판단해야 합니다.

EDA에서 가장 흔한 오해는 두 가지입니다. 첫째, 평균 하나로 데이터를 이해했다고 착각하는 것. 분포가 한쪽으로 치우쳐 있거나 이상치가 있으면 평균은 실제 전형값을 잘 설명하지 못합니다. 둘째, 상관관계를 인과로 읽는 것. AI가 상관관계 히트맵을 그려주면 높은 상관을 보인 두 변수가 원인-결과 관계처럼 보입니다. 하지만 상관은 인과를 의미하지 않습니다.

AI에게 EDA를 요청할 때 "분포를 그려줘"가 아니라 "분포를 그리고 이상치 여부와 치우침을 해석해줘"라고 요청하면 훨씬 유용한 결과를 얻을 수 있습니다. AI가 관찰을 행동 제안으로 연결하게 하는 것이 바이브코딩 EDA의 핵심입니다.

> AI EDA의 결과는 데이터를 이해하는 시작점이지, 분석의 끝이 아닙니다. 해석은 항상 사람이 해야 합니다.

## 이 글에서 다룰 문제
- AI가 EDA를 해줬는데 왜 팀에 설명하기가 어려울까요?
- 평균만 보면 왜 자주 오해가 생기나요?
- AI가 만든 상관관계 히트맵을 어떻게 해석해야 할까요?
- AI에게 EDA를 요청할 때 어떤 지시를 추가해야 할까요?
- EDA 결과를 다음 분석 행동으로 연결하는 방법은 무엇일까요?

## EDA에서 AI가 놓치기 쉬운 것들

AI는 데이터를 빠르게 요약합니다. 하지만 해석의 맥락은 AI가 자동으로 넣어주지 않습니다.

| AI가 잘 하는 것 | 사람이 확인해야 할 것 |
|---|---|
| 기술 통계량 계산 | 평균이 이상치로 왜곡됐는지 판단 |
| 상관관계 히트맵 생성 | 상관이 인과인지 확인 |
| 결측치 현황 출력 | 결측 패턴이 분석에 미치는 영향 판단 |
| 분포 히스토그램 | 치우침이 모델링에 어떤 의미인지 해석 |
| Cardinality 계산 | 인코딩 전략에 어떤 영향을 미치는지 판단 |

## AI에게 EDA를 더 잘 요청하는 방법

```python
# 단순 EDA 요청 (좋지 않음)
"""
이 데이터 EDA 해줘
"""

# 해석을 포함한 EDA 요청 (좋음)
"""
다음 EDA를 수행하고 각 결과에 대한 해석과 다음 분석 행동을 제안해줘:
1. amount 컬럼의 분포 - 치우침 여부와 이상치 비율 포함
2. 주요 수치형 변수 간 상관관계 - 높은 상관(>0.7)이 인과를 의미하는지 주의점 포함
3. 범주형 컬럼의 cardinality - 인코딩 전략 추천 포함
4. 결측치 패턴 - MCAR/MAR/MNAR 구분 시도
5. 각 관찰에 대해 "다음에 확인할 것" 형식으로 후속 분석 제안
"""

import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

df = pd.read_csv("orders.csv", parse_dates=["order_date"])

# 1. 분포 확인
print("=== amount 분포 ===")
print(df["amount"].describe())
print(f"왜도(skewness): {df['amount'].skew():.2f}")
print(f"이상치 비율 (IQR 기준): {((df['amount'] > df['amount'].quantile(0.75) + 1.5*(df['amount'].quantile(0.75)-df['amount'].quantile(0.25))).mean()):.2%}")

# 2. 상관관계
print("\n=== 상관관계 (주의: 인과가 아님) ===")
corr = df.select_dtypes("number").corr()
print(corr.round(2))

# 3. cardinality
print("\n=== 범주형 cardinality ===")
print(df.select_dtypes("object").nunique().sort_values(ascending=False))

# 4. 결측치
print("\n=== 결측치 비율 ===")
print(df.isna().mean().sort_values(ascending=False).head(10))
```

## 상관관계는 인과가 아니다

AI가 만든 상관관계 히트맵에서 높은 상관을 보이는 변수 쌍을 발견했을 때 자주 생기는 오해입니다. "A와 B의 상관이 0.85니까 A가 B를 일으키는 거겠지."

이건 잘못된 해석입니다. 예를 들어:
- 아이스크림 판매량과 익사 사고 수의 상관이 높지만, 아이스크림이 익사를 일으키는 게 아니라 둘 다 여름에 증가합니다 (공통 원인: 더운 날씨)
- 신발 크기와 읽기 능력의 상관이 높지만, 둘 다 나이와 관련이 있습니다

AI에게 "상관이 높은 변수 쌍을 찾아줘"라고 요청할 때 "인과 관계가 아닐 수 있는 이유도 함께 제시해줘"라고 추가하면 더 균형 잡힌 결과를 얻을 수 있습니다.

## Before / After

**Before**: AI에게 "EDA 해줘"라고 요청했더니 차트 20개가 나왔습니다. 팀 미팅에서 "이게 뭘 말하는 건가요?"라는 질문에 대답하지 못했습니다.

**After**: AI에게 "분포 확인, 상관관계, cardinality를 분석하고 각 결과에 대해 다음 분석 행동을 제안해줘"라고 요청했습니다. AI가 관찰-근거-다음 행동 형식으로 결과를 정리해주어서 팀에 바로 공유할 수 있었습니다.

## 바이브코딩할 때 자주 하는 실수
| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 평균만 보고 결론 내리기 | 이상치나 치우침을 놓침 | 중앙값, 분위수, 분포 형태 함께 확인 |
| 상관관계를 인과로 해석 | 잘못된 의사결정으로 이어짐 | "상관 ≠ 인과" 주의점을 AI에게도 요청 |
| EDA 결과를 팀에 그대로 공유 | 해석 없는 숫자와 차트만 남음 | 관찰-근거-다음 행동 형식으로 정리 |
| 전체 데이터를 한 번에 시각화 | 메모리 부족, 패턴 파악 어려움 | 샘플링(2000-5000행)해서 시각화 |

## AI에게 데이터 분석 요청하는 팁

EDA를 AI에게 요청할 때 관찰을 행동으로 연결하게 하는 것이 핵심입니다:

```
관찰: "모바일 채널의 주문 금액 중앙값이 웹 대비 낮습니다"
근거: "박스플롯 기준 중앙값 약 18% 차이"
가설: "모바일 결제 플로우의 이탈 가능성"
다음 행동: "모바일 체크아웃 단계 로그 추가 수집"
```

이 구조로 AI에게 EDA 결과를 작성해달라고 요청하면 단순 관찰이 분석 계획으로 이어집니다.

## 운영 체크리스트
- [ ] AI EDA 결과에서 평균이 이상치로 왜곡됐는지 확인합니다
- [ ] 상관관계가 높아도 인과로 해석하지 않습니다
- [ ] EDA 결과마다 "다음에 확인할 것"을 한 줄씩 작성합니다
- [ ] 시각화는 전체 데이터 대신 샘플링해서 진행합니다
- [ ] cardinality가 높은 컬럼은 인코딩 전략을 미리 검토합니다
- [ ] 결측 패턴이 분석에 어떤 편향을 만들지 검토합니다

## 처음 질문으로 돌아가기

"AI가 EDA를 완벽하게 해줬는데 왜 팀에 설명하기가 어려울까요?"

AI는 데이터를 빠르게 요약하는 코드를 씁니다. 하지만 해석은 코드가 아닌 사람의 영역입니다. 평균이 이상치로 왜곡됐는지, 상관이 인과인지, 결측 패턴이 분석에 어떤 영향을 미치는지는 사람이 판단해야 합니다. AI에게 해석까지 포함한 EDA를 요청하는 방법을 익히면 훨씬 유용한 결과를 얻을 수 있습니다.

## 정리

EDA는 AI가 대신 해주는 것이 아니라 AI와 함께 하는 것입니다. AI가 빠르게 계산하고, 사람이 해석하고, 다음 행동을 결정하는 구조가 바이브코딩 EDA의 올바른 흐름입니다. 다음 글에서는 AI가 만든 차트가 어떻게 오해를 만들 수 있는지, 시각화의 함정을 다룹니다.
