# 바이브코딩을 위한 데이터 사이언스 기초 (2/10): 비즈니스 질문을 데이터 질문으로 바꾸는 법

이 글은 바이브코딩을 위한 데이터 사이언스 기초 시리즈의 2번째 글입니다.

AI 코딩 도구로 데이터 분석을 하는 사람들이 가장 많이 경험하는 좌절이 있습니다. AI에게 "왜 매출이 떨어졌지?"라고 물었더니 코드는 멋지게 짜주는데, 결과를 보고 나서도 왜 매출이 떨어졌는지 여전히 모르는 상황입니다. AI가 잘못한 게 아닙니다. 질문 자체가 AI가 답할 수 있는 형태가 아니었던 것입니다.

바이브코딩에서 데이터 분석의 절반은 질문을 다시 쓰는 작업입니다. "왜 매출이 떨어졌지?"라는 질문은 무엇을 측정할지, 어느 기간을 비교할지, 누구를 대상으로 볼지가 빠져 있습니다. 이 상태로 AI에게 던지면 AI는 기술적으로 올바른 코드를 쓰지만 실제로 답하고 싶었던 질문과 다른 분석을 하게 됩니다.

AI에게 더 좋은 결과를 얻으려면 더 정확한 질문을 해야 합니다. "최근 30일 동안 체험판을 제외한 유료 구독자의 월 매출이 직전 30일보다 5% 이상 감소했는가?"라는 형태로 바꾸는 순간, AI가 어떤 데이터를 어떻게 분석해야 할지 즉시 명확해집니다. 그리고 나온 결과도 의사결정으로 바로 연결됩니다.

좋은 데이터 팀은 모호한 요청을 받으면 바로 AI에게 코드를 짜달라고 하지 않습니다. 먼저 질문을 다시 씁니다. 바이브코딩에서도 마찬가지입니다. AI 프롬프트를 잘 쓰는 사람은 코딩 명령보다 데이터 질문 작성에 더 많은 시간을 씁니다.

> 정확한 데이터 질문 한 줄이 AI와의 몇 번의 대화 왕복을 아껴 줍니다.

---

## 이 글에서 다룰 문제
- "왜 매출이 떨어졌지?" 같은 질문은 왜 AI도 바로 답하기 어려울까요?
- 지표, 기간, 대상 집단은 왜 데이터 질문의 핵심 요소일까요?
- AI가 제대로 분석할 수 있는 질문은 어떤 형태여야 할까요?
- 바이브코딩 환경에서 질문을 잘못 쓰면 어떤 일이 벌어질까요?
- 5단계 프레이밍으로 질문을 어떻게 바꿀 수 있을까요?

## 왜 AI가 막연한 질문에 엉뚱한 결과를 내는가

AI 코딩 도구는 코드 작성은 뛰어납니다. 하지만 질문이 흐릿하면 어떤 코드를 써야 할지 AI도 추측을 해야 합니다. 같은 "매출 분석"이라도 팀마다 다른 기간을 보고, 다른 집단을 보면 완전히 다른 결론이 나옵니다.

| 흐릿한 질문 | AI가 추측하는 것 | 실제 원하는 것 |
|---|---|---|
| "매출이 왜 떨어졌지?" | 전체 기간의 전체 사용자 매출 추세 | 특정 기간의 특정 세그먼트 매출 변화 |
| "이탈이 늘었나?" | 전체 사용자 이탈 통계 | 유료 구독자 중 특정 패턴의 이탈 |
| "캠페인 효과 있었나?" | 전후 비교만 | 통제군 대비 실험군 전환율 변화 |

질문을 정확히 쓰는 것만으로 AI와의 협업 효율이 크게 달라집니다.

## 5단계 프레이밍: AI가 바로 분석할 수 있는 질문 만들기

### 1단계 — 막연한 질문을 그대로 적기
```text
"매출이 떨어지는 것 같다"
```
이 상태에서 바로 AI에게 요청하지 않습니다. 먼저 무엇이 빠져 있는지 확인합니다.

### 2단계 — 지표 고르기
```text
측정 지표: 월간 매출 (monthly_revenue)
```
매출인지, 활성 사용자 수인지, 주문 건수인지에 따라 AI가 다른 코드를 씁니다.

### 3단계 — 기간 고르기
```text
비교 기간: 최근 30일 vs 직전 30일
```
어떤 기간을 비교할지 명시하지 않으면 AI가 임의로 선택합니다.

### 4단계 — 대상 집단 좁히기
```text
대상: 체험판 제외 유료 구독자
```
전체 사용자와 유료 구독자를 섞으면 중요한 패턴이 묻힙니다.

### 5단계 — 반증 가능한 문장으로 다시 쓰기
```text
"체험판을 제외한 유료 구독자의 월 매출이 최근 30일 동안 직전 30일 대비 5% 이상 감소했는가?"
```
이제 AI에게 줄 수 있는 질문이 됩니다. 맞는지 틀린지 확인 가능하고, 필요한 분석도 분명합니다.

## Before / After

**Before**: "매출이 왜 떨어졌는지 AI에게 물어봤는데 전체 기간 전체 사용자 추세 그래프만 나왔다. 팀원에게 공유했더니 '그래서?'라는 반응만 돌아왔다."

**After**: "지표(월 매출), 기간(최근 30일 vs 직전 30일), 대상(유료 구독자, 체험판 제외), 임계값(5% 감소)을 명시해서 요청했더니 AI가 바로 원인 세그먼트를 찾아줬다."

## 바이브코딩할 때 자주 하는 실수
| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| 질문 없이 데이터만 넘기기 | AI가 무엇을 분석해야 할지 추측 | 5단계 프레임으로 질문 먼저 작성 |
| 여러 질문을 한 번에 묻기 | 결과가 섞여서 원인 파악 불가 | 한 번에 하나의 질문만 |
| 기간을 명시하지 않기 | AI가 임의의 기간으로 분석 | 시작일, 종료일 또는 비교 기간 명시 |
| 반증 불가능한 가설 사용 | 결과를 어떻게 해석해야 할지 모름 | "X% 이상 감소"처럼 임계값 포함 |

## AI에게 데이터 분석 요청하는 팁

질문을 완성한 뒤 AI에게 넘길 때 이 형식을 쓰면 효과적입니다:

```
분석 목적: [비즈니스 결정을 위한 목적]
측정 지표: [구체적인 숫자 지표]
비교 기간: [기간 A] vs [기간 B]
대상 집단: [포함/제외 기준]
기대 결과: [어떤 형태의 결과물]
판단 기준: [임계값이나 비교 기준]
```

이 형식으로 요청하면 AI가 첫 번째 응답에서 바로 원하는 분석을 해줄 가능성이 크게 높아집니다.

## 운영 체크리스트
- [ ] AI에게 데이터 분석을 요청하기 전에 지표, 기간, 대상을 먼저 정합니다
- [ ] "왜?"라는 질문을 "X 기간 동안 Y 집단의 Z 지표가 얼마나 변했는가?"로 바꿉니다
- [ ] 임계값(5% 감소 등)을 포함해 반증 가능한 형태로 질문을 씁니다
- [ ] 하나의 분석 요청에는 하나의 질문만 담습니다
- [ ] AI 결과가 원래 질문에 답하고 있는지 검토합니다

## 처음 질문으로 돌아가기

"비즈니스 질문을 데이터 질문으로 바꾸는 게 왜 그렇게 중요한가요?"

AI는 질문이 명확할수록 더 좋은 결과를 냅니다. 지표, 기간, 대상 집단, 반증 가능한 임계값이 모두 들어간 질문은 AI가 첫 번째 시도에서 정확한 분석을 할 수 있게 합니다. 반면 흐릿한 질문은 여러 번의 수정 요청이 필요하고, 최종 결과도 의사결정으로 연결되기 어렵습니다.

## 정리

데이터 분석에서 질문을 잘 쓰는 것은 코드를 잘 쓰는 것만큼 중요합니다. 바이브코딩에서는 더욱 그렇습니다. AI에게 코드 작성을 맡기기 전에 5단계 프레이밍으로 질문을 완성하면, AI와의 협업 효율이 크게 올라갑니다. 다음 글에서는 이렇게 정의한 질문을 뒷받침할 데이터를 AI에게 모으게 하는 방법을 다룹니다.
