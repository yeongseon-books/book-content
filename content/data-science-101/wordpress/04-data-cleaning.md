# 바이브코딩을 위한 데이터 사이언스 기초 (4/10): AI가 더러운 데이터로 분석하면 결과도 더럽다

이 글은 바이브코딩을 위한 데이터 사이언스 기초 시리즈의 4번째 글입니다.

AI 코딩 도구를 쓰다 보면 이런 유혹이 생깁니다. "그냥 CSV 파일을 던져줘도 AI가 알아서 처리하겠지." 어느 정도는 맞습니다. AI는 결측치가 있는 데이터도 코드를 써줍니다. 문제는 AI가 결측치를 "어떻게 처리했는지"를 사람이 확인하지 않는 경우입니다. AI가 결측치를 자동으로 0으로 채우거나 해당 행을 조용히 삭제했을 때, 분석 결과가 달라지는 걸 모를 수 있습니다.

더러운 데이터로 AI에게 분석을 시키면 더러운 결과가 나옵니다. 이건 AI의 잘못이 아니라 입력의 문제입니다. 결측치가 많은 중요한 컬럼을 AI가 자동으로 평균값으로 채웠다면, 그 이후의 모든 분석과 모델은 왜곡된 기반 위에 서게 됩니다.

바이브코딩에서 데이터 정제를 AI에게 맡길 때 가장 중요한 것은 AI가 내린 결정을 확인하는 것입니다. 결측치를 어떻게 처리했는지, 이상치를 삭제했는지 표시만 했는지, 타입 변환에서 실패한 값이 몇 개인지를 AI가 리포트 형태로 보고하게 하면 됩니다. AI에게 "정제해줘"만 요청하지 말고 "정제 과정과 결과를 리포트로 알려줘"라고 요청하는 것이 핵심입니다.

정제는 지루하게 보이지만 이후의 모든 분석, 시각화, 모델링의 신뢰도를 결정합니다. AI가 아무리 정교한 분석을 해도 입력 데이터가 오염되어 있으면 결과도 오염됩니다.

> AI에게 데이터 정제를 맡길 때는 "어떻게 처리했는지"를 반드시 리포트로 받아야 합니다.

## 이 글에서 다룰 문제
- AI에게 더러운 데이터를 넘기면 어떤 일이 벌어질까요?
- 결측치, 중복, 이상치, 타입 불일치를 AI에게 어떻게 처리시켜야 할까요?
- AI가 결측치를 "자동으로" 처리했을 때 왜 위험할까요?
- 정제 과정을 AI에게 기록하게 하는 방법은 무엇일까요?
- AI가 만든 정제 코드가 맞는지 어떻게 검증할까요?

## 네 가지 데이터 품질 문제와 AI 요청 방법

| 품질 문제 | 증상 | AI에게 요청할 때 주의점 |
|---|---|---|
| 결측치 (Missing) | NaN, None, 빈 문자열 | "결측을 어떻게 처리했는지 비율과 함께 리포트해줘" |
| 중복 (Duplicate) | 같은 사용자가 여러 번 | "중복을 왜 제거했는지 이유도 함께 기록해줘" |
| 이상치 (Outlier) | 분포에서 극단적으로 벗어난 값 | "이상치를 삭제하지 말고 먼저 표시(flag)만 해줘" |
| 타입 불일치 (Type mismatch) | 날짜가 문자열로 저장 | "변환 실패한 값의 개수와 위치를 알려줘" |

## AI에게 정제를 맡길 때 좋은 프롬프트 형태

```python
# AI에게 이런 형태로 요청할 수 있습니다
"""
다음 데이터 정제를 수행하고 각 단계의 결과를 리포트해줘:
1. signup_at, amount 컬럼 타입 변환 (변환 실패 개수 포함)
2. user_id 기준 중복 제거 (제거된 행 수 포함)
3. user_id, signup_at가 결측인 행 제거, country는 'UNKNOWN'으로 채우기
4. amount의 이상치를 IQR 방법으로 표시만 하기 (삭제 금지)
5. 정제 전후 행 수, 컬럼별 결측 비율, 이상치 비율을 dict로 출력
"""

import pandas as pd

def clean_users(df: pd.DataFrame) -> tuple[pd.DataFrame, dict]:
    out = df.copy()

    # 1. 타입 변환
    out["signup_at"] = pd.to_datetime(out["signup_at"], errors="coerce")
    out["amount"] = pd.to_numeric(out["amount"], errors="coerce")
    type_fail = out[["signup_at", "amount"]].isna().sum().to_dict()

    # 2. 중복 제거
    before = len(out)
    out = out.drop_duplicates(subset=["user_id"], keep="last")
    dropped_dups = before - len(out)

    # 3. 결측 처리
    out = out.dropna(subset=["user_id", "signup_at"])
    out["country"] = out["country"].fillna("UNKNOWN")

    # 4. 이상치 표시 (삭제 안 함)
    q1, q3 = out["amount"].quantile([0.25, 0.75])
    iqr = q3 - q1
    out["amount_outlier"] = ~out["amount"].between(q1 - 1.5*iqr, q3 + 1.5*iqr)

    # 5. 정제 리포트
    report = {
        "raw_rows": len(df),
        "clean_rows": len(out),
        "dropped_duplicates": dropped_dups,
        "type_conversion_fails": type_fail,
        "null_rate": out.isna().mean().to_dict(),
        "outlier_rate": float(out["amount_outlier"].mean()),
    }
    return out, report
```

## 이상치를 바로 삭제하면 안 되는 이유

바이브코딩에서 자주 발생하는 패턴은 AI에게 "이상치 제거해줘"라고 요청하는 것입니다. AI는 즉시 이상치를 삭제한 코드를 씁니다. 하지만 이상치가 실제로 중요한 신호일 수 있습니다:

- 매출 이상치 → VIP 고객 또는 비정상 거래
- 로그인 횟수 이상치 → 봇 계정 또는 매우 활성화된 사용자
- 날짜 이상치 → 데이터 수집 오류

AI에게는 "이상치를 IQR 방법으로 표시(flag)만 해줘, 삭제는 내가 판단할게"라고 요청하는 것이 좋습니다.

## Before / After

**Before**: AI에게 "데이터 정제해줘"라고 요청했더니 결측치를 0으로 채우고 이상치를 자동으로 삭제했습니다. 나중에 매출 평균이 이상하게 낮아진 원인을 분석해보니 AI가 중요한 VIP 거래를 이상치로 삭제했다는 것을 알았습니다.

**After**: AI에게 "결측치 처리 전략과 이상치 표시 방법을 리포트해줘"라고 요청했습니다. AI가 결측 비율, 처리 방식, 이상치 개수를 상세히 보고해주어서 내가 최종 결정을 내릴 수 있었습니다.

## 바이브코딩할 때 자주 하는 실수
| 실수 | 왜 문제인가 | 해결 |
|---|---|---|
| "정제해줘"만 요청 | AI가 내린 결정을 모르게 됨 | 정제 리포트를 함께 요청 |
| 이상치 즉시 삭제 요청 | 중요한 신호를 잃을 수 있음 | 먼저 표시(flag)하고 검토 |
| 결측치를 무조건 0으로 채우기 | 평균, 분포 왜곡 | 결측 비율 확인 후 전략 결정 |
| 원본 데이터에 직접 정제 적용 | 되돌릴 방법 없음 | 복사본에서 작업하도록 요청 |

## AI에게 데이터 분석 요청하는 팁

AI에게 데이터 정제를 요청할 때 이 요소들을 포함하면 좋습니다:

1. **각 처리 단계의 결과 수치**: "제거된 행 수, 채워진 결측 수 포함"
2. **이상치는 표시만**: "삭제하지 말고 outlier 컬럼으로 표시"
3. **원본 보호**: "df.copy()로 복사본에서 작업"
4. **정제 리포트**: "전후 행 수, 결측 비율, 이상치 비율을 dict로 출력"
5. **재사용 가능한 함수**: "나중에 같은 데이터에 다시 적용할 수 있도록 함수로 작성"

## 운영 체크리스트
- [ ] AI에게 정제를 요청할 때 정제 리포트를 함께 요청합니다
- [ ] 이상치는 즉시 삭제하지 않고 표시(flag)만 먼저 합니다
- [ ] 결측치 처리 전 비율을 확인하고 전략을 결정합니다
- [ ] 정제 코드는 원본 데이터의 복사본에서 실행됩니다
- [ ] 정제 전후 행 수 변화를 항상 확인합니다
- [ ] 정제 과정을 함수로 만들어 재현 가능하게 합니다

## 처음 질문으로 돌아가기

"AI가 더러운 데이터로 분석하면 정말 결과도 더러워지나요?"

예. AI는 받은 데이터를 그대로 사용합니다. 결측치를 처리하지 않으면 AI가 임의로 결정을 내립니다. 이상치를 자동으로 삭제하면 중요한 패턴을 잃을 수 있습니다. 타입이 맞지 않으면 AI가 오류를 내거나 엉뚱한 계산을 할 수 있습니다. AI에게 데이터 정제를 맡길 때는 "어떻게 처리했는지"를 항상 확인해야 합니다.

## 정리

데이터 정제는 AI에게 넘기기 전에 해야 할 지루한 사전 작업이 아닙니다. AI가 어떤 결정을 내렸는지 확인하고, 이상치는 즉시 삭제하지 않고 표시만 하고, 결측치 처리 전략을 명시하는 과정입니다. AI에게 정제 리포트를 요청하는 습관 하나가 이후 모든 분석의 신뢰도를 높입니다. 다음 글에서는 AI에게 EDA(탐색적 데이터 분석)를 시키기 전에 알아야 할 것들을 다룹니다.
