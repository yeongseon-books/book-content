# 바이브코딩을 위한 LLM 파인튜닝 (1/6): LLM 파인튜닝 입문

이 글은 바이브코딩을 위한 LLM 파인튜닝 시리즈의 1번째 글입니다.

바이브코딩 시대에 LLM 파인튜닝을 이해하는 것은 AI와 더 효과적으로 협업하는 기반이 됩니다. 파인튜닝은 단순히 모델을 한 번 더 학습시키는 작업처럼 보이지만, 실제 출발점은 무엇을 바꾸고 무엇을 그대로 둘지 정하는 일입니다. 이 결정을 세 가지 변수로 나눠 보고, 이후 글들을 흔들리지 않게 받쳐 줄 계산 감각을 먼저 맞추겠습니다.

처음부터 큰 모델과 GPU 실험으로 들어가면 학습률, 데이터셋 형식, 어댑터 랭크가 한꺼번에 흔들립니다. 1편의 목적은 모델 실행을 잠시 미루고, 왜 LoRA가 싸고 빠른지, 언제 이 선택이 합리적인지를 숫자로 먼저 이해하는 데 있습니다.

> 파인튜닝은 학습 문제이기 전에 결정 문제입니다 — 무엇을 바꾸고 무엇을 고정할지, 그 선택이 어떻게 얽히는지를 먼저 정해야 학습률·데이터 형식·어댑터 rank가 동시에 흔들리지 않습니다.

---

## 이 글에서 다룰 문제

- LoRA가 풀 파인튜닝보다 훨씬 가벼운 이유를 어떻게 계산할 수 있을까요?
- 프롬프트로 해결할 수 있는 문제와 파인튜닝이 필요한 문제를 어떻게 구분할 수 있을까요?
- GPU 없이도 1편에서 무엇을 검증할 수 있을까요?
- 자주 하는 실수와 그 해결책은 무엇일까요?
- 이 개념을 실무에 적용하는 방법은 무엇일까요?

LLM 파인튜닝은 반드시 GPU 실습부터 시작해야 하는 주제가 아닙니다. 오히려 먼저 필요한 것은 산술 감각입니다. LoRA가 실제로 얼마나 적은 파라미터만 학습하는지, 그 비율이 왜 데이터셋 규모와 학습 시간 추정에까지 연결되는지 이해해야 이후 글들이 한 덩어리로 보입니다.

## Before / After

**Before — AI에게 컨텍스트 없이 질문:**

```
Q: "LoRA로 모델 파인튜닝하는 코드 만들어줘"
→ 막연한 요청으로 범용적인 답변 수령
→ rank, target_modules 의미를 몰라 설정을 그대로 복사
```

**After — 개념을 이해하고 구체적으로 질문:**

```
Q: "GPT-2 small 구조에서 LoRA r=8로 학습 가능한 파라미터 비율을
    계산하고, 풀 파인튜닝 대비 VRAM 절감 효과를 보여줘"
→ 수치 기반 설계 결정 가능
→ rank, alpha, target_modules 선택의 근거를 이해하고 조정 가능
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 모델 크기와 학습 파라미터 수를 혼동 | LoRA를 써도 추론 시 베이스 모델이 VRAM에 올라감 | 학습 파라미터와 추론 메모리를 분리해서 생각 |
| 랭크가 클수록 무조건 좋다고 생각 | r=64 이상은 과적합 위험, 일반화 나빠짐 | r=8~16에서 시작 |
| 모든 선형 레이어에 LoRA를 붙임 | 학습 파라미터가 두세 배로 늘어남 | q_proj, v_proj만으로 시작 |
| 나쁜 데이터를 LoRA가 구해줄 것으로 기대 | 작은 어댑터도 잘못된 라벨에 과적합 | 데이터 품질 먼저 점검 |
| 베이스와 어댑터의 토크나이저를 섞음 | 토큰 정렬이 어긋나 결과가 망가짐 | 어댑터와 베이스는 한 쌍으로 관리 |

## AI 협업 팁

LLM 파인튜닝 관련 효과적인 AI 프롬프트 패턴:

1. **파라미터 수 계산 요청**: "hidden_size=768, num_layers=12 구조에서 LoRA r=8의 학습 파라미터 비율을 계산해줘"
2. **비교 요청**: "풀 파인튜닝, LoRA, QLoRA의 VRAM 사용량을 7B 모델 기준으로 비교해줘"
3. **의사결정 요청**: "응답 톤만 바꾸려면 LoRA와 RAG 중 무엇이 적합한지 이유와 함께 알려줘"

예시 프롬프트:
> "GPT-2 small 구조 기준으로 LoRA r=8을 적용했을 때 학습 가능한 파라미터 수와 비율을 계산해줘. 풀 파인튜닝과 비교하고 VRAM 차이도 보여줘."

## 운영 체크리스트

- [ ] 랭크가 커질수록 학습 파라미터가 선형으로 증가한다는 점을 이해했는가?
- [ ] 풀 파인튜닝, LoRA, RAG를 각각 언제 써야 하는지 한 문장으로 설명할 수 있는가?

## 처음 질문으로 돌아가기

LLM 파인튜닝을 배운 지금, AI에게 이 주제로 더 정확한 질문을 할 수 있게 되었습니다. LoRA가 왜 가볍고 언제 선택해야 하는지를 숫자로 이해한 사람과 그렇지 않은 사람이 AI에게 받는 답변의 품질은 크게 다릅니다. 더 나은 질문이 더 나은 코드를 만듭니다.

## 정리

LLM 파인튜닝 입문은 바이브코딩을 위한 LLM 파인튜닝의 핵심 주제 중 하나입니다. LoRA가 풀 파인튜닝보다 가벼운 이유를 파라미터 계산으로 확인하고, 풀 파인튜닝·LoRA·RAG를 각각 언제 써야 하는지 판단 기준을 잡았습니다. 다음 글에서는 데이터셋 준비와 전처리를 다룹니다.
