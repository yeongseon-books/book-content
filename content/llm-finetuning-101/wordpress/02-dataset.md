# 바이브코딩을 위한 LLM 파인튜닝 (2/6): 데이터셋 준비와 전처리

이 글은 바이브코딩을 위한 LLM 파인튜닝 시리즈의 2번째 글입니다.

파인튜닝 데이터셋은 대개 크기보다 모양 때문에 더 자주 실패합니다. 원본 샘플, 템플릿이 적용된 텍스트, 토큰화된 텐서라는 세 층으로 문제를 나눠서, 학습 전에 무엇을 확인해야 하는지 정리합니다. 같은 1,000개 샘플이어도 형식이 일관되면 LoRA r=8로 충분할 수 있고, 형식이 섞이면 더 큰 랭크와 더 많은 데이터로도 수렴이 흔들릴 수 있습니다.

바이브코딩에서 이 개념이 중요한 이유는 단순합니다. AI에게 데이터 전처리를 요청할 때 세 층(원본·템플릿·텐서)을 명시하지 않으면, 생성된 코드가 어느 층에 문제가 생겼는지 진단하기 어려워집니다.

> 데이터셋 작업은 크기가 아니라 모양에서 무너집니다 — 원본 샘플·템플릿 텍스트·토큰 텐서의 세 층으로 나눠 각 층을 검증해야, 학습 중 손실 곡선이 거짓말할 여지를 줄일 수 있습니다.

---

## 이 글에서 다룰 문제

- instruction / input / output 세 필드를 어떤 형태로 잡아야 할까요?
- Hugging Face datasets로 작은 JSONL 파일을 어떻게 바로 읽을 수 있을까요?
- 전처리 단계에서 반드시 확인해야 할 최소 검증 포인트는 무엇일까요?
- 자주 하는 실수와 그 해결책은 무엇일까요?
- 이 개념을 실무에 적용하는 방법은 무엇일까요?

데이터셋 단계에서 가장 중요한 것은 양이 아니라 형식 일관성입니다. 이것이 바이브코딩 시대에 데이터 전처리 개념을 배우는 이유입니다.

## Before / After

**Before — AI에게 컨텍스트 없이 질문:**

```
Q: "파인튜닝 데이터셋 전처리 코드 만들어줘"
→ 어떤 형식인지, 어느 층을 처리하는지 불명확
→ labels 마스킹이 빠져 학습 품질 저하
```

**After — 개념을 이해하고 구체적으로 질문:**

```
Q: "instruction/input/output JSONL 파일을 읽어
    Alpaca 템플릿으로 변환하고, 응답 구간에만
    손실이 걸리도록 labels를 -100으로 마스킹해줘"
→ 세 층 모두를 명확히 처리
→ EOS 토큰 추가, pad_token 설정까지 포함
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 데이터가 많을수록 무조건 좋다고 생각 | 중복과 형식 혼합이 수렴을 방해 | 500개 일관된 샘플이 5000개 잡음보다 나음 |
| labels를 학습 전에 꼭 만들어야 한다고 생각 | 데이터 콜레이터가 자동 처리 가능 | 4편 콜레이터 패턴 활용 |
| EOS를 빼먹음 | 모델이 멈추는 법을 배우지 못해 무한 생성 | 응답 뒤에 `<eos>` 명시적 추가 |
| max_length를 지나치게 짧게 잡음 | 64토큰 학습 후 256토큰 답변 기대 불가 | 데이터 길이의 p95를 보고 결정 |
| train/eval 분할 생략 | 같은 데이터를 평가에 다시 쓰면 의미 없는 점수 | 최소 90/10 분할 유지 |

## AI 협업 팁

데이터셋 준비 관련 효과적인 AI 프롬프트 패턴:

1. **형식 변환 요청**: "instruction/input/output JSONL을 Alpaca 템플릿으로 변환하는 함수 작성해줘"
2. **검증 요청**: "JSONL 파일에서 필수 필드 누락, 빈 output, 길이 초과 샘플을 찾는 검증 함수 만들어줘"
3. **통계 요청**: "토큰화 후 길이 분포(min, mean, p95, max)를 출력해줘"

예시 프롬프트:
> "JSONL 형식의 instruction 데이터셋을 읽어 Alpaca 템플릿으로 변환하고, 응답 구간 labels를 -100으로 마스킹하는 전처리 파이프라인을 작성해줘. pad_token 설정과 EOS 처리도 포함해줘."

## 운영 체크리스트

- [ ] JSONL 원본 샘플이 instruction / input / output 구조를 따르는가?
- [ ] datasets.load_dataset()으로 실제 파일을 읽어봤는가?
- [ ] 토큰화 후 컬럼과 길이를 확인했는가?
- [ ] pad_token이 설정되어 있고, 응답 뒤에 EOS가 붙는가?
- [ ] train/eval 분할이 준비되어 있는가?

## 처음 질문으로 돌아가기

데이터셋 준비와 전처리를 배운 지금, AI에게 이 주제로 더 정확한 질문을 할 수 있게 되었습니다. 형식 일관성이 학습 품질을 결정한다는 것을 이해한 사람과 그렇지 않은 사람이 AI에게 받는 답변의 품질은 크게 다릅니다.

## 정리

데이터셋 준비는 바이브코딩을 위한 LLM 파인튜닝의 핵심 주제 중 하나입니다. 세 층(원본·템플릿·텐서)을 분리해 각각 검증하면 학습 실패의 원인을 빠르게 찾을 수 있습니다. 다음 글에서는 LoRA 어댑터 구성을 다룹니다.
