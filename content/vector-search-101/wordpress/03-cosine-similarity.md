# 바이브코딩을 위한 벡터 검색 (3/6): 코사인 유사도와 벡터 검색

이 글은 바이브코딩을 위한 벡터 검색 시리즈의 3번째 글입니다.

벡터를 만들었다면 다음 질문은 그것들을 어떻게 비교할지입니다. 거리 척도는 여러 가지가 있고 어떤 척도를 선택하느냐에 따라 검색 결과도 달라집니다. 코사인 유사도는 가장 흔히 사용되지만 내적과 유클리드 거리가 더 적합한 경우도 있습니다. 더 중요한 것은 FAISS 인덱스 유형이 거리 척도와 연결된다는 점입니다. IndexFlatL2는 유클리드 거리, IndexFlatIP는 내적을 사용합니다. 정규화된 벡터에서는 내적이 코사인 유사도와 같아집니다. 이 연결 관계를 모르면 코드가 동작해도 잘못된 순위를 반환합니다.

바이브코딩에서 이 개념이 중요한 이유는 단순합니다. AI에게 유사도 검색 코드를 요청할 때 거리 척도와 정규화 여부를 명시하지 않으면, 의도와 다른 인덱스 타입이 선택되어 검색 순위가 잘못될 수 있기 때문입니다.

> 벡터 검색에서 유사도 함수는 단순한 수학 공식이 아니라, 무엇을 비슷하다고 볼지 정하는 검색 정책입니다.

---

## 이 글에서 다룰 문제

- 벡터가 있으면 왜 바로 검색이 끝나는 게 아니라 거리 척도를 골라야 할까요?
- 코사인 유사도와 내적, L2 거리는 결과를 어떻게 다르게 만들까요?
- 정규화 여부가 검색 순위와 FAISS 인덱스 선택에 왜 영향을 줄까요?
- 자주 하는 실수와 그 해결책은 무엇일까요?
- 이 개념을 실무에 적용하는 방법은 무엇일까요?

거리 척도를 이해하면 AI에게 "정규화된 벡터와 IndexFlatIP로 코사인 유사도 검색을 구현하고 L2 검색과 순위를 비교하는 코드"를 정확하게 요청할 수 있습니다. 이것이 바이브코딩 시대에 이 개념을 배우는 이유입니다.

## Before / After

**Before — AI에게 컨텍스트 없이 질문:**

```
Q: "FAISS로 유사 문서를 검색하는 코드 작성해줘"
→ IndexFlatL2 기본 사용 (L2 거리)
→ 정규화 여부 명시 없음
→ 코사인 유사도와 다른 결과 가능
```

**After — 개념을 이해하고 구체적으로 질문:**

```
Q: "코사인 유사도 검색을 구현해줘.
    faiss.normalize_L2(vectors)로 정규화 후
    IndexFlatIP에 저장해줘.
    정규화하지 않은 IndexFlatL2 결과와 top-3 순위를 비교해줘"
→ 의도한 거리 척도 보장
→ 정규화 효과 가시화
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| L2와 코사인을 같다고 가정 | 정규화 안 된 벡터에서 순위 다름 | 코사인 원할 때 normalize 후 IndexFlatIP |
| 정규화 없이 IndexFlatIP 사용 | 벡터 크기 차이가 내적 결과에 영향 | `faiss.normalize_L2(vectors)` 먼저 |
| 척도를 중간에 변경 | 기존 저장 인덱스와 새 쿼리 불일치 | 인덱스 타입과 정규화를 파일명에 기록 |
| 유사도 점수 범위 오해 | L2는 작을수록 유사, IP는 클수록 유사 | 척도별 해석 방향을 코드 주석에 명시 |
| 단일 척도만 실험 | 도메인에 따라 최적 척도 다름 | 두 척도를 같은 데이터로 비교 실험 |

## AI 협업 팁

거리 척도와 벡터 검색 관련 효과적인 AI 프롬프트 패턴:

1. **코사인 유사도 구현 요청**: "numpy로 코사인 유사도를 계산하는 함수와 FAISS normalize+IndexFlatIP 버전을 둘 다 구현하고 결과를 비교하는 코드 작성해줘"
2. **척도 비교 실험 요청**: "같은 쿼리로 IndexFlatL2와 IndexFlatIP(정규화 후) 검색 결과 top-5를 나란히 출력하고 순위 차이를 분석하는 코드 작성해줘"
3. **정규화 효과 검증 요청**: "정규화 전후 벡터의 L2 norm 분포를 히스토그램으로 비교하는 코드 작성해줘"

예시 프롬프트:
> "10개 문서 벡터로 세 가지 유사도 검색을 구현해줘. 1) numpy 코사인 유사도, 2) FAISS IndexFlatL2, 3) FAISS normalize+IndexFlatIP. 같은 쿼리에 대한 top-3 결과를 나란히 출력해 순위 차이를 비교."

## 정리

코사인 유사도와 거리 척도는 바이브코딩을 위한 벡터 검색에서 검색 정책을 결정하는 핵심 선택입니다. L2와 내적의 차이, 정규화가 코사인 유사도로 연결되는 원리를 이해했습니다. 다음 글에서는 대규모 벡터 검색을 위한 FAISS 인덱스 구조를 다룹니다.
