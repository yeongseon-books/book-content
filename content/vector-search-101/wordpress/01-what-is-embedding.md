# 바이브코딩을 위한 벡터 검색 (1/6): 임베딩이란 무엇인가

이 글은 바이브코딩을 위한 벡터 검색 시리즈의 1번째 글입니다.

"Python async programming"과 "handling concurrency in Python"은 같은 뜻이지만 키워드 기반 검색만으로는 두 문장을 연결하기 어렵습니다. 키워드 검색은 표현이 달라지는 순간 결과를 놓칩니다. 반대로 "데이터베이스"를 검색했는데 "DB"나 "데이터 저장소"가 포함된 문서를 찾지 못하는 것도 같은 이유입니다. 임베딩은 이 문제를 다른 방식으로 풉니다. 텍스트를 숫자 벡터로 바꿔서 의미가 비슷한 문장이 고차원 공간에서 가깝게 놓이도록 만듭니다. 벡터 사이의 거리가 의미의 차이를 나타냅니다.

바이브코딩에서 이 개념이 중요한 이유는 단순합니다. AI에게 검색 기능 코드를 요청할 때 임베딩 기반 의미 검색을 원하는지 키워드 검색을 원하는지 명시하지 않으면, 요구 사항과 다른 방식의 검색 코드가 생성되기 때문입니다.

> 임베딩은 텍스트를 저장하는 형식이 아니라, 의미를 거리로 비교할 수 있게 만드는 표현 방식입니다.

---

## 이 글에서 다룰 문제

- 키워드가 같은데도 검색 결과가 빗나가거나, 표현만 달라서 결과를 놓칠 때 무엇이 부족한 걸까요?
- 임베딩 벡터의 "가깝다"는 말은 실제로 무엇을 비교한다는 뜻일까요?
- 첫 모델을 고를 때 차원 수, 언어, 토큰 한도 중 무엇을 먼저 확인해야 할까요?
- 자주 하는 실수와 그 해결책은 무엇일까요?
- 이 개념을 실무에 적용하는 방법은 무엇일까요?

임베딩의 원리를 이해하면 AI에게 "sentence-transformers로 텍스트를 임베딩하고 코사인 유사도로 의미 기반 검색을 구현하는 코드"를 정확하게 요청할 수 있습니다. 이것이 바이브코딩 시대에 이 개념을 배우는 이유입니다.

## Before / After

**Before — AI에게 컨텍스트 없이 질문:**

```
Q: "문서 검색 기능 구현해줘"
→ 키워드 매칭 기반 구현
→ 동의어나 표현 변형 검색 불가
→ 의미 유사도 없음
```

**After — 개념을 이해하고 구체적으로 질문:**

```
Q: "sentence-transformers의 all-MiniLM-L6-v2로
    문서 리스트를 임베딩하고
    코사인 유사도로 쿼리와 가장 유사한 문서 top-3를 찾는 코드 작성해줘.
    같은 의미의 다른 표현도 검색되는지 확인해줘"
→ 표현이 달라도 의미 기반으로 검색
→ 유사도 점수와 함께 결과 반환
```

## 바이브코딩할 때 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 |
|------|------------|------|
| 문서와 쿼리에 다른 모델 사용 | 다른 벡터 공간, 거리 비교 무의미 | 반드시 동일한 모델 인스턴스 사용 |
| 차원 수 확인 없이 벡터 연결 | shape 불일치로 연산 오류 | `embedding.shape`으로 먼저 확인 |
| 한국어 문서에 영어 전용 모델 사용 | 한국어 의미 포착 실패 | 다국어 또는 한국어 전용 모델 선택 |
| 토큰 한도 초과 확인 없음 | 긴 문서는 잘려서 임베딩됨 | 모델 max_seq_length 확인 후 청킹 |
| 정규화 없이 코사인 유사도 계산 | 크기 차이가 결과에 영향 | normalize_embeddings=True 설정 |

## AI 협업 팁

임베딩과 의미 검색 관련 효과적인 AI 프롬프트 패턴:

1. **임베딩 기초 요청**: "sentence-transformers로 5개 문장을 임베딩하고 numpy로 벡터 shape과 첫 5개 값을 출력하는 코드 작성해줘"
2. **유사도 비교 요청**: "두 문장의 코사인 유사도를 numpy로 계산하고 0~1 사이 점수로 출력하는 함수 작성해줘"
3. **모델 비교 요청**: "all-MiniLM-L6-v2와 multilingual-e5-small로 같은 한국어 문장을 임베딩하고 코사인 유사도를 비교하는 코드 작성해줘"

예시 프롬프트:
> "sentence-transformers의 all-MiniLM-L6-v2로 10개 문서를 임베딩해줘. 쿼리 문장과 코사인 유사도를 계산하고 top-3를 점수와 함께 출력해줘. '동시성'과 'concurrency'가 유사하게 검색되는지 확인해줘."

## 정리

임베딩은 바이브코딩을 위한 벡터 검색의 출발점입니다. 텍스트를 벡터로 변환해 의미 거리를 계산하는 원리, 모델 선택 기준(차원, 언어, 토큰 한도)을 이해했습니다. 다음 글에서는 HuggingFace 임베딩을 실제로 만들고 저장하고 재사용하는 실습을 다룹니다.
