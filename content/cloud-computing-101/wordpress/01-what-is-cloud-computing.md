# 바이브코딩을 위한 클라우드 컴퓨팅 기초 (1/10): Cloud Computing이란 무엇인가?

이 글은 **바이브코딩을 위한 클라우드 컴퓨팅 기초** 시리즈의 1편입니다. AI가 만든 앱을 실제로 클라우드에 올리려면 클라우드가 어떻게 동작하는지 알아야 합니다. 10편에 걸쳐 클라우드의 핵심 개념을 바이브코딩 관점에서 정리합니다.

---

바이브코딩으로 AI 앱을 뚝딱 만들었는데, 이제 어디에 올려야 할까요? "그냥 클라우드에 올리면 되지 않나요?"라고 생각했다가 첫 청구서를 보고 당황한 경험, 한 번쯤 있을 겁니다. 클라우드는 편리하지만, 어떻게 작동하는지 모르면 속도만 빠르고 비용은 통제 불능이 됩니다.

클라우드를 "남의 서버를 빌려 쓰는 것"으로만 이해하면 절반만 맞습니다. 더 중요한 점은 자원을 필요할 때 만들고, 사용한 만큼 비용을 내며, 공급자와 사용자가 책임을 나눠 갖는 방식이라는 사실입니다. 이 구조를 이해하면 AI 앱을 배포할 때 "어디에, 어떻게, 얼마나"를 제대로 결정할 수 있습니다.

> "클라우드의 핵심은 기술 이름이 아니라, 초기 투자 없이 필요에 따라 자원을 프로비저닝하고, 사용한 만큼 비용을 내며, 공급자와 사용자가 운영 책임을 명확히 나누는 실행 모델에 있습니다."

- NIST가 정의한 클라우드의 다섯 가지 필수 특성은 무엇인가요?

## 바이브코딩과 클라우드: 왜 지금 클라우드를 배워야 하나요?

바이브코딩으로 AI 앱을 만드는 속도는 빨라졌습니다. 문제는 그 앱을 어디에 올리느냐입니다. 로컬에서만 돌리면 혼자만 쓸 수 있고, 실제 사용자에게 서비스하려면 클라우드가 필요합니다.

**AI 앱을 클라우드에 올릴 때 마주치는 현실:**

```python
# 바이브코딩으로 만든 간단한 AI 챗봇
import openai

def chat(user_message):
    response = openai.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": user_message}]
    )
    return response.choices[0].message.content

# 로컬에서는 잘 돌아감
# 그런데 이걸 100명이 동시에 쓰려면?
# → 서버가 필요하고, 그 서버는 클라우드에 있어야 함
```

### Before: 클라우드 개념 없이 배포하기

```
AI 앱 완성 → "일단 어디다 올리지?" → AWS 검색 → EC2 생성
→ 24시간 켜둠 → 한 달 뒤 청구서 $300 → 당황
→ 사용하지 않는 리소스 방치 → 비용 계속 누적
```

### After: 클라우드 구조를 이해하고 배포하기

```
AI 앱 완성 → 트래픽 예상 → 적절한 서비스 모델 선택
→ 예산 알림 설정 → 사용량 기반 과금 활용
→ 비용 예측 가능 → 안정적 운영
```

## 클라우드의 다섯 가지 필수 특성

NIST SP 800-145에서는 클라우드 컴퓨팅의 필수 특성을 다섯 가지로 정리합니다. 이 중 하나라도 빠지면 엄밀히는 클라우드가 아닙니다.

| 특성 | 설명 | 바이브코딩 관점 |
| --- | --- | --- |
| 온디맨드 셀프서비스 | 사람 개입 없이 자원을 프로비저닝 | AI 앱 배포를 코드 한 줄로 시작 가능 |
| 광범위한 네트워크 접근 | 어디서든 인터넷으로 접근 | 팀원, 사용자 모두 접근 가능 |
| 리소스 풀링 | 여러 고객이 인프라를 공유 | 비용이 낮아지는 이유 |
| 빠른 탄력성 | 수요에 따라 자동 확장·축소 | 갑자기 트래픽이 몰려도 앱이 버팀 |
| 측정 가능한 서비스 | 사용량 기반 과금 | 쓴 만큼만 비용 발생 |

```python
# AWS SDK(boto3)로 S3 버킷 생성 - 온디맨드 셀프서비스의 실제 예
import boto3

s3 = boto3.client("s3")

def create_bucket(name: str):
    s3.create_bucket(Bucket=name)
    return name

def upload(bucket: str, key: str, data: bytes):
    s3.put_object(Bucket=bucket, Key=key, Body=data)
    return f"s3://{bucket}/{key}"

# AI 앱 결과물을 클라우드 스토리지에 저장
result_url = upload("my-ai-app-bucket", "output.json", b'{"result": "success"}')
print(result_url)
```

## 온프레미스 vs 클라우드: AI 앱 배포 관점

| 비교 항목 | 온프레미스 | 클라우드 |
| --- | --- | --- |
| 시작 비용 | 서버 구매 수백만 원~ | 0원 (쓴 만큼) |
| 배포 시간 | 며칠~몇 주 | 몇 분 |
| AI 모델 서빙 | GPU 서버 직접 구매 | GPU 인스턴스 시간 단위 대여 |
| 확장 | 서버 추가 주문 | 클릭 한 번 |
| 폐기 | 서버 처분 필요 | 리소스 삭제로 즉시 종료 |

**바이브코딩 관점에서 핵심:** AI 앱 아이디어를 빠르게 검증할 수 있습니다. 실패해도 서버 구매 비용은 없습니다. 사용한 시간만큼만 냅니다.

---

## 공동 책임 모델: AI 앱 배포자가 알아야 할 것

클라우드에 올렸다고 보안 걱정이 없어지는 게 아닙니다. 책임이 나뉠 뿐입니다.

| 운영 항목 | AWS가 책임 | 바이브코더가 책임 |
| --- | --- | --- |
| 데이터센터 물리 보안 | O | X |
| 하이퍼바이저 | O | X |
| OS 패치 (EC2 기준) | X | O |
| AI 모델 접근 권한 | X | O |
| API 키 관리 | X | O |
| S3 버킷 공개 설정 | X | O |

**가장 흔한 실수:** AI 앱의 API 키를 코드에 하드코딩하거나, S3 버킷을 실수로 공개 설정하는 경우입니다. 이건 AWS가 막아주지 않습니다.

---

## 자주 하는 실수

| 실수 | 설명 | 올바른 접근 |
| --- | --- | --- |
| 루트 계정으로 모든 작업 | 계정 전체가 위험에 노출됨 | IAM 사용자 생성, 루트 계정 잠금 |
| 예산 알림 미설정 | 청구서 폭탄 | 월 예산과 50/80/100% 알림 설정 |
| 테스트 리소스 방치 | 쓰지 않아도 비용 발생 | 실습 후 즉시 삭제 습관 |
| API 키 코드에 하드코딩 | 키 유출 시 전체 계정 위험 | 환경 변수나 Secrets Manager 사용 |
| 리전 무시 | 비용과 지연 시간에 영향 | 사용자 위치에 맞는 리전 선택 |

## AI 팁: 바이브코딩으로 클라우드 리소스 관리하기

1. **AI에게 인프라 코드 생성 요청**: "AWS에 Flask 앱을 배포하는 코드 작성해줘"라고 하면 boto3 코드를 만들어줍니다. 하지만 비용과 보안 설정은 직접 검토해야 합니다.
2. **비용 감각 유지**: AI가 생성한 코드가 어떤 AWS 서비스를 쓰는지 파악하세요. m5.2xlarge를 t3.micro 대신 쓰면 비용이 10배입니다.
3. **환경 변수 습관**: API 키는 절대 코드에 넣지 마세요. `.env` 파일과 `python-dotenv`를 기본 패턴으로 사용합니다.
4. **정리 코드도 함께 작성**: 생성 코드를 AI에게 요청할 때 삭제 코드도 같이 요청하세요.

- [ ] 테스트로 만든 리소스를 삭제하는 습관이 있다

## 처음 질문으로 돌아가기

- **클라우드가 온프레미스 서버와 근본적으로 다른 점은 무엇인가요?**
  초기 투자 없이 즉시 시작하고, 사용한 만큼만 비용을 내며, 확장과 축소가 자동화됩니다. AI 앱 아이디어를 빠르게 검증할 수 있는 이유입니다.

- **공동 책임 모델은 바이브코더에게 왜 중요한가요?**
  AWS가 데이터센터를 지켜도, AI 앱의 API 키 관리나 S3 버킷 공개 설정은 개발자 책임입니다. "클라우드에 올렸으니 보안은 AWS가 알아서"는 틀린 생각입니다.

- **AI 앱을 배포할 때 비용이 갑자기 커지는 이유는 무엇인가요?**
  테스트 리소스 방치, 불필요하게 큰 인스턴스 선택, 예산 알림 미설정이 주요 원인입니다. 클라우드는 편리한 만큼 방치하면 비용이 조용히 쌓입니다.

클라우드는 AI 앱을 세상에 내놓는 기반입니다. 온디맨드, 탄력성, 종량제 과금이라는 세 가지 특성을 이해하면 왜 바이브코딩과 클라우드가 잘 맞는지 알 수 있습니다. 다음 글에서는 IaaS, PaaS, SaaS의 차이와 AI 앱을 어떤 모델로 배포해야 하는지 살펴봅니다.
