# 바이브코딩을 위한 MLOps 기초 (7/10): 데이터 드리프트와 모델 드리프트

이 글은 "바이브코딩을 위한 MLOps 기초" 시리즈의 7번째 글입니다.

---

바이브코딩에서 AI는 ML 모니터링 코드를 빠르게 만들어 줍니다. 그런데 많은 팀이 "정확도 하락"만 보고 뒤늦게 문제를 인지합니다. 실제 현장에서는 입력 분포 변화가 먼저 나타나고, 그다음에야 비즈니스 손실이나 성능 저하가 보이는 경우가 많습니다.

운영 중인 모델이 예전 같지 않다고 느껴질 때, 원인은 하나가 아닙니다. 입력 데이터 분포가 바뀌었을 수도 있고(데이터 드리프트), 입력은 비슷한데 레이블과의 관계가 바뀌었을 수도 있습니다(개념 드리프트). 둘을 구분하지 않으면 대응도 자꾸 헛짚게 됩니다.

세상은 멈추지 않습니다. 사용자 행동도, 계절성도, 정책도 계속 바뀝니다. 학습 시점에는 정상적이던 분포가 한 달 뒤에도 그대로 유지된다고 가정하는 순간 운영 모델은 서서히 낡기 시작합니다.

데이터 드리프트와 모델 드리프트의 차이, PSI와 KS 검정을 통한 조기 탐지, MLflow 모델 레지스트리 연동을 중심으로 정리합니다.

> **핵심 인사이트:** 드리프트 감지 없이는 손실이 조용히 쌓입니다. PSI > 0.2면 분포가 크게 바뀐 신호입니다. 기준선(baseline)을 학습 데이터에서 잡아야 드리프트가 제대로 보입니다.

## 이 글에서 다룰 문제

- 데이터 드리프트와 모델 드리프트는 무엇이 다를까요?
- 왜 기준 분포를 잘못 잡으면 드리프트가 안 보이게 될까요?
- PSI와 KS 검정은 어떤 상황에서 유용할까요?
- 드리프트 감지를 재학습 트리거와 어떻게 연결할까요?
- AI가 만든 드리프트 감지 코드에서 확인해야 할 것은 무엇인가요?

## 드리프트 감지 핵심 패턴

```python
import numpy as np

# PSI (Population Stability Index): 분포 안정성 지표
# PSI < 0.1 → 안정, 0.1~0.2 → 주의, > 0.2 → 드리프트
def psi(base, live, bins=10):
    base_hist, edges = np.histogram(base, bins=bins, density=True)
    live_hist, _ = np.histogram(live, bins=edges, density=True)
    base_hist = np.where(base_hist == 0, 1e-4, base_hist)
    live_hist = np.where(live_hist == 0, 1e-4, live_hist)
    return np.sum((live_hist - base_hist) * np.log(live_hist / base_hist))

# 예시: 기준 데이터(학습 시점) vs 현재 데이터(운영 중)
base = np.random.normal(0, 1, 1000)    # 학습 시점 분포
live = np.random.normal(0.5, 1, 1000)  # 운영 중 분포 (이동됨)

score = psi(base, live)
print(f"PSI: {score:.3f}")
if score > 0.2:
    print("경고: 심각한 드리프트 감지 → 재학습 검토 필요")
```

```python
# KS 검정: 두 연속 분포의 차이를 수치로 비교
from scipy.stats import ks_2samp

stat, p_value = ks_2samp(base, live)
print(f"KS statistic: {stat:.3f}, p-value: {p_value:.4f}")
if p_value < 0.05:
    print("통계적으로 유의미한 분포 차이 감지")
```

## 변경 전후 비교

**Before: 드리프트 감지 없음**
```text
- 비즈니스 손실이 실제로 발생한 후에야 정확도 하락 인지
- 원인이 데이터인지 모델인지 구분 불가
- 재학습 시점을 감으로 결정
- 어떤 피처가 드리프트했는지 파악 불가
```

**After: PSI 기반 드리프트 감지**
```text
- PSI > 0.2 감지 시 자동 알림 → 즉시 조사 시작
- 피처별 PSI로 드리프트 발생 피처 특정
- 데이터 드리프트 vs 개념 드리프트 구분 가능
- 드리프트 이력으로 재학습 주기 데이터 기반 결정
```

## 자주 하는 실수

| 실수 | 왜 문제인가 | 해결 방법 |
|------|-------------|-----------|
| 기준선을 최근 데이터로 잡음 | 드리프트가 기준선과 함께 이동해 안 보임 | 학습 시점 데이터를 기준선으로 고정 |
| 정확도만 모니터링 | 라벨 없으면 측정 불가 | 입력 분포 변화를 선행 지표로 활용 |
| PSI 임계값 없이 숫자만 확인 | 언제 행동할지 모름 | PSI > 0.1 경고, > 0.2 재학습 트리거 |
| 전체 분포만 확인 | 특정 피처 드리프트를 놓침 | 피처별 PSI 계산 |
| 드리프트와 재학습 연결 없음 | 경보가 떠도 행동이 없음 | 드리프트 → 재학습 트리거 자동화 |

## 운영 체크리스트

- [ ] 학습 데이터에서 기준 분포를 저장하고 고정한다
- [ ] 피처별 PSI를 주기적으로(일별/주별) 계산한다
- [ ] PSI > 0.1 경고, PSI > 0.2 재학습 트리거 임계값이 있다
- [ ] 드리프트 메트릭이 MLflow 또는 대시보드에 기록된다
- [ ] 데이터 드리프트와 개념 드리프트를 구분하는 절차가 있다

## 처음 질문으로 돌아가기

- **데이터 드리프트와 개념 드리프트의 차이는?** 데이터 드리프트는 입력 X의 분포가 달라지는 현상입니다. 개념 드리프트는 X와 Y(레이블)의 관계 자체가 바뀌는 현상입니다. 동일한 입력이어도 정답이 달라집니다.
- **PSI가 유용한 이유는?** 0.1 미만은 안정, 0.1~0.2는 주의, 0.2 이상은 심각 변화로 해석되어 임계값 기반 자동화에 적합합니다. 라벨 없이도 입력 분포만으로 계산 가능합니다.
- **기준선을 학습 데이터로 고정해야 하는 이유는?** 최근 데이터를 기준선으로 쓰면 드리프트가 기준선과 함께 이동해 변화가 감지되지 않습니다. 모델 학습 시점 분포가 진짜 기준입니다.

## 정리

바이브코딩에서 AI가 만들어 준 드리프트 감지 코드에서 기준선 고정, 피처별 PSI 계산, 임계값 기반 자동화를 반드시 확인하세요. 드리프트 감지가 없으면 손실이 조용히 쌓입니다. 다음 글에서는 재학습을 다룹니다.
